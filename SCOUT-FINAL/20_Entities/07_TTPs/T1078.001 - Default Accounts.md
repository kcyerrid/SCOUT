# Default Accounts (T1078.001)

## 1. Summary
Default Accounts describes adversary use of pre-configured or vendor-supplied accounts that are present on systems, applications, network devices, or cloud services. These accounts are often well known, poorly monitored, or left unchanged after deployment, making them attractive targets for initial access and persistence.

This subtechnique is particularly dangerous because exploitation may not require malware or exploits, relying instead on weak configuration and credential hygiene.

---

## 2. Technical Overview
Default accounts are created automatically by operating systems, applications, appliances, or cloud services. Examples include built-in administrator accounts, service accounts, or vendor maintenance credentials.

Adversaries abuse these accounts by:
- Using unchanged default passwords
- Guessing or brute-forcing well-known credentials
- Leveraging default API keys or tokens
- Accessing management interfaces exposed to the internet

Artifacts include authentication events, management interface access logs, and cloud identity activity.

---

## 3. Subtechnique Considerations
T1078.001 differs from other Valid Account subtechniques by focusing on **accounts that exist by design**, rather than those created or compromised through user activity.

This subtechnique is especially relevant in:
- Network appliances and OT environments
- SaaS platforms with default tenant admins
- Cloud services with auto-provisioned roles
- Legacy systems lacking identity governance

---

## 4. Procedure Examples
Observed adversary procedures include:
- Logging into exposed devices using vendor default credentials
- Accessing SaaS admin portals with unchanged default passwords
- Leveraging default cloud service accounts to enumerate resources
- Maintaining persistence via overlooked built-in administrator accounts

Analysts may observe successful logins shortly after deployment or following external scanning activity.

---

## 5. Detection Guidance
Detection strategies should emphasize configuration-aware monitoring:
- Authentication events involving default or built-in accounts
- Successful logins without prior credential rotation
- Access to management interfaces from untrusted networks
- Cloud role usage inconsistent with expected baselines

### Data Source Notes
- **Authentication Logs:** High signal when default account names are tracked
- **Network Traffic:** Useful for identifying exposed management interfaces
- **Cloud Logs:** Strong signal when default roles are abused

---

## 6. Response Guidance
When Default Account abuse is suspected:
- Immediately disable or rotate credentials
- Restrict network access to management interfaces
- Audit usage of built-in and vendor accounts
- Assess environment for additional misconfigurations

Preserve authentication and configuration logs for investigation.

## 8. SOC Relevance
Default Account abuse remains a common root cause of breaches, particularly in cloud, network device, and SaaS environments. Detection maturity is often low due to poor inventory and weak configuration management.

This subtechnique represents a high-impact, low-complexity threat vector.

---

## 9. Threat Actor Usage
Default Accounts are frequently abused by:
- Ransomware affiliates seeking rapid access
- Opportunistic cybercriminals scanning the internet
- Advanced actors exploiting weak operational hygiene

Confidence in widespread usage is high.

---

## 10. Campaign Usage
This subtechnique appears in:
- Ransomware campaigns targeting exposed infrastructure
- Cloud tenant compromise incidents
- Appliance and network device exploitation campaigns

---

## 11. Malware Usage
While Default Account abuse often does not require malware, follow-on tooling may include:
- [[30_CIPHER/05_Malware/S0154 - Cobalt Strike|Cobalt Strike]]
- [[30_CIPHER/05_Malware/S0266 - TrickBot|TrickBot]]

These tools are typically deployed after access is established.

---

## 12. Mitigations
Effective mitigations include:
- Disabling or renaming default accounts
- Enforcing credential rotation at deployment
- Restricting management access by network location
- Continuous configuration monitoring
- Applying vendor hardening guides

---

## 13. Testing & Validation
Validation approaches include:
- Auditing systems for active default accounts
- Purple team simulations of default credential abuse
- Controlled testing of management interface access

Success criteria include detection of unauthorized access and timely alerting.
