# Masquerading: Masquerade File Type (T1036.008)

## 1. Summary
Masquerade File Type describes adversaries **causing a file to appear as a different type than it actually is**, misleading users and defenders about its true behavior. This is commonly achieved by manipulating file extensions, icons, metadata, or container formats so that executable content appears to be a benign document, image, or archive.

Attackers use this technique to:
- Trick users into opening malicious files
- Bypass file-type–based security controls
- Reduce suspicion during manual review
- Increase the effectiveness of social engineering

---

## 2. Technical Overview
Operating systems and applications infer file type using a combination of file extensions, MIME types, headers (magic bytes), and icons. Adversaries exploit inconsistencies in this model by:

- Assigning misleading extensions to executable content
- Embedding executable code within container formats
- Manipulating file headers to confuse content inspection
- Using document formats that support embedded code or scripts

Key characteristics:
- File extension does not reflect true content
- MIME type and file header may mismatch
- User-facing icon suggests benign content
- Execution or scripting occurs after user interaction

Indicators include:
- Discrepancies between file extension and MIME type
- Executables masquerading as documents or images
- Files triggering execution when opened unexpectedly
- Security controls bypassed due to misclassification

---

## 3. Subtechnique Considerations
Key considerations for T1036.008:
- Frequently overlaps with **Double File Extension (T1036.007)**
- Commonly paired with **User Execution (T1204)**
- Often combined with **Obfuscated Files or Information (T1027)**
- Relies on gaps between UI representation and actual content

This technique is particularly effective in **email- and download-based delivery chains**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering executable content disguised as documents
- Using container formats to conceal payloads
- Manipulating file headers to mislead scanners
- Exploiting applications that auto-execute embedded content

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **content validation over appearance**:
- Compare file headers to declared file types
- Validate MIME types during ingestion
- Alert on execution triggered by non-executable file types
- Monitor for abnormal behavior following file open events

### Data Source Notes
- **Email gateway logs**: Detect mismatched attachments
- **File system telemetry**: Identify anomalous file properties
- **EDR telemetry**: Capture execution context

Common false positives:
- Legitimate container formats
- Complex document types with embedded media

Tuning guidance:
- Focus on externally sourced files
- Elevate severity when file-type anomalies precede execution

---

## 6. Response Guidance
When suspected:
1. Quarantine the suspicious file
2. Inspect file headers and metadata
3. Identify delivery vector and affected users
4. Remove malicious content safely
5. Expand hunt for similar masqueraded files

## 8. SOC Relevance
T1036.008 is highly relevant when:
- Files behave differently than expected when opened
- File-type–based controls fail
- Users report unexpected execution events

It highlights the need for **deep content inspection**.

---

## 9. Threat Actor Usage
Commonly used by:
- Phishing operators
- Malware distributors
- Initial access brokers

---

## 10. Campaign Usage
Observed in:
- Email-delivered malware campaigns
- Drive-by download operations
- Opportunistic intrusion attempts

---

## 11. Malware Usage
Associated with:
- Trojans and droppers
- Malware embedded in documents or archives
- Payloads requiring user interaction

---

## 12. Mitigations
Recommended mitigations:
- Enforce content-based file inspection
- Block or sandbox suspicious file types
- Disable auto-execution of embedded content
- Educate users on file-type deception

---

## 13. Testing & Validation
Validation approaches:
- Deliver benign test files with mismatched headers
- Validate alerts on file-type anomalies
- Test SOC workflows for deceptive file delivery
