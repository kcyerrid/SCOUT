# AppleScript (T1059.002)

## 1. Summary
AppleScript describes adversary abuse of Apple’s native scripting language on macOS to execute commands, automate actions, and interact with system components and applications. Because AppleScript is designed for legitimate automation and application control, malicious usage can blend into normal user and system activity.

This subtechnique is most commonly observed in macOS-focused intrusion campaigns and malware targeting developer or executive workstations.

---

## 2. Technical Overview
AppleScript enables automation of macOS applications and system functions through high-level scripting constructs. Scripts can be executed via:
- `osascript`
- Embedded AppleScript within applications
- Script files (`.scpt`, `.applescript`)
- Application bundles containing AppleScript components

Adversaries may use AppleScript to launch shell commands, manipulate files, prompt users for credentials, or interact with other applications. Execution artifacts include `osascript` process creation, Apple Unified Log entries, and file access events.

---

## 3. Subtechnique Considerations
T1059.002 is specific to macOS environments and differs from other interpreter-based subtechniques by:
- Deep integration with GUI applications
- Ability to automate user interactions
- Reliance on macOS privacy and automation permissions (TCC)

Attackers may abuse user-granted permissions to bypass security controls.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Using AppleScript to execute shell commands via `do shell script`
- Embedding AppleScript within malicious application bundles
- Prompting users with fake dialogs to capture credentials
- Automating execution of secondary payloads

Analysts may observe script execution without traditional terminal usage.

---

## 5. Detection Guidance
Detection should focus on:
- Execution of `osascript` from unexpected parent processes
- AppleScript launching shell interpreters or network tools
- Script execution shortly after user interaction
- AppleScript files executing from unusual directories

Correlation between Unified Logs and process execution improves detection fidelity.

### Data Source Notes
- **Process Execution:** Primary indicator of script execution
- **Unified Logs:** Provide contextual execution details
- **File Creation:** Useful for identifying dropped scripts

---

## 6. Response Guidance
When malicious AppleScript activity is suspected:
- Identify and terminate malicious script execution
- Remove associated script files or application bundles
- Review TCC permissions granted to affected applications
- Assess for follow-on payload execution

Preserve Unified Logs and script artifacts for forensic analysis.

## 8. SOC Relevance
AppleScript abuse is less prevalent than PowerShell but represents a significant risk in macOS environments with limited endpoint visibility. SOCs supporting macOS fleets must ensure adequate process and script execution telemetry.

---

## 9. Threat Actor Usage
This subtechnique has been observed in:
- macOS-focused malware campaigns
- Targeted intrusions against executives and developers
- Social engineering-driven attacks

Confidence in moderate usage is medium.

---

## 10. Campaign Usage
AppleScript execution has appeared in:
- macOS malware delivery campaigns
- Phishing-based initial access chains
- Post-exploitation automation on macOS endpoints

## 12. Mitigations
Effective mitigations include:
- Restricting AppleScript execution where possible
- Monitoring `osascript` usage
- Enforcing macOS privacy (TCC) controls
- Reviewing automation permissions granted to applications
- Applying least-privilege principles

---

## 13. Testing & Validation
Validation approaches include:
- Simulated AppleScript execution via `osascript`
- Purple team testing of script-based execution
- Review of detection logic for script execution anomalies

Successful validation results in detection of unauthorized AppleScript activity.
