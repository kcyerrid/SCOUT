# Process Injection: Thread Local Storage (T1055.005)

## 1. Summary
Thread Local Storage (TLS) Injection describes adversaries **abusing the TLS callback mechanism in Windows Portable Executable (PE) files** to execute malicious code when a thread or process is initialized. TLS callbacks execute before the program’s entry point, making them an effective stealth mechanism for early execution.

T1055.005 is commonly used to:
- Execute payloads before normal application logic
- Evade static and dynamic analysis
- Hide malicious execution paths
- Support stealthy persistence or loader functionality

---

## 2. Technical Overview
Windows PE files support TLS callbacks that are executed by the loader when a process or thread starts. Adversaries abuse this by:
- Injecting or modifying PE structures in memory
- Registering malicious TLS callback functions
- Triggering execution during process or thread initialization
- Executing payloads before main program logic runs

Artifacts often include:
- PE images with abnormal TLS directories
- Execution occurring prior to standard entry points
- In-memory modifications to executable structures
- Legitimate processes performing unexpected actions early in execution

---

## 3. Subtechnique Considerations
Key considerations for T1055.005:
- Execution occurs very early in process lifecycle
- Difficult to observe with traditional runtime hooks
- Often combined with packing or obfuscation
- Detection requires PE structure awareness

TLS injection is favored for stealthy loaders and advanced malware.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting a malicious PE with TLS callbacks into a target process
- Modifying TLS directories of in-memory executables
- Executing payloads before security products fully initialize
- Combining TLS callbacks with reflective loaders

These actions typically occur during process creation or early execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying abnormal TLS callbacks in loaded modules
- Detecting execution before expected entry points
- Monitoring in-memory PE structure manipulation
- Correlating early execution with suspicious behavior

### Data Source Notes
- **Module load telemetry**: Required for TLS directory inspection
- **Memory telemetry**: Critical for detecting in-memory PE tampering
- **Process telemetry**: Useful for timing-based anomaly detection

---

## 6. Response Guidance
When suspected:
1. Identify affected processes and injected modules
2. Isolate compromised systems
3. Capture memory images for forensic analysis
4. Remove malicious payloads from disk if present
5. Investigate for follow-on persistence or injection techniques

## 12. Mitigations
Recommended mitigations:
- Inspect TLS callbacks in executable analysis pipelines
- Use EDR capable of early-process monitoring
- Monitor abnormal module initialization behavior
- Restrict execution of untrusted binaries
- Apply least privilege principles
