# Impair Defenses: Disable or Modify Network Device Firewall (T1562.013)

## 1. Summary
Disable or Modify Network Device Firewall describes adversaries **tampering with firewalls on network devices**—such as routers, switches, perimeter firewalls, or network security appliances—to weaken network protections. By altering or disabling these controls, attackers enable unauthorized access, lateral movement, and command-and-control traffic.

Attackers use this technique to:
- Open inbound or outbound network paths
- Bypass perimeter and internal segmentation
- Facilitate lateral movement and persistence
- Conceal malicious traffic from monitoring tools

---

## 2. Technical Overview
Network device firewalls enforce traffic rules at infrastructure boundaries. Adversaries impair these defenses by:

- Disabling firewall services on network appliances
- Modifying access control lists (ACLs) or rule sets
- Adding overly permissive allow rules
- Removing deny rules protecting sensitive segments
- Disabling firewall logging or inspection features

Common targets include:
- Enterprise perimeter firewalls
- Network routers and switches with ACLs
- Virtual appliances in cloud or data center environments

Typical indicators include:
- Unexpected firewall rule changes
- Sudden exposure of previously protected services
- Firewall logging disabled or reduced
- Network traffic flows inconsistent with baseline

---

## 3. Subtechnique Considerations
Key considerations for T1562.013:
- Often follows **network or identity compromise**
- Strongly overlaps with lateral movement and C2 enablement
- Requires administrative access to network devices
- High-confidence indicator of malicious intent

Firewall modification on network devices is rarely routine outside approved change windows.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Opening management ports on network devices
- Allowing unrestricted inbound or outbound traffic
- Removing segmentation rules between network zones
- Disabling inspection or logging features

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **firewall configuration integrity**:
- Alert on firewall rule creation, deletion, or modification
- Detect changes broadening access scope
- Monitor for logging or inspection disablement
- Correlate firewall changes with suspicious identity activity

### Data Source Notes
- **Firewall configuration logs**: Primary detection source
- **Network device logs**: Track administrative actions
- **Network flow logs**: Detect newly allowed traffic paths

Common false positives:
- Planned network maintenance
- Approved change management activities

Tuning guidance:
- Require approvals for firewall modifications
- Baseline expected rules per device and segment

---

## 6. Response Guidance
When suspected:
1. Immediately review and revert unauthorized firewall changes
2. Identify exposed services and time windows
3. Investigate network traffic during exposure
4. Audit administrative access to network devices
5. Rotate credentials and strengthen access controls

## 8. SOC Relevance
T1562.013 is **critical for network-centric environments**. Network device firewall changes often enable broad attacker movement and should be treated as high-severity incidents.

---

## 9. Threat Actor Usage
This technique is used by:
- Advanced persistent threat groups
- Ransomware operators targeting network infrastructure
- Actors conducting hands-on-keyboard network intrusions

Its use indicates **strategic control over network defenses**.

---

## 10. Campaign Usage
Observed in:
- Network infrastructure compromise campaigns
- Data center and cloud hybrid intrusions
- Attacks involving exposed management interfaces

---

## 11. Malware Usage
Associated with:
- Post-exploitation frameworks
- Automation scripts abusing network management APIs
- Malware leveraging compromised network credentials

---

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege for network device administration
- Require MFA for network management access
- Monitor and alert on firewall configuration changes
- Use immutable configuration and version control
- Segment management planes from user networks

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign firewall changes in lab environments
- Validate alerts on rule modifications
- Test SOC response to network exposure events
- Ensure rollback procedures are documented and effective
