## 1. Summary
ARP cache poisoning positions an adversary within a local network segment by deceiving hosts about the correct IP↔MAC mapping, enabling interception, observation, and possible manipulation of traffic. This can facilitate credential interception and collection of sensitive data transmitted over insecure protocols.

## 2. Technical Overview
- ARP resolves IPv4 addresses to link-layer MAC addresses on a LAN.
- Because ARP is stateless and lacks authentication, endpoints may accept malicious updates:
  - **Fast response to ARP requests** to beat the legitimate host reply
  - **Gratuitous ARP** announcements to broadcast false ownership of an IP address
- Once victims map the adversary’s MAC to a target IP, traffic can be redirected through the adversary-controlled system.

## 3. Subtechnique Considerations
- ARP poisoning is **LAN-local**; detections should key on **segment boundaries** (VLANs, wired vs wireless).
- Strongly impacted by network defenses:
  - Dynamic ARP Inspection (DAI), DHCP snooping, and static ARP entries can reduce attack viability.
- Correlate ARP anomalies with authentication events and new sessions to sensitive services.

## 4. Procedure Examples
Documented examples include:
- [[30_CIPHER/03_Threat_Actors/G0003 - Cleaver|Cleaver]]: used custom tooling to facilitate ARP cache poisoning.
- [[30_CIPHER/03_Threat_Actors/G1014 - LuminousMoth|LuminousMoth]]: used ARP spoofing to redirect a compromised machine to an actor-controlled website.

## 5. Detection Guidance
Detection strategy emphasizes identifying anomalous ARP traffic and ARP cache modifications:
- **Network indicators**
  - Multiple IP addresses resolving to a single MAC address
  - Unsolicited ARP replies from unauthorized devices
  - Repeated gratuitous ARP replies and inconsistent IP↔MAC mappings
- **Endpoint indicators**
  - Sudden ARP table churn (frequent changes to gateway/critical hosts)
  - New outbound sessions or authentication attempts following ARP anomalies
- **Correlation**
  - ARP anomalies → unexpected network sessions → abnormal authentication events

### Data Source Notes
Telemetry commonly used in detection strategies:
- Packet capture/IDS for ARP request/reply and gratuitous ARP patterns
- Endpoint logging for ARP cache changes (where available) and network session creation
- Network infrastructure logs for DAI/DHCP snooping triggers (if enabled)

## 6. Response Guidance
1. Identify the poisoned segment and likely source MAC(s); isolate suspected host(s).
2. Validate integrity of gateway/critical ARP entries (switch CAM tables, endpoint ARP tables).
3. Look for follow-on impacts: credential use, lateral movement, redirections, or data interception.
4. Remediate: flush ARP caches as appropriate, enforce DAI/DHCP snooping, consider static ARP for critical infrastructure.

## 8. SOC Relevance
Common in internal intrusion chains because it is:
- Fast to execute on flat networks
- High payoff when legacy/insecure protocols exist
- Detectable with strong network baselining (ARP “who-has/is-at” consistency)

Operational best practices:
- Alert on IP↔MAC mapping conflicts for gateways and high-value servers.
- Treat repeated gratuitous ARP bursts as priority when paired with new sessions/auth events.

## 12. Mitigations
- **M1042 Disable or Remove Feature or Program:** Consider disabling ARP cache updates on gratuitous ARP replies where feasible.
- **M1041 Encrypt Sensitive Information:** Ensure wired/wireless traffic is encrypted; use strong authentication (e.g., Kerberos).
- **M1037 Filter Network Traffic:** Enable DHCP snooping and Dynamic ARP Inspection on switches to block bogus mappings.
- **M1035 Limit Access to Resource Over Network:** Use static ARP entries for critical devices (where feasible).
- **M1031 Network Intrusion Prevention:** Deploy NIDS/NIPS to detect AiTM patterns.
- **M1017 User Training:** Train users to treat certificate errors as suspicious (possible interception).

## 13. Testing & Validation
- Validate detections for:
  - Unsolicited ARP replies and IP↔MAC conflicts
  - Correlation between ARP anomalies and subsequent abnormal sessions/auth
- Verify prevention controls (DAI/DHCP snooping) generate actionable logs and block expected patterns in a controlled test network.
