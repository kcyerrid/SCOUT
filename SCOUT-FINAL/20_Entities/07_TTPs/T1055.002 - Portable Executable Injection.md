# Process Injection: Portable Executable Injection (T1055.002)

## 1. Summary
Portable Executable (PE) Injection describes adversaries **injecting a full Windows PE file (EXE or DLL) into the address space of another process** and executing it from memory. Unlike simple shellcode injection, this technique maps an entire executable image into memory, preserving its structure and functionality while avoiding writing the file to disk.

T1055.002 is commonly used to:
- Execute complex payloads stealthily
- Evade file-based detection and allowlisting
- Run malware within trusted process contexts
- Enable persistence, credential access, or lateral movement

---

## 2. Technical Overview
Windows PE files consist of headers and sections that must be correctly mapped into memory to execute. Adversaries perform PE injection by:
- Allocating memory in a remote process
- Writing the PE headers and sections into memory
- Resolving imports and relocations manually or via loaders
- Transferring execution to the PE entry point

Common APIs and mechanisms involved:
- `VirtualAllocEx`
- `WriteProcessMemory`
- `CreateRemoteThread`
- Manual PE loaders (reflective loaders)

Artifacts often include:
- Executable memory regions resembling PE structures
- Loaded modules without corresponding files on disk
- Remote thread creation in trusted processes
- Unusual memory permission changes (RW → RX)

---

## 3. Subtechnique Considerations
Key considerations for T1055.002:
- More complex than DLL injection but more flexible
- Enables execution of full-featured malware
- Requires careful memory manipulation
- Detection depends on deep memory inspection

This subtechnique is favored by sophisticated malware frameworks.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting PE payloads into `svchost.exe` or `explorer.exe`
- Using reflective loaders to execute EXEs from memory
- Loading secondary-stage malware via PE injection
- Pairing injection with encrypted payload staging

These actions typically occur after initial access or loader execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying PE headers in memory without backing files
- Detecting remote thread creation targeting trusted processes
- Monitoring anomalous memory allocation and protection changes
- Correlating injection behavior with prior process access

### Data Source Notes
- **Memory telemetry**: Essential for detecting in-memory PE artifacts
- **Module load data**: Useful for spotting phantom modules
- **API telemetry**: Required to identify PE injection patterns

---

## 6. Response Guidance
When suspected:
1. Identify affected processes hosting injected PEs
2. Isolate impacted systems
3. Capture memory images for forensic analysis
4. Terminate malicious processes if safe to do so
5. Investigate for additional injection or persistence mechanisms

## 8. SOC Relevance
T1055.002 is highly relevant in:
- Advanced malware intrusions
- Fileless or memory-resident attacks
- Environments relying heavily on signature-based detection

PE injection enables powerful payload execution with minimal disk artifacts.

## 11. Malware Usage
Malware leveraging PE injection includes:
- Reflective loaders
- In-memory backdoors
- Advanced ransomware loaders

---

## 12. Mitigations
Recommended mitigations:
- Use EDR with memory inspection and behavior analysis
- Monitor and block suspicious remote thread creation
- Enable exploit mitigation features (DEP, ASR rules)
- Restrict inter-process memory access
- Apply least privilege principles
