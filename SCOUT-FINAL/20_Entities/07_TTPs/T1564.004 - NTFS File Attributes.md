# Hide Artifacts: NTFS File Attributes (T1564.004)

## 1. Summary
NTFS File Attributes describes adversaries **abusing NTFS file attribute flags to conceal malicious files and directories from casual user discovery**. By setting attributes such as *Hidden*, *System*, or *Not Content Indexed*, attackers reduce the likelihood that payloads or supporting artifacts will be noticed during normal system use.

T1564.004 is commonly used to:
- Conceal payloads, tooling, and configuration files
- Reduce visibility during post-exploitation staging
- Support stealthy persistence mechanisms
- Complement other artifact-hiding techniques

---

## 2. Technical Overview
NTFS supports multiple file attribute flags that affect how files are displayed, indexed, and handled by the operating system. Adversaries commonly abuse:

- **Hidden (`FILE_ATTRIBUTE_HIDDEN`)**
- **System (`FILE_ATTRIBUTE_SYSTEM`)**
- **Not Content Indexed**
- **Archive** (in some cases to blend with backup workflows)

Attackers may set or modify attributes using:
- Native Windows utilities
- Scripting engines
- Windows APIs for file metadata manipulation

Typical artifacts and indicators include:
- Executable files with hidden/system attributes
- Attribute changes immediately following file creation
- Execution of binaries from directories containing hidden files
- Attribute modifications performed by non-interactive processes

---

## 3. Subtechnique Considerations
Key considerations for T1564.004:
- Attribute changes alone are low signal; **context matters**
- High risk when applied to executable content
- Often paired with:
  - Permission modification (T1222)
  - Execution flow hijacking (T1574)
  - Hidden directories (T1564.001)

Detection maturity depends on file metadata telemetry availability.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Dropping a payload and immediately setting Hidden/System attributes
- Concealing configuration or log files used by malware
- Marking persistence-related files to reduce administrator discovery
- Blending malicious files among legitimate hidden system files

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **behavioral context and sequencing**:
- File creation → attribute modification → execution
- Hidden/system attributes on executables in user-writable directories
- Attribute changes initiated by unusual parent processes
- Execution from locations that rarely host hidden binaries

### Data Source Notes
- **File metadata telemetry**: Required for attribute visibility
- **Process telemetry**: Links attribute changes to responsible processes
- **FIM solutions**: Useful for baselining expected attributes

Common false positives:
- Legitimate OS and application files
- Software installers and updaters
- Backup and indexing workflows

Tuning guidance:
- Baseline attribute usage by path and file type
- Elevate alerts when hidden attributes precede execution

---

## 6. Response Guidance
When suspected:
1. Enumerate hidden/system files in affected paths
2. Validate legitimacy via file signing and hash reputation
3. Review creation and attribute modification timelines
4. Check for follow-on execution or persistence
5. Quarantine or remove malicious artifacts after confirmation

## 12. Mitigations
Recommended mitigations:
- Monitor attribute changes on executable files
- Restrict execution from user-writable directories
- Use EDR to enumerate hidden/system files
- Baseline file attributes for critical paths
- Pair file metadata monitoring with execution telemetry

---

Validation approaches:
- Create test files and modify attributes in a lab
- Validate alerting on hidden executables
- Test correlation between attribute change and execution
- Review SOC workflows for artifact enumeration
