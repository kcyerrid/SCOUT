# Hide Artifacts: Hidden Files and Directories (T1564.001)

## 1. Summary
Hidden Files and Directories describes adversaries **concealing malicious files or directories by leveraging operating system features that suppress their visibility** in standard user interfaces and directory listings. This technique is used to reduce the likelihood of user discovery and to evade casual inspection by administrators.

T1564.001 commonly supports:
- Stealthy payload staging
- Concealment of persistence artifacts
- Reduced detection during long dwell intrusions
- Support for follow-on execution and persistence

---

## 2. Technical Overview
Operating systems provide mechanisms to hide files and directories:

- **Windows**
  - File attributes such as `Hidden` and `System`
  - Alternate Data Streams (often combined, but distinct techniques)
- **Linux/macOS**
  - Dot-prefixed files/directories (e.g., `.config`, `.cache`)
  - Extended file attributes (where supported)
  - Placement in less-monitored directories

Adversaries may:
- Set hidden/system attributes on payloads
- Store tooling in dot-directories
- Hide configuration and log files alongside legitimate hidden files
- Blend malicious artifacts with OS or application metadata

Typical artifacts include:
- File metadata flags inconsistent with baseline
- Hidden directories containing executable content
- Execution from locations rarely used for binaries
- File creation followed by attribute modification

---

## 3. Subtechnique Considerations
Key considerations for T1564.001:
- Hidden files are common on Unix-like systems; **context is critical**
- Windows hidden/system attributes are higher signal on executable files
- Often paired with:
  - Permission changes (T1222)
  - Execution flow hijacking (T1574)
  - Persistence mechanisms writing to hidden paths

Detection maturity depends heavily on file metadata visibility.

---

## 4. Procedure Examples
Representative adversary patterns include:
- Dropping payloads into dot-directories and marking them executable
- Setting Windows binaries as hidden/system after deployment
- Concealing configuration files and logs to reduce forensic artifacts
- Using hidden directories as staging areas for toolkits

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **behavioral context**, not presence alone:
- Creation of executable files with hidden attributes
- Execution originating from hidden directories
- Hidden files written shortly before persistence or execution
- Attribute changes performed by non-interactive or unusual processes

### Data Source Notes
- **File metadata telemetry**: Required for attribute and flag changes
- **Process telemetry**: Needed to link execution to hidden paths
- **FIM tools**: Useful for baselining expected hidden directories

Common false positives:
- Legitimate application metadata
- OS configuration files
- Developer tooling and caches

---

## 6. Response Guidance
When suspected:
1. Enumerate hidden files and directories on affected hosts
2. Validate legitimacy based on path, file type, and signing
3. Review creation and modification timelines
4. Check for follow-on execution or persistence mechanisms
5. Remove or quarantine malicious artifacts after validation

T1564.001 is relevant when:
- Investigating stealthy intrusions
- Hunting for staging or persistence artifacts
- Responding to “nothing obvious” endpoint alerts

Hidden artifacts often explain missing evidence during triage.

## 9. Threat Actor Usage
This subtechnique is used by:
- Advanced persistent threats
- Ransomware operators
- Commodity malware families seeking stealth

Confidence should be based on corroborating telemetry.

---

## 10. Campaign Usage
Observed in:
- Long-dwell espionage campaigns
- Post-exploitation staging phases
- Ransomware preparation activity

---

## 11. Malware Usage
Commonly associated with:
- Loaders and droppers
- Backdoors that hide configs and payloads
- Toolkits that conceal operational artifacts

---

## 12. Mitigations
Recommended mitigations:
- Monitor execution from hidden paths
- Baseline expected hidden directories per host role
- Use EDR to enumerate hidden files beyond GUI tools
- Restrict write access to sensitive directories
- Pair file monitoring with execution telemetry

---

## 13. Testing & Validation
Validation approaches:
- Create hidden files/directories in a lab and verify alerting
- Test execution from hidden paths
- Validate correlation between attribute changes and execution
- Review SOC playbooks for artifact enumeration steps
