# Abuse Elevation Control Mechanism: TCC Manipulation (T1548.006)

## 1. Summary
This subtechnique describes adversaries abusing **Transparency, Consent, and Control (TCC)** on macOS to gain unauthorized access to protected system resources. TCC is Apple’s privacy framework designed to require explicit user consent before applications can access sensitive data and services such as **Full Disk Access, Screen Recording, Camera, Microphone, and Accessibility**.

Adversaries manipulate TCC controls to:
- Bypass user consent dialogs
- Gain stealthy access to sensitive user data
- Enable surveillance and credential harvesting
- Evade macOS security protections without exploiting kernel vulnerabilities

---

## 2. Technical Overview
macOS enforces TCC decisions via a SQLite database (`TCC.db`) and system policy frameworks. Adversaries abuse TCC by:
- Modifying or replacing the TCC database
- Injecting malicious applications into trusted code-signing contexts
- Leveraging pre-approved entitlements or MDM profiles
- Exploiting weak file permissions or backup/restore workflows

Common artifacts include:
- Unauthorized changes to `~/Library/Application Support/com.apple.TCC/TCC.db`
- Execution of processes with unexpected privacy entitlements
- Access to protected resources without user interaction
- Persistence of privacy grants across reboots

---

## 3. Subtechnique Considerations
Key considerations for T1548.006:
- Strictly macOS-specific
- Increasingly targeted by sophisticated adversaries
- Often combined with credential access or surveillance objectives
- Detection is challenging due to limited default logging

Modern macOS versions reduce exposure, but misconfigurations and legacy systems remain vulnerable.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Modifying TCC.db to grant Full Disk Access to malicious binaries
- Injecting code into signed or trusted applications
- Abusing MDM or PPPC (Privacy Preferences Policy Control) profiles
- Leveraging backup restores to reintroduce malicious TCC permissions

These actions often enable follow-on credential theft or persistent surveillance.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring file integrity changes to TCC.db
- Alerting on unexpected access to protected services
- Detecting execution of binaries with unusual entitlements
- Correlating TCC access events with non-interactive execution

### Data Source Notes
- **Unified Logs**: Limited visibility but useful when tuned
- **File integrity monitoring**: Critical for TCC.db detection
- **MDM logs**: Essential in managed environments

---

## 6. Response Guidance
When detected:
1. Validate whether TCC changes were user-approved or MDM-authorized
2. Revoke unauthorized privacy grants immediately
3. Identify all processes with access to protected resources
4. Isolate affected systems if surveillance or credential theft is suspected
5. Review MDM and configuration profiles for abuse

## 8. SOC Relevance
T1548.006 is highly relevant in:
- macOS-heavy enterprise environments
- Executive or developer workstation fleets
- Organizations relying on Full Disk Access–protected data

TCC manipulation enables stealthy access to high-value information with minimal alerts.

Usage reflects increasing attacker investment in macOS tradecraft.

## 11. Malware Usage
Malware leveraging TCC manipulation includes:
- macOS backdoors
- Credential and keychain stealers
- Surveillance-focused implants

---

## 12. Mitigations
Recommended mitigations:
- Enforce strict TCC protections and system integrity settings
- Use MDM to control PPPC profiles
- Enable file integrity monitoring for TCC.db
- Limit Full Disk Access grants to approved applications
- Keep macOS fully patched

---

## 13. Testing & Validation
Validation approaches:
- Monitor and test TCC.db modification alerts
- Simulate unauthorized privacy grants in lab environments
- Conduct red team exercises focused on macOS privacy abuse
- Validate SOC visibility into TCC-related activity
