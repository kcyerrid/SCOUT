# T1021.006 - Remote Services: Windows Remote Management

## 1. Summary
Adversaries may use Windows Remote Management (WinRM) to interact with remote Windows systems for lateral movement. WinRM enables remote execution and management actions (e.g., running executables, modifying the registry/services) using valid credentials.

## 2. Technical Overview
WinRM abuse often manifests as:
- Remote command execution via PowerShell remoting/WinRM endpoints.
- Rapid operational chaining: authenticate to a host → run commands/tools → pivot again.
- Blending with legitimate administrative automation if WinRM is widely used.

High-signal behaviors:
- WinRM activity to hosts that the initiating account does not normally administer.
- WinRM from user workstations (vs. sanctioned admin/jump infrastructure) to servers and high-value systems.
- WinRM usage closely following credential access alerts, password spraying, or newly observed logons.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- WinRM is a common enterprise management plane; detection quality depends heavily on environment baselining (approved admin hosts, expected service accounts, and expected targets).
- Where WinRM is required, segmentation and allowlisting are typically more effective than pure anomaly detection.

## 4. Procedure Examples
MITRE ATT&CK documents WinRM usage including:
- [[30_CIPHER/05_Malware/S0154 - Cobalt Strike|Cobalt Strike]] using WinRM to execute payloads on remote hosts.
- [[30_CIPHER/05_Malware/S1063 - Brute Ratel C4|Brute Ratel C4]] using WinRM for pivoting.
- [[30_CIPHER/03_Threat_Actors/G0102 - Wizard Spider|Wizard Spider]] using WinRM for lateral movement.
- During **C0024 - SolarWinds Compromise**, [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] used WinRM (via PowerShell) to execute remote commands/payloads.

## 5. Detection Guidance
Detection should focus on **WinRM session establishment + short-window execution effects** on the destination.

Recommended analytic patterns:
- WinRM connection/session indicators followed by:
  - Process creation on the target (especially scripting interpreters, LOLBins, or unusual admin tooling).
  - WMI usage shortly after WinRM usage (common chaining pattern in intrusions).
  - Service/task creation, or registry/service modifications soon after remote activity.
- Baseline and alert on rare:
  - Source host → destination host WinRM pairs
  - Account → destination host WinRM pairs
  - WinRM usage outside maintenance windows

MITRE Detection Strategy (technique analytics):
- **DET0477 – Behavioral Detection of WinRM-Based Remote Access** (described as correlating service use, network activity, remote session logon, and process creation within a short temporal window).

### 5.1. Data Source Notes
Telemetry requirements commonly include:
- Endpoint telemetry on the destination: process creation, command line, parent/child, and service/task modifications.
- Windows authentication and logon telemetry aligned to WinRM activity windows.
- Network telemetry: WinRM endpoints and connections (source/destination, timing, volume).
- Asset/account context: approved WinRM admin hosts, expected service accounts, and approved target sets.

## 6. Response Guidance
- Contain: restrict WinRM at host firewall or network controls to approved admin infrastructure if misuse is suspected.
- Validate: confirm whether the initiating account and source host are authorized for WinRM to the target.
- Scope: hunt for additional WinRM activity by the same account/source; identify downstream lateral movement from newly accessed hosts.
- Remediate: rotate impacted credentials; remove persistence; and restore secure WinRM configurations.

## 8. SOC Relevance
High-value pivots:
- Identify whether WinRM originated from an approved admin host (jump server, orchestration node).
- Determine whether the account is expected to administer the destination.
- Inspect destination process tree immediately after WinRM activity for suspicious execution chains.
- Look for fan-out: rapid WinRM to multiple hosts, especially servers and privileged tiers.

## 12. Mitigations
ATT&CK-listed mitigations for T1021.006 include:
- **M1042 – Disable or Remove Feature or Program**: disable the WinRM service where not required.
- **M1030 – Network Segmentation**: if required, lock down enclaves with separate WinRM infrastructure and restrict access to/from specific devices.
- **M1026 – Privileged Account Management**: constrain WinRM accounts/permissions and avoid using highly privileged accounts for routine administration.

## 13. Testing & Validation
- Validate WinRM telemetry coverage: ensure both network and destination endpoint execution telemetry are present.
- Confirm that sanctioned admin paths (approved jump hosts/service accounts) are allowlisted and do not generate noisy alerts.
- Perform controlled testing to verify “WinRM session → process creation within short window” correlation logic.
