## 1. Summary
Adversaries may abuse **ClickOnce** deployment artifacts (e.g., `.appref-ms`, `.application`) to proxy execution through trusted Windows components such as **dfsvc.exe/dfshim.dll**, reducing friction for execution and potentially evading application control. Detection focuses on **dfsvc.exe** and **rundll32.exe dfshim.dll** patterns, unexpected child processes, and abnormal module loads.

## 2. Technical Overview
ClickOnce enables self-updating Windows-based .NET applications that can install/run from file shares or web sources with limited prompts.

Abuse patterns (defender-relevant):
- User is induced to launch or install a ClickOnce application (often paired with social engineering).
- Execution chain may include:
  - **dfsvc.exe** launching application processes
  - **rundll32.exe** invoking **dfshim.dll** with ClickOnce-related verbs
- Potential persistence by placing ClickOnce refs in startup locations (paired with persistence mechanisms).

Key telemetry focus:
- Parent/child lineage around dfsvc.exe and rundll32.exe.
- Module loads of dfshim.dll.
- Unusual children spawned from dfsvc.exe (e.g., script interpreters) or unexpected payload paths.

## 3. Subtechnique Considerations
- ClickOnce can exist legitimately in some enterprise apps; prioritize:
  - **Rare/first-seen** ClickOnce apps,
  - Executions on **non-standard endpoints**,
  - Suspicious child process + module load behavior.

## 5. Detection Guidance
- **Core signatures**
  - rundll32.exe invoking dfshim.dll with ClickOnce activation patterns.
  - dfsvc.exe spawning unexpected child processes.

- **Behavior anomalies**
  - dfsvc.exe launches from unusual paths or triggers processes from user-writable directories.
  - Unsigned/rare modules loaded during ClickOnce execution.
  - Correlate with user interaction signals (browser → ClickOnce prompt, recent download events).

### Data Source Notes
**MITRE Detection Strategy (DET0191 / AN0550) log sources:**
- Process Creation — Security 4688
- Module Load — Sysmon 7
- Process Metadata — ETW/security telemetry indicating ClickOnce deployment processes launching payloads

## 6. Response Guidance
1. **Triage**
   - Identify dfsvc.exe / rundll32.exe activity and the associated ClickOnce artifacts (.appref-ms, .application).
   - Determine the delivered application identity (publisher/signature), source URL or share, and execution path.

2. **Contain**
   - Isolate endpoint if suspicious child processes or follow-on activity exists.
   - Block untrusted ClickOnce sources and tighten trust prompt behavior.

3. **Eradicate**
   - Remove malicious ClickOnce artifacts and any persistence created (startup placements, scheduled tasks, etc.).
   - Hunt for the same ClickOnce artifacts or publisher across fleet.

## 12. Mitigations
- **Code Signing (M1045):** enforce signature verification and application integrity controls.
- **Disable or Remove Feature or Program (M1042):** disable ClickOnce if not required; restrict internet-based ClickOnce installs.
- **Restrict Web-Based Content (M1021):** reduce installation/execution from untrusted web sources.

## 13. Testing & Validation
Defender-safe validation:
- Inventory legitimate ClickOnce applications and publishers.
- Validate detections fire for:
  - rundll32.exe loading dfshim.dll in unexpected contexts,
  - dfsvc.exe spawning unusual children.
- Confirm telemetry coverage for process creation and module load events on pilot endpoints.
