## Summary
User Activity Based Checks (T1497.002) uses indicators of human interaction (unlock/login events, mouse/keyboard behavior, user artifact presence, GUI/input state) to decide whether to proceed—helping adversaries evade automated sandboxes and analysis systems.

## Technical Overview
Common patterns:
- **Input/GUI state probing**: checking foreground window state, cursor position changes, or key/button state.
- **Artifact validation**: inspecting user directories or history files (shell/browser artifacts) to confirm “real user” presence.
- **Interaction gating**: requiring a user action (open/close, click, double-click) before stage activation.

Defender impact: this frequently causes sandbox “no behavior” outcomes and delays suspicious behaviors until real-user execution.

## Subtechnique Considerations
Compared to T1497.001 and T1497.003:
- More reliant on **session context** and **user timeline events**.
- Higher value correlation: **recent unlock/login** → process starts → probes user artifacts/input state.
- Potentially noisier on endpoints with legitimate automation/RPA; tune with allowlists for known automation tools and management scripts.

## Procedure Examples
MITRE procedure examples include:
- **Darkhotel (Group)** repeatedly checking mouse cursor position to determine real-user presence.
- **FIN7 (Group)** using interaction-gated document lures (payload activates on a user double-click).
- **Okrum (Software)** requiring multiple mouse clicks before executing payload.
- **TONESHELL (Software)** comparing GUI-related API results to detect sandboxing.

(See MITRE’s T1497.002 procedure examples for details.)

## Detection Guidance
Primary approach: correlate **user session events** with **artifact/input probing**.

High-signal detections:
1. **Unlock-to-probe correlation**: process execution that probes user artifacts shortly after user unlock/login, especially from suspicious parents.
2. **File access to history**: reads of shell history or browser artifact locations by newly executed, low-prevalence binaries.
3. **GUI/input utilities** (Linux): execution of tools that query input state (or access to input device nodes) preceding payload activity.
4. **API-level input checks** (macOS): OS API execution signals consistent with input detection, followed by stage progression.

### Data Source Notes
MITRE detection strategy **DET0420** highlights log sources including:
- **Process Creation (DC0032)** (e.g., Sysmon EventCode 1; auditd execve; macOS unified log spawns),
- **Process Access (DC0035)** (e.g., Sysmon EventCode 10),
- **Logon Session Metadata (DC0088)** (e.g., Windows unlock/lock events),
- **File Access (DC0055)** (e.g., reads of shell history / browser artifacts),
- **Command Execution (DC0064)** (e.g., Linux input-query tooling),
- **OS API Execution (DC0021)** for GUI/input detection APIs (macOS).

## Response Guidance
1. Validate whether the suspected sample suppressed behavior in sandbox but activates on real endpoints.
2. Collect and review:
   - process ancestry and command-lines,
   - file access telemetry around user artifact locations,
   - session/unlock events around process start,
   - follow-on behaviors after user interaction.
3. If confirmed, contain the endpoint and hunt for staged artifacts and persistence.

## SOC Relevance
High relevance for:
- Email/doc detonation pipelines (interaction-gated payloads).
- Endpoint hunting focused on user-session correlation.
- Identifying “quiet loaders” that only activate with real user context.

## Threat Actor Usage
MITRE procedure examples cite actor use including **FIN7** and **Darkhotel**. Treat as broadly applicable across phishing and loader ecosystems.

## Campaign Usage
Often appears as part of initial infection chains to defeat automated detonation and triage.

## Malware Usage
MITRE includes multiple software examples using user-activity probes and gating; use these for pivots and enrichment.

## Mitigations
MITRE notes preventive mitigation is difficult as this abuses legitimate system features. Practical focus:
- Improve telemetry and detections around session events + artifact probing.
- Strengthen sandbox realism if used for malware triage (user artifacts, interaction simulation controls).
- Reduce attacker benefit by detecting gating attempts early and escalating for deeper analysis.

## Testing & Validation
- Simulate benign reads of history files and correlate with login/unlock events to validate alert logic (avoid malicious payloads).
- Validate Windows collection of Sysmon + Security events needed for unlock-to-probe correlation.
- Validate Linux auditd coverage for file reads of user history locations and execution of input-query tooling.
