# Hide Artifacts: Hidden Users (T1564.002)

## 1. Summary
Hidden Users describes adversaries **creating, modifying, or leveraging user accounts in ways that prevent them from appearing in standard administrative views or user interfaces**. This technique enables attackers to maintain access while avoiding detection during routine user and account reviews.

T1564.002 commonly supports:
- Stealthy persistence
- Long-term access without raising suspicion
- Credential abuse with reduced administrative visibility
- Blending malicious accounts with legitimate system or service users

---

## 2. Technical Overview
Operating systems and identity platforms provide mechanisms that can suppress user visibility. Adversaries abuse these by:

- **Windows**
  - Creating accounts with attributes that hide them from login screens
  - Modifying registry or account flags to suppress enumeration
  - Abusing service or system-type user classifications

- **Linux/macOS**
  - Creating users with low UIDs below normal login thresholds
  - Omitting home directories or shells
  - Marking accounts as system/service users

- **Cloud / SaaS**
  - Creating service principals or users excluded from default views
  - Assigning roles without interactive login permissions
  - Leveraging API-only identities

Artifacts and indicators include:
- Accounts present in backend identity stores but missing from UI lists
- Authentication activity from users not visible in admin consoles
- Inconsistent UID/GID ranges or account attributes
- Privileged access granted to non-interactive or system-classified users

---

## 3. Subtechnique Considerations
Key considerations for T1564.002:
- Hidden users often coexist with valid credentials (T1078)
- Account creation alone is not sufficient—**visibility suppression is key**
- Particularly dangerous in environments with weak identity monitoring
- Often paired with account manipulation techniques (T1098)

Detection requires authoritative identity inventory, not UI-only views.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Creating a local admin account hidden from the Windows logon screen
- Adding a Linux user with a UID below the standard login range
- Registering a cloud service principal excluded from interactive views
- Granting privileges to a system-classified user account

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **identity reconciliation and behavior**:
- Enumerate users via authoritative APIs, not just UI tools
- Detect authentication events from accounts not listed in expected inventories
- Alert on UID/GID anomalies or unusual account flags
- Monitor privilege grants to service or system-classified accounts

### Data Source Notes
- **Identity management logs**: Primary source of truth for account creation/modification
- **Authentication logs**: Reveal use of hidden accounts
- **OS audit logs**: Capture local account changes
- **Cloud control plane logs**: Required for service principals and API identities

Common false positives:
- Legitimate service accounts
- Managed identities and automation accounts
- Legacy system users

Tuning guidance:
- Baseline expected system/service accounts
- Alert on hidden accounts with interactive authentication or elevated privileges

---

## 6. Response Guidance
When suspected:
1. Enumerate all users via authoritative sources (local, domain, cloud APIs)
2. Identify accounts not visible in standard administrative views
3. Review authentication and privilege usage for those accounts
4. Disable or remove unauthorized hidden users
5. Investigate for associated persistence or lateral movement

## 8. SOC Relevance
T1564.002 is especially relevant in:
- Investigations involving unexplained authentication events
- Long-dwell intrusions with minimal artifacts
- Cloud and hybrid identity environments

Hidden users frequently explain “mystery logins” and privilege drift.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Advanced persistent threats
- Intrusion sets seeking long-term access
- Actors targeting identity infrastructure

Usage often reflects planning and intent to persist quietly.

---

## 10. Campaign Usage
Observed in:
- Espionage campaigns
- Cloud identity compromise operations
- Post-exploitation persistence phases

---

## 11. Malware Usage
Typically associated with:
- Post-exploitation frameworks
- Identity manipulation tooling
- Manual operator activity rather than commodity malware

---

## 12. Mitigations
Recommended mitigations:
- Regularly reconcile user inventories against authoritative sources
- Monitor for authentication from non-enumerated accounts
- Restrict who can create or modify user accounts
- Enforce least privilege on service and system users
- Review cloud IAM and directory configurations regularly

---

## 13. Testing & Validation
Validation approaches:
- Create test hidden users in lab environments
- Verify detection of authentication from hidden accounts
- Validate SOC workflows for identity reconciliation
- Test alerts on privilege grants to non-interactive users
