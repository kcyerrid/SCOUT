# T1021.008 - Remote Services: Direct Cloud VM Connections

## 1. Summary
Adversaries may leverage valid accounts to log directly into accessible cloud-hosted compute infrastructure through cloud-native interactive connection methods (e.g., serial console or provider-native instance connection services). These connections can provide highly privileged access (root/SYSTEM) on the VM and enable lateral movement by pivoting through the environment.

## 2. Technical Overview
Direct cloud VM connection methods are typically:
- Invoked through the cloud API/control plane (not necessarily via traditional SSH/RDP paths).
- Designed to provide interactive console access to a VM for administration and troubleshooting.
- Authorized through cloud IAM permissions and may support multiple authentication methods (passwords, access tokens, SSH keys), depending on provider and configuration.

High-signal behaviors:
- Use of console/serial/instance-connect features where not used operationally.
- Direct VM access initiated from the cloud control plane shortly after suspicious sign-ins or IAM changes.
- Follow-on privileged command execution on the VM leading to additional lateral movement (e.g., outbound SSH/RDP to other assets, credential access, or persistence actions).

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- This subtechnique is distinct from traditional remote protocols because initial access to the VM session is often controlled by cloud IAM/API rather than network reachability to the VM.
- Cloud logging and IAM permission review are mandatory for high-fidelity detection.

## 5. Detection Guidance
Detect **cloud-native interactive VM access** and correlate it with **VM-side privileged activity**.

Detection ideas:
- Alert on use of serial console / instance-connect / systems-management interactive session features:
  - By users/roles that do not normally require it
  - Against sensitive instances (directory services, CI/CD runners, secrets stores, management nodes)
  - From atypical source IPs/locations or following IAM changes
- Correlate cloud events with host-side telemetry:
  - Privileged session start followed by command execution or configuration changes
  - New users/keys, persistence artifacts, or credential access activity

MITRE Detection Strategy (technique analytics):
- **DET0211 – Detection of Direct VM Console Access via Cloud-Native Methods** (described as direct login via cloud-native methods followed by command execution or privilege escalation).

### 5.1. Data Source Notes
Telemetry requirements:
- Cloud audit logs for interactive VM access features (who, when, from where, which instance, which method).
- IAM change logs (role assignments, permission grants, policy modifications).
- VM endpoint telemetry for privileged session activity and command execution, where available.
- Asset context: instance criticality, expected admin paths (bastion vs. console), and approved IAM principals.

## 6. Response Guidance
- Contain: remove/limit permissions enabling direct VM console access for compromised identities; revoke sessions/tokens where possible.
- Scope: enumerate other instances accessed via the same method; review cloud audit trails and correlate to VM-side activity.
- Remediate: rotate credentials/secrets exposed on impacted instances; check for persistence; validate no new IAM principals/keys were created.
- Harden: restrict console/serial/instance connect features to break-glass workflows; enforce conditional access and least privilege.

## 8. SOC Relevance
Key pivots:
- Which IAM principal initiated the interactive VM access and whether it is expected for the role.
- Whether the access occurred during a known break-glass/incident workflow.
- Whether the VM subsequently initiated outbound lateral connections or exhibited privilege escalation/persistence.
- Whether the access method bypassed standard bastion/jump host controls.

## 12. Mitigations
ATT&CK-listed mitigations for T1021.008 include:
- **M1042 – Disable or Remove Feature or Program**: disable direct VM connection types where not required.
- **M1018 – User Account Management**: limit which users are allowed to access compute infrastructure via cloud-native methods.

## 13. Testing & Validation
- Confirm cloud audit visibility for serial console/instance connect/SSM-style session events.
- Validate detections against:
  - Approved break-glass usage (expected/no alert or high-severity but acknowledged).
  - Unapproved IAM principals or unusual source locations (alert).
- Ensure VM-side telemetry (process/auth logs) can be correlated to cloud event timestamps.
