## 1. Summary
Adversaries may acquire credentials from **Windows Credential Manager**, which stores credentials used for websites, applications, and network authentication (NTLM/Kerberos). Attackers may enumerate stored entries via native utilities/APIs or read encrypted credential locker files for later decryption.

## 2. Technical Overview
Credential Manager storage and access patterns:
- **Credential Lockers / Vaults:** Encrypted `.vcrd` files and associated policy files (e.g., `Policy.vpol`) under user profile paths.
- **Native enumeration:** `vaultcmd.exe` can enumerate stored credentials.
- **API enumeration:** Windows APIs such as `CredEnumerateA` may be used to list credentials.
- **Backup/restore abuse:** Credential backup/restore UI via `rundll32.exe keymgr.dll ...` may expose access patterns and artifacts.

High-signal characteristics:
- Enumeration utilities or APIs invoked by **non-admin**, **non-IT** processes.
- Direct access to vault file locations by unsigned or newly dropped binaries.
- Correlation with privilege escalation or tool transfer.

## 3. Subtechnique Considerations
- Windows-only; separate detections from browser credential databases and DPAPI-focused theft.
- Some browser web credentials (IE/Edge) may be managed via Credential Manager; consider correlating with T1555.003 for browser credential events.

## 4. Procedure Examples
Documented examples include:
- Use of Credential Manager stealing utilities during operations and campaigns.
- Use of public tools to parse Vault files and enumerate stored credentials.
- Use of PowerShell-based tooling to enumerate Windows Vault credentials.

## 5. Detection Guidance
High-signal detections:
- **Process creation:** `vaultcmd.exe` execution outside IT automation baselines.
- **Process creation:** `rundll32.exe keymgr.dll ...` usage (credential backup/restore UI) on non-admin endpoints.
- **API telemetry:** Calls to credential enumeration APIs (where available) by unusual processes.
- **File access:** Reads of credential locker directories and `.vcrd/.vpol` files by non-system binaries.

Correlation ideas:
- Suspicious process → credential enumeration/file reads → immediate outbound connection or archive creation.
- Credential access → follow-on lateral movement (new RDP/SMB logons) using the same user context.

### Data Source Notes
- Endpoint: process creation + command line, file access telemetry for credential locker paths, API telemetry (CredEnumerate*), and script block logging for PowerShell-based enumeration.
- Identity: authentication logs to detect credential reuse after enumeration.

## 6. Response Guidance
1. **Contain:** Isolate host if active enumeration/stealing is detected; terminate suspicious processes.
2. **Credential response:** Reset impacted credentials and invalidate cached authentication material as appropriate; prioritize privileged users and service accounts.
3. **Scope:** Hunt for `vaultcmd.exe` and `rundll32.exe keymgr.dll` patterns, and for vault file access across endpoints.
4. **Hardening:** Enforce policies to reduce/stage credential storage where feasible and restrict credential manager storage of network passwords if organizationally acceptable.

## 8. SOC Relevance
- **Severity:** Critical (can expose domain, VPN, application, and shared resource credentials).
- **Best signals:** `vaultcmd.exe` usage and unusual access to `.vcrd/.vpol` in credential locker directories.
- **False positives:** Legitimate credential management by IT scripts or endpoint management tools—reduce via signed allowlists and known admin automation hosts.

## 12. Mitigations
- **Disable or Remove Feature or Program (M1042):** Consider policies that prevent storage of network passwords/credentials for network authentication where acceptable.
- **Privileged Account Management (M1026):** Reduce who can access/harvest stored credentials; limit admin use on workstations.
- **User education/policy:** Reduce storing high-value credentials in local vaults where possible; enforce MFA.

## 13. Testing & Validation
- Validate detections using controlled lab endpoints by:
  - Triggering alerts on `vaultcmd.exe` execution and suspicious credential locker file reads.
  - Confirming correlation rules with follow-on authentication telemetry.
- Atomic Red Team coverage can be used to validate detection logic in a lab environment.
