# T1547.002 – Authentication Package

## 1. Technique Overview
**Authentication Package (T1547.002)** is a sub-technique of **Boot or Logon Autostart Execution (T1547)** in MITRE ATT&CK v18. Adversaries abuse Windows **authentication packages**, which are dynamic-link libraries (DLLs) loaded by the Local Security Authority Subsystem Service (LSASS) during user authentication. By registering a malicious authentication package, attackers ensure their code is executed whenever authentication events occur.

Because authentication packages operate within the security authentication pipeline, this technique can provide both **persistence** and **privilege escalation**.

## 2. Adversary Objectives
Adversaries use this technique to:
- Achieve persistent execution during logon events
- Execute code within the context of LSASS
- Intercept or manipulate authentication processes
- Gain access to credentials or authentication material

## 3. Common Abuse Patterns
- Registering a malicious DLL as an authentication package via:
  - `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\Authentication Packages`
- Modifying existing authentication package entries to include attacker-controlled DLLs
- Masquerading malicious packages as legitimate security components
- Leveraging the technique to harvest credentials or inject additional payloads
- Combining authentication package abuse with credential dumping techniques

## 4. Detection Considerations
Detection requires **deep system and registry visibility**, including:
- Monitoring changes to LSA-related registry keys
- Detecting new or unexpected DLLs loaded by LSASS
- Alerting on unsigned or anomalous authentication packages
- Correlating authentication package changes with credential access attempts
- Reviewing system boot and logon behavior anomalies

## 5. Defensive Mitigations
- Restrict administrative access to LSA registry keys
- Enable credential protection features such as LSASS protection
- Monitor and alert on changes to authentication package configurations
- Enforce code signing requirements for security-sensitive DLLs
- Perform regular integrity checks on authentication-related components

## 6. Operational Impact
If successful, T1547.002 can:
- Provide stealthy, long-term persistence
- Enable execution in a highly privileged security context
- Facilitate credential theft and authentication manipulation
- Severely complicate detection and remediation efforts

## 7. Analyst Notes
Authentication package abuse is rare but extremely high impact. Because LSASS is a core security process, any unauthorized modification to authentication packages should be treated as a **critical security incident**. Remediation often requires offline analysis or full system reimaging due to the risk of deep compromise.
