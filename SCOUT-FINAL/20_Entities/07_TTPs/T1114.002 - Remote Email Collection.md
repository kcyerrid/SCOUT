## 1. Summary
Adversaries collect email remotely by accessing email accounts or servers (e.g., enterprise mail platforms) to steal messages and attachments. This often overlaps with account compromise, delegated access abuse, and administrative export features.

## 2. Technical Overview
Remote email collection can include:
- Direct mailbox access via webmail or client protocols from adversary-controlled hosts.
- API-based access (service-side operations) consistent with cloud email ecosystems.
- Administrative actions to export mailboxes or extract mailbox contents at scale.

Defender-relevant signals:
- Unusual mailbox access from atypical IPs/devices/locations.
- Mailbox export/search operations not aligned with normal admin workflows.
- Correlation with new privileged role assignments, consent grants, or mailbox delegation changes.

## 3. Subtechnique Considerations
- SaaS environments: prioritize **Unified Audit Logs**, mailbox audit logs, and identity logs.
- On-prem Exchange: leverage PowerShell/Exchange admin logs and Windows security logs for cmdlet execution and administrative access.
- Remote collection can be “low-noise” if adversaries blend into legitimate access patterns—strong baselining is essential.

## 4. Procedure Examples
Examples observed in ATT&CK procedure examples include:
- [[30_CIPHER/05_Malware/S0476 - Valak|Valak]] collecting sensitive mailing information from Exchange servers.
- During **C0024 - SolarWinds Compromise**, [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] collected emails from specific individuals using mailbox export-related cmdlets.
- [[30_CIPHER/03_Threat_Actors/G1033 - Star Blizzard|Star Blizzard]] remotely accessing victims’ email accounts to steal messages/attachments.

## 5. Detection Guidance
High-signal detections
- **Mailbox export/search at scale**:
  - Export requests, eDiscovery exports, or unusual mailbox content searches initiated by uncommon actors.
- **Admin cmdlet anomalies**:
  - Cmdlets used rarely in your org, run by accounts that typically don’t administer email.
- **Identity risk**:
  - Risky sign-ins followed by mailbox access or export actions.
- **Mailbox “targeting”**:
  - Access focused on executives/IR/legal users.

Suggested correlations
- privileged auth event → mailbox export/search → external egress or new forwarding rules
- new app consent/delegation → mailbox access via API → data movement

### Data Source Notes
- Collect and retain:
  - mail platform audit logs (mailbox access, admin actions, rule changes),
  - identity provider logs (MFA, conditional access outcomes, impossible travel),
  - admin role changes and app consent events.

## 6. Response Guidance
1) **Contain**
- Revoke sessions/tokens and enforce MFA/CA for affected accounts.
- Disable suspicious admin accounts and remove unauthorized role assignments/delegations.

2) **Scope**
- Enumerate mailboxes accessed/exported and determine what was collected (subjects, attachments, date ranges where available).
- Identify persistence paths: forwarding rules, app permissions, delegated mailbox rights.

3) **Recover**
- Rotate credentials, review for BEC follow-on, and notify stakeholders if sensitive correspondence was exposed.

- **Critical**: Remote email collection often leads directly to major business impact (data theft, BEC, extortion, credential harvesting).
- Mailbox export and delegated access abuse are high-priority SOC detections.

## 12. Mitigations
- **M1041 Encrypt Sensitive Information**: Use encryption for sensitive email content where feasible.
- **M1032 Multi-factor Authentication**: Enforce MFA for webmail/admin portals; restrict legacy auth.
- **M1060 Out-of-Band Communications Channel**: Require OOB verification for high-risk requests/actions driven by email content.

## 13. Testing & Validation
- Validate alerting on:
  - mailbox export/search actions,
  - admin cmdlet usage anomalies,
  - risky sign-ins followed by mailbox access.
- Confirm incident workflow can rapidly:
  - revoke sessions,
  - enumerate mailbox access history,
  - and identify forwarding/delegation/app-consent persistence.
