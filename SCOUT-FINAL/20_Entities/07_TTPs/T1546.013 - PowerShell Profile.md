# T1546.013 – PowerShell Profile

## 1. Technique Overview
**PowerShell Profile (T1546.013)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse **PowerShell profile scripts**, which are executed automatically when a PowerShell session starts, to run malicious commands or scripts without explicit user invocation.

This technique provides user-level persistence and is especially effective in environments where PowerShell is frequently used for administration or automation.

## 2. Adversary Objectives
Adversaries use PowerShell profiles to:
- Establish persistence tied to PowerShell usage
- Execute malicious code during routine administrative activity
- Blend malicious logic into legitimate scripting environments
- Avoid traditional startup persistence mechanisms

## 3. Common Abuse Patterns
- Modifying PowerShell profile files such as:
  - `$PROFILE`
  - `Microsoft.PowerShell_profile.ps1`
- Appending malicious commands or sourcing attacker-controlled scripts
- Targeting profiles that apply to all users or hosts
- Using obfuscation to hide malicious logic within profile scripts
- Leveraging profiles to launch secondary payloads

## 4. Detection Considerations
Detection relies on **script integrity and PowerShell telemetry**, including:
- Monitoring creation or modification of PowerShell profile files
- Alerting on unexpected changes to profile scripts
- Analyzing PowerShell logs for suspicious startup activity
- Comparing profile scripts against known-good baselines
- Detecting obfuscated or encoded commands in profiles

## 5. Defensive Mitigations
- Monitor and alert on PowerShell profile modifications
- Enforce script signing and execution policies
- Use PowerShell logging (Script Block, Module, Transcription)
- Restrict write permissions to profile locations
- Remove unauthorized profile scripts during incident response

## 6. Operational Impact
If successful, T1546.013 can:
- Provide low-noise, user-driven persistence
- Execute malicious code during legitimate administrative workflows
- Evade detection focused on system startup artifacts
- Complicate forensic timelines due to delayed execution

## 7. Analyst Notes
PowerShell profile abuse is often overlooked because profiles are expected to contain automation logic. Analysts should inspect **all applicable profile scopes** (current user, all users, current host) and validate the intent of each command when investigating PowerShell-based persistence.
