# Hide Artifacts: Hidden Window (T1564.003)

## 1. Summary
Hidden Window describes adversaries **executing programs in a way that suppresses or hides visible windows from the user**, reducing the likelihood of user observation and reporting. This technique is frequently used to hide script execution, command prompts, or staged payload activity during interactive user sessions.

T1564.003 commonly supports:
- Stealthy execution on user workstations
- Reduced user suspicion during phishing-driven compromise
- Operator activity that avoids visual indicators
- Concealed staging of tools and payloads

---

## 2. Technical Overview
Many operating systems and frameworks provide options to run processes without creating visible windows or to hide existing windows. Adversaries may abuse:

- **Windows**
  - Process creation flags to hide consoles/windows
  - Script hosts and launchers that support hidden execution modes
  - Parent process choices that reduce UI artifacts

- **macOS**
  - Background execution patterns (launch agents/daemons)
  - Scripted execution that avoids interactive UI components

- **Linux**
  - Non-interactive execution via shells and background processes
  - Display server interactions that suppress windows (environment-dependent)

Artifacts and indicators may include:
- Command interpreters running with no visible window during interactive sessions
- Parent/child chains associated with scripting engines
- Execution immediately following user actions (opening documents, clicking links)
- Short-lived processes that perform network calls or file writes without UI

---

## 3. Subtechnique Considerations
Key considerations for T1564.003:
- Hidden windows are common in legitimate automation; context matters
- More suspicious when paired with:
  - Office process spawning script engines
  - Unexpected network connections
  - Persistence installation
- Visibility is dependent on endpoint telemetry; OS logs may not record “window state”

---

## 4. Procedure Examples
Representative adversary patterns include:
- Launching script interpreters with hidden console windows after a user clicks a link
- Running system utilities in a hidden window to stage payloads
- Executing commands via trusted binaries that suppress UI output
- Using background execution to avoid user observation

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **process context and behavior**:
- Script engines or command shells spawned by user-facing applications (e.g., Office, browsers)
- Hidden execution correlated with immediate network activity
- Suspicious parent/child chains with “quiet” or “hidden” execution patterns
- Repeated short-lived command executions without user context

### Data Source Notes
- **Process creation telemetry**: Critical (parent/child, command line, integrity level)
- **Command-line logging**: Detect hidden/quiet execution flags where visible
- **Application logs**: Identify initiating user action context
- **Windowing telemetry**: If available, can help confirm suppressed UI

Common false positives:
- Enterprise automation scripts
- Software updaters and installers
- Legitimate background tasks

Tuning guidance:
- Baseline admin tooling and sanctioned automation
- Elevate alerts when hidden execution follows user application spawning
- Correlate with network and file behaviors for higher fidelity

---

## 6. Response Guidance
When suspected:
1. Capture process ancestry and command-line details
2. Identify initiating user context and timeline
3. Review network connections and file writes during the hidden execution window
4. Isolate host if follow-on compromise indicators exist
5. Hunt for persistence and credential access techniques

## 8. SOC Relevance
T1564.003 is especially relevant for:
- Phishing-driven compromises on user endpoints
- Interactive intrusions where operators want to avoid user reports
- Situations where malware “does something” but users report seeing nothing

Hidden execution often correlates strongly with malicious staging activity.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Ransomware operators (initial foothold staging)
- Commodity malware campaigns
- Advanced intrusion sets seeking stealth during workstation activity

---

## 10. Campaign Usage
Observed in:
- Spearphishing campaigns
- Loader-based intrusion chains
- Multi-stage payload deployments

---

## 11. Malware Usage
Frequently associated with:
- Loaders and droppers
- Script-based first-stage payloads
- Post-exploitation frameworks

---

## 12. Mitigations
Recommended mitigations:
- Constrain script execution (policy controls, application control)
- Harden Office and browser process spawning behaviors
- Increase endpoint telemetry coverage for process creation and command lines
- Train users to report suspicious outcomes even without visible windows

---

## 13. Testing & Validation
Validation approaches:
- Simulate hidden execution in a lab environment (benign commands)
- Validate alerting on suspicious parent/child chains
- Test correlation rules linking hidden execution to network/file behaviors
- Review false positives from sanctioned automation and tune accordingly
