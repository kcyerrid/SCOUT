# Pre-OS Boot: TFTP Boot (T1542.005)

## 1. Summary
TFTP Boot describes adversaries **abusing Trivial File Transfer Protocol (TFTP) boot mechanisms on network devices or embedded systems** to load attacker-controlled firmware or operating system images during the pre-operating-system boot phase. By manipulating TFTP boot configurations, adversaries can establish highly stealthy and durable persistence.

Adversaries use this technique to:
- Load malicious images during device boot
- Establish persistence outside the primary OS
- Bypass OS-level security and logging
- Maintain control across reboots and reimaging

---

## 2. Technical Overview
Many network devices and embedded systems support booting from a TFTP server for provisioning, recovery, or diskless operation. Adversaries may exploit this by:
- Modifying boot variables to reference attacker-controlled TFTP servers
- Replacing legitimate boot images with malicious versions
- Abusing unsecured or misconfigured TFTP infrastructure
- Leveraging compromised provisioning workflows

Common targets include:
- Routers, switches, and firewalls
- Embedded appliances
- PXE/TFTP-enabled network devices

Indicators include:
- Unexpected TFTP traffic during device boot
- Boot images fetched from unauthorized servers
- Configuration changes enabling TFTP boot
- Persistence that survives OS reflashing

---

## 3. Subtechnique Considerations
Key considerations for T1542.005:
- Relies on insecure or unauthenticated TFTP workflows
- Often paired with weak network segmentation
- Detection depends heavily on network visibility
- Common in legacy or embedded environments

TFTP boot abuse exploits **trust in network-based provisioning mechanisms**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Reconfiguring devices to boot from attacker-controlled TFTP servers
- Hosting malicious boot images on compromised infrastructure
- Persisting altered boot variables across reboots
- Using TFTP boot to reintroduce malicious firmware after remediation

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **boot behavior and network monitoring**:
- Monitor for TFTP traffic during device boot
- Detect unauthorized changes to boot configuration
- Identify boot images sourced from non-approved servers
- Correlate persistence across reimaging events

### Data Source Notes
- **Network traffic logs**: Detect TFTP sessions at boot time
- **Device logs**: Capture boot and provisioning events
- **Configuration management**: Track boot variable changes

Common false positives:
- Legitimate provisioning or recovery operations
- Authorized device reimaging workflows

Tuning guidance:
- Maintain allowlists of approved TFTP servers
- Alert on TFTP usage outside approved maintenance windows

---

## 6. Response Guidance
When suspected:
1. Isolate the affected device from the network
2. Validate boot configuration and variables
3. Inspect and verify boot images
4. Reconfigure devices to use trusted boot sources
5. Investigate provisioning infrastructure compromise

## 8. SOC Relevance
T1542.005 is critical because:
- Persistence is achieved via trusted provisioning mechanisms
- Network devices may lack robust security monitoring
- Remediation may disrupt critical infrastructure

SOC teams must closely monitor **network-based boot workflows**.

---

## 9. Threat Actor Usage
Commonly used by:
- Nation-state threat actors
- Network-focused intrusion groups
- Supply-chain compromise operators

---

## 10. Campaign Usage
Observed in:
- Infrastructure compromise campaigns
- Long-term network persistence operations
- Embedded system intrusions

---

## 11. Malware Usage
Associated with:
- Network firmware implants
- Malicious boot images
- Persistent infrastructure-level malware

---

## 12. Mitigations
Recommended mitigations:
- Disable TFTP boot where not required
- Restrict and authenticate provisioning services
- Segment provisioning networks
- Monitor and log all boot-related network activity

---

## 13. Testing & Validation
Validation approaches:
- Test alerting on unauthorized TFTP boot traffic
- Validate configuration drift detection for boot variables
- Conduct tabletop exercises for provisioning abuse
- Verify recovery procedures for compromised boot workflows

Include:
- Preconditions: network telemetry enabled; baselines established
- Required roles/tools: network engineering, DFIR, provisioning admins
- Expected outcomes: detection of unauthorized TFTP boot activity
- Success criteria: restoration of trusted boot configuration
