# T1574.013 – KernelCallbackTable

## 1. Technique Overview
**KernelCallbackTable (T1574.013)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries may abuse the **KernelCallbackTable (KCT)** within a process’s **Process Environment Block (PEB)** by modifying callback function entries so that execution returns to attacker-controlled code when the operating system dispatches those callbacks. This mechanism is prevalent in GUI-related Windows processes and can lead to stealthy persistence and privilege escalation. :contentReference[oaicite:5]{index=5}

## 2. Adversary Objectives
Adversaries use this technique to:
- Execute attacker-controlled code inside legitimate processes
- Establish stealthy persistence tied to callback invocation
- Escalate privileges by targeting high-privilege GUI applications
- Evade detection by leveraging legitimate OS callback mechanisms

## 3. Common Abuse Patterns
- Identifying processes that register callback functions (e.g., GUIs like `explorer.exe`, `notepad.exe`)
- Writing attacker-controlled payloads into memory regions containing the KCT
- Overwriting one or more callback function pointers in the PEB
- Causing the OS to invoke malicious code via legitimate callback dispatch flows
- Leveraging user-interaction or system events to trigger execution

## 4. Detection Considerations
Detection relies on **memory and behavior telemetry**, including:
- Monitoring modifications to callback function tables in process memory
- Detecting abnormal use of APIs like `WriteProcessMemory` targeting KCT regions
- Correlating altered callback tables with unusual process behavior (e.g., network activity)
- Auditing GUI process callback invocation sequences for anomalies
- Using Endpoint Detection and Response (EDR) tools with memory inspection capabilities :contentReference[oaicite:6]{index=6}

## 5. Defensive Mitigations
- Restrict unauthorized memory access to critical processes
- Monitor and alert on modifications to process memory that include callback tables
- Use advanced EDR memory integrity protections
- Regularly review trusted applications for unexpected callback invocations
- Educate defenders on KCT abuse patterns and detection artifacts

## 6. Operational Impact
If successful, T1574.013 can:
- Provide stealthy execution within legitimate processes
- Enable persistence without standard autorun mechanisms
- Undermine trust in GUI process behavior
- Complicate incident response due to in-memory execution

## 7. Analyst Notes
KernelCallbackTable abuse is a sophisticated hijack technique where execution is triggered via legitimate OS callback paths, making it difficult to detect through file-oriented monitoring alone. Analysts should include **memory integrity inspection** and **callback invocation tracking** in persistence hunting playbooks. :contentReference[oaicite:7]{index=7}
