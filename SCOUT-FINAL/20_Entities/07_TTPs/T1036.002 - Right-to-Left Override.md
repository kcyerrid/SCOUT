# Masquerading: Right-to-Left Override (T1036.002)

## 1. Summary
Right-to-Left Override (RTLO) describes adversaries **using Unicode control characters** to manipulate how filenames are displayed, making malicious files appear benign to users and analysts. This technique exploits the right-to-left text rendering used by certain languages to disguise file extensions.

Attackers use RTLO to:
- Trick users into executing malicious files
- Evade visual inspection during triage
- Masquerade executable files as documents or images
- Increase the success rate of social engineering

---

## 2. Technical Overview
Unicode includes special characters that control text direction, including the **Right-to-Left Override (U+202E)**. When embedded in filenames, this character causes subsequent characters to be rendered in reverse order.

Adversaries exploit this behavior by:
- Inserting RTLO characters into filenames
- Crafting filenames that visually end with benign extensions
- Hiding executable extensions in reversed text
- Delivering files via email, downloads, or removable media

Key characteristics:
- Filename display does not match actual file extension
- Underlying filesystem records correct filename
- UI-level deception rather than filesystem manipulation

Indicators include:
- Filenames containing Unicode control characters
- Mismatch between displayed and actual file extension
- Execution of files that appear non-executable to users
- Suspicious attachments with misleading names

---

## 3. Subtechnique Considerations
Key considerations for T1036.002:
- Highly effective in phishing and user-driven execution
- Commonly paired with **User Execution (T1204)**
- Platform-agnostic across modern operating systems
- Relies on UI and human perception weaknesses

RTLO is particularly dangerous in environments with limited file extension visibility.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Sending email attachments with RTLO-manipulated filenames
- Hosting disguised executables on download sites
- Embedding RTLO characters to mask true file type
- Leveraging user trust in file icons and names

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **filename integrity and Unicode analysis**:
- Detect Unicode RTLO characters in filenames
- Alert on mismatches between file extension and MIME type
- Monitor execution of files with suspicious Unicode characters
- Correlate RTLO usage with phishing delivery vectors

### Data Source Notes
- **File system monitoring**: Identify Unicode characters in filenames
- **Email security logs**: Detect malicious attachments
- **EDR telemetry**: Capture execution of disguised binaries

Common false positives:
- Legitimate files using right-to-left languages
- Multilingual document handling

Tuning guidance:
- Limit alerts to files with executable MIME types
- Elevate severity when RTLO appears in user-accessible locations

---

## 6. Response Guidance
When suspected:
1. Quarantine affected files immediately
2. Inspect filenames for Unicode control characters
3. Identify delivery vector (email, web, removable media)
4. Educate affected users on file execution risks
5. Expand hunt for similarly named files

## 11. Malware Usage
Associated with:
- Trojans and droppers
- Malware delivered via email attachments
- Payloads requiring user interaction

---

## 12. Mitigations
Recommended mitigations:
- Display full file extensions to users
- Block or flag files with RTLO characters
- Enhance email attachment inspection
- Train users to recognize suspicious filenames

---

## 13. Testing & Validation
Validation approaches:
- Create benign files with RTLO characters in lab
- Validate alerts on Unicode filename manipulation
- Test SOC workflows for phishing-based delivery
