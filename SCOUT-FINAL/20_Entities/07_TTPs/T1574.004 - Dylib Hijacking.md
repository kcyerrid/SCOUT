# T1574.004 – Dylib Hijacking

## 1. Technique Overview
**Dylib Hijacking (T1574.004)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries exploit how macOS applications resolve and load **dynamic libraries (`.dylib`)** so that attacker-controlled libraries are loaded during application execution.

This technique abuses legitimate macOS dynamic linking behavior and often targets applications that load libraries without absolute paths or that rely on weakly protected library search paths.

## 2. Adversary Objectives
Adversaries use dylib hijacking to:
- Execute malicious code within trusted application contexts
- Achieve stealthy persistence without explicit startup artifacts
- Escalate privileges by targeting elevated or auto-started applications
- Evade detection by blending into normal library loading behavior

## 3. Common Abuse Patterns
- Placing malicious `.dylib` files in directories searched before legitimate library paths
- Exploiting application-relative library loading (`@rpath`, `@loader_path`, `@executable_path`)
- Targeting unsigned or improperly protected applications
- Hijacking libraries loaded by background services or login items
- Combining dylib hijacking with other macOS persistence techniques

## 4. Detection Considerations
Detection relies on **process execution and dynamic library load telemetry**, including:
- Monitoring dylib loads from user-writable or unexpected directories
- Detecting unsigned or anomalous dylibs loaded by trusted applications
- Correlating application launches with unusual library resolution paths
- Baseline comparison of known-good dylib load behavior
- Inspecting Mach-O binaries for weak or unsafe load commands

## 5. Defensive Mitigations
- Enforce code signing and notarization for applications and libraries
- Restrict write access to application and library directories
- Use absolute library paths where possible during development
- Monitor dynamic library loading with endpoint security tooling
- Reinstall or re-sign compromised applications during remediation

## 6. Operational Impact
If successful, T1574.004 can:
- Provide stealthy execution within legitimate applications
- Enable persistence without modifying common autorun locations
- Facilitate privilege escalation via trusted binaries
- Complicate detection due to legitimate execution context

## 7. Analyst Notes
Dylib hijacking is a prevalent macOS execution technique, especially against third-party or legacy software that lacks hardened runtime protections. Analysts should focus on **why a dylib was resolved from a specific path**, not just whether the dylib itself appears malicious.
