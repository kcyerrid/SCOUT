# Modify Cloud Compute Infrastructure: Create Snapshot (T1578.001)

## 1. Summary
Create Snapshot describes adversaries **creating snapshots or backups of cloud compute resources** to enable data theft, persistence, or future access. Snapshots can capture full disk images, including credentials, configuration secrets, and sensitive data.

Attackers use this technique to:
- Exfiltrate sensitive data indirectly
- Preserve access to compromised environments
- Bypass endpoint-based security controls
- Enable offline analysis or future redeployment

---

## 2. Technical Overview
Most cloud providers allow privileged identities to create snapshots of disks or instances. Adversaries abuse this capability by:

- Creating snapshots of compromised virtual machines
- Exporting snapshots to attacker-controlled storage
- Using snapshots to spin up new instances later
- Retaining access even after original resources are cleaned

Common targets:
- VM disks and attached volumes
- Persistent disks backing container workloads
- Images used in autoscaling or templating

Indicators include:
- Snapshot creation outside maintenance windows
- Snapshots created by unusual or recently authenticated identities
- Snapshot creation followed by export or sharing activity
- Persistence artifacts embedded in captured images

---

## 3. Subtechnique Considerations
Key considerations for T1578.001:
- Often overlaps with **Data from Cloud Storage (T1530)**
- Frequently paired with **Valid Accounts (T1078)**
- Enables long-term persistence without active infrastructure
- May bypass many endpoint security controls entirely

Snapshots represent **silent persistence** and **delayed exploitation** risk.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Creating snapshots immediately after privilege escalation
- Capturing disks containing secrets or credentials
- Exporting snapshots to attacker-controlled accounts
- Retaining snapshots for later redeployment

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **control-plane activity**:
- Monitor audit logs for snapshot creation events
- Alert on snapshots created by non-administrative identities
- Correlate snapshot activity with suspicious authentication
- Detect snapshot sharing or export actions

### Data Source Notes
- **Cloud audit logs**: Primary detection source
- **IAM logs**: Attribute snapshot creation to identities
- **Storage logs**: Detect access or export activity

Common false positives:
- Legitimate backup operations
- Disaster recovery testing

Tuning guidance:
- Baseline backup automation identities
- Require approvals for snapshot creation
- Elevate severity when snapshots follow suspicious login events

---

## 6. Response Guidance
When suspected:
1. Identify all snapshots created by the actor
2. Revoke access to unauthorized snapshots
3. Rotate credentials stored on affected instances
4. Review access logs for snapshot usage or export
5. Implement stricter snapshot governance

## 8. SOC Relevance
T1578.001 is critical because:
- Snapshots persist beyond incident response
- Data theft may occur without network exfiltration
- Compromise impact can extend long after cleanup

SOC teams must treat snapshots as **high-risk artifacts**.

---

## 9. Threat Actor Usage
Commonly used by:
- Cloud-focused intrusion groups
- Actors targeting long-term access
- Adversaries prioritizing stealth and persistence

---

## 10. Campaign Usage
Observed in:
- Cloud account takeover campaigns
- Supply-chain–adjacent cloud intrusions
- Espionage-focused operations

---

## 11. Malware Usage
Associated with:
- Minimal malware usage
- Script-based cloud abuse
- Control-plane–only intrusions

---

## 12. Mitigations
Recommended mitigations:
- Restrict snapshot creation permissions
- Monitor and alert on snapshot events
- Encrypt snapshots and enforce access controls
- Implement snapshot lifecycle policies

---

## 13. Testing & Validation
Validation approaches:
- Simulate snapshot creation in test environments
- Validate alerts on unauthorized snapshot activity
- Test SOC workflows for snapshot abuse
- Ensure incident response includes snapshot review
