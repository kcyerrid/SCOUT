## 1. Summary
**Proc Filesystem (T1003.007)** is a Linux credential dumping subtechnique where adversaries read process memory mappings and/or memory through `/proc/<pid>/maps` and `/proc/<pid>/mem` to locate credential material (e.g., browser or process-resident secrets). It is typically **high-signal** when a process reads other processes’ memory via `/proc`, especially under elevated privileges.

## 2. Technical Overview
Key behaviors defenders should expect:
- **Targeted access to `/proc/<pid>/maps` and `/proc/<pid>/mem`** to identify readable memory regions and extract contents.
- **Cross-process memory access**: most impactful when a process reads memory of *other* processes (browsers, SSH agents, authentication helpers).
- **Privilege context matters**: broad harvesting across many PIDs generally implies **root** or equivalent capability (or a local weakness enabling memory reads).
- **Follow-on**: recovered secrets often enable subsequent authentication, lateral movement, or persistence—so detections should pivot to new auth events after the dump window.

## 3. Subtechnique Considerations
- This is a **Linux-only** subtechnique and often overlaps operationally with other “memory credential” patterns (process access, debugging/ptrace-like behaviors).
- High-value targets include:
  - Browser processes (credential patterns in memory)
  - Remote access tooling (SSH, VPN clients)
  - Service processes holding API tokens/keys in memory
- Expect evasion attempts such as short-lived collectors, living-off-the-land utilities, or embedding reads into otherwise benign processes.

## 4. Procedure Examples
MITRE ATT&CK procedure examples include:
- [[30_CIPHER/05_Malware/S0349 - LaZagne]] using `/proc/<pid>/maps` + `/proc/<pid>/mem` to search for patterns and dump cleartext credentials from a browser process.
- [[30_CIPHER/05_Malware/S0179 - MimiPenguin]] using `/proc` memory interfaces to search for patterns and dump process memory.
- [[30_CIPHER/05_Malware/S1109 - PACEMAKER]] extracting credentials from OS memory.

## 5. Detection Guidance
Prioritize **multi-event correlation**:

High-signal analytics:
- **Suspicious reads of `/proc/<pid>/mem` or `/proc/<pid>/maps`**
  - Non-debug tooling accessing these paths
  - Access spanning **multiple** PIDs in a short interval (enumeration + harvest)
- **Unusual privilege + /proc memory access**
  - Processes running as root reading `/proc/*/mem` shortly after privilege escalation events
- **Process lineage anomalies**
  - Script/interpreter → memory reader → outbound connection
  - Web-facing process (nginx/apache/app runtime) suddenly accessing `/proc/<pid>/mem`
- **Post-collection credential usage**
  - New logins, sudo events, SSH auths, or token-based API usage shortly after `/proc` memory reads

False-positive management:
- Some legitimate debuggers/perf tools may touch `/proc/<pid>/maps`—treat `/proc/<pid>/mem` and broad multi-PID harvesting as far higher risk.

### Data Source Notes
Recommended telemetry:
- Linux **process execution** (command-line + parent/child)
- **File access auditing** for `/proc/<pid>/mem` and `/proc/<pid>/maps` (e.g., auditd rules or EDR file telemetry)
- Privilege escalation indicators (sudo, setuid exec, capability changes)
- Network telemetry for exfil or immediate token usage after collection

## 6. Response Guidance
- **Contain**: isolate the host if active collection is confirmed; terminate suspected collectors.
- **Preserve evidence**: capture process tree, open files, and recent file access telemetry around `/proc/<pid>/*`.
- **Credential actions**: rotate credentials/tokens plausibly exposed (browser sessions, service tokens, SSH keys if memory-resident).
- **Scope**: hunt for the same collector behaviors on peer Linux systems; pivot on the same binary hash/path/parent process.

## 8. SOC Relevance
- High relevance in Linux estates, container hosts, and developer endpoints.
- Best pivots:
  - Identify which PIDs were targeted (browsers, auth agents, service daemons)
  - Determine whether memory reads preceded new auth activity or outbound transfers
  - Confirm privilege context (root vs user-only self-memory reads)

## 12. Mitigations
- **M1027 - Password Policies**: ensure privileged/root accounts have complex, unique passwords to reduce value of recovered hashes/secrets.
- **M1026 - Privileged Account Management**: minimize root exposure; restrict interactive root; segment high-value Linux hosts.
- Harden endpoints to reduce opportunities for untrusted code execution and privilege escalation that enables cross-process memory reads.

## 13. Testing & Validation
- In a controlled lab:
  - Validate alerting for any process accessing `/proc/<pid>/mem`, especially across multiple PIDs.
  - Validate correlation of `/proc` memory reads with subsequent auth anomalies (SSH/sudo/new sessions).
- Ensure allowlists for legitimate debugging/performance tools are explicit and scoped.
