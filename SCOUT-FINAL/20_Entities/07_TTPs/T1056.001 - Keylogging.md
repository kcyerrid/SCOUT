## 1. Summary
Keylogging (T1056.001) is a form of input capture where adversaries **log user keystrokes** to steal credentials, sensitive text, and other typed data. It is frequently used when credential dumping is blocked or when the attacker needs credentials as the user types them.

## 2. Technical Overview
High-level categories:
- **User-mode API hooking / event taps** to intercept keystrokes.
- **Polling-based capture** (reading key state repeatedly).
- **Driver/low-level capture** on some platforms.
- **Console/session capture** on certain network devices or via tampered system images/firmware.

Defender-observable outcomes:
- Unexpected processes interfacing with input APIs or device interfaces.
- Module loads/hook patterns inconsistent with the process role (non-UI services intercepting keystrokes).
- Output artifacts (files/registry entries) and outbound exfiltration shortly after capture windows.

## 5. Detection Guidance
Keylogging detection is best approached as **behavioral + context** detection rather than static signatures.

**High-signal detection themes**
- **Windows**
  - Suspicious usage of input-hook APIs (e.g., event hooks / key state queries) from non-UI or unusual parent/child process chains.
  - Unexpected drivers or registry changes that enable low-level capture.
- **Linux**
  - Unexpected processes accessing input interfaces and related syscalls.
- **macOS**
  - Unauthorized event-tap behavior or suspicious access patterns to input services, especially from unsigned/untrusted binaries.
- **Network devices**
  - Integrity changes suggesting modified images/firmware enabling console/remote session keystroke capture.

### Data Source Notes
- **EDR telemetry:** process execution, module loads, injection/hook detections, driver install events.
- **OS logs/auditing:** Windows Security + enhanced logging; Linux audit; macOS unified logs where available.
- **Network telemetry:** suspicious outbound connections following capture activity; unusual DNS/HTTP patterns from non-browser binaries.
- **DLP/credential telemetry (optional):** downstream credential use that follows suspected capture windows.

## 6. Response Guidance
1. **Contain**
   - Isolate host(s); restrict remote sessions; identify and disable suspicious persistence.
2. **Credential response**
   - Reset credentials typed on affected systems; revoke sessions/tokens; prioritize privileged and high-value accounts.
3. **Eradication**
   - Remove offending binaries/extensions/drivers; verify startup items; check for secondary payloads and lateral movement.
4. **Hunt**
   - Pivot across fleet for similar API/device access behavior and common tooling indicators.

## 8. SOC Relevance
- **High detection value** when you have EDR telemetry for API hooks/device access.
- **Best alerts** combine: suspicious hook/device access + unexpected data writes + outbound beacons.
- **Triage accelerators:** identify the capturing process, its parent chain, persistence, and any immediate credential use.

## 12. Mitigations
- MITRE notes this technique cannot be easily mitigated with preventive controls because it can rely on legitimate system features.
- Compensating controls (defender best practice):
  - Enforce application control and driver signing enforcement where feasible.
  - Minimize admin rights; restrict accessibility permissions and monitor for abuse.
  - Increase EDR coverage for API hook and device-access telemetry.

## 13. Testing & Validation
- Use controlled validation to confirm detections fire on:
  - Suspicious input-hook API usage patterns
  - Non-UI process access to input interfaces
  - Associated module loads and persistence behaviors
- Atomic Red Team exists for this sub-technique; use only in a lab and focus on **visibility verification** (events produced, fields captured, correlation accuracy).
