# Impair Defenses: Disable or Modify Cloud Security Controls (T1562.006)

## 1. Summary
Disable or Modify Cloud Security Controls describes adversaries **weakening or disabling cloud-native security mechanisms** such as threat detection services, security monitoring, guardrails, or protective policies. By impairing these controls, attackers reduce visibility and enforcement in cloud and SaaS environments.

Attackers use this technique to:
- Evade cloud-native detection and alerting
- Bypass preventative guardrails
- Enable unauthorized resource creation or access
- Support long-dwell cloud compromise

---

## 2. Technical Overview
Cloud platforms provide security controls such as threat detection services, policy enforcement, and monitoring. Adversaries impair these defenses by:

- Disabling cloud threat detection services
- Modifying security policies or guardrails
- Reducing alert severity or scope
- Suppressing notifications and alerts
- Altering monitoring configurations

Common environments affected:
- AWS (GuardDuty, Security Hub)
- Azure (Defender for Cloud)
- Google Cloud (Security Command Center)
- SaaS security monitoring platforms

Typical indicators include:
- Security services disabled or downgraded
- Policy enforcement turned off
- Alerting configurations modified
- Security dashboards showing reduced coverage

---

## 3. Subtechnique Considerations
Key considerations for T1562.006:
- Often follows cloud account compromise (T1098)
- Frequently paired with **Disable or Modify Cloud Logs (T1562.008)**
- Requires elevated permissions
- High-confidence indicator of malicious cloud activity

Cloud security control impairment is rarely justified outside planned maintenance.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Turning off cloud threat detection services
- Downgrading security policies to permissive modes
- Disabling security alerts or notifications
- Removing security integrations

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **security service and policy integrity**:
- Alert on security control disablement
- Detect changes to security policy configurations
- Monitor alerting and notification suppression
- Correlate security control changes with suspicious identity activity

### Data Source Notes
- **Cloud audit logs**: Primary detection source
- **Security configuration logs**: Track control changes
- **Identity logs**: Identify who modified security settings

Common false positives:
- Planned security service changes
- Legitimate environment setup or teardown

Tuning guidance:
- Require approval workflows for security control changes
- Baseline expected security service states per account

---

## 6. Response Guidance
When suspected:
1. Immediately restore cloud security controls
2. Preserve audit logs and configuration history
3. Review identity activity around control changes
4. Investigate actions taken while controls were impaired
5. Rotate credentials and review access permissions

## 8. SOC Relevance
T1562.006 is one of the **highest-severity techniques in cloud environments**. Disabling security controls dramatically increases attacker success and reduces detection fidelity.

Any unexplained cloud security control change should be escalated immediately.

---

## 9. Threat Actor Usage
This technique is commonly used by:
- Cloud-focused APT groups
- Financially motivated attackers targeting SaaS
- Ransomware operators expanding into cloud workloads

---

## 10. Campaign Usage
Observed in:
- Cloud account takeover campaigns
- SaaS data theft operations
- Long-dwell cloud intrusions

---

## 11. Malware Usage
Associated with:
- Cloud post-exploitation frameworks
- Automation scripts abusing cloud APIs
- Malware leveraging compromised cloud credentials

---

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege for cloud security administration
- Monitor and alert on security control state changes
- Enable immutable configuration and logging
- Require MFA for administrative cloud roles
- Periodically audit cloud security posture

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign security control disablement in test accounts
- Validate alerts on security service changes
- Test SOC workflows for cloud control impairment
- Ensure rollback and recovery procedures are effective
