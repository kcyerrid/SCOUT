# T1069.003 - Permission Groups Discovery: Cloud Groups

## 1. Summary
Adversaries enumerate **cloud permission groups/roles** (and their membership) to understand administrative structure and identify paths to privileged access in cloud and SaaS environments. This is a Discovery action that often precedes abuse of high-privilege roles, API-driven persistence, and data access.

## 2. Technical Overview
Common approaches include:
- **Identity provider role/group enumeration** (e.g., Azure AD / Entra ID roles, Google Cloud Identity groups).
- **Cloud IAM policy/role inspection** (AWS IAM roles/policies; Azure RBAC roles; GCP permissions).
- **SaaS/Office suite enumeration** (admin roles, security groups, distribution lists) via service APIs.

Execution modalities:
- CLI commands and SDK/API calls (cloud audit trail visibility)
- PowerShell modules for Microsoft ecosystems
- Post-exploitation cloud tooling

## 3. Subtechnique Considerations
- Cloud group discovery can be **extremely high signal** when performed by:
  - Non-admin identities
  - New/rare user agents (unknown tooling)
  - Suspicious IPs, TOR/VPN egress, or impossible travel patterns
- Group enumeration frequently pairs with **policy/role mapping** to identify privilege escalation opportunities (role chaining, misconfigurations, or overly permissive service principals).

## 4. Procedure Examples
MITRE procedure examples include:
- Use of cloud enumeration tooling such as [[30_CIPHER/05_Malware/S0677 - AADInternals|AADInternals]] and [[30_CIPHER/05_Malware/S0684 - ROADTools|ROADTools]] to enumerate Azure AD groups.
- Use of cloud offensive tooling like [[30_CIPHER/05_Malware/S1091 - Pacu|Pacu]] to enumerate IAM-related permissions.
- Reported actor usage includes [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider|Scattered Spider]] performing Azure AD access to obtain bulk lists of group members (per MITRE procedure examples).

## 5. Detection Guidance
Detection should focus on **API/CLI enumeration patterns** and deviations from admin baselines.

High-signal detection patterns:
- Spikes in group/role listing operations over short time windows (enumeration bursts).
- Group membership download/export behavior (bulk reads) by identities that do not normally perform directory administration.
- Enumeration from suspicious infrastructure (new ASN, residential proxies, anomalous geo/time-of-day).
- Repeated access-denied responses followed by a successful privileged session (indicates exploration and later privilege gain).

Practical analytics ideas:
- Alert on **role/group list operations** from non-admin identities, especially if followed by:
  - credential access attempts, token theft signals, or new app/service principal consent
  - policy modification or new access key/session creation
- Baseline expected admin tools/user agents (portal vs CLI/SDK). Flag unusual user-agent strings and automation.

### Data Source Notes
- **Cloud audit logs**:
  - Azure: Entra ID/Azure AD sign-in and audit logs; directory read operations where available; Azure activity logs.
  - AWS: CloudTrail events for IAM list/get operations (roles, policies, groups), plus S3 ACL/permissions calls.
  - GCP: Admin activity and data access logs for identity/group and IAM policy queries.
- **IdP telemetry**: sign-in risk, MFA prompts/denials, device compliance signals.
- **CASB / SaaS logs**: admin API calls, directory exports, mailbox/SharePoint/Teams admin role discovery.

## 6. Response Guidance
1. **Validate identity context**: confirm the principal (user/service principal), MFA status, device posture, and sign-in risk indicators.
2. **Scope reads**: identify which groups/roles were listed, and whether **privileged roles** were enumerated.
3. **Hunt follow-on actions**: look for policy changes, new credentials, session/token anomalies, and data access.
4. **Contain**: revoke sessions/tokens, rotate keys, enforce MFA, restrict API access, and quarantine suspicious principals.

## 12. Mitigations
Because this can leverage legitimate APIs, focus on:
- Strong **conditional access** (device compliance, geo/IP restrictions, risk-based policies)
- **Least privilege** for directory read/export capabilities
- Tight governance of **service principals** and automation credentials (short-lived creds, approvals, inventory)
- Monitor and restrict **admin API** usage; enforce approved tooling where possible

## 13. Testing & Validation
- In a lab tenant, perform controlled group/role listing via:
  - portal vs CLI vs SDK
- Validate:
  - audit log completeness, user-agent capture, principal identity resolution
  - detections for enumeration bursts and anomalous sign-in context
