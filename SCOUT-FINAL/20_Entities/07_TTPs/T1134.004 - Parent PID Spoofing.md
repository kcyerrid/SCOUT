# Access Token Manipulation: Parent PID Spoofing (T1134.004)

## 1. Summary
Parent PID Spoofing describes adversaries **creating a new process while specifying a false parent process**, causing the child process to appear as though it was spawned by a trusted or benign parent. While this technique does not directly modify tokens, it abuses Windows process creation mechanics closely tied to access control and token inheritance, enabling privilege escalation and defense evasion.

T1134.004 is commonly used to:
- Evade parent-child process-based detections
- Blend malicious execution with trusted system processes
- Obscure the true execution chain during investigations

---

## 2. Technical Overview
Windows allows processes to be created with extended startup attributes. Adversaries abuse this by:
- Supplying a different parent process handle at creation time
- Leveraging `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`
- Spawning processes that inherit security context from a legitimate parent

Common APIs and mechanisms involved:
- `CreateProcess`
- `UpdateProcThreadAttribute`
- `InitializeProcThreadAttributeList`

Artifacts often include:
- Child processes whose parent is inconsistent with execution context
- SYSTEM-level parent processes spawning user-context children
- Broken or misleading process ancestry chains

---

## 3. Subtechnique Considerations
Key considerations for T1134.004:
- Requires sufficient privileges to obtain a handle to the spoofed parent
- Often paired with token theft or injection
- Does not inherently elevate privileges but facilitates evasion
- Detection requires strong process lineage analysis

This subtechnique primarily enhances stealth rather than raw access.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Spoofing `explorer.exe` or `services.exe` as parent for malware
- Launching payloads that appear to originate from system services
- Pairing parent PID spoofing with process injection
- Using spoofed ancestry to bypass behavioral rules

These procedures are typically executed early in post-exploitation.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying implausible parent-child process relationships
- Detecting mismatches between user sessions and parent context
- Monitoring use of extended process creation attributes
- Alerting on trusted parents spawning unexpected children

### Data Source Notes
- **Process telemetry**: Essential for lineage validation
- **Security logs**: Useful for corroborating context
- **API telemetry**: Required for detecting attribute misuse

---

## 6. Response Guidance
When detected:
1. Validate whether the parent-child relationship is legitimate
2. Identify the true origin of process execution
3. Terminate suspicious child processes
4. Investigate for follow-on activity such as injection or lateral movement
5. Harden detection rules against spoofed ancestry

## 11. Malware Usage
Malware leveraging parent PID spoofing includes:

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege on process handle access
- Monitor and alert on suspicious parent-child relationships
- Use EDR capable of detecting ancestry spoofing
- Apply OS and security patches
