## 1. Summary
Email Account discovery (T1087.003) involves enumerating email addresses/accounts—often by querying Exchange/Exchange Online address lists (e.g., GAL) or harvesting from local mail client data. This can enable phishing targeting, privilege discovery, and mailbox access planning.

## 2. Technical Overview
Common behaviors include:
- Enumerating Exchange address lists and mailbox-related metadata via PowerShell cmdlets.
- Pulling organizational directory listings via email ecosystem integrations (e.g., directory APIs or synchronization services).
- Scraping local email clients (Outlook/Thunderbird) for stored addresses, PST/OST artifacts, or address books.

Defender-relevant intent:
- Identify admins and high-value users (IT, finance, executives).
- Build target lists for internal spearphishing or BEC-style operations.
- Map mailboxes for subsequent search/exfiltration.

## 4. Procedure Examples
Observed examples include:
- Seen malware collecting address book information from Outlook.
- LDAP queries used to discover email accounts for domain users.
- Tools that enumerate Exchange users / dump the GAL.
- Modules scraping email addresses from Outlook and parsing PST files.

## 5. Detection Guidance
Email account enumeration is high-signal when:
- Performed from **non-mailserver hosts** or atypical admin endpoints.
- Occurs in **high volume** (bulk directory/address list retrieval).
- Initiated by **unusual PowerShell sessions**, newly created accounts, or suspicious remote management sessions.

Detection ideas:
- Detect Exchange/Exchange Online PowerShell usage that queries address lists or mailbox directories from abnormal sources/users.
- Look for mailbox/address book enumeration followed quickly by mailbox search/exfiltration patterns or new inbox rules.
- On endpoints, detect processes accessing Outlook data stores in bulk and exporting/reading PST/OST at unusual times or by suspicious processes.

### Data Source Notes
Recommended telemetry:
- Exchange/Exchange Online administrative audit logs (cmdlets executed, actor identity, client IP/device).
- Azure AD / IdP sign-in logs for Exchange admin sessions (where applicable).
- Endpoint process/file access telemetry for mail client data stores (Outlook profiles, PST/OST access).
- PowerShell logging (script block, module logging) for Exchange-related cmdlets.

## 6. Response Guidance
1. Confirm whether the actor is a legitimate mail admin workflow (change windows, known admin hosts).
2. If suspicious, scope:
   - Which cmdlets/queries were executed
   - How many objects were enumerated
   - Which client IPs/devices initiated the activity
3. Hunt follow-on actions: mailbox search/export, forwarding rules, OAuth app consent, suspicious sign-ins.
4. Contain: revoke sessions, reset passwords, disable remote PowerShell for impacted accounts, review mailbox permissions and delegated access.

## 12. Mitigations
MITRE notes this behavior can be difficult to prevent as it often abuses built-in email/directory features. Focus on:
- Tightening who can run remote Exchange PowerShell / admin APIs.
- Enforcing MFA and conditional access for admin operations.
- Monitoring and limiting directory/address list access for service accounts and apps.

## 13. Testing & Validation
- Confirm Exchange auditing is enabled and retained sufficiently for investigations.
- Validate alerts on:
  - Address list enumeration from non-admin devices
  - High-volume directory queries
  - Abnormal PowerShell sessions (new device/IP, unusual user agent)
