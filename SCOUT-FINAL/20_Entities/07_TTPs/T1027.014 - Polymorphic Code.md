# Obfuscated Files or Information: Polymorphic Code (T1027.014)

## 1. Summary
Polymorphic Code describes adversaries **continuously modifying the structure, appearance, or encoding of malicious code while preserving its functionality**, enabling each instance of the payload to appear unique. This technique is designed to defeat signature-based detection and complicate malware analysis.

Adversaries use this technique to:
- Evade static and hash-based detections
- Generate unique payload variants per victim
- Increase malware longevity
- Degrade analyst confidence in indicators

---

## 2. Technical Overview
Polymorphic malware alters its code structure at runtime or during delivery by:
- Re-encrypting payloads with variable keys
- Mutating instruction sequences
- Inserting random junk instructions
- Reordering functions or code blocks

Typical polymorphic behaviors:
- Unique hashes for each payload instance
- Runtime decryption stubs
- Variable instruction patterns
- Consistent behavior despite code variance

Indicators include:
- Rapidly changing binaries with identical behavior
- Similar runtime execution flows across variants
- Decryption routines preceding execution
- Memory-resident decoded payloads

---

## 3. Subtechnique Considerations
Key considerations for T1027.014:
- Often paired with **Software Packing (T1027.002)**
- Can coexist with **Junk Code Insertion (T1027.016)**
- Strongly impacts static detection efficacy
- Behavioral detection becomes essential

Polymorphism targets **pattern recognition**, not execution.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Generating per-delivery payload variants
- Mutating decryption stubs dynamically
- Encrypting payloads with random keys
- Delivering functionally identical but structurally distinct binaries

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **behavioral consistency over code similarity**:
- Identify identical execution flows across different binaries
- Correlate process behaviors despite differing hashes
- Detect repeated decode-and-execute patterns
- Use machine-learning or heuristic detections

### Data Source Notes
- **EDR telemetry**: Observe consistent behavior across variants
- **Memory analysis**: Reveal decoded payloads
- **Malware analysis**: Compare execution traces

Common false positives:
- Legitimate software employing packers or protectors
- DRM-protected applications

Tuning guidance:
- Baseline known polymorphic legitimate software
- Elevate alerts when polymorphism enables malicious actions

---

## 6. Response Guidance
When suspected:
1. Capture multiple samples for comparison
2. Analyze runtime behavior rather than static features
3. Extract decoded payloads from memory
4. Hunt for similar behavioral patterns
5. Update detections to focus on behavior

## 8. SOC Relevance
T1027.014 is critical because:
- Signature-based detections rapidly degrade
- Hash-based blocking becomes ineffective
- Behavior correlation is mandatory

SOC teams must prioritize **behavioral analytics and correlation**.

---

- Evasion-focused adversaries

## 12. Mitigations
Recommended mitigations:
- Deploy behavior-based endpoint detection
- Limit execution of unknown binaries
- Use sandboxing and detonation
- Monitor decode-and-execute behaviors

## 13. Testing & Validation
Validation approaches:
- Execute multiple polymorphic samples in lab
- Validate detection on behavioral similarity
- Test SOC workflows for variant correlation
- Ensure tooling captures memory artifacts
