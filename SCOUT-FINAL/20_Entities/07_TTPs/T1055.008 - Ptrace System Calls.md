# Process Injection: Ptrace System Calls (T1055.008)

## 1. Summary
Ptrace System Calls describes adversaries **abusing the Linux `ptrace` debugging interface** to inject code, manipulate execution, or control another running process. Originally intended for debuggers, `ptrace` allows one process to observe and modify the memory and registers of another, making it a powerful mechanism for process injection.

T1055.008 is commonly used to:
- Inject shellcode into running Linux processes
- Hijack execution flow without spawning new processes
- Evade userland monitoring and security tooling
- Support stealthy post-exploitation activity

---

## 2. Technical Overview
The `ptrace` system call enables a tracer process to:
- Attach to a target process (`PTRACE_ATTACH`)
- Read and write process memory
- Inspect and modify registers
- Control execution (pause, single-step, resume)

Adversaries abuse this by:
- Attaching to long-lived or privileged processes
- Writing malicious instructions into memory
- Redirecting instruction pointers
- Resuming execution under attacker control

Artifacts often include:
- Unexpected `ptrace` attachments
- Memory writes to running processes
- Process execution flow anomalies
- Audit or syscall logs showing `ptrace` usage

---

## 3. Subtechnique Considerations
Key considerations for T1055.008:
- Requires sufficient permissions (often same UID or CAP_SYS_PTRACE)
- Frequently blocked or restricted in hardened environments
- Highly stealthy if audit logging is weak
- Common in Linux server and container breakouts

This subtechnique is Linux-specific and rarely seen in commodity malware.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Attaching to SSH daemons or application servers
- Injecting shellcode into memory via `ptrace`
- Modifying registers to redirect execution
- Using `ptrace` as a fileless injection mechanism

These actions typically occur post-compromise.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring `ptrace` system call usage
- Alerting on `PTRACE_ATTACH` events
- Detecting unexpected memory writes to running processes
- Correlating ptrace activity with privilege escalation attempts

### Data Source Notes
- **Audit logs (auditd)**: Primary detection source
- **Syscall telemetry**: Required for ptrace visibility
- **Process telemetry**: Useful for execution anomalies

---

## 6. Response Guidance
When detected:
1. Identify tracer and target processes
2. Isolate the affected system
3. Terminate malicious tracer processes
4. Capture memory and process state for analysis
5. Review permissions and ptrace restrictions

T1055.008 is especially relevant in:

Usage reflects elevated attacker capability.

## 10. Campaign Usage
Observed in:
- Targeted Linux intrusions
- Cloud and container compromise campaigns
- Stealthy post-exploitation operations

---

## 11. Malware Usage
Malware leveraging ptrace injection includes:
- Custom Linux backdoors
- In-memory implants
- Advanced post-exploitation toolkits

---

## 12. Mitigations
Recommended mitigations:
- Restrict ptrace via YAMA (`/proc/sys/kernel/yama/ptrace_scope`)
- Monitor and audit ptrace usage
- Limit CAP_SYS_PTRACE capability
- Apply least privilege principles
- Harden Linux servers and containers

---

## 13. Testing & Validation
Validation approaches:
- Simulate ptrace-based injection in lab systems
- Validate SOC alerts for ptrace syscalls
- Conduct red team testing focused on Linux internals
- Review auditd and syscall telemetry coverage
