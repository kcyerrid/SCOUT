## 1. Summary
NTDS (T1003.003) is credential dumping from the Active Directory domain database (NTDS.dit) on a domain controller (or from backups/virtual disk copies containing it). Access to NTDS.dit can expose domain credential hashes and other sensitive directory data, enabling rapid escalation to domain-wide compromise.

## 2. Technical Overview
Common paths to NTDS credential material:
- **Direct access on DCs**: reading/copying `%SystemRoot%\NTDS\ntds.dit` and related supporting files.
- **Snapshot and backup abuse**: leveraging Volume Shadow Copy or mounted backups/VHDs to obtain copies without file locks.
- **Built-in utility misuse**: use of legitimate admin utilities associated with directory maintenance/backup/export workflows.
- **Offline extraction**: parsing copied NTDS data to recover hashes and account information.

The highest signal often comes from **shadow copy creation + access to NTDS.dit + subsequent parsing/exfil**, especially from non-standard admin sessions.

## 3. Subtechnique Considerations
- NTDS access is often an **endgame** credential action on Windows domains.
- Many intrusions prefer stealthier replication-based dumping (see T1003.006 DCSync) when they have the right privileges; NTDS copying is more artifact-heavy but still common, especially with DC file/backup access.

## 4. Procedure Examples
ATT&CK procedure examples include:
- [[30_CIPHER/03_Threat_Actors/G0007 - APT28]] using utilities and snapshot creation to export Active Directory data.
- [[30_CIPHER/03_Threat_Actors/G0096 - APT41]] obtaining copies of NTDS data using built-in tooling.
- [[30_CIPHER/03_Threat_Actors/G0125 - HAFNIUM]] stealing copies of NTDS.DIT.
- [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider]] extracting NTDS.dit via volume shadow copies of virtual domain controller disks.
- [[30_CIPHER/05_Malware/S0357 - Impacket]] and [[30_CIPHER/05_Malware/S0488 - CrackMapExec]] supporting directory credential dumping workflows in some documented cases.

## 5. Detection Guidance
Treat this as a **critical domain event**.

High-signal detection patterns:
- **Shadow copy / snapshot activity on DCs**
  - Volume shadow copy creation events correlated to subsequent access of NTDS paths.
  - Snapshot creation initiated from unusual accounts, hosts, or remote sessions.
- **Sensitive file access**
  - Reads/copies of `%SystemRoot%\NTDS\ntds.dit` and related directory database artifacts.
  - NTDS access followed by creation of large files in temp/staging locations.
- **Backup/VHD mounting**
  - Mounting and browsing of DC backups/VHDs by non-backup operators or from unusual endpoints.
- **Post-extraction impact**
  - Rapid new authentications and privilege escalation after suspected NTDS access.
  - New replication, golden ticket usage, or mass lateral movement consistent with domain hash compromise.

### Data Source Notes
Useful telemetry sources:
- Domain controller file access auditing (where feasible and tuned)
- Volume shadow copy creation and management telemetry
- Process execution telemetry for directory/backup utilities on DCs
- Backup system audit logs and VHD mount events
- Authentication telemetry for sudden spread after suspected dumping

## 6. Response Guidance
- **Contain & preserve**: isolate affected DCs if feasible; preserve volatile and disk artifacts; identify and stop active dumping sessions.
- **Credential actions**: initiate an AD incident plan (KRBTGT resets, privileged credential rotations, tiered admin containment).
- **Scope**: determine if NTDS data left the environment; hunt for staging archives and outbound transfers.
- **Recovery**: expect broad compromise; prioritize DC integrity checks, admin workstation rebuild considerations, and complete credential hygiene.

## 8. SOC Relevance
- NTDS access is one of the strongest indicators of **domain credential catastrophe**.
- Top triage questions:
  - Which account performed snapshot/file access?
  - Was data staged, compressed, or transmitted?
  - What privileged actions followed immediately after?

## 9. Threat Actor Usage
- Documented in ATT&CK examples across both APT and financially motivated intrusions (e.g., [[30_CIPHER/03_Threat_Actors/G0125 - HAFNIUM]], [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider]], [[30_CIPHER/03_Threat_Actors/G0102 - Wizard Spider]]).

## 10. Campaign Usage
- C0051 - APT28 Nearest Neighbor Campaign: NTDS acquisition through snapshot-based approaches.
- C0048 - Operation MidnightEclipse: actors obtained AD credentials via NTDS.DIT access.

## 11. Malware Usage
- [[30_CIPHER/05_Malware/S0357 - Impacket]] and [[30_CIPHER/05_Malware/S0488 - CrackMapExec]] are referenced in ATT&CK procedure examples as enabling NTDS credential dumping approaches.

## 12. Mitigations
- **M1041 - Encrypt Sensitive Information**: secure and encrypt domain controller backups; ensure backup repositories are strongly protected.
- **M1027 - Password Policies**: enforce strong, unique local admin passwords and strong privileged password hygiene.
- **M1026 - Privileged Account Management**: reduce who can access DC files/backups; separate duties; enforce tiered admin.
- **M1017 - User Training**: reduce credential overlap and improve privileged access practices.

## 13. Testing & Validation
- In a lab/domain test environment:
  - Simulate snapshot creation and a benign read of NTDS paths, then validate alerting on the **sequence** (snapshot → NTDS access → staging).
  - Validate SOC playbooks for domain-wide credential compromise response.
- Ensure backup system auditing is integrated into SIEM for correlation.
