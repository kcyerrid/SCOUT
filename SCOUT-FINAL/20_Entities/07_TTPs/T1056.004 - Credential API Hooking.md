## 1. Summary
Credential API Hooking (T1056.004) involves adversaries hooking operating system or library functions that receive credentials as parameters (e.g., authentication APIs), allowing them to capture credentials during normal authentication workflows. This differs from keylogging by targeting **credential-bearing API calls**, not raw keystrokes.

## 2. Technical Overview
Common implementation patterns:
- **Windows userland hooks** (e.g., hook procedures, import address table (IAT) hooking, inline patching) placed into processes that handle credentials (RDP clients, browsers, authentication helpers).
- **Linux/macOS library injection hooks**
  - `LD_PRELOAD` (Linux) or `DYLD_INSERT_LIBRARIES` (macOS) to load malicious libraries and intercept functions (e.g., `read()` used by SSH/SCP contexts).

Defender-relevant behaviors:
- Hook installation functions and memory modifications in userland.
- Suspicious injected modules or unexpected shared libraries loaded into credential-sensitive processes.
- Environment-variable based library injection patterns on Unix-like systems.

## 3. Subtechnique Considerations
- This technique often overlaps with broader process injection and library hijacking behaviors; detections should emphasize **where** the hook lands (credential-sensitive process) and **how** it persists.

## 4. Procedure Examples
- [[30_CIPHER/05_Malware/S0484 - Carberp]] hooked Windows API functions to steal credentials.
- [[30_CIPHER/05_Malware/S0363 - Empire]] leveraged API hooking modules (e.g., credential interception modules).
- [[30_CIPHER/05_Malware/S0182 - FinFisher]] hooked processes via IAT pointer modification.
- [[30_CIPHER/05_Malware/S0353 - NOKKI]] used SetWindowsHookEx and injected into GUI processes.
- [[30_CIPHER/03_Threat_Actors/G0068 - PLATINUM]] used Windows hook interfaces for information gathering such as credential access.
- [[30_CIPHER/05_Malware/S0416 - RDFSNIFFER]] hooked Win32 API functions to hijack remote system management UI elements.
- [[30_CIPHER/05_Malware/S0266 - TrickBot]] captured RDP credentials by capturing a Windows credential-related API.
- [[30_CIPHER/05_Malware/S0386 - Ursnif]] hooked APIs for information theft, including browser traffic monitoring.
- [[30_CIPHER/05_Malware/S1154 - VersaMem]] hooked and overrode an authentication method to intercept plaintext credentials.
- [[30_CIPHER/05_Malware/S0251 - Zebrocy]] installed an application-defined Windows hook and used it for follow-on behaviors.
- [[30_CIPHER/05_Malware/S0330 - Zeus Panda]] used IAT hooking.
- [[30_CIPHER/05_Malware/S0412 - ZxShell]] hooked API functions to spawn threads.

## 5. Detection Guidance
Effective detection emphasizes **hooking artifacts** + **credential-process targeting**.

Recommended analytics:
- **Hook installation + suspicious module load**
  - Alert on SetWindowsHookEx-like patterns combined with injection indicators or unexpected DLLs in many GUI processes.
- **IAT/inline patch indicators**
  - Memory region changes in loaded modules (code pages modified), atypical call stacks, or EDR-detected userland hooks in credential-sensitive processes.
- **Unix-like library injection**
  - Processes (ssh/scp/sudo/auth helpers) launched with suspicious `LD_PRELOAD`/`DYLD_INSERT_LIBRARIES` values, or unexpected shared libraries loaded from user-writable paths.

### Data Source Notes
- EDR: module load events, memory tampering/hook detections, injection telemetry, process ancestry.
- Windows: Sysmon/ETW (where available) for image loads and process creation; security logs for follow-on credential use.
- Linux/macOS: process environment capture, dynamic loader logs (where available), filesystem telemetry for injected libraries.
- Network: outbound connections from affected processes following credential interception (exfil/beacon correlation).

## 6. Response Guidance
- Isolate impacted endpoints; identify the hooked process set and injected modules.
- Rotate credentials potentially exposed; prioritize interactive/privileged accounts and remote access credentials (RDP/VPN/SSH).
- Hunt for persistence that re-establishes hooks (startup items, service modifications, injected library placement).

## 12. Mitigations
- MITRE notes this is difficult to prevent with purely preventive controls because it abuses system features.
- Compensating controls:
  - Application control and driver/module trust enforcement where feasible.
  - Reduce local admin exposure; harden endpoints to limit injection/library placement.

## 13. Testing & Validation
- Validate visibility in a lab:
  - Confirm your EDR flags userland hooks (SetWindowsHookEx/IAT/inline) and records module metadata (signer/path).
  - Confirm you capture process environment variables relevant to `LD_PRELOAD` / `DYLD_INSERT_LIBRARIES`.
