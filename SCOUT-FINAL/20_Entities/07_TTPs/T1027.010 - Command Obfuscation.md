# Obfuscated Files or Information: Command Obfuscation (T1027.010)

## 1. Summary
Command Obfuscation describes adversaries **intentionally obscuring command-line instructions or script logic** to hide their true purpose from defenders, security tooling, and logging systems. This technique is commonly used during execution and post-exploitation to evade detection and analysis.

Adversaries use this technique to:
- Evade command-line–based detections
- Obscure malicious intent in logs
- Bypass script inspection controls
- Delay analyst understanding during incident response

---

## 2. Technical Overview
Command obfuscation alters how commands appear without changing their outcome. Adversaries apply obfuscation to:

- Shell commands
- Scripted payloads
- Interpreter arguments
- Inline execution strings

Common obfuscation methods include:
- String concatenation or reordering
- Character substitution or encoding
- Excessive use of environment variables
- Indirect command invocation
- Runtime decoding or expansion

Indicators include:
- Overly complex command lines for simple actions
- Use of encoded or dynamically constructed arguments
- Commands that decode or reconstruct instructions at runtime
- Mismatch between visible command text and executed behavior

---

## 3. Subtechnique Considerations
Key considerations for T1027.010:
- Often paired with **Command and Scripting Interpreter (T1059)**
- Common in PowerShell, Bash, and Windows CMD abuse
- Obfuscation depth varies widely
- Often layered with encoding or encryption

Command obfuscation targets **log readability and static inspection**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Encoding command arguments and decoding at runtime
- Splitting commands across multiple variables
- Dynamically assembling execution strings
- Using indirect execution mechanisms to mask intent

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **behavioral intent over literal strings**:
- Normalize or decode commands before analysis
- Detect execution of decoding routines
- Identify suspicious interpreter usage patterns
- Correlate command execution with follow-on behavior

### Data Source Notes
- **Command-line logs**: Primary visibility into obfuscation
- **Script logs**: Reveal decoding or reconstruction logic
- **EDR telemetry**: Correlate commands with behavior

Common false positives:
- Legitimate administrative scripts
- Automation frameworks

Tuning guidance:
- Baseline expected scripting behavior
- Elevate alerts for obfuscated commands enabling suspicious actions

---

## 6. Response Guidance
When suspected:
1. Decode or normalize obfuscated commands
2. Analyze reconstructed intent and behavior
3. Identify affected hosts and users
4. Hunt for similar obfuscation patterns
5. Update detections to catch normalized logic

## 8. SOC Relevance
T1027.010 is critical because:
- Logs may conceal true adversary intent
- Analysts may overlook malicious commands
- Automation can mask high-risk activity

SOC teams should **normalize and enrich command-line data**.

---

## 9. Threat Actor Usage
Commonly used by:
- Advanced persistent threats
- Living-off-the-land operators
- Red team and adversary simulation frameworks

---

## 10. Campaign Usage
Observed in:
- Post-exploitation activity
- Lateral movement and persistence stages
- Long-dwell intrusions

---

## 11. Malware Usage
Associated with:
- Script-based malware
- Fileless attacks
- Loader and execution frameworks

---

## 12. Mitigations
Recommended mitigations:
- Enable enhanced command-line logging
- Decode and normalize commands in SIEM
- Restrict interpreter usage where possible
- Apply script block logging and AMSI

---

## 13. Testing & Validation
Validation approaches:
- Execute benign obfuscated commands in lab
- Validate detection on normalized command output
- Test SOC workflows for script analysis
- Ensure tooling captures full command context
