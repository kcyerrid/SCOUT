# Impair Defenses: Disable Windows Event Logging (T1562.002)

## 1. Summary
Disable Windows Event Logging describes adversaries **disabling, clearing, or otherwise impairing Windows Event Log generation and retention** to reduce forensic visibility and evade detection. By suppressing logging, attackers can conceal execution, persistence, and lateral movement activity.

This subtechnique is commonly used to:
- Prevent detection by SIEM and SOC monitoring
- Obscure attacker activity during and after intrusion
- Reduce forensic evidence available for investigation
- Support long-dwell or stealth-focused operations

---

## 2. Technical Overview
Windows Event Logging is a core telemetry source for security monitoring. Adversaries impair logging by:

- Stopping or disabling the Windows Event Log service
- Modifying registry settings controlling logging behavior
- Clearing event logs to remove historical evidence
- Disrupting log forwarding or collection mechanisms
- Tampering with audit policy configuration

Common artifacts and indicators include:
- Windows Event Log service state changes
- Sudden gaps or drops in event volume
- Audit policy modifications
- Log clearing events followed by suspicious activity

---

## 3. Subtechnique Considerations
Key considerations for T1562.002:
- Strongly associated with **Indicator Removal on Host (T1070)**
- Often paired with **Hide Artifacts (T1564)**
- Requires administrative or elevated privileges
- High-confidence indicator of malicious intent

Disabling logging is rarely justified outside of controlled maintenance.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Disabling the Windows Event Log service
- Clearing security, system, or application logs
- Modifying audit policy to suppress events
- Preventing log forwarding to centralized collectors

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **log integrity and continuity**:
- Alert on Windows Event Log service stop or disable events
- Detect audit policy changes
- Monitor for unexpected log clearing
- Alert on telemetry gaps or log ingestion silence

### Data Source Notes
- **Windows Event Logs**: Primary detection source
- **EDR telemetry**: Detect service tampering
- **Registry monitoring**: Identify logging configuration changes
- **SIEM ingestion metrics**: Detect sudden drops in log volume

Common false positives:
- Legitimate maintenance or troubleshooting
- Log rotation or retention configuration changes

Tuning guidance:
- Require change approval for logging configuration modifications
- Baseline expected event volume per host role

---

## 6. Response Guidance
When suspected:
1. Verify the state of Windows Event Log services
2. Restore logging and audit policy settings
3. Preserve remaining logs immediately
4. Investigate activity before and after logging disruption
5. Treat log impairment as a security incident

## 8. SOC Relevance
T1562.002 is one of the **highest-severity defense evasion techniques**. Loss of Windows Event Logs directly degrades detection, response, and forensic capability.

Any unexplained logging disruption should trigger immediate escalation.

---

## 9. Threat Actor Usage
This technique is commonly used by:
- Ransomware operators
- Advanced persistent threats
- Financially motivated intruders

Its use strongly correlates with **hands-on-keyboard activity**.

---

## 10. Campaign Usage
Observed in:
- Ransomware deployment phases
- Espionage campaigns
- Intrusions involving privilege escalation
- Long-dwell enterprise compromises

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Post-exploitation frameworks
- Loaders and droppers designed to evade logging

---

## 12. Mitigations
Recommended mitigations:
- Protect Windows Event Log services from tampering
- Forward logs to centralized, immutable storage
- Restrict administrative privileges
- Monitor for log service state changes
- Enforce tamper protection and audit policies

---

## 13. Testing & Validation
Validation approaches:
- Simulate log service disablement in lab environments
- Validate alerts on log clearing events
- Test SOC response to telemetry loss
- Ensure log forwarding detects ingestion gaps
