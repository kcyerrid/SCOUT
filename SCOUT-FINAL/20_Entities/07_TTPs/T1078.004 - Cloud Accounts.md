# Cloud Accounts (T1078.004)

## 1. Summary
Cloud Accounts describes adversary abuse of valid credentials associated with cloud service providers or SaaS platforms. This subtechnique enables attackers to access management consoles, APIs, and hosted resources using legitimate authentication workflows, often bypassing traditional perimeter defenses.

Because activity leverages trusted identity providers and APIs, malicious use frequently blends with normal cloud administrative or user behavior, making detection challenging without strong identity telemetry.

---

## 2. Technical Overview
Adversaries obtain cloud account credentials through phishing, token theft, OAuth abuse, credential reuse, malware, or purchasing access from initial access brokers. Once obtained, credentials, tokens, or API keys are used to authenticate to cloud consoles or programmatic interfaces.

Common technical mechanisms include:
- Web-based console authentication
- API calls using access keys or OAuth tokens
- Abuse of federated identity or single sign-on (SSO)

Artifacts include authentication events, token issuance, API activity logs, and configuration changes.

---

## 3. Subtechnique Considerations
T1078.004 differs from other Valid Account subtechniques in that:
- Authentication may be token- or API-based rather than password-based
- Activity may occur entirely outside traditional endpoint visibility
- Privilege escalation can be rapid through role assignment or policy changes

This subtechnique is especially relevant in cloud-native and SaaS-first environments.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Logging into cloud management portals using stolen credentials
- Using compromised API keys to enumerate or modify resources
- Abusing OAuth grants to maintain persistent access

Analysts may observe administrative actions performed by accounts that do not typically manage cloud resources.

---

## 5. Detection Guidance
Detection should emphasize cloud-native identity analytics:
- Anomalous logins to cloud consoles or SaaS platforms
- API activity from new IPs, regions, or user agents
- Creation or modification of roles, policies, or OAuth grants
- Authentication without expected MFA challenges

Correlation between authentication events and configuration changes is critical.

### Data Source Notes
- **Cloud Service Logs:** Primary detection source; ensure admin and API events are enabled
- **Authentication Logs:** High value when enriched with MFA and device context
- **API Call Logs:** Essential for detecting non-interactive abuse

---

## 6. Response Guidance
When Cloud Account abuse is suspected:
- Immediately revoke active sessions, tokens, and API keys
- Reset credentials and enforce MFA
- Review role assignments, policies, and recent changes
- Investigate for persistence mechanisms (e.g., OAuth apps, new users)

Preserve cloud audit and identity logs for forensic analysis.

## 8. SOC Relevance
Cloud Account abuse is one of the fastest paths to large-scale impact in modern environments, enabling data theft, service disruption, and downstream compromise. Detection maturity is often lower in SaaS platforms, making this a high-priority technique for SOC coverage.

---

## 9. Threat Actor Usage
This subtechnique is commonly used by:
- Cloud-focused ransomware operators
- Financially motivated fraud and extortion actors
- Advanced persistent threat groups targeting cloud infrastructure

Confidence in widespread usage is extremely high.

---

## 10. Campaign Usage
Cloud Accounts appear in:
- Cloud ransomware and extortion campaigns
- SaaS account takeover incidents
- Espionage campaigns targeting cloud-hosted data

---

## 11. Malware Usage
Malware and tooling frequently associated with cloud account abuse include:
- [[30_CIPHER/05_Malware/S0266 - TrickBot|TrickBot]]
- [[30_CIPHER/05_Malware/S0650 - QakBot|QakBot]]

These tools are often used to obtain credentials or session material prior to cloud access.

---

## 12. Mitigations
Effective mitigations include:
- Enforcing MFA for all cloud and SaaS accounts
- Implementing conditional access and risk-based authentication
- Restricting API key creation and rotation frequency
- Monitoring for unauthorized OAuth applications
- Applying least privilege to cloud roles and policies

---

## 13. Testing & Validation
Validation approaches include:
- Atomic tests simulating cloud credential abuse
- Purple team exercises targeting cloud identity controls
- Manual review of anomalous API and admin activity

Successful validation produces timely alerts with minimal false positives.
