## 1. Summary
This subtechnique covers adversary abuse of **Windows link-local name resolution** (LLMNR) and **NetBIOS Name Service** (NBT-NS) to coerce victims into authenticating to an adversary-controlled host, often enabling **credential capture** and/or **NTLM relay** to other services.

## 2. Technical Overview
- **Poisoning:** Adversary responds to LLMNR (UDP 5355) or NBT-NS (UDP 137) queries, impersonating the requested host so victims connect to the adversary.
- **Credential interception:** Victims may send username + NTLM challenge/response, enabling offline cracking or relay.
- **Relay:** Captured NTLMv1/v2 material can be relayed to services (e.g., SMB/LDAP/HTTP) when protections are absent/misconfigured (e.g., SMB signing not enforced).

MITRE detection strategy emphasizes anomalous UDP 5355/137 traffic combined with relay attempts and suspicious configuration drift that re-enables multicast name resolution.

## 3. Subtechnique Considerations
- Distinguish from generic T1557 by focusing on **name-resolution and NTLM authentication telemetry**.
- Coverage overlaps with other credential access behaviors; prioritize correlation (poisoning → authentication attempts → lateral movement).
- Ensure detections account for legitimate LLMNR/NBT-NS traffic in legacy environments (baseline first).

## 5. Detection Guidance
Core detections:
- **Network:**  
  - Spikes or unusual patterns of LLMNR (UDP 5355) / NBT-NS (UDP 137) responses from non-standard hosts.  
  - Multiple victims resolving many names to a single responder host.  
  - SMB relay indicators: unexpected SMB auth attempts to high-value hosts immediately following poisoning events.
- **Endpoint/Config drift:**  
  - Registry/policy modifications that re-enable multicast name resolution or NetBIOS where disabled.  
  - Suspicious service creation indicative of on-host responder tooling.
- **Correlation:** poisoning source ↔ victim authentication ↔ privileged target authentication attempts (SMB/LDAP/HTTP).

### Data Source Notes
Telemetry that typically enables high-quality detection:
- Packet capture/NetFlow/IDS logs for UDP 5355/137 and SMB authentication patterns
- Windows event telemetry for authentication failures/successes and service/process creation
- Configuration auditing for LLMNR/NetBIOS settings and policy changes

## 6. Response Guidance
1. Identify poisoning source(s) and isolate the host(s) from the network.
2. Validate whether NTLM relay succeeded (SMB/LDAP auth anomalies, new sessions, remote service creation).
3. Reset/rotate credentials for impacted accounts; prioritize privileged accounts observed authenticating post-poisoning.
4. Harden environment (disable LLMNR/NetBIOS where possible; enforce SMB signing; segment sensitive systems).

High-impact, high-signal in Windows-heavy environments:
- Often a **prelude to lateral movement** and privilege escalation.
- Strong detection ROI via combined network + auth correlation.
- Treat unexpected LLMNR/NBT-NS responders as priority incidents, especially in segments containing servers or admin workstations.

## 12. Mitigations
- **M1042 Disable or Remove Feature or Program:** Disable LLMNR and NetBIOS when not required.
- **M1037 Filter Network Traffic:** Block LLMNR/NetBIOS traffic; enforce SMB signing to reduce NTLM relay viability.
- **M1031 Network Intrusion Prevention:** Detect/block AiTM-related traffic patterns at the network layer.
- **M1030 Network Segmentation:** Limit spread and reduce opportunities for poisoning/relay across segments.

## 13. Testing & Validation
- Validate IDS/analytics detect:
  - Non-standard hosts responding to UDP 5355/137
  - Poisoning → SMB auth attempts to servers (relay patterns)
- Confirm tuning against legitimate legacy name resolution traffic to reduce false positives.
- Run tabletop exercises for rapid credential rotation and isolation of poisoning sources.
