# T1547.007 – Re-opened Applications

## 1. Technique Overview
**Re-opened Applications (T1547.007)** is a sub-technique of **Boot or Logon Autostart Execution (T1547)** in MITRE ATT&CK v18. Adversaries exploit operating system or application features that automatically **restore previously opened applications** after a user logs back in or a system restarts. By manipulating what is restored, attackers can achieve persistence without relying on traditional startup locations.

This technique leverages legitimate usability features and therefore often blends into normal user behavior.

## 2. Adversary Objectives
Adversaries use this technique to:
- Regain execution after user logon or reboot
- Avoid creating obvious autostart artifacts
- Blend malicious execution into legitimate application behavior
- Maintain persistence with minimal configuration changes

## 3. Common Abuse Patterns
- Configuring applications to reopen malicious documents or scripts
- Leveraging OS-level “restore previous apps” settings
- Modifying session restore files or state data
- Using trusted applications (e.g., browsers, productivity tools) as execution vectors
- Triggering execution via malicious macros or embedded scripts in reopened files

## 4. Detection Considerations
Detection relies on **application behavior and state monitoring**, including:
- Unexpected applications reopening on logon
- Session restore files referencing unusual file paths or content
- Applications executing scripts or child processes immediately after restore
- Correlating reopen behavior with suspicious file modifications
- Monitoring configuration changes enabling automatic app restoration

## 5. Defensive Mitigations
- Disable automatic application reopening where not required
- Monitor and restrict execution of scripts or macros within applications
- Use application control to limit child process execution
- Educate users on unexpected application restore behavior
- Review application session state and restore configurations during response

## 6. Operational Impact
If successful, T1547.007 can:
- Provide low-noise persistence tied to user behavior
- Evade traditional startup and autorun detections
- Enable repeated execution of malicious content
- Complicate analysis due to reliance on legitimate features

## 7. Analyst Notes
Re-opened Applications persistence is subtle and often overlooked during investigations because it relies on **user convenience features** rather than explicit autostart mechanisms. Analysts should consider this technique when traditional persistence artifacts are absent but malware consistently executes after user logon.
