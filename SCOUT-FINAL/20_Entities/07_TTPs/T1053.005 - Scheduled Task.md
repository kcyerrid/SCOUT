# Scheduled Task (T1053.005)

## 1. Summary
Scheduled Task (Windows) describes adversary abuse of the Windows Task Scheduler to execute malicious code at a specified time, on system startup, or in response to specific system events. This subtechnique is frequently used to establish persistence, automate execution, and, in some cases, achieve execution under elevated privileges.

Because scheduled tasks are commonly used by administrators and legitimate software, malicious tasks can blend into normal system activity if not carefully monitored.

---

## 2. Technical Overview
Windows Task Scheduler allows users and applications to define tasks that execute programs or scripts based on triggers such as time, user logon, or system events.

Adversaries may:
- Create new scheduled tasks using `schtasks.exe`, PowerShell, or APIs
- Modify existing tasks to execute malicious payloads
- Configure tasks to run with highest privileges
- Obfuscate task names and command arguments

Artifacts include task XML definitions, registry entries, scheduler operational logs, and child process execution events.

---

## 3. Subtechnique Considerations
T1053.005 is the Windows-specific implementation of scheduled execution and persistence.

Key considerations include:
- Tasks may run under SYSTEM or administrator contexts
- Event-triggered tasks may evade time-based detection
- Malicious tasks may be hidden or disguised as legitimate maintenance jobs

Detection requires visibility into task creation and modification events.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Creating a scheduled task that launches a backdoor at startup
- Scheduling PowerShell scripts to run at regular intervals
- Modifying existing maintenance tasks to execute malicious binaries
- Using encoded command lines within task definitions

Analysts may observe recurring execution of suspicious processes aligned with scheduler activity.

---

## 5. Detection Guidance
Detection should focus on:
- Creation or modification of scheduled tasks outside approved change windows
- Tasks executing from user-writable or temporary directories
- Tasks configured to run with elevated privileges unexpectedly
- Use of `schtasks.exe` or Task Scheduler APIs by non-admin users

Correlation between scheduler logs and process execution improves detection fidelity.

### Data Source Notes
- **Task Scheduler Logs:** High-fidelity but sometimes disabled
- **Process Execution:** Required to confirm payload execution
- **Registry:** Useful for identifying task storage artifacts

---

## 6. Response Guidance
When malicious scheduled tasks are identified:
- Disable and remove the task immediately
- Identify associated payloads and execution history
- Review for additional persistence mechanisms
- Rotate credentials used to create or run the task

Preserve task definitions and scheduler logs for forensic analysis.

## 8. SOC Relevance
Scheduled Task abuse is one of the most common persistence and execution mechanisms observed in Windows intrusions. SOCs must maintain strong visibility into task creation and execution to detect abuse effectively.

## 12. Mitigations
Effective mitigations include:
- Restricting scheduled task creation to approved administrators
- Monitoring and alerting on new or modified tasks
- Enforcing least-privilege execution contexts
- Reviewing scheduled tasks during incident response
- Hardening Task Scheduler configurations

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for scheduled task creation
- Purple team simulations of persistence via scheduled tasks
- Review of alerts tied to `schtasks.exe` usage

Successful validation results in detection of unauthorized task creation.
