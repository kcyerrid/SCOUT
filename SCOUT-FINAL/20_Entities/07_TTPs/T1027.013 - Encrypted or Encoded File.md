# Obfuscated Files or Information: Encrypted or Encoded File (T1027.013)

## 1. Summary
Encrypted or Encoded File describes adversaries **protecting malicious content by encrypting or encoding files** so their contents cannot be directly inspected or understood without a decoding or decryption step. This technique impedes static analysis, signature-based detection, and content inspection by security controls.

Adversaries use this technique to:
- Hide malicious logic from scanners and analysts
- Evade content-based security controls
- Delay or complicate forensic analysis
- Protect payloads during transit and staging

---

## 2. Technical Overview
Adversaries encrypt or encode files that contain:
- Executables or shellcode
- Scripts or configuration data
- Secondary payloads or modules

Common methods include:
- Symmetric encryption (custom or standard algorithms)
- Simple encodings (Base64, XOR, custom alphabets)
- Layered encoding/encryption schemes
- Runtime decryption or decoding prior to execution

Typical behaviors:
- Files with high entropy or unreadable content
- Decoding or decryption routines executed before use
- Execution of decoded content in memory
- Removal of encrypted artifacts after use

Indicators include:
- High-entropy files accessed shortly before execution
- Decoding routines invoked by scripting engines
- Network transfers of encoded payloads
- Absence of readable strings in malicious artifacts

---

## 3. Subtechnique Considerations
Key considerations for T1027.013:
- Frequently paired with **Deobfuscate/Decode Files or Information (T1140)**
- Used across nearly all malware families
- Encryption strength varies from trivial to robust
- Often layered with packing or embedding techniques

Encrypted or encoded files primarily target **static detection mechanisms**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering encrypted payloads that decrypt at runtime
- Storing encoded configuration data within scripts
- Downloading encoded binaries and decoding locally
- Executing decrypted content directly from memory

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **decode-and-execute behavior**:
- Identify decryption or decoding routines preceding execution
- Monitor scripting engines handling high-entropy content
- Correlate file access with runtime transformation
- Detect execution of data that was previously unreadable

### Data Source Notes
- **File monitoring**: Identify high-entropy or unreadable files
- **Script logs**: Reveal decode/decrypt logic
- **EDR telemetry**: Correlate decoding with execution

Common false positives:
- Legitimate encrypted archives
- Protected commercial software

Tuning guidance:
- Baseline legitimate encryption usage
- Elevate alerts when decoding enables execution

---

## 6. Response Guidance
When suspected:
1. Preserve encrypted/encoded artifacts
2. Capture runtime memory to extract decoded content
3. Analyze decryption routines and keys
4. Identify delivery and execution chains
5. Hunt for similar encoded artifacts across hosts

## 8. SOC Relevance
T1027.013 is critical because:
- Content inspection may see only unreadable data
- Detection hinges on observing transformation and execution
- Encryption can mask intent until the last moment

SOC teams must monitor **when and how data becomes executable**.

## 12. Mitigations
Recommended mitigations:
- Employ behavior-based detection
- Inspect runtime decoding and execution
- Restrict execution of unknown binaries
- Monitor scripting engines closely

---

## 13. Testing & Validation
Validation approaches:
- Analyze benign encrypted files in lab environments
- Validate alerts on decode-and-execute patterns
- Test SOC playbooks for encrypted payload handling
- Ensure tooling captures memory-resident content
