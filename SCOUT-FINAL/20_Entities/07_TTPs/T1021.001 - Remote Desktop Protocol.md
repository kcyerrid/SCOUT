# T1021.001 - Remote Desktop Protocol

## 1. Summary
Adversaries use Remote Desktop Protocol (RDP/RDS) to interactively access remote Windows systems for lateral movement when the service is enabled and they possess valid credentials.

## 2. Technical Overview
Common attacker behaviors:
- Interactive logon to servers/workstations via RDP (often after credential theft).
- Post-auth activity: manual tooling, privilege escalation attempts, lateral pivoting, and staging ransomware or other payloads.
- Use of legitimate admin features (clipboard, drive mapping, remote assistance workflows) to blend into normal operations.

High-signal indicators:
- RDP logons to privileged-tier systems from non-admin endpoints.
- RDP by accounts that do not normally use interactive remote sessions (service accounts).
- New/rare source→destination pairs, especially after authentication failures or password spray activity.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- RDP is high-signal because it is typically interactive and leaves strong authentication artifacts on the destination host.
- Expect legitimate noise in environments with jump hosts and remote admin teams; tune based on sanctioned pathways (RD Gateway/bastion).

## 4. Procedure Examples
ATT&CK documents RDP usage by multiple groups and tools, including:
- [[30_CIPHER/03_Threat_Actors/G0102 - Wizard Spider|Wizard Spider]] using RDP for lateral movement and interactive ransomware deployment.
- [[30_CIPHER/03_Threat_Actors/G0087 - APT39|APT39]] using RDP in intrusion activity.
- [[30_CIPHER/05_Malware/S0030 - Carbanak|Carbanak]] using RDP as a lateral movement mechanism.
- [[30_CIPHER/05_Malware/S0670 - WarzoneRAT|WarzoneRAT]] using RDP-related behavior.
- [[30_CIPHER/05_Malware/S0412 - ZxShell|ZxShell]] with remote desktop functionality.

## 5. Detection Guidance
Prioritize correlation: **RDP logon → suspicious post-auth actions**.

Detection ideas:
- Alert on successful RDP logons (especially Type 10/RemoteInteractive) to sensitive systems, followed by:
  - Unusual process execution (cmd/powershell/mshta/rundll32, living-off-the-land tools) on the destination host.
  - Lateral movement fan-out from the newly accessed host.
  - Rapid creation/modification of services, scheduled tasks, or new local users.
- Identify RDP logons from:
  - Non-standard admin jump hosts
  - Newly observed devices
  - Unusual subnets/VPN endpoints
- Detect “interactive admin” anomalies:
  - RDP sessions at unusual times for the account
  - RDP sessions that coincide with credential access alerts or account compromise indicators

### 5.1. Data Source Notes
Useful telemetry typically includes:
- Windows Security authentication logs on destination (successful/failed logons; RemoteInteractive).
- RDP/RDS operational logs (where enabled) for session lifecycle.
- Network telemetry for TCP/3389 (or RD Gateway paths) and session metadata.
- Endpoint telemetry on destination: process creation and parent/child relationships after RDP logon.

## 6. Response Guidance
- Contain: isolate destination host if post-auth activity indicates compromise; restrict RDP temporarily to approved admin paths.
- Credentials: disable/reset the account used; validate MFA posture and conditional access for remote admin.
- Scope: identify other RDP sessions by the account/source; look for additional hosts accessed.
- Remediate: validate persistence mechanisms, remove unauthorized tools, and confirm no new privileged accounts.

Investigation pivots:

- Session start time and duration; concurrent sign-ins (VPN, O365, etc.).
- Destination host process tree immediately after RDP authentication.
- Any subsequent remote actions originating from the destination host.

## 12. Mitigations
ATT&CK-listed mitigations for T1021.001 include:
- M1047 Audit: review Remote Desktop Users group membership; remove unnecessary accounts/groups.
- M1042 Disable or Remove Feature or Program: disable RDP where unnecessary.
- M1035 Limit Access to Resource Over Network: use remote desktop gateways.
- M1032 Multi-factor Authentication: enforce MFA for remote logins where possible.
- M1030 Network Segmentation: avoid exposing RDP to the internet; restrict RDP between internal security zones.
- M1028 Operating System Configuration: configure session timeouts and limits via policy.
- M1026 Privileged Account Management: restrict/admin-limit groups allowed to log in via RDP.
- M1018 User Account Management: limit remote permissions if remote access is required.

## 13. Testing & Validation
- Validate that RDP logons generate expected authentication and RDP operational events.
- Simulate authorized RDP access from a sanctioned jump host vs. an unsanctioned workstation and confirm detections differentiate them.
- Run ATT&CK-aligned emulation tests in a lab to ensure “RDP logon → post-auth actions” correlation works.
