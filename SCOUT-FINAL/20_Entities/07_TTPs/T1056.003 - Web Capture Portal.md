## 1. Summary
Web Portal Capture (T1056.003) involves adversaries installing or modifying code on externally facing web portals (e.g., VPN or webmail login pages) to **capture credentials entered by users**, typically transmitting them to attacker infrastructure while still allowing the login flow to proceed.

## 2. Technical Overview
Common approaches:
- **Portal code modification** (e.g., JavaScript injection into the login page) to siphon username/password/OTP input.
- **Compromised authentication components** (webshells/plugins) that log inputs server-side.
- **Phishing portal hosting** that mimics real portals (overlaps with other phishing techniques; this subtechnique focuses on capture via web portal mechanisms).

Defender-relevant behaviors:
- Unplanned changes to login page assets (HTML/JS/CSS), often with obfuscation or additional outbound requests.
- New/unknown scripts loaded from unusual domains at login time.
- Server-side logging artifacts or unexpected outbound connections from portal hosts during authentication events.

## 3. Subtechnique Considerations
- Web Portal Capture can appear:
  - **Post-compromise** (attacker already has admin access; adds capture as backup credential harvesting)
  - **As part of initial access** via exploitation of an internet-facing service, followed by portal modification
- Detections are strongest when you baseline portal assets and auth flows, then alert on deltas.

## 4. Procedure Examples
- C0029 - Cutting Edge: threat actors modified JavaScript loaded by an Ivanti Connect Secure login page to capture entered credentials.
- [[30_CIPHER/05_Malware/S1022 - IceApple]] credential logger monitored for OWA authentication requests and logged credentials.
- C0030 - Triton Safety Instrumented System Attack: [[30_CIPHER/03_Threat_Actors/G0088 - TEMP.Veles]] captured credentials as they were being changed by redirecting text-based login codes to attacker-controlled websites.
- [[30_CIPHER/05_Malware/S1116 - WARPWIRE]] captured credentials submitted during web logon to enable access to layer-seven applications.
- [[30_CIPHER/03_Threat_Actors/G1035 - Winter Vivern]] hosted look-alike web pages mimicking government email logon sites to collect logon information.

## 5. Detection Guidance
Focus on **integrity monitoring** and **auth-flow anomalies**.

Recommended analytics:
- **Portal asset integrity drift**
  - Alert on changes to login page JS/HTML/CSS outside approved change windows (hash diff + signer/package validation).
  - Alert on new script includes, especially remote scripts or newly introduced endpoints.
- **Suspicious outbound requests during login**
  - From client side: login page causing browser to call unusual domains (collecting form fields).
  - From server side: portal host initiating unusual egress during authentication (webhook-style exfil).
- **Auth logging artifacts**
  - New files/DB writes or log entries containing raw credential fields, or unexpectedly verbose logging in auth components.
- **Exploit-to-modification chaining**
  - Exploit attempt on portal host → file changes in web root → credential capture indicators.

### Data Source Notes
- Web server: file integrity monitoring (web root), deployment logs, WAF logs, web server access/error logs.
- Network: DNS/HTTP logs for script destinations; portal host egress monitoring.
- Identity: VPN/OWA auth logs and MFA/OTP flows for correlation to portal host activity.
- EDR on portal hosts: process/file telemetry for web service processes modifying portal assets.

## 6. Response Guidance
- Immediately isolate or restrict access to affected portal hosts; fail over to known-good infrastructure if available.
- Restore portal from a trusted baseline; rotate credentials potentially captured (prioritize privileged and VPN/SSO accounts).
- Review authentication logs for accounts that logged in during the suspected capture window and hunt for follow-on abuse.

## 8. SOC Relevance
- High priority for perimeter systems: VPN, webmail, SSO proxies.
- Best SOC detections combine: **portal asset drift** + **new outbound endpoints** + **auth activity spikes**.
- Common blind spot: portal hosts excluded from EDR/FIM due to uptime concerns—mitigate with lightweight integrity checks and change control enforcement.

## 12. Mitigations
- Enforce strong change control and integrity monitoring for portal assets.
- Segment and restrict administrative access to portal hosts; require MFA and hardened admin workstations.
- Deploy WAF rules and patch management to reduce exploitation paths for internet-facing services.

## 13. Testing & Validation
- Baseline and continuously hash critical portal assets (login HTML/JS templates).
- In a lab, verify alerts for:
  - Unauthorized web root modifications
  - New external script includes during authentication
  - Unexpected egress from portal hosts at login time
