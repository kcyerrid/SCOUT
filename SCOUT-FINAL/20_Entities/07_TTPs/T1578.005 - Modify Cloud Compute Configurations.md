# Modify Cloud Compute Infrastructure: Modify Cloud Compute Configurations (T1578.005)

## 1. Summary
Modify Cloud Compute Configurations describes adversaries **altering configuration settings of cloud compute resources** to establish persistence, weaken security controls, or enable follow-on activity. These changes may be subtle and blend into normal infrastructure management activity.

Attackers use this technique to:
- Maintain persistent access in cloud environments
- Disable or weaken security controls
- Enable covert access paths
- Facilitate lateral movement or data exfiltration

---

## 2. Technical Overview
Cloud compute resources rely on configuration parameters that control access, networking, and behavior. Adversaries abuse this by modifying:

- Instance metadata and startup scripts
- Attached IAM roles or service accounts
- Network security groups and firewall rules
- Logging, monitoring, or agent configurations
- Autoscaling, load balancer, or health check settings

Key characteristics:
- Configuration drift outside change windows
- Security controls silently disabled or relaxed
- Metadata or startup logic modified
- Persistent access enabled without new resources

Indicators include:
- Configuration changes by unusual identities
- Security settings altered shortly after suspicious authentication
- Changes inconsistent with approved infrastructure templates
- Repeated reconfiguration to reintroduce access

---

## 3. Subtechnique Considerations
Key considerations for T1578.005:
- Often paired with **Account Manipulation (T1098)** and **Valid Accounts (T1078)**
- May complement **Impair Defenses (T1562)** in cloud contexts
- Changes may persist across reboots and redeployments
- Impact may be widespread if templates are modified

This technique focuses on **configuration persistence rather than resource creation**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Modifying instance metadata to enable remote access
- Relaxing firewall rules to allow attacker connectivity
- Disabling logging or monitoring agents
- Altering IAM roles to expand permissions

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **configuration monitoring and governance**:
- Monitor audit logs for configuration changes
- Alert on security-relevant setting modifications
- Correlate configuration changes with authentication anomalies
- Detect drift from approved infrastructure baselines

### Data Source Notes
- **Cloud audit logs**: Primary detection source
- **Configuration logs**: Identify drift and unauthorized changes
- **IAM logs**: Attribute actions to identities
- **Network logs**: Detect exposure changes

Common false positives:
- Legitimate infrastructure maintenance
- Approved configuration updates

Tuning guidance:
- Baseline approved configurations
- Require approvals for security-sensitive changes
- Increase severity when changes follow suspicious login events

---

## 6. Response Guidance
When suspected:
1. Identify and document configuration changes
2. Roll back unauthorized modifications
3. Rotate affected credentials and keys
4. Review logs for follow-on activity
5. Strengthen change control and monitoring

## 8. SOC Relevance
T1578.005 is critical because:
- Small configuration changes can have large security impact
- Persistence may exist entirely in control-plane settings
- Traditional endpoint detections may not apply

SOC teams must monitor **configuration state as a security signal**.

---

## 9. Threat Actor Usage
Commonly used by:
- Cloud-focused intrusion groups
- Actors abusing stolen credentials
- Adversaries seeking long-term cloud persistence

---

## 10. Campaign Usage
Observed in:
- Cloud account takeover campaigns
- Long-term cloud intrusions
- Hybrid on-prem/cloud attack chains

---

## 11. Malware Usage
Associated with:
- Little or no malware
- Script-based cloud abuse
- Cloud-native management tooling misuse

---

## 12. Mitigations
Recommended mitigations:
- Enforce least-privilege IAM policies
- Monitor and alert on configuration changes
- Implement infrastructure-as-code with drift detection
- Require approvals for security-sensitive changes

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign configuration changes in test environments
- Validate alerts on unauthorized modifications
- Test SOC workflows for cloud configuration abuse
- Ensure rollback and recovery processes are effective
