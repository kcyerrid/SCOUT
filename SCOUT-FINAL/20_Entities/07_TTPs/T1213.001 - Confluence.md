## 1. Summary
Adversaries may mine Atlassian Confluence for high-value internal documentation (architecture diagrams, operational procedures, project plans) and, critically, insecurely stored secrets (e.g., credentials embedded in pages). This activity is often high-signal when performed in bursts, via API automation, or by privileged/rarely-used identities.

## 2. Technical Overview
Confluence data mining typically manifests as:
- Interactive browsing of spaces/pages and attachments via the web UI.
- Programmatic collection via Confluence REST API (e.g., enumerating spaces, listing pages, exporting content).
- Bulk access patterns (rapid page views, export operations, attachment downloads) from a single identity, token, or client.
- Access by accounts that do not normally interact with documentation repositories (e.g., service accounts, admins outside engineering).

Key defender-relevant behaviors:
- Page/space enumeration and high-rate content access.
- Unusual user agent strings (non-browser clients) and API-heavy request mixes.
- Pivoting from Confluence findings into follow-on access (e.g., discovery of credentials or links to other internal systems).

## 3. Subtechnique Considerations
- Confluence is frequently “adjacent” to other collaboration tooling (e.g., Jira); adversaries may hop between platforms during collection.
- SaaS Confluence and self-managed deployments differ in logging granularity and where logs live (Confluence audit vs. IdP logs vs. reverse proxy/WAF).
- The highest-risk Confluence content is often “innocent” documentation that encodes access paths (VPN instructions, admin runbooks, escalation procedures) or leaks secrets.

## 5. Detection Guidance
Focus on “who + how + how much + from where”:
- **Burst analytics**: Alert on page/attachment access counts per user (or token) over short windows; separate thresholds for read vs. export/download.
- **API vs. UI mix**: Detect unusual REST API usage (especially from non-browser user agents) and scripted access patterns.
- **Identity context**: Flag access by privileged, rarely-used, or non-engineering accounts to sensitive spaces.
- **Impossible/rare sign-ins**: Correlate Confluence access bursts with anomalous logon sessions (new device/IP/geo, new token, conditional access failures).
- **Sensitive space focus**: Apply tighter thresholds for “Crown Jewel” spaces (network diagrams, security, IAM, IR, HR, finance, build/release).

### Data Source Notes
- Confluence access/audit telemetry should capture page/space accessed, action type (view/export/download), actor identity, IP, user agent, and time.
- Identity logs should capture sign-in anomalies and session/token creation.
- Network telemetry can help identify REST API access from non-browser agents and high-rate scraping patterns.
- MITRE detection strategy DET0358 provides an analytic pattern for excessive/programmatic Confluence access and highlights key mutable thresholds.

## 6. Response Guidance
1. **Scope access**: Identify affected spaces/pages/attachments and the time window; enumerate content accessed/exported.
2. **Contain identity**: Reset passwords, revoke active sessions/tokens, rotate API keys, and review connected apps.
3. **Assess exposure**: Treat accessed content as potentially compromised; prioritize documents containing credentials, diagrams, VPN/onboarding runbooks, and incident-response chatter.
4. **Hunt follow-on**: Look for subsequent use of discovered credentials (new logins, privilege changes, access to linked systems).
5. **Harden**: Reduce overbroad Confluence permissions, implement MFA/conditional access, and enforce content handling policies.

## 8. SOC Relevance
High SOC relevance when:
- A privileged or rarely-used account accesses Confluence at high volume.
- Access is API-heavy or comes from automation tooling.
- Access bursts occur shortly after suspicious sign-in activity or account takeover indicators.

Common triage pivots:
- User/device/IP novelty, conditional access outcomes, token issuance.
- Space sensitivity and whether content includes credentials or incident-response discussions.

## 12. Mitigations
- **Audit (M1047)**: Periodically review accounts/privileges for sensitive Confluence spaces; validate least-privilege and remove stale access.
- **User Account Management (M1018)**: Enforce least-privilege and strong authentication/authorization controls for Confluence access.
- **User Training (M1017)**: Define and enforce policies on what information may be stored in Confluence; reduce the presence of secrets in pages.

## 13. Testing & Validation
- Create a controlled test account with least-privilege access to a non-production Confluence space.
- Generate benign “burst” patterns (e.g., rapid page views or exports) via approved admin testing to ensure alerts trigger.
- Validate detections on:
  - API-heavy access (distinct user agents)
  - High-rate page views
  - Export/download events
  - Correlation with anomalous sign-ins (new IP/device)
- Confirm that thresholds are tuned per space sensitivity to avoid constant false positives for normal documentation usage.
