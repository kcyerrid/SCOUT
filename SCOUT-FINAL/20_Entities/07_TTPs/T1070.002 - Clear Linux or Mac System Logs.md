# Indicator Removal on Host: Clear Linux or macOS Logs (T1070.002)

## 1. Summary
Clear Linux or macOS Logs describes adversaries **deleting, truncating, or otherwise modifying system and application log files** on Linux and macOS systems to remove evidence of malicious activity. This subtechnique is a common anti-forensic measure during hands-on intrusions.

Attackers use this technique to:
- Obscure execution, persistence, and lateral movement
- Reduce SOC and SIEM visibility
- Delay detection and investigation
- Complicate forensic reconstruction

---

## 2. Technical Overview
Linux and macOS systems rely on plaintext and structured logs for security and operational visibility. Adversaries clear these logs by:

- Deleting or truncating log files (e.g., `/var/log/*`)
- Modifying log retention or rotation configurations
- Disabling or tampering with logging daemons
- Removing historical entries following malicious activity

Common logs targeted include:
- Authentication logs
- System logs
- Application logs
- Security and audit logs

Indicators include:
- Missing or truncated log files
- Sudden gaps in log timelines
- Log deletion following suspicious execution
- Configuration changes to logging services

---

## 3. Subtechnique Considerations
Key considerations for T1070.002:
- Often follows **Impair Defenses (T1562)** or **Hide Artifacts (T1564)**
- Frequently paired with **Command History Impairment (T1562.003)**
- Requires elevated privileges
- High-confidence indicator of malicious intent

Legitimate log deletion outside automated rotation is rare.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Deleting system or authentication logs
- Truncating logs to remove historical entries
- Clearing logs after privilege escalation
- Automating log cleanup as part of post-exploitation workflows

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **log integrity and continuity**:
- Alert on log file deletion or truncation
- Detect sudden log volume drops
- Monitor changes to logging daemon configuration
- Correlate log deletion with suspicious processes

### Data Source Notes
- **File system monitoring**: Detect log file changes
- **Audit logs**: Identify log access and deletion
- **EDR telemetry**: Capture anti-forensic behavior

Common false positives:
- Automated log rotation
- System maintenance activities

Tuning guidance:
- Baseline expected log rotation behavior
- Require approval for manual log deletion

---

## 6. Response Guidance
When suspected:
1. Preserve remaining logs immediately
2. Identify which logs were affected and when
3. Correlate activity before and after deletion
4. Investigate for additional defense evasion techniques
5. Treat evidence destruction as a security incident

## 8. SOC Relevance
T1070.002 is a **high-severity SOC detection**. Log clearing on Linux or macOS systems often indicates intentional intrusion activity and should trigger immediate investigation.

---

## 9. Threat Actor Usage
This subtechnique is widely used by:
- Ransomware operators
- APT groups
- Financially motivated intruders

Its use indicates **hands-on-keyboard activity**.

---

## 10. Campaign Usage
Observed in:
- Ransomware deployment phases
- Espionage operations
- Long-dwell intrusions

---

## 11. Malware Usage
Associated with:
- Post-exploitation frameworks
- Linux backdoors
- Automation scripts for anti-forensics

---

## 12. Mitigations
Recommended mitigations:
- Centralize and protect logs
- Enforce immutable or append-only logging
- Restrict administrative privileges
- Monitor for log deletion activity
- Validate log integrity regularly

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign log deletion in lab environments
- Validate alerts on log truncation
- Test SOC response to telemetry loss
- Ensure log ingestion gap detection is effective
