## 1. Summary
Local Account discovery (T1087.001) covers enumeration of **local users and groups** on a host (or hypervisor), often to identify administrator accounts, interactive users, and potential credential targets.

## 2. Technical Overview
Common behaviors include:
- Querying local user/group databases using built-in utilities and OS-native commands.
- Reading local account files or databases (e.g., local user registries / account files) to list principals.
- Enumerating hypervisor local accounts (e.g., on ESXi management surfaces).

What defenders should look for:
- **Account enumeration commands** executed from unusual processes/users.
- Enumeration followed by privilege checks (e.g., local administrators group membership).
- Repeated execution across many hosts (spray recon).

## 4. Procedure Examples
Observed examples include:
- Use of OS-native account listing commands to enumerate users/groups.
- Collection of account information by commodity malware families.
- Scripting-based collection of local account names.

## 5. Detection Guidance
High-confidence detections typically require **process telemetry + context**.

Detection ideas:
- **Suspicious parent process**: local account enumeration launched by Office apps, browsers, document readers, or other non-admin tooling.
- **Execution by anomalous account**: enumeration performed by newly created local users, service accounts, or accounts without admin function.
- **Remote orchestration pattern**: the same enumeration binaries/commands executed across many endpoints within a short time window.

Practical considerations:
- Many IT tools legitimately enumerate local users. Focus on **rare binaries**, **rare command-lines**, and **rare initiating principals**.

### Data Source Notes
Recommended telemetry:
- Endpoint process creation (command line, parent, signer).
- PowerShell logging where applicable.
- Authentication/session telemetry to correlate “enumerate → attempt logon / credential access”.
- ESXi/hypervisor audit logs where available for account listing actions.

## 6. Response Guidance
1. Identify the initiating process chain (parent → child), signer reputation, and user context.
2. Determine scope: single host vs. fleet-wide enumeration.
3. Search for follow-on actions: credential dumping, token theft, privilege escalation attempts, lateral movement.
4. Contain if suspicious: isolate host, revoke sessions, and rotate impacted local admin credentials (especially shared local admin patterns).

## 12. Mitigations
- Reduce standing local admin access; use just-in-time/local admin password rotation (e.g., LAPS-style controls).
- Separate admin workstations from user endpoints and restrict remote admin channels.
- Monitor/limit ESXi management access and audit account listing activity.

## 13. Testing & Validation
- Ensure EDR is capturing command line + parent chain for account listing utilities.
- Validate detections across:
  - Standard IT scripts (baseline allowlists)
  - Non-admin workstation contexts
  - Malware-like process chains (Office → shell → enumeration)
