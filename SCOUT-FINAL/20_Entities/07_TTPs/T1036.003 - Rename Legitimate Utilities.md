# Masquerading: Rename Legitimate Utilities (T1036.003)

## 1. Summary
Rename Legitimate Utilities describes adversaries **renaming trusted system or administrative utilities** to disguise their execution and evade detections that rely on process names or known utility lists. By changing filenames while preserving functionality, attackers blend malicious activity into normal operational noise.

Attackers use this technique to:
- Evade name- or rule-based detections
- Abuse trusted utilities without triggering alerts
- Obscure execution intent during triage
- Increase dwell time by reducing suspicion

---

## 2. Technical Overview
Many legitimate utilities can be renamed without affecting execution. Adversaries exploit this by:

- Copying trusted binaries and renaming them
- Renaming utilities to appear benign or unrelated
- Deploying renamed tools in user-writable directories
- Executing renamed binaries to bypass allowlists or alerts

Key characteristics:
- Binary hash matches known utility
- Filename does not match expected utility name
- Execution behavior consistent with original utility
- Path and name mismatch with known baselines

Indicators include:
- Execution of renamed utilities from unusual paths
- Trusted binaries with unexpected filenames
- Parent–child relationships inconsistent with filename
- Utilities executed where not typically required

---

## 3. Subtechnique Considerations
Key considerations for T1036.003:
- Overlaps with **Signed Binary Proxy Execution (T1218)**
- Common in LOLBin-based intrusions
- Effective against detections relying on process names
- Often paired with **Hide Artifacts (T1564)**

Renaming utilities does not change their trust level but **changes how they are perceived**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Copying a system utility and renaming it before execution
- Deploying renamed utilities in staging directories
- Executing renamed binaries to avoid alerts
- Combining renamed utilities with script-based execution

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **behavior and binary identity**:
- Detect trusted binaries executing under unexpected names
- Compare file hashes against known utility hashes
- Monitor execution from unusual directories
- Correlate renamed utility execution with suspicious activity

### Data Source Notes
- **File system monitoring**: Detect binary copies and renames
- **Image load telemetry**: Identify trusted binaries with unexpected names
- **EDR telemetry**: Provide binary identity and lineage

Common false positives:
- Administrative scripts copying utilities
- Software installers bundling utilities

Tuning guidance:
- Baseline expected utility execution paths and names
- Increase severity when renamed utilities perform suspicious actions

---

## 6. Response Guidance
When suspected:
1. Identify renamed utility and original binary source
2. Validate file hash against known-good utilities
3. Analyze execution context and behavior
4. Investigate related activity using the same utility
5. Expand hunt for similarly renamed binaries

## 8. SOC Relevance
T1036.003 is especially relevant when:
- Known utilities appear under unfamiliar names
- Alerts based on process names are bypassed
- LOLBins are abused stealthily

It highlights the importance of **binary identity over naming**.

## 11. Malware Usage

---

## 12. Mitigations
Recommended mitigations:
- Use hash- and signature-based detections
- Monitor execution of trusted binaries from non-standard paths
- Apply application allowlisting
- Restrict utility execution to approved contexts

---

## 13. Testing & Validation
Validation approaches:
- Rename benign utilities in lab environments
- Validate alerts on renamed binary execution
- Test SOC workflows for masqueraded utility usage
- Ensure detections are resilient to filename changes
