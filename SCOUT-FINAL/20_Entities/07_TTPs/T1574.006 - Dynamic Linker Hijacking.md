# T1574.006 – Dynamic Linker Hijacking

## 1. Technique Overview
**Dynamic Linker Hijacking (T1574.006)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries abuse how Unix-like operating systems resolve and load shared libraries at runtime, causing **attacker-controlled shared objects** to be loaded instead of legitimate dependencies.

This technique targets the **dynamic linker/loader** (e.g., `ld-linux.so`, `ld.so`) and is primarily observed on **Linux and Unix systems**.

## 2. Adversary Objectives
Adversaries use dynamic linker hijacking to:
- Execute malicious code within trusted processes
- Achieve stealthy persistence without explicit autorun artifacts
- Escalate privileges by targeting elevated binaries
- Evade detection by leveraging legitimate runtime linking behavior

## 3. Common Abuse Patterns
- Manipulating environment variables such as:
  - `LD_PRELOAD`
  - `LD_LIBRARY_PATH`
- Abusing weak or writable `RPATH` / `RUNPATH` entries in binaries
- Modifying linker configuration files:
  - `/etc/ld.so.conf`
  - `/etc/ld.so.conf.d/*`
- Placing malicious `.so` files in directories searched by the linker
- Targeting SUID or system-managed binaries where feasible

## 4. Detection Considerations
Detection relies on **process execution and shared library load telemetry**, including:
- Monitoring use of linker-related environment variables
- Detecting execution of processes that preload unexpected `.so` files
- Correlating binary execution with libraries loaded from user-writable paths
- Auditing binaries for unsafe RPATH/RUNPATH configurations
- Inspecting linker configuration changes

## 5. Defensive Mitigations
- Restrict use of `LD_PRELOAD` and related variables in privileged contexts
- Enforce least-privilege file permissions on library directories
- Audit binaries for insecure RPATH/RUNPATH usage
- Monitor shared library loading with endpoint detection tools
- Remove unauthorized linker configuration changes during incident response

## 6. Operational Impact
If successful, T1574.006 can:
- Provide stealthy execution within legitimate processes
- Enable persistence without modifying startup mechanisms
- Facilitate privilege escalation through trusted binaries
- Complicate forensic analysis due to runtime-only execution artifacts

## 7. Analyst Notes
Dynamic Linker Hijacking is a **core Linux persistence and escalation technique** and is frequently overlooked compared to Windows DLL abuse. Analysts should always investigate **why a shared library was loaded from a particular path**, especially when investigating anomalous behavior in system or SUID binaries.
