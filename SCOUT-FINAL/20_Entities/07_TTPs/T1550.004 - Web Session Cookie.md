## 1. Summary
Web Session Cookie (T1550.004) is adversary authentication to web applications/services using stolen session cookies, bypassing interactive authentication (including some MFA designs) because the session is already authenticated.

## 2. Technical Overview
- **Core behavior:** Reuse/import of a victim’s session cookie into an attacker-controlled browser or client to impersonate the user.
- **Typical sources of cookies (collection methods):** Browser profile theft, session hijacking via adversary-in-the-middle frameworks, malware targeting browser storage.
- **Defender challenge:** Cookie reuse can look like normal web traffic unless you enforce and monitor strong session binding (device posture, user-agent, IP reputation/geo, token binding).

## 3. Subtechnique Considerations
- Sub-technique of [[20_Entities/07_TTPs/TA0005 - Defense Evasion/T1550 - Use Alternate Authentication Material|T1550]].
- Compared to Application Access Token (T1550.001), this is **session-layer** reuse: the “credential” is the existing web session cookie rather than an OAuth access token.

## 4. Procedure Examples
MITRE procedure examples include:
- **SolarWinds Compromise:** APT29 used stolen cookies to access cloud resources and forged a `duo-sid` cookie to bypass MFA on an email account.
- **Star Blizzard:** Bypassed MFA on victim email accounts using stolen session cookies. :contentReference[oaicite:68]{index=68}

## 5. Detection Guidance
Detect **session misuse** by correlating session token usage with expected authentication events and stable client fingerprints.

**Core analytic goals (from MITRE detection strategy)**
- Identify session token use without preceding login/MFA, from anomalous locations/devices, or with client fingerprint drift.
- Detect session reuse across unmanaged clients (e.g., browser → curl) and across cloud/native app contexts. :contentReference[oaicite:69]{index=69}

**High-signal patterns**
- **No prerequisite auth**
  - Session token usage without nearby legitimate login/MFA events.
- **Fingerprint anomalies**
  - Same session ID/cookie value appearing with different user-agent, device ID, browser fingerprints.
- **Geo/network anomalies**
  - Impossible travel, new ASN/country, TOR/VPN egress, or sudden IP reputation shifts.
- **Session replay timing**
  - Reuse shortly after cookie theft indicators (new browser profile access, endpoint alerts).

## 6. Response Guidance
1. **Invalidate sessions**
   - Force logout and revoke sessions across the affected SaaS/IdP; rotate session keys where platform supports.
2. **Contain**
   - If endpoint theft is suspected, isolate affected endpoints and inspect browser profile access artifacts.
3. **Scope**
   - Enumerate all accesses tied to the session identifier/cookie timeframe; identify data accessed and actions performed.
4. **Remediate**
   - Fix conditional access/session policies: reduce session lifetime, require re-auth on risk signals, enforce device compliance.
5. **User protection**
   - Re-issue MFA devices if the workflow allows cookie-based MFA bypass; strengthen phishing-resistant MFA where possible.

## 8. SOC Relevance
- **High** priority for SaaS and email security; cookie replay is a common path to bypass MFA protections tied only to initial login.
- **SOC must-have telemetry:** IdP/SaaS unified audit, session IDs, device posture, user-agent/browser fingerprinting, geo/IP intelligence.

## 12. Mitigations
- **Software Configuration:** Configure browsers/tasks to regularly delete persistent cookies (reduces replay window). :contentReference[oaicite:76]{index=76}

## 13. Testing & Validation
- Validate detections for:
  - Session reuse from different geos/devices/user-agents.
  - Token usage without prior MFA/login in the defined time window.
- Playbook drills:
  - Session revocation and forced re-auth across SaaS/IdP.
