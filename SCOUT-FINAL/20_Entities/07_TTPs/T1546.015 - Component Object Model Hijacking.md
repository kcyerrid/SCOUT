# T1546.015 – Component Object Model Hijacking

## 1. Technique Overview
**Component Object Model Hijacking (T1546.015)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse **COM object registration mechanisms** so that when a legitimate COM object is instantiated, attacker-controlled code is loaded instead of (or in addition to) the intended component.

Because COM is deeply integrated into Windows and used extensively by the operating system and applications, hijacking COM registrations provides stealthy, event-driven execution.

## 2. Adversary Objectives
Adversaries use COM hijacking to:
- Achieve persistence tied to legitimate application or system behavior
- Execute malicious code within trusted processes
- Evade detection by leveraging normal COM activation flows
- Maintain access without obvious startup artifacts

## 3. Common Abuse Patterns
- Modifying COM registration keys under:
  - `HKCU\Software\Classes\CLSID`
  - `HKLM\Software\Classes\CLSID`
- Redirecting `InprocServer32` or `LocalServer32` values to malicious DLLs or executables
- Targeting COM objects instantiated during logon or application startup
- Using per-user COM registrations to avoid administrative privileges
- Masquerading malicious components as legitimate system libraries

## 4. Detection Considerations
Detection relies on **registry, module load, and behavior monitoring**, including:
- Monitoring changes to COM CLSID registration keys
- Alerting on unexpected changes to COM server paths
- Correlating COM object instantiation with suspicious DLL loads
- Auditing systems for non-default COM registrations
- Reviewing per-user COM overrides for anomalies

## 5. Defensive Mitigations
- Monitor and alert on COM registration modifications
- Enforce code signing for COM servers
- Restrict permissions required to modify COM registry keys
- Regularly audit COM registrations against known-good baselines
- Remove unauthorized COM hijacks during incident response

## 6. Operational Impact
If successful, T1546.015 can:
- Provide stealthy, application-triggered persistence
- Enable execution within trusted process contexts
- Evade detection focused on startup or scheduled execution
- Complicate forensic analysis due to indirect execution triggers

## 7. Analyst Notes
COM hijacking is a favored persistence technique among sophisticated Windows adversaries due to its flexibility and low visibility. Analysts should include **COM registration auditing** as a standard step in Windows persistence investigations, especially when suspicious behavior coincides with normal application launches.
