# Impair Defenses: Safe Mode Boot (T1562.009)

## 1. Summary
Safe Mode Boot describes adversaries **forcing a system to boot into Windows Safe Mode** to bypass or disable security controls that do not load in that configuration. Many endpoint protection products, monitoring agents, and security services are inactive or limited in Safe Mode, giving attackers a window to tamper with defenses.

Attackers use this technique to:
- Disable or uninstall security software
- Remove persistence blockers
- Evade EDR and antivirus protections
- Perform remediation-resistant actions

---

## 2. Technical Overview
Windows Safe Mode is a diagnostic boot mode that loads a minimal set of drivers and services. Adversaries abuse this behavior by:

- Modifying Boot Configuration Data (BCD) to force Safe Mode
- Configuring systems to repeatedly boot into Safe Mode
- Using Safe Mode to disable or remove security tooling
- Executing actions that would normally be blocked in standard boot mode

Typical indicators and artifacts include:
- Unexpected BCD configuration changes
- Reboots followed by Safe Mode startup
- Security services not loading post-boot
- Registry modifications related to Safe Mode startup

---

## 3. Subtechnique Considerations
Key considerations for T1562.009:
- Strongly associated with **pre-impact and remediation-resistant attacks**
- Often paired with **Disable or Modify Security Software (T1562.005)**
- Requires administrative or SYSTEM-level privileges
- High-confidence indicator of malicious intent

Safe Mode boot manipulation is rarely legitimate outside IT troubleshooting.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Forcing Safe Mode boot to disable EDR
- Removing security software while protections are inactive
- Preventing security services from starting on normal boot
- Leveraging Safe Mode to establish persistence

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **boot integrity and Safe Mode transitions**:
- Alert on BCD modifications forcing Safe Mode
- Detect unexpected reboots into Safe Mode
- Monitor security service startup failures post-boot
- Correlate Safe Mode events with security tampering

### Data Source Notes
- **Boot configuration logs**: Primary source for BCD changes
- **Windows Event Logs**: Detect boot mode changes
- **EDR telemetry**: Identify security agent disablement

Common false positives:
- Legitimate troubleshooting by IT
- User-initiated Safe Mode for diagnostics

Tuning guidance:
- Require approval for Safe Mode boot configuration changes
- Alert on repeated or forced Safe Mode boots

---

## 6. Response Guidance
When suspected:
1. Inspect BCD configuration for forced Safe Mode
2. Restore normal boot settings
3. Reinstall or re-enable disabled security software
4. Investigate actions taken during Safe Mode operation
5. Consider full system rebuild if tampering is extensive

## 8. SOC Relevance
T1562.009 is **extremely high risk**. Safe Mode boot manipulation directly undermines endpoint defenses and often precedes ransomware deployment or irreversible impact.

Any unexplained Safe Mode boot should trigger immediate investigation.

---

## 9. Threat Actor Usage
This technique has been observed in:
- Ransomware operations
- Hands-on-keyboard intrusions
- Attacks targeting hardened endpoints

Its use indicates **deliberate attempts to neutralize defenses**.

---

## 10. Campaign Usage
Observed in:
- Ransomware pre-encryption phases
- Intrusions involving EDR bypass
- Persistence hardening efforts

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Post-exploitation frameworks
- Malware designed to evade endpoint protections

---

## 12. Mitigations
Recommended mitigations:
- Monitor and restrict BCD modifications
- Enable EDR protections that persist in Safe Mode
- Require administrative approval for boot configuration changes
- Audit Safe Mode usage regularly
- Enforce tamper protection for security software

---

## 13. Testing & Validation
Validation approaches:
- Simulate Safe Mode boot configuration changes in lab environments
- Validate alerts on BCD modification
- Test SOC response to Safe Mode boot events
- Ensure detection persists across reboots
