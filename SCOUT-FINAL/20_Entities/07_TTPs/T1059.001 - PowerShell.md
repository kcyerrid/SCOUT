# PowerShell (T1059.001)

## 1. Summary
PowerShell describes adversary abuse of the Windows PowerShell framework to execute commands and scripts for malicious purposes. PowerShell provides deep access to the Windows operating system, .NET framework, and administrative APIs, making it a highly flexible and powerful execution mechanism.

Because PowerShell is widely used by administrators and built into modern Windows systems, malicious activity can blend into legitimate operational workflows if not properly instrumented and monitored.

---

## 2. Technical Overview
PowerShell supports interactive commands, script execution, and in-memory operations through the .NET runtime.

Adversaries commonly abuse PowerShell by:
- Executing inline or encoded commands
- Downloading and executing payloads from remote locations
- Performing in-memory execution without writing files to disk
- Leveraging PowerShell remoting or WMI integration

Key artifacts include PowerShell process creation (`powershell.exe`, `pwsh.exe`), command-line arguments, Script Block Logging events, and network activity initiated by PowerShell processes.

---

## 3. Subtechnique Considerations
T1059.001 is a subtechnique of **T1059 – Command and Scripting Interpreter** and focuses specifically on PowerShell.

Important considerations include:
- PowerShell versions (Windows PowerShell vs. PowerShell Core)
- Use of encoded (`-EncodedCommand`) or obfuscated scripts
- Differences in logging coverage based on configuration
- Abuse of legitimate administrative modules

Detection efficacy is highly dependent on logging configuration and policy enforcement.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing encoded PowerShell commands to evade inspection
- Using PowerShell to download second-stage payloads
- Loading .NET assemblies directly into memory
- Automating post-exploitation tasks via PowerShell scripts

Analysts may observe PowerShell spawning unusual child processes or initiating outbound network connections.

---

## 5. Detection Guidance
Detection should focus on behavioral and content-based indicators:
- PowerShell execution with encoded or obfuscated command lines
- Use of suspicious cmdlets or .NET reflection
- PowerShell processes initiating network connections
- Execution initiated by unusual parent processes

Script Block Logging significantly increases detection fidelity when enabled.

### Data Source Notes
- **PowerShell Logs:** High value but require explicit configuration
- **Script Block Logging:** Provides deep visibility into executed code
- **Process Execution:** Useful for identifying execution chains

---

## 6. Response Guidance
When malicious PowerShell activity is suspected:
- Capture full command-line arguments and script content
- Isolate affected systems if execution is confirmed
- Identify downloaded payloads or in-memory artifacts
- Review credential exposure and lateral movement indicators

Preserve PowerShell logs and related endpoint telemetry for analysis.

## 8. SOC Relevance
PowerShell abuse is one of the most common and high-risk execution mechanisms observed in Windows environments. SOCs must prioritize PowerShell telemetry due to its prevalence in ransomware, post-exploitation frameworks, and advanced intrusions.

- Commodity malware families

Confidence in ubiquitous usage is extremely high.

## 12. Mitigations
Effective mitigations include:
- Enabling PowerShell Script Block and Module Logging
- Constraining PowerShell usage via Constrained Language Mode
- Blocking encoded or obfuscated command execution
- Applying least-privilege principles
- Monitoring PowerShell network activity

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for PowerShell execution
- Purple team simulations using encoded and in-memory scripts
- Review of alerts tied to PowerShell logging events

Successful validation results in detection of unauthorized PowerShell activity.
