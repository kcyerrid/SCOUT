## 1. Summary
Cloud Account discovery (T1087.004) involves enumerating accounts in cloud identity providers and SaaS/IaaS environments (users, service accounts, roles, and privileged principals). It is often a critical precursor to privilege escalation, persistence, and data access in cloud-centric intrusions.

## 2. Technical Overview
Typical behaviors:
- Listing users, roles, and group members via cloud admin portals, APIs, or CLIs.
- Enumerating privileged role members and administrative groups.
- Enumerating IAM users/roles/policies in IaaS providers.

Defender-relevant intent:
- Identify global admins / privileged roles.
- Identify service principals and automation identities with high permissions.
- Map group membership and role assignments for privilege escalation paths.

## 5. Detection Guidance
Cloud account discovery is often visible in **audit logs** and can be detected effectively using volume + context.

High-signal patterns:
- **Bulk listing** of users/groups/role members.
- Enumeration by **newly created**, **recently consented**, or **rarely used** apps/service principals.
- Directory reads from **unusual geolocation**, **new device**, **TOR/VPN-like egress**, or outside normal admin hours.
- Repeated queries for privileged roles/groups (global admin, privileged role administrator, etc.).

Detection ideas:
- Alert on spikes in “list users / list role members / list groups” operations per principal.
- Identify enumeration immediately following suspicious sign-ins, MFA fatigue, token theft indicators, or OAuth consent events.
- Detect principals enumerating identity while also modifying roles, adding credentials to apps, or creating new tokens.

### Data Source Notes
Recommended telemetry:
- Cloud identity audit logs (directory read/list operations; group/role membership reads).
- Sign-in logs with device, IP, and client app context.
- Cloud provider audit logs (e.g., IaaS IAM list users/roles/policies).
- Admin activity logs for role changes, app consent, and privileged access workflows.

## 6. Response Guidance
1. Identify the actor (user/service principal), source IP/device, and the precise enumeration operations performed.
2. Determine privilege: does the actor have rights to list users/roles/groups legitimately?
3. Hunt correlated actions:
   - Role assignment changes
   - App consent / delegated permission grants
   - Token/session anomalies
   - Subsequent resource access (mailboxes, storage, compute)
4. Contain:
   - Revoke refresh tokens/sessions
   - Disable or rotate credentials for affected identities
   - Restrict directory read permissions where feasible
   - Review conditional access and require MFA for directory admin functions

## 12. Mitigations
- **M1047 – Audit**: Routinely review permissions to ensure only expected users/apps can list identities or enumerate cloud accounts.
- **M1018 – User Account Management**: Apply least privilege for directory read/list operations; tightly control privileged role membership and service principal permissions.

## 13. Testing & Validation
- Verify audit logging is enabled and retained for:
  - directory list/read operations
  - group/role membership reads
  - IAM “list” actions in IaaS
- Validate detections on:
  - bulk user/group enumeration by a non-admin user
  - enumeration from a new device/IP/app context
  - enumeration followed by privileged role checks
