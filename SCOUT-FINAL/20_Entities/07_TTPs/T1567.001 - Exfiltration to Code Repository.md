# Exfiltration to Cloud Storage (T1567.001)

## 1. Summary
Exfiltration to Cloud Storage describes adversary transfer of stolen data to attacker-controlled cloud storage services such as file-sharing platforms or object storage providers. By leveraging trusted and widely used services over encrypted channels, adversaries can conceal data theft within normal outbound traffic.

This subtechnique is commonly used during the final stages of intrusions, particularly in ransomware and espionage campaigns.

---

## 2. Technical Overview
Adversaries authenticate to cloud storage services using attacker-controlled accounts, stolen credentials, or API keys, then upload data using web interfaces, synchronization clients, or APIs.

Common mechanisms include:
- Uploading data via HTTPS to cloud storage providers
- Using sync clients to incrementally exfiltrate data
- Leveraging APIs or SDKs to automate uploads
- Compressing or encrypting data prior to transfer

Artifacts include outbound HTTPS connections, authentication events to cloud services, API calls, and anomalous upload volumes.

---

## 3. Subtechnique Considerations
T1567.001 specifically focuses on **cloud storage services**, distinguishing it from:
- Code repository exfiltration
- Exfiltration over command-and-control channels

Detection difficulty varies based on whether the service is sanctioned or unsanctioned within the environment.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Uploading sensitive documents to attacker-controlled cloud drives
- Using legitimate cloud storage APIs for bulk data transfer
- Leveraging sync tools to evade size-based detection thresholds
- Encrypting archives prior to upload to avoid content inspection

Analysts may observe sustained outbound uploads to cloud services outside normal usage patterns.

---

## 5. Detection Guidance
Detection should focus on behavioral anomalies:
- Large or unusual upload volumes to cloud storage
- Authentication to cloud services not previously used by the user or host
- Use of unsanctioned storage providers
- Upload activity outside normal working hours

Correlation between proxy, network, and cloud audit logs is essential.

### Data Source Notes
- **Cloud Storage Audit Logs:** Critical for identifying unauthorized access and uploads
- **Web Proxy Logs:** Useful for detecting volume and destination anomalies
- **Authentication Logs:** Help identify compromised credentials used for access

---

## 6. Response Guidance
When cloud storage exfiltration is suspected:
- Immediately restrict access to the abused storage service
- Identify scope and sensitivity of exfiltrated data
- Revoke credentials or API keys used for access
- Engage legal, compliance, and leadership stakeholders as required

Preserve network and cloud audit logs for forensic analysis.

## 8. SOC Relevance
Cloud storage exfiltration is difficult to detect due to encrypted traffic and the prevalence of legitimate cloud service usage. SOC teams must rely on behavioral baselining, service allowlisting, and DLP controls.

---

## 9. Threat Actor Usage
This subtechnique is widely used by:
- Ransomware operators conducting double extortion
- Espionage-focused advanced persistent threat groups
- Insider threat actors abusing legitimate access

Confidence in widespread usage is high.

---

## 10. Campaign Usage
Exfiltration to cloud storage appears in:
- Double-extortion ransomware campaigns
- Long-dwell espionage operations
- Insider data theft incidents

## 12. Mitigations
Effective mitigations include:
- Egress filtering and proxy enforcement
- Restricting use of unsanctioned cloud storage
- Data loss prevention (DLP) controls
- Monitoring upload volume and frequency
- Enforcing strong identity controls for cloud services

---

## 13. Testing & Validation
Validation approaches include:
- Simulated data exfiltration to cloud storage
- Purple team exercises focusing on cloud service abuse
- Review of proxy and cloud audit log alerting

Successful validation identifies anomalous upload behavior.
