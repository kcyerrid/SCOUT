# Python (T1059.006)

## 1. Summary
Python describes adversary abuse of the Python interpreter to execute malicious code across multiple platforms. Python’s extensive standard library, cross-platform availability, and support for in-memory execution make it a highly flexible execution mechanism for both commodity malware and advanced intrusion campaigns.

This subtechnique is frequently observed in Linux server compromises, cloud workloads, and post-exploitation frameworks.

---

## 2. Technical Overview
Python code can be executed via:
- Interactive interpreter sessions
- Script files (`.py`)
- Inline execution using command-line arguments
- Embedded Python within applications or installers

Adversaries abuse Python to automate tasks, download payloads, execute system commands, and interact with network services. Artifacts include Python interpreter process execution, script file creation, imported modules, and network connections initiated by Python processes.

---

## 3. Subtechnique Considerations
T1059.006 applies across multiple operating systems and environments.

Key considerations include:
- Differences between system-installed and bundled Python runtimes
- Use of compiled Python bytecode (`.pyc`)
- In-memory execution without writing scripts to disk
- Abuse of trusted Python packages or virtual environments

Detection must account for legitimate Python usage by developers and automation tooling.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing Python one-liners to download and execute payloads
- Using Python scripts for reconnaissance and lateral movement
- Embedding Python interpreters within malware packages
- Leveraging Python for cloud and API interactions

Analysts may observe Python processes spawning system utilities or making unexpected outbound connections.

---

## 5. Detection Guidance
Detection should focus on:
- Python execution by unexpected parent processes
- Script execution from temporary or user-writable directories
- Python processes initiating suspicious network activity
- Use of obfuscated or encoded Python code

Correlation between process execution, file creation, and network telemetry improves detection fidelity.

### Data Source Notes
- **Process Execution:** Primary indicator of Python usage
- **File Creation:** Useful for identifying dropped scripts
- **Network Traffic:** Critical for detecting payload retrieval or C2

---

## 6. Response Guidance
When malicious Python activity is suspected:
- Capture full command-line arguments and script content
- Identify downloaded payloads or secondary stages
- Isolate affected systems or workloads if compromise is confirmed
- Review credentials and access keys used by Python processes

Preserve scripts, bytecode, and execution logs for forensic analysis.

## 12. Mitigations
Effective mitigations include:
- Restricting Python execution where feasible
- Monitoring Python interpreter usage
- Applying least-privilege principles
- Reviewing Python package installation activity
- Hardening cloud and automation credentials

---

Validation approaches include:
- Atomic Red Team tests for Python execution
- Purple team simulations using Python-based payloads
- Review of alerts tied to Python process activity

Successful validation results in detection of unauthorized Python execution.
