# T1021.005 - Remote Services: VNC

## 1. Summary
Adversaries may use Virtual Network Computing (VNC) to remotely control a target’s desktop session for lateral movement. VNC provides interactive control (screen, mouse, keyboard) and can be abused to operate as the logged-on user after authenticating with valid credentials or VNC-specific credentials.

## 2. Technical Overview
VNC abuse commonly involves:
- Establishing remote interactive control over an endpoint/server to perform actions “hands-on-keyboard.”
- Using interactive access to navigate file systems, open documents, stage tools, and execute commands while blending with normal user behavior.
- Leveraging existing remote support tooling (e.g., legitimate VNC deployments) to reduce friction and evade simplistic controls.

Common defensive choke points:
- VNC server installation/enablement where it is not expected.
- Unexpected VNC listeners (commonly TCP/5900; additional ports vary by implementation).
- Sudden interactive user activity patterns (input simulation) following VNC process/service startup.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- VNC may appear as legitimate remote support in some environments; detections must distinguish sanctioned tooling (asset groups, helpdesk subnets, approved service binaries) from unauthorized deployments and abnormal usage.
- macOS environments may surface VNC activity via Apple remote screen sharing components and unified logging; treat unexpected remote screen sharing enablement as high signal.

## 4. Procedure Examples
MITRE ATT&CK documents VNC usage including:

- [[30_CIPHER/03_Threat_Actors/G0047 - Gamaredon Group|Gamaredon Group]] using VNC tools (e.g., UltraVNC) to interact with hosts.

- [[30_CIPHER/05_Malware/S0670 - WarzoneRAT|WarzoneRAT]] providing remote desktop access via a VNC console.

## 5. Detection Guidance
Prioritize detection of **unauthorized VNC enablement** and **unexpected VNC session patterns** over simple “port 5900 seen” logic.

High-value detection patterns:
- New/rare VNC server processes/services on endpoints that are not in an approved support set.
- VNC process/service start followed by:
  - User session creation and interactive desktop activity (mouse/keyboard simulation) in a short time window.
  - New listening ports consistent with VNC server behavior.
- VNC network connections to sensitive assets (admin workstations, servers) from non-approved support networks.

MITRE Detection Strategy (technique analytics):
- **DET0178 – Behavioral Detection of Unauthorized VNC Remote Control Sessions** (examples include detecting unexpected VNC process/service start and interactive activity; and VNC-related processes coupled with port listening behavior).

### 5.1. Data Source Notes
Minimum telemetry to support strong detections:
- Endpoint process/service creation telemetry (including command line, signer/publisher where available).
- Network connection telemetry (source/destination, ports, byte counts, session duration).
- User session and interactive activity telemetry (logon/session creation; correlated timing to VNC start).
- Asset context (approved remote-support hosts, helpdesk networks, approved binaries/hashes).

## 6. Response Guidance
Recommended response actions when unauthorized VNC activity is suspected:
- Contain: isolate the host or block the VNC path at host/network controls (especially if VNC was newly enabled/installed).
- Validate: determine whether VNC is sanctioned on the asset; compare binaries/services to approved baseline.
- Scope: hunt for the same VNC binary/service across fleet; identify other hosts accessed by the same operator/source IP.
- Eradicate: remove unauthorized VNC software, revert configuration changes, and rotate credentials associated with the session/user context.

## 8. SOC Relevance
Primary triage pivots:
- Is VNC expected on this host (role, owner, business unit, remote support model)?
- Is the VNC server binary/service approved (publisher/signature, install path, version)?
- Source of VNC connections (helpdesk subnet vs. unusual workstation/VPN egress).
- Timing correlation: VNC enablement/start → interactive activity → follow-on execution or lateral movement.

## 12. Mitigations
ATT&CK-listed mitigations for T1021.005 include:
- **M1047 – Audit**: inventory endpoints for unauthorized VNC server software.
- **M1042 – Disable or Remove Feature or Program**: uninstall VNC server software where not required.
- **M1037 – Filter Network Traffic**: restrict/block VNC traffic (VNC defaults include TCP/5900; other ports may apply).
- **M1033 – Limit Software Installation**: restrict installation privileges to reduce unauthorized VNC deployment.

## 13. Testing & Validation
- Verify that starting an approved VNC server generates the expected process/service and listening-port telemetry.
- Validate detections against:
  - Approved helpdesk remote-support paths (expected/no alert).
  - VNC binaries running from non-standard paths or unsigned builds (alert).
- Confirm network controls (firewall rules/segmentation) effectively prevent VNC connections from non-approved subnets.
