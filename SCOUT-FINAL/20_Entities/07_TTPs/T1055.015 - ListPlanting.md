# Process Injection: ListPlanting (T1055.015)

## 1. Summary
ListPlanting describes adversaries **manipulating Windows internal data structures—specifically loader-linked lists—to inject or conceal malicious modules within a process**. Instead of relying on traditional injection APIs, attackers insert malicious entries into process-maintained lists, causing code execution or stealthy module presence.

T1055.015 is commonly used to:
- Evade module-based detection mechanisms
- Hide malicious payloads from userland enumeration
- Execute code under trusted process contexts
- Support stealthy persistence and defense evasion

---

## 2. Technical Overview
Windows processes maintain multiple internal linked lists (e.g., in the Process Environment Block, or PEB) to track loaded modules. Adversaries abuse this by:
- Injecting malicious DLLs or shellcode
- Manually inserting entries into loader data tables
- Manipulating linked-list pointers to hide or register payloads
- Avoiding standard module-loading APIs

Key structures and components involved:
- Process Environment Block (PEB)
- `PEB_LDR_DATA`
- InLoadOrderModuleList / InMemoryOrderModuleList
- Low-level memory writes and pointer manipulation

Artifacts often include:
- Memory-resident modules not reflected in module enumeration
- Discrepancies between API-reported and memory-observed modules
- Execution from memory regions without corresponding disk artifacts
- Legitimate processes exhibiting anomalous behavior

---

## 3. Subtechnique Considerations
Key considerations for T1055.015:
- Highly stealthy and difficult to detect
- Bypasses many EDR and AV enumeration techniques
- Requires detailed knowledge of Windows internals
- Detection depends on deep memory inspection

ListPlanting is most often seen in advanced malware or red-team tooling.

---

## 4. Procedure Examples
Observed or theorized adversary procedures include:
- Injecting a malicious DLL and manually registering it in loader lists
- Hiding injected modules by unlinking legitimate entries
- Executing payloads while remaining invisible to standard tools
- Combining list manipulation with reflective loading

These actions typically occur after initial execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Comparing module lists from multiple enumeration methods
- Detecting execution from memory regions lacking module metadata
- Monitoring low-level memory writes to PEB structures
- Identifying inconsistencies between disk-backed and memory-loaded modules

### Data Source Notes
- **Memory telemetry**: Critical for detecting list manipulation
- **API telemetry**: Useful for identifying bypassed load mechanisms
- **EDR deep inspection**: Required for reliable detection

---

## 6. Response Guidance
When suspected:
1. Identify affected processes and capture memory
2. Isolate compromised systems
3. Perform deep memory analysis for hidden modules
4. Terminate malicious processes if operationally safe
5. Investigate for additional injection or persistence techniques
