# Indicator Removal on Host: File Deletion (T1070.004)

## 1. Summary
File Deletion describes adversaries **removing files from a system** to eliminate evidence of malicious activity, reduce attribution artifacts, or impede incident response. This can include deleting payloads, tools, logs, staged data, or temporary files used during exploitation.

Attackers use this technique to:
- Remove malware binaries and tooling after use
- Destroy forensic artifacts (logs, scripts, configs)
- Remove staged data or exfiltration archives
- Reduce the footprint of an intrusion

---

## 2. Technical Overview
File deletion occurs across operating systems and environments, including endpoints, servers, containers, and cloud workloads. Adversaries may:

- Delete dropped tools after execution
- Remove logs, scripts, and staging directories
- Delete evidence tied to persistence or lateral movement
- Remove or purge files from temporary directories
- Perform targeted deletion of security artifacts

Key technical dimensions:
- **Userland deletion** via standard APIs and utilities
- **Privilege context** (standard user vs admin/root) determines what can be removed
- **Recovery and remnants** may still exist via:
  - filesystem journaling
  - shadow copies/snapshots
  - EDR/backup systems
  - undelete/forensic carving

Typical artifacts and indicators:
- Deletion events correlated with suspicious process execution
- Removal of recently created binaries or scripts
- Deletion of logs immediately after sensitive actions
- Rapid cleanup activity following intrusion milestones

---

## 3. Subtechnique Considerations
Key considerations for T1070.004:
- Often follows **tool execution** and precedes attacker exit
- Frequently paired with **Hide Artifacts (T1564)** and **Obfuscation (T1027)**
- May occur at high volume during ransomware operations (cleanup phases)
- Can be leveraged to disrupt operations (e.g., deleting system files), though that overlaps with destructive techniques

This subtechnique is **post-action cleanup** and is a strong signal when correlated with other suspicious behaviors.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Dropping a tool, executing it, then deleting it
- Removing temporary payloads and scripts from common staging locations
- Deleting logs and artifacts after privilege escalation
- Cleaning up staging folders used for collection or exfil packaging

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **file deletion telemetry and behavioral correlation**:
- Alert on deletion of newly created executables or scripts
- Detect deletion of security logs or audit artifacts
- Monitor suspicious processes performing bulk deletions
- Correlate deletions with known intrusion phases (post-exploitation, staging, pre-ransomware)

### Data Source Notes
- **File system monitoring**: Primary detection for delete events
- **EDR telemetry**: Identify the deleting process, ancestry, and context
- **Audit logs**: Attribute deletions to users/services
- **Cloud/container telemetry**: Detect deletion in ephemeral environments where host logs may be limited

Common false positives:
- Legitimate cleanup jobs (temp cleaners, log rotation)
- Software uninstallers and patching
- Container lifecycle cleanup

Tuning guidance:
- Baseline expected deletion behavior by host role
- Increase severity when deletions target:
  - logs
  - security tool directories
  - recent payload drop paths
  - staging/exfil directories

---

## 6. Response Guidance
When suspected:
1. Identify which files were deleted, by whom, and when
2. Determine whether deleted artifacts relate to tooling, logs, or staging
3. Collect EDR telemetry, file system metadata, and backups/snapshots
4. Attempt recovery via backups, shadow copies, or forensic methods
5. Expand hunt to other hosts for similar deletion patterns

## 8. SOC Relevance
T1070.004 is highly relevant because file deletion is a common “cleanup” step for intruders and is frequently observed:
- After tool execution
- After privilege escalation
- Before ransomware deployment
- During attacker exit

File deletion alone can be noisy, but when correlated with suspicious execution it becomes a strong signal.

---

## 9. Threat Actor Usage
This subtechnique is commonly used by:
- Ransomware operators (cleanup and anti-forensics)
- APT groups (stealth and long-dwell operations)
- Financially motivated intruders (tooling cleanup)

---

## 10. Campaign Usage
Observed in:
- Ransomware staging and execution phases
- Espionage operations with post-action cleanup
- Intrusions involving interactive post-exploitation tooling

---

## 11. Malware Usage
Associated with:
- Ransomware families and affiliates
- Loaders and droppers deleting installers
- Post-exploitation frameworks removing artifacts

---

## 12. Mitigations
Recommended mitigations:
- Centralize and protect logs (so deletion on host does not eliminate visibility)
- Enable EDR file event capture (create/modify/delete)
- Restrict administrative privileges to limit deletion capability
- Implement robust backup/snapshot strategies
- Monitor and restrict deletion of protected paths (where feasible)

---

## 13. Testing & Validation
Validation approaches:
- Delete benign files in controlled lab environments and validate alerts
- Simulate “drop–execute–delete” workflows and ensure visibility
- Confirm backups/snapshots support recovery requirements
- Test SOC workflows for identifying deleted artifact scope
