## 1. Summary
Adversaries may acquire credentials stored by web browsers by reading browser-specific files (e.g., credential databases) and/or by searching browser process memory for credential patterns. Stolen browser credentials and session material can enable rapid account takeover, internal access expansion, and data theft.

## 2. Technical Overview
Common browser credential storage patterns:
- **File-based stores:** Databases and JSON/profile files containing login entries (often encrypted at rest).
- **OS-assisted decryption:** On Windows, decrypted values may be recoverable using OS cryptographic services in the user context (e.g., DPAPI via CryptUnprotectData).
- **Session/token material:** Cookies and session tokens (distinct from passwords) may also be harvested from browser profiles, enabling immediate impersonation.

Typical adversary workflow (defender-relevant):
1. Locate browser profile and credential store files (per browser/user profile).
2. Read credential database(s) and extract encrypted values.
3. Decrypt using OS/user context or steal from memory.
4. Reuse credentials/tokens to expand access.

## 3. Subtechnique Considerations
- Treat this as **high-volume, commodity** credential theft as well as an APT tradecraft component.
- Detection should be browser-agnostic where possible: focus on **non-browser processes accessing browser profile paths** and **post-access authentication anomalies**.

## 4. Procedure Examples
Observed behaviors include:
- Dumping Chrome/Edge credential databases and decrypting stored passwords through OS APIs.
- Using public recovery tools to extract browser-saved credentials across multiple browser families.
- Stealing browser profiles containing credential artifacts from Firefox/Chromium-based browsers.

## 5. Detection Guidance
High-signal analytics:
- **Non-browser process reads** of browser credential stores (especially from user download/temp locations).
- **Command-line patterns** associated with credential dumping utilities, SQLite querying, or suspicious scripting around browser profile paths.
- **Process memory access** into browser processes by unfamiliar binaries (where telemetry exists).

Practical correlations:
- Unknown process → read of browser “Login Data” / credential DB → outbound network connection or archive creation.
- Credential store access → subsequent suspicious sign-ins (new geos, impossible travel, first-time device) using the same user account.

Response-oriented enrichment:
- Identify which browser(s) were targeted and which user profiles were accessed.
- Determine whether password values were decrypted vs. only copied (still assume compromise if exfil is possible).

### Data Source Notes
- Endpoint: process creation + command-line, file access telemetry for browser profile locations, module loads/API telemetry (CryptUnprotectData usage where available), and process access events into browser processes.
- Identity: authentication logs for credential reuse detection and token-based sign-ins.

## 6. Response Guidance
1. **Contain:** Isolate endpoint and stop suspicious process(es); block identified tools/hashes.
2. **Credential actions:** Force password resets and revoke active sessions/tokens for impacted users; prioritize admin and SSO accounts.
3. **Scope:** Hunt for same file access patterns across fleet and for similar credential dumping tooling.
4. **User safety:** Review browser password storage policies; encourage password manager + MFA rather than browser “save password” for privileged accounts.

## 8. SOC Relevance
- **Severity:** Critical when affecting SSO/admin users or when correlated with session theft.
- **Best signals:** Non-browser process reading browser login DB/cookie stores; follow-on anomalous sign-ins.
- **False positives:** Forensics tools, browser migration utilities, enterprise management agents—reduce with signed binary allowlists and managed tooling inventories.

## 12. Mitigations
- Reduce storage of privileged credentials in browsers through policy and training.
- Enforce MFA and conditional access; treat token theft as an expected follow-on.
- Application control to restrict execution of unsigned/unapproved credential recovery tools.

## 13. Testing & Validation
- Use safe, sanctioned tests to confirm:
  - Alerts trigger when a non-browser process reads browser credential DBs.
  - Identity detections trigger on post-theft anomalous sign-ins.
- Atomic Red Team coverage can be used to validate detection logic in a lab environment.
