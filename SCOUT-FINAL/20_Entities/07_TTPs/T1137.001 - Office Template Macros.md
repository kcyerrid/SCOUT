# T1137.001 – Office Template Macros

## 1. Technique Overview
**Office Template Macros (T1137.001)** is a sub-technique of [[20_Entities/07_TTPs/T1137 - Office Application Startup|T1137]] in **MITRE ATT&CK v18**. Adversaries abuse **Microsoft Office template startup behavior** by placing malicious, macro-enabled templates in locations that Office loads automatically (e.g., global templates). When an Office application launches, embedded macros execute without additional user interaction.

This provides reliable user-context persistence tied to routine Office usage.

## 2. Adversary Objectives
Adversaries use template macro persistence to:
- Achieve execution whenever Office applications start
- Maintain persistence without traditional autorun mechanisms
- Blend execution into trusted Office workflows
- Evade detection through legitimate extensibility features

## 3. Common Abuse Patterns
- Dropping malicious templates (e.g., `.dotm`, `.xltm`) into startup directories
- Leveraging global templates that load across multiple Office apps
- Embedding auto-executing macros (e.g., `AutoOpen`, `Document_Open`)
- Obfuscating macro logic to evade static analysis
- Combining with initial access via phishing or document delivery

## 4. Detection Considerations
Detection relies on **Office configuration and macro visibility**, including:
- Auditing Office startup and template directories for unauthorized files
- Monitoring creation or modification of macro-enabled templates
- Detecting macro execution at application startup
- Correlating Office launches with unexpected child processes or network activity
- Applying file integrity monitoring to trusted template locations

## 5. Defensive Mitigations
- Restrict write access to Office template and startup directories
- Disable or restrict macro execution via policy
- Enforce macro signing requirements
- Monitor and control Office template deployment
- Use endpoint security tools with macro behavior detection

## 6. Operational Impact
If successful, T1137.001 can:
- Provide consistent, low-noise persistence
- Execute code in the user context on every Office launch
- Support follow-on actions such as data exfiltration or lateral movement
- Complicate detection due to trusted application context

## 7. Analyst Notes
Template macro persistence is often established **immediately after initial access**. Analysts should examine Office template locations early in investigations involving document-based malware or suspicious Office behavior, as templates may persist even after malicious documents are removed.
