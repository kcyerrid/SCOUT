# Modify System Image: Patch System Image (T1601.001)

## 1. Summary
Patch System Image describes adversaries **modifying existing system images by adding, altering, or replacing components** to introduce malicious functionality while preserving the appearance of a legitimate update. This enables stealthy persistence and large-scale propagation.

Attackers use this technique to:
- Embed backdoors or persistence mechanisms
- Pre-compromise future system deployments
- Evade endpoint-based detections
- Abuse trusted image distribution pipelines

---

## 2. Technical Overview
System images are often updated (“patched”) to add features, fix vulnerabilities, or deploy configuration changes. Adversaries abuse this process by:

- Injecting malicious binaries or scripts into images
- Adding startup services, tasks, or hooks
- Modifying configuration files to weaken security
- Leveraging legitimate patch workflows to hide tampering

Common targets:
- Golden VM images
- Cloud instance templates
- OS deployment media
- Container base images
- Network appliance firmware

Indicators include:
- Image hash changes without approved change records
- Unexpected binaries or services in freshly deployed systems
- Security controls disabled across new deployments
- Identical malicious artifacts appearing on multiple hosts

---

## 3. Subtechnique Considerations
Key considerations for T1601.001:
- More subtle than image replacement
- Often masquerades as legitimate maintenance
- Can bypass downstream security validation
- Impact scales with image reuse

This technique **corrupts trust in update processes**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Adding backdoors during image patching
- Injecting malicious startup scripts
- Altering logging or security agent settings
- Using trusted pipelines to distribute compromise

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **image integrity and provenance**:
- Monitor image modification events
- Validate hashes and signatures post-update
- Compare deployed systems against known-good images
- Detect unauthorized repository access

### Data Source Notes
- **Image modification logs**: Detect patch activity
- **Integrity monitoring**: Identify unauthorized changes
- **Repository logs**: Attribute access and changes

Common false positives:
- Legitimate image updates
- Approved security patches

Tuning guidance:
- Enforce signed image updates
- Require approvals for image modifications
- Elevate severity for changes outside maintenance windows

---

## 6. Response Guidance
When suspected:
1. Quarantine affected images immediately
2. Identify all systems deployed from compromised images
3. Redeploy from trusted, verified images
4. Rotate embedded credentials and secrets
5. Audit image pipeline access controls

## 8. SOC Relevance
T1601.001 is critical because:
- Compromise propagates silently at scale
- Endpoint detections may miss root cause
- Recovery actions may reintroduce malware

SOC teams must treat **image patch pipelines as security-critical infrastructure**.

## 11. Malware Usage
Associated with:

- Preinstalled persistence mechanisms
- Supply-chain–delivered malware

---

## 12. Mitigations
Recommended mitigations:
- Use signed and immutable images
- Restrict image modification access
- Monitor and alert on image changes
- Implement reproducible builds

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign image patching in test environments
- Validate alerts on unauthorized modifications
- Test IR playbooks for image compromise
- Verify rollback and redeployment procedures
