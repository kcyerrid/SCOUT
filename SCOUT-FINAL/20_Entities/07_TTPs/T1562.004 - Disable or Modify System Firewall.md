# Impair Defenses: Disable or Modify System Firewall (T1562.004)

## 1. Summary
Disable or Modify System Firewall describes adversaries **disabling host-based firewalls or altering firewall rules** to allow unauthorized network communication. By weakening or removing firewall protections, attackers enable command-and-control traffic, lateral movement, and data exfiltration that would otherwise be blocked.

This technique is commonly used to:
- Open inbound or outbound network paths
- Enable C2 communication
- Facilitate lateral movement
- Bypass network segmentation controls

---

## 2. Technical Overview
Host-based firewalls enforce rules governing inbound and outbound network traffic. Adversaries impair these defenses by:

- Disabling firewall services entirely
- Modifying or deleting existing firewall rules
- Adding permissive allow rules
- Changing firewall profiles (e.g., Domain → Public)
- Disabling logging for firewall activity

Platform-specific considerations:
- **Windows**: Windows Defender Firewall service and rule sets
- **Linux**: iptables, nftables, firewalld, ufw
- **macOS**: Application firewall and packet filter (pf)
- **Cloud**: Host-level firewalls combined with security groups

Indicators include:
- Firewall service stopped or disabled
- Unexpected rule additions or deletions
- Sudden increases in allowed network connections
- Network traffic bypassing expected controls

---

## 3. Subtechnique Considerations
Key considerations for T1562.004:
- Often paired with **Network Service Discovery (T1046)** and **Remote Services (T1021)**
- Frequently precedes lateral movement or C2 activity
- Requires administrative or elevated privileges
- High-confidence signal of intentional defense evasion

Firewall modification is rarely justified outside controlled change windows.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Disabling host-based firewall services
- Adding allow-all inbound or outbound rules
- Opening specific ports for remote access tools
- Suppressing firewall logging to avoid detection

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **firewall integrity and configuration monitoring**:
- Alert on firewall service state changes
- Detect rule modifications or new allow rules
- Monitor changes to firewall profiles
- Correlate firewall changes with suspicious network traffic

### Data Source Notes
- **Firewall logs**: Primary source for rule and traffic visibility
- **Service configuration logs**: Detect firewall disablement
- **EDR telemetry**: Identify tampering attempts
- **Cloud audit logs**: Track host-level and cloud firewall changes

Common false positives:
- Legitimate IT troubleshooting
- Software installation requiring temporary rule changes
- Approved configuration updates

Tuning guidance:
- Require change approval for firewall modifications
- Baseline expected rules per system role

---

## 6. Response Guidance
When suspected:
1. Verify firewall service status and rule configuration
2. Restore baseline firewall rules and profiles
3. Identify the process or account responsible for changes
4. Investigate network activity enabled by the modification
5. Contain affected systems if unauthorized access is identified

## 8. SOC Relevance
T1562.004 is a **high-priority detection** because firewall changes often immediately precede malicious network activity. Unauthorized firewall modifications should be escalated as potential intrusions.

---

## 9. Threat Actor Usage
This technique is commonly used by:
- Ransomware operators
- Advanced persistent threats
- Financially motivated intruders

It strongly correlates with **hands-on-keyboard activity**.

---

## 10. Campaign Usage
Observed in:
- Ransomware staging and execution phases
- Lateral movement campaigns
- Intrusions requiring persistent network access

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Remote access trojans
- Post-exploitation frameworks
- Custom C2 implants

---

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege for firewall management
- Monitor and alert on firewall configuration changes
- Use centralized firewall policy management
- Enable firewall logging and retain logs centrally
- Validate firewall state as part of incident response

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign firewall rule changes in lab environments
- Validate alerts on firewall service disablement
- Test SOC workflows for unauthorized rule additions
- Ensure network traffic monitoring detects newly allowed flows
