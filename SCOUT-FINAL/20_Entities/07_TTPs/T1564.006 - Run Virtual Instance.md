# Hide Artifacts: Run Virtual Instance (T1564.006)

## 1. Summary
Run Virtual Instance describes adversaries **executing malicious code inside a virtual machine or isolated virtualized environment** in order to conceal artifacts and activity from host-based security controls. By operating within a guest instance, attackers reduce visibility into filesystem, process, and memory activity from traditional endpoint detection solutions.

This technique is commonly used to:
- Evade host-based EDR and AV tooling
- Isolate malicious execution from monitored environments
- Conceal tooling, payloads, and runtime artifacts
- Enable long-dwell or stealthy execution workflows

---

## 2. Technical Overview
Modern operating systems and hypervisors support a wide range of virtualization technologies. Adversaries abuse these capabilities by:

- Spawning **local virtual machines** (e.g., VirtualBox, Hyper-V, QEMU)
- Running **headless or background guest instances**
- Executing malware **entirely inside the guest OS**
- Using the host only as a launcher or controller

Common environments include:
- Desktop hypervisors on endpoints
- Server-based hypervisors (e.g., ESXi)
- Emulated environments used to stage tooling or decrypt payloads

Typical artifacts and indicators:
- Hypervisor or VM management processes starting unexpectedly
- Disk images created or accessed without business justification
- Guest network traffic not correlated with host processes
- Resource usage (CPU, memory) inconsistent with visible host activity

---

## 3. Subtechnique Considerations
Key considerations for T1564.006:
- Strongly overlaps with **sandbox/virtualization evasion (T1497)** but is distinct in purpose
- Focused on **using virtualization offensively**, not detecting it
- Detection is difficult without visibility into hypervisor and guest activity
- More common in advanced or targeted intrusions

This technique reflects **higher operational maturity**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Launching a hidden virtual machine to execute payloads
- Using a guest OS to stage tools and decrypt secondary payloads
- Running command-and-control clients inside a VM
- Performing malicious operations in an isolated sandbox to avoid host monitoring

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection requires **host + hypervisor correlation**:
- Alert on unexpected hypervisor or VM process creation
- Monitor creation and access of VM disk images
- Correlate network traffic from guest interfaces
- Detect virtualization tooling on systems where it is not standard

### Data Source Notes
- **Process telemetry**: Identify VM launch and management activity
- **Hypervisor logs**: Required for guest lifecycle visibility
- **Network telemetry**: Detect guest-originated traffic
- **Application logs**: Identify VM management interactions

Common false positives:
- Developer workstations
- IT virtualization labs
- Backup and testing environments

Tuning guidance:
- Baseline systems authorized to run virtualization software
- Elevate alerts when virtualization appears on user endpoints

---

## 6. Response Guidance
When suspected:
1. Identify whether virtualization software is authorized on the system
2. Enumerate running and dormant guest instances
3. Capture disk images and memory (if feasible)
4. Inspect guest OS artifacts and network activity
5. Remove unauthorized virtualization tooling and remediate host access

## 8. SOC Relevance
T1564.006 is highly relevant in:
- Targeted attacks against mature security environments
- Incidents with unexplained resource usage
- Scenarios where host telemetry shows minimal malicious activity

Running a virtual instance often explains “blind spots” in host-based detections.

---

## 9. Threat Actor Usage
This technique has been observed among:
- Advanced persistent threat groups
- Espionage-focused operators
- Actors willing to trade complexity for stealth

Its use typically signals **intentional evasion of modern EDR**.

---

## 10. Campaign Usage
Observed in:
- Long-dwell espionage campaigns
- Stealthy post-exploitation phases
- Operations targeting highly monitored endpoints

---

## 11. Malware Usage
Associated with:
- Advanced loaders
- Custom espionage implants
- Toolchains designed to operate in isolated environments

---

## 12. Mitigations
Recommended mitigations:
- Restrict installation and execution of virtualization software
- Monitor and log hypervisor and VM management activity
- Apply application control to prevent unauthorized VM tooling
- Segment networks to limit guest communication paths
- Include virtualization artifacts in IR procedures

---

## 13. Testing & Validation
Validation approaches:
- Deploy benign virtualization tooling in a lab and validate alerts
- Test detection of unauthorized VM creation
- Verify SOC access to hypervisor and guest telemetry
- Simulate guest-originated network traffic and ensure visibility
