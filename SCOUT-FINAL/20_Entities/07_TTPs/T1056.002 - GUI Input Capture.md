## 1. Summary
GUI Input Capture (T1056.002) involves adversaries presenting **spoofed graphical prompts** (OS dialogs or application login prompts) to trick users into entering credentials or other sensitive input (e.g., MFA codes), which are then captured by the adversary.

## 2. Technical Overview
Common patterns include:
- **Spoofed privilege prompts** (e.g., UAC-like dialogs) designed to look legitimate.
- **Spoofed application prompts** (email/browser/VPN “re-auth” dialogs), sometimes timed to user behavior (e.g., when the user is actively using a sensitive app).
- **Scripted prompt creation** using native UI tooling (AppleScript, PowerShell, shell dialogs on Linux) that renders convincing dialogs.

Defender-relevant behaviors:
- Scripting engines or unusual binaries spawning UI dialogs with authentication-themed text.
- Prompt creation correlated with **process discovery** (e.g., enumerating windows/apps) to time the lure.
- Immediate outbound connections or local writes containing captured credentials after prompt display.

## 3. Subtechnique Considerations
- This subtechnique is **socially-assisted**: success depends on user interaction.
- High-fidelity detections typically combine **UI prompt generation** + **suspicious parent process lineage** + **credential-use follow-on**.

## 5. Detection Guidance
Detection should focus on **(a) suspicious prompt generation** and **(b) correlation to credential handling/use**.

Recommended analytics:
- **Suspicious GUI prompt creation from atypical parents**
  - Script hosts (PowerShell, AppleScript, shell) or unsigned binaries spawning dialogs that reference authentication, system settings, “password”, “VPN”, “mail”, “security”, etc.
- **User interaction lures aligned with sensitive app usage**
  - Prompt creation within seconds/minutes of launching Outlook/browser/VPN clients, or after enumerating windows/apps.
- **Post-prompt collection/exfil indicators**
  - Prompt creation followed by creation of new files containing text blobs, clipboard access patterns, or immediate outbound network to unusual destinations.

### Data Source Notes
- Endpoint: process creation with command line, parent/child chains, script block logging (where applicable), module loads.
- macOS: AppleScript/osascript execution telemetry; TCC-related prompts/logs where available.
- Linux: dialog utilities (e.g., zenity/kdialog/dialog) invoked by non-interactive shells or suspicious parents.
- Network: outbound connections immediately after prompt execution, especially from script hosts or uncommon binaries.

## 6. Response Guidance
- Contain affected endpoints and identify the process lineage generating prompts.
- Reset credentials entered on affected hosts; review downstream logins for anomalous sessions/devices.
- Hunt fleet-wide for the same prompt generator (hash, signer, command line, script content) and related staging/exfil behavior.

## 12. Mitigations
- User awareness training focused on credential prompts and “re-auth” dialogs.
- Reduce script execution abuse surface (script control policies, signed script enforcement where feasible).
- Harden endpoint policy around accessibility/automation tooling where applicable.

## 13. Testing & Validation
- Validate that your telemetry captures:
  - Script host executions that generate dialogs (osascript/PowerShell/dialog tools)
  - Parent/child chains and command-line content
- Test detections using benign UI prompts in a lab (do not collect real credentials), ensuring alerts fire on suspicious parents and wording patterns.
