# T1546.017 – Udev Rules

## 1. Technique Overview
**Udev Rules (T1546.017)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse **udev**, the Linux device manager, by creating or modifying udev rules that execute attacker-controlled commands when specific hardware-related events occur (e.g., device addition, removal, or state changes).

Because udev rules are processed automatically by the system and often run with elevated privileges, this technique provides a reliable event-driven persistence and potential privilege escalation mechanism.

## 2. Adversary Objectives
Adversaries use udev rules to:
- Achieve persistence triggered by system or hardware events
- Execute malicious code with elevated privileges
- Blend malicious execution into legitimate device management workflows
- Regain execution after reboots or device changes

## 3. Common Abuse Patterns
- Creating or modifying rule files under:
  - `/etc/udev/rules.d/`
  - `/lib/udev/rules.d/`
- Defining `RUN+=` actions that execute shell commands or scripts
- Triggering execution on common events such as USB device insertion
- Masquerading malicious rules as legitimate hardware management entries
- Using udev execution to deploy or re-launch secondary payloads

## 4. Detection Considerations
Detection relies on **configuration, file integrity, and process monitoring**, including:
- Monitoring creation or modification of udev rule files
- Alerting on rules that include `RUN+=` directives
- Correlating hardware events with unexpected process execution
- Auditing udev rules for unauthorized or anomalous entries
- Reviewing system logs related to device management activity

## 5. Defensive Mitigations
- Restrict write permissions to udev rule directories
- Monitor and alert on changes to udev configuration files
- Use file integrity monitoring on udev rule paths
- Audit udev rules regularly for unauthorized execution logic
- Remove malicious udev rules during incident response

## 6. Operational Impact
If successful, T1546.017 can:
- Provide durable, event-driven persistence
- Enable privileged execution without user interaction
- Evade detection focused on startup or scheduled execution
- Complicate incident response due to indirect execution triggers

## 7. Analyst Notes
Udev rule abuse is often overlooked because it is tied to hardware management rather than traditional persistence locations. Analysts should explicitly inspect **all udev rules containing execution directives**, especially in environments where removable media or dynamic hardware changes are common.
