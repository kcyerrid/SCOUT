# T1110.001 - Password Guessing

## 1. Summary
Password Guessing (T1110.001) describes attempts to authenticate to accounts using common passwords or dictionary-style guesses without prior possession of valid credential material. This activity is frequently observed against exposed management services, identity providers, and web authentication portals.

## 2. Technical Overview
Typical characteristics:
- Attempts focus on **known/likely usernames** (directory-derived, email formats, “admin”-like accounts) plus **common password lists**.
- Targets include SSH, RDP gateways, LDAP/Kerberos auth paths, web admin panels, and SaaS/IdP sign-in flows.
- Adversaries may tune guesses to match likely complexity requirements and throttle attempts to avoid lockouts/detection.

Key differentiator vs spraying:
- **Guessing** tends to focus on one/few accounts with many passwords (or a modest dictionary).
- **Spraying** uses one/few passwords across many accounts.

## 3. Subtechnique Considerations
- Parent technique: [[20_Entities/07_TTPs/TA0006 - Credential Access/T1110 - Brute Force|T1110]]
- If attempts are one-password-many-users, classify as **T1110.003 Password Spraying** instead.

## 5. Detection Guidance
Detection objective: **identify repeated authentication failures consistent with dictionary guesses and tie them to account impact and post-authentication behavior**.

Recommended detections:
- **Per-user failure thresholds**:
  - Multiple failures for the same user from a single source within a time window.
  - Failures followed by a success for the same user/source/client fingerprint.
- **Protocol/service-aware rules**:
  - Windows: repeated 4625 patterns (logon type, workstation name, source IP) followed by 4624.
  - Linux/macOS: sshd/loginwindow/unified log failures with repetitive username prompts.
  - Web apps/IdP: repeated invalid password outcomes for a single principal, especially from new devices/locations.
- **Edge correlation**:
  - VPN/WAF/reverse proxy auth failures correlated with backend auth failures/success.

Enrichment:
- Geo-velocity/impossible travel indicators on subsequent success
- ASN/proxy detection for source
- Target account tiering (admins/service accounts highest risk)

This technique page does not present an explicit ATT&CK “Data Sources” list in the technique header; prioritize:

- Remote access logs (VPN, gateways, reverse proxies)
- Network device AAA/syslog where applicable

## 6. Response Guidance
- Temporarily block/limit abusive sources (IP/ASN, client fingerprints) where safe.
- Reset credentials and revoke sessions for impacted accounts; enforce MFA for targets.
- Review account lockout settings and ensure “smart lockout”/risk-based lockout if supported.
- Investigate for credential exposure and follow-on activity post-success (remote sessions, mailbox access, privilege escalation).

## 8. SOC Relevance
High-volume guessing is noisy and often blocked quickly, but **low-rate guessing** can bypass simplistic thresholds. SOC value comes from:
- Correlation of failures→success
- Risk scoring by account sensitivity and source reputation
- Rapid containment to prevent lateral movement or mailbox compromise

## 12. Mitigations
ATT&CK-listed mitigations for this subtechnique include:
- **M1036 - Account Use Policies**: lockout + conditional access constraints; restrict auth from risky networks.
- **M1032 - Multi-factor Authentication**: enforce MFA on exposed services and high-value accounts.
- **M1027 - Password Policies**: prevent weak/common passwords; align with modern guidance.
- **M1051 - Update Software**: keep management services up to date, especially where policy enforcement improves.

## 13. Testing & Validation
- Validate per-user failure thresholds across key services (IdP, VPN, SSH/RDP gateways).
- Test that benign automation (health checks, scanners, password managers) does not trigger escalations.
- Confirm response workflows: auto-block + user notification + forced reset + session revocation.
