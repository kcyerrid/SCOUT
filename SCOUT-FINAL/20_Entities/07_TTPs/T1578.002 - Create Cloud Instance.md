# Modify Cloud Compute Infrastructure: Create Cloud Instance (T1578.002)

## 1. Summary
Create Cloud Instance describes adversaries **deploying new cloud compute resources** within a compromised cloud environment to enable persistence, staging, lateral movement, or malicious operations. These instances may be short-lived or long-running and often blend into legitimate infrastructure.

Attackers use this technique to:
- Establish covert infrastructure inside trusted cloud environments
- Bypass perimeter defenses and network monitoring
- Stage tools or data internally
- Maintain access independent of compromised endpoints

---

## 2. Technical Overview
Cloud providers allow authorized identities to create new compute resources programmatically. Adversaries abuse this capability by:

- Creating virtual machines, containers, or serverless functions
- Using stolen or abused credentials and roles
- Deploying instances in existing networks or security groups
- Leveraging automation or infrastructure-as-code tools

Common deployment methods:
- Manual creation via cloud consoles
- API-based provisioning using SDKs or CLI tools
- Reusing templates, images, or snapshots
- Launching instances with preconfigured startup scripts

Indicators include:
- Instance creation outside approved workflows
- Compute resources created by unusual identities
- Instances lacking asset inventory or ownership
- New workloads communicating externally or laterally

---

## 3. Subtechnique Considerations
Key considerations for T1578.002:
- Often paired with **Valid Accounts (T1078)** and **Account Manipulation (T1098)**
- May enable **Cloud Infrastructure Discovery (T1577)**
- Can act as a pivot point for lateral movement
- Infrastructure may persist even after endpoint cleanup

This technique turns the **cloud itself into attacker infrastructure**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Creating hidden instances for C2 or staging
- Deploying compute resources for cryptomining
- Spawning instances to access internal networks
- Launching workloads with malicious startup scripts

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **control-plane monitoring and governance**:
- Monitor audit logs for instance creation events
- Alert on compute resources created by unexpected identities
- Detect instances created without asset tagging
- Correlate instance creation with suspicious authentication

### Data Source Notes
- **Cloud audit logs**: Primary detection source
- **IAM logs**: Attribute actions to identities
- **Configuration logs**: Identify unauthorized resources
- **Network logs**: Detect anomalous communication

Common false positives:
- Legitimate autoscaling events
- Approved infrastructure deployments

Tuning guidance:
- Baseline expected automation and CI/CD identities
- Require approvals for instance creation
- Elevate severity when creation follows suspicious login activity

---

## 6. Response Guidance
When suspected:
1. Inventory newly created compute resources
2. Identify ownership and deployment context
3. Isolate or terminate unauthorized instances
4. Rotate credentials used to create resources
5. Review logs for additional abuse

## 8. SOC Relevance
T1578.002 is critical because:
- Attackers can operate entirely within cloud environments
- Malicious infrastructure may appear legitimate
- Traditional endpoint detections may be bypassed

SOC teams must treat **new cloud resources as potential threats**.

---

## 9. Threat Actor Usage
Commonly used by:
- Cloud-focused intrusion groups
- Cryptomining and resource abuse actors
- Adversaries leveraging stolen credentials

---

## 10. Campaign Usage
Observed in:
- Cloud account takeover campaigns
- Cryptomining operations
- Lateral movement within cloud environments

---

## 11. Malware Usage
Associated with:
- Minimal malware usage
- Script-based cloud abuse
- Cloud-native tooling

---

## 12. Mitigations
Recommended mitigations:
- Restrict instance creation permissions
- Enforce tagging and ownership policies
- Monitor for unauthorized resource creation
- Apply least-privilege IAM roles

---

## 13. Testing & Validation
Validation approaches:
- Simulate instance creation in test environments
- Validate alerts on unauthorized provisioning
- Test SOC workflows for cloud resource abuse
- Ensure rapid detection and response capabilities
