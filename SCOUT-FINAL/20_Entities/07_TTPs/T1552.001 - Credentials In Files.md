## 1. Summary
Adversaries may search local file systems and remote file shares for files containing **insecurely stored credentials**, such as plaintext passwords, API keys, tokens, connection strings, or embedded secrets in configuration/source/binaries.

## 2. Technical Overview
Common target artifact classes:
- **Application config**: `.env`, `.ini`, `.yaml`, `.json`, `.xml`, `web.config`, `machine.config`
- **Cloud creds**: `~/.aws/credentials`, SDK/CLI profiles, kubeconfig, Docker auth, IaC templates
- **Credential caches/export files**: export dumps, backups, copied profiles
- **Embedded secrets**: hardcoded strings inside scripts, source, or binaries

Defender-relevant behavior patterns:
- Broad file discovery across user profiles, app directories, CI/CD workspaces, and shared drives
- Keyword-driven searching (e.g., “password”, “token”, “key”, “secret”, “conn”, “aws_access_key_id”)
- Staging/collection actions (copying config files, exfil patterns) followed by authentication use

## 3. Subtechnique Considerations
- As a sub-technique, this often overlaps with development/ops workflows (legitimate config reads).
- Highest signal comes from:
  - **Nonstandard processes** reading credential-bearing files
  - Reads outside normal app execution windows
  - Reads from **unexpected hosts** (e.g., user workstation reading server-only secrets)
  - Reads immediately followed by **new auth activity** (cloud logins, RDP/SSH, service access)

## 4. Procedure Examples
MITRE documents multiple examples including:
- [[30_CIPHER/05_Malware/S0677 - AADInternals|AADInternals]] gathering unsecured Azure AD-related credentials from local systems.
- [[30_CIPHER/05_Malware/S0331 - Agent Tesla|Agent Tesla]] extracting credentials from configuration/support files.
- [[30_CIPHER/03_Threat_Actors/G0022 - APT3|APT3]] locating credentials in browser-related files.
- [[30_CIPHER/03_Threat_Actors/G0064 - APT33|APT33]] leveraging publicly available tooling such as [[30_CIPHER/05_Malware/S0349 - LaZagne|LaZagne]] to gather credentials.
- C0058 - SharePoint ToolShell Exploitation involving extraction of sensitive configuration values from `web.config` / `machine.config`.

## 5. Detection Guidance
High-confidence detections should combine **artifact access** + **context** + **follow-on use**.

Detection patterns:
- Reads of known secret-bearing files by:
  - scripting engines and “utility” processes not associated with the target app
  - remote admin tools running under unusual parent processes
- Rapid enumeration of many files + credential keyword matching behavior
- Reading common cloud credential paths followed by cloud API activity from the same host/user

Suggested analytics:
- “Sensitive file read” rules for known secret paths and high-risk extensions
- Correlation: file read → outbound network connection to identity/service endpoint → auth event
- Alert on bulk file-search commands touching secret directories

### Data Source Notes
Telemetry to prioritize (vendor-neutral):
- EDR file read/open telemetry (path, process, user, hash)
- Process creation + command-line (search utilities, scripting engines)
- File share access logs (SMB share reads of config/secret directories)
- Cloud audit logs (API calls, role assumptions shortly after local credential file access)
- DLP/egress monitoring (exfil of config files)

## 6. Response Guidance
1. **Containment**
   - Assume exposed creds are compromised; **rotate** immediately (keys/tokens/passwords).
2. **Scope**
   - Identify which files were accessed; determine all secrets contained.
   - Trace downstream usage: sign-ins, API calls, service auth, lateral movement.
3. **Eradication**
   - Remove plaintext secrets from files; migrate to secret vaults/managed identities.
4. **Hardening**
   - Implement secret scanning (repos + endpoints), least-privilege permissions, and short-lived creds.

## 8. SOC Relevance
SOC value is high because this can expose:
- Cloud root keys / service principals
- Database admin credentials / connection strings
- Lateral movement jump points via reused secrets

Operational triage:
- Identify *which* secrets were present (blast radius).
- Look for near-term “new” auth usage from unusual sources.
- Prioritize incidents involving shared admin/service creds.

## 12. Mitigations
- **M1047 - Audit**: Proactively search for plaintext secrets; remediate and monitor access.
- **M1027 - Password Policies**: Prohibit storing passwords in files; enforce secure secret handling.
- **M1022 - Restrict File and Directory Permissions**: Apply least privilege to config/secret directories and shares.
- **M1017 - User Training**: Train developers/admins on secure configuration and secret vault usage.

## 13. Testing & Validation
- Validate “sensitive file read” analytics using benign test secrets in a lab environment and confirm:
  - File access telemetry includes process/user context
  - Alerting triggers on nonstandard process reads
  - Correlation works (file read → auth event)
