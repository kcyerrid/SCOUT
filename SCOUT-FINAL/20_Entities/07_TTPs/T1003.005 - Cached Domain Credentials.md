## 1. Summary
Cached Domain Credentials (T1003.005) is the extraction of locally cached authentication material used when a domain controller is unavailable. On Windows, this commonly relates to cached domain logon artifacts; on Linux, it can involve caches maintained by AD integration components (e.g., SSSD-like caches). Recovered hashes are typically used for offline cracking and follow-on credential abuse.

## 2. Technical Overview
Key patterns:
- **Windows cached logons**
  - Access to cached credential storage and registry settings controlling caching behavior.
  - Offline cracking workflows are commonly required; pass-the-hash is not always applicable.
- **Linux AD cache stores**
  - Credential caches stored in local databases maintained by AD integration software.
  - Adversaries may copy these databases and attempt offline extraction/cracking.

Defender view:
- Typically requires elevated privileges (SYSTEM/root) and is often chained with other credential access once the attacker is already local admin.

## 3. Subtechnique Considerations
- This subtechnique often appears in intrusions where:
  - DC reachability is limited, or attackers want credentials without touching DCs
  - Attackers focus on endpoints with frequent domain logons (admin workstations, jump hosts)
- Cached credentials can persist across time; prioritize endpoints belonging to admins and service operators.

## 4. Procedure Examples
ATT&CK procedure examples include:
- [[30_CIPHER/03_Threat_Actors/G0064 - APT33]] using credential collection tooling to gather credentials aligned with cached credential access.
- [[30_CIPHER/03_Threat_Actors/G0069 - MuddyWater]] and [[30_CIPHER/03_Threat_Actors/G0049 - OilRig]] using tooling such as [[30_CIPHER/05_Malware/S0349 - LaZagne]] for credential collection.
- [[30_CIPHER/05_Malware/S0119 - Cachedump]] extracting cached password hashes.
- [[30_CIPHER/05_Malware/S0349 - LaZagne]] performing credential dumping from cached credential sources.

## 5. Detection Guidance
Prioritize detections on **file/registry access** plus **privilege context**.

High-signal detection patterns:
- **Access to cached credential stores**
  - Unusual processes reading cached credential files/DBs, especially under SYSTEM/root.
  - Copying/archiving of cache databases from endpoints that rarely see admin tooling.
- **Registry and configuration interactions (Windows)**
  - Access to registry locations controlling cached logon behavior, paired with credential dumping indicators.
- **Behavior chains**
  - Cache store read → dump artifact created → compression/encryption → outbound transfer.
  - Cache access followed by offline cracking indicators on another host (if you monitor lab/IR environments, tune carefully).

### Data Source Notes
Useful telemetry sources:
- Endpoint file access telemetry (sensitive directories / cache DB locations)
- Process execution + lineage (EDR)
- Windows registry auditing for cached logon configuration paths (tuned)
- Authentication logs for “new credential use” after the suspected dump window

## 6. Response Guidance
- **Contain**: isolate affected endpoint(s) if active dumping suspected; prevent further artifact staging.
- **Credential actions**: reset exposed accounts (prioritize privileged accounts); enforce stronger password policies to increase cracking difficulty.
- **Scope**: identify which accounts logged onto the endpoint and could have been cached; determine whether artifacts left the host.
- **Hardening**: reduce cached credential footprint where feasible (policy), and protect high-value endpoints with stronger isolation and privileged access controls.

## 8. SOC Relevance
- Often indicates the attacker is harvesting credentials from endpoints as a stepping stone.
- Best pivots:
  - Identify the endpoint role (admin workstation/jump host = high impact)
  - Determine which accounts had interactive logons
  - Hunt for staging/exfil and immediate lateral movement

## 12. Mitigations
- **M1015 - Active Directory Configuration**: where applicable, use protected user and privileged account controls to reduce caching and credential exposure.
- **M1028 - Operating System Configuration**: consider limiting cached credential counts and hardening endpoints to reduce cache access.
- **M1027 - Password Policies**: strong passwords and rotation reduce success of offline cracking.
- **M1026 - Privileged Account Management**: reduce privileged logons to untrusted endpoints; enforce PAWs/jump hosts.
- **M1017 - User Training**: reduce credential reuse and promote privileged hygiene.

## 13. Testing & Validation
- In a lab:
  - Simulate reads of cached credential stores (Windows and Linux scenarios) and validate alerting on file access + privilege context.
  - Validate correlation rules tying cache access to subsequent authentication spread.
- Ensure legitimate endpoint management workflows are allowlisted (with tight scoping).
