# T1137.004 – Outlook Home Page

## 1. Technique Overview
**Outlook Home Page (T1137.004)** is a sub-technique of [[20_Entities/07_TTPs/T1137 - Office Application Startup|T1137]] in **MITRE ATT&CK v18**. Adversaries abuse **Microsoft Outlook Home Page functionality**, which allows folders to display custom HTML content, by configuring folders to load attacker-controlled pages. When a user accesses the affected folder, the malicious content is rendered automatically.

This technique enables user-context persistence tied directly to normal email navigation behavior.

## 2. Adversary Objectives
Adversaries use Outlook Home Page abuse to:
- Execute malicious scripts or load external content during routine email access
- Maintain persistence without traditional autorun or macro mechanisms
- Blend malicious execution into trusted Outlook workflows
- Evade detection by leveraging legitimate application features

## 3. Common Abuse Patterns
- Setting a folder’s Home Page to a local or remote malicious HTML file
- Using embedded scripts to launch secondary payloads
- Leveraging external web resources for command-and-control or updates
- Targeting frequently accessed folders (e.g., Inbox)
- Combining with registry or configuration changes to persist settings

## 4. Detection Considerations
Detection relies on **Outlook configuration and content inspection**, including:
- Auditing Outlook folder Home Page settings
- Monitoring registry changes related to Outlook Home Page configuration
- Detecting Outlook rendering external or unexpected local HTML content
- Correlating folder access with anomalous process or network activity
- Baseline comparison of known-good Outlook folder configurations

## 5. Defensive Mitigations
- Disable Outlook Home Page functionality where not required
- Monitor and alert on changes to Outlook folder Home Page settings
- Restrict script execution within Outlook-rendered content
- Educate users and administrators about Outlook persistence risks
- Remove unauthorized Home Page configurations during remediation

## 6. Operational Impact
If successful, T1137.004 can:
- Provide reliable persistence triggered by normal email usage
- Execute code without explicit macro enablement
- Leverage trusted Outlook behavior to reduce suspicion
- Complicate detection due to benign-appearing user actions

## 7. Analyst Notes
Outlook Home Page–based persistence is often overlooked because it relies on **content rendering rather than executable loading**. Analysts should inspect Outlook folder properties during investigations involving suspicious behavior tied to email navigation rather than document interaction.
