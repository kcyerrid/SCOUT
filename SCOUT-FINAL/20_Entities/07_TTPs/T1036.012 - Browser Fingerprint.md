# Masquerading: Browser Fingerprint (T1036.012)

## 1. Summary
Browser Fingerprint describes adversaries **modifying, mimicking, or replaying browser-identifying characteristics** so that malicious web activity appears to originate from a legitimate user, device, or session. This technique targets security controls that rely on browser identity, session continuity, or behavioral baselining.

Attackers use this technique to:
- Evade web and SaaS security controls
- Blend malicious activity into normal user behavior
- Bypass conditional access and anomaly detection
- Maintain access to cloud and web resources

---

## 2. Technical Overview
Modern web applications and security platforms identify clients using a combination of browser attributes, often referred to as a *browser fingerprint*. Adversaries exploit this by:

- Replicating legitimate user-agent strings
- Reusing cookies, tokens, or session identifiers
- Matching browser versions, plugins, and OS attributes
- Manipulating TLS, JavaScript, and HTTP header characteristics

Common fingerprint components include:
- User-Agent and Accept headers
- Screen resolution and timezone
- Installed fonts, plugins, and extensions
- TLS handshake and cipher preferences
- Cookie and session token data

Indicators include:
- Authentication events from browsers with “known-good” fingerprints but anomalous behavior
- Reuse of identical browser fingerprints across disparate locations
- Session continuity anomalies
- Cloud or SaaS access without corresponding endpoint activity

---

## 3. Subtechnique Considerations
Key considerations for T1036.012:
- Strong overlap with **Valid Accounts (T1078)** and **Use Alternate Authentication Material (T1550)**
- Frequently used in cloud and SaaS intrusions
- Often paired with session theft or token abuse
- Targets behavioral and risk-based access controls

This technique emphasizes **identity deception over technical exploitation**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Replaying stolen session cookies with matching browser attributes
- Spoofing browser fingerprints to evade anomaly detection
- Maintaining consistent browser identity across malicious activity
- Mimicking victim browser configurations in automated tooling

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **behavioral and contextual anomalies**:
- Detect reuse of identical browser fingerprints across locations
- Monitor browser identity changes within active sessions
- Correlate SaaS access with endpoint telemetry
- Alert on impossible travel or timing anomalies despite matching fingerprints

### Data Source Notes
- **Web proxy logs**: Capture browser and session metadata
- **Authentication logs**: Identify anomalous access patterns
- **EDR telemetry**: Validate endpoint presence and activity
- **Network telemetry**: Correlate access sources

Common false positives:
- Enterprise proxies and shared browsers
- Virtual desktop environments

Tuning guidance:
- Baseline browser fingerprints per user
- Elevate severity when fingerprint consistency masks abnormal behavior

---

## 6. Response Guidance
When suspected:
1. Invalidate affected sessions and tokens
2. Force re-authentication with strong verification
3. Review recent access activity for abuse
4. Identify initial access vector (phishing, token theft)
5. Expand hunt for similar browser fingerprints

## 12. Mitigations
Recommended mitigations:
- Enforce phishing-resistant MFA
- Bind sessions to device and network context
- Monitor for anomalous SaaS access patterns
- Implement conditional access policies

---

## 13. Testing & Validation
Validation approaches:
- Simulate session replay with controlled fingerprints
- Validate alerts on fingerprint reuse anomalies
- Test SOC workflows for SaaS account takeover
- Ensure correlation between endpoint and web telemetry
