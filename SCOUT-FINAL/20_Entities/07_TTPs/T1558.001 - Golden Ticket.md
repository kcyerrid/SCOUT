## 1. Summary
**Golden Ticket (T1558.001)** is the forging of Kerberos Ticket Granting Tickets (TGTs) using the **KRBTGT** account hash in Active Directory. Golden Tickets can enable broad, durable domain access and are typically **Tier 0 / domain-wide** impact.

## 2. Technical Overview
Defender-relevant behaviors:
- **TGT forgery** enabling authentication material for arbitrary AD accounts.
- **Follow-on service access**: forged TGTs are commonly used to request TGS tickets from the KDC to access specific resources.
- **Preconditions** usually include compromise that yields **KRBTGT** secrets (often preceded by domain controller access and credential dumping).
- **Detection challenge**: tickets may appear valid, so detection often hinges on **anomalous Kerberos ticket properties** and **behavioral deviations**.

## 3. Subtechnique Considerations
- Golden Tickets are more expansive than Silver Tickets because they can be used to mint access broadly across the domain.
- Incident handling often requires **domain recovery operations** (not just account password resets).
- Detections are strongest when correlating **KDC logs + endpoint credential access signals + identity analytics**.

## 5. Detection Guidance
Prioritize **domain controller Kerberos telemetry** and ticket anomalies:

High-signal detection themes (aligned to ATT&CK Detection Strategy **DET0144**):
- **Anomalous ticket lifetimes** inconsistent with policy/baseline.
- **Unexpected encryption types** (e.g., legacy/weak types in a modern AES-only domain).
- **Malformed or unusual fields** observed in logon/logoff or Kerberos-related events.
- **TGS request patterns** that are inconsistent with expected preceding authentication behavior.
- **Privilege behavior anomalies**: elevated access across multiple systems shortly after suspicious Kerberos activity.

Correlations to raise fidelity:
- Suspected credential dumping / DC access → Kerberos anomalies → widespread service access attempts.
- Single host/account suddenly touching many resources atypical for baseline.

### Data Source Notes
Recommended telemetry:
- Domain Controller security logs (Kerberos/KDC and logon events)
- Centralized authentication analytics (impossible travel, new device, abnormal access scope)
- Endpoint telemetry on suspected operator hosts (process lineage, credential access indicators)

## 6. Response Guidance
- **Containment (Tier 0)**: treat as a domain compromise until disproven; isolate suspected operator hosts and any compromised DCs.
- **Invalidate forged tickets**: follow KRBTGT password reset guidance (requires careful sequencing and replication awareness).
- **Scope and hunt**: identify affected services/resources accessed with suspicious tickets; pivot from abnormal Kerberos patterns to originating hosts.
- **Recovery**: consider broader AD hardening and privileged access redesign if KRBTGT compromise is confirmed.

## 12. Mitigations
- **M1015 - Active Directory Configuration**: reset the KRBTGT account password (twice, with replication considerations) to invalidate previously generated Golden Tickets.
- **M1026 - Privileged Account Management**: limit Domain Admin use to domain controllers/limited servers; delegate admin functions to separate accounts.

## 13. Testing & Validation
- Validate detection coverage for:
  - Anomalous Kerberos ticket lifetime/encryption type baselines
  - DC-side Kerberos patterns consistent with ticket forgery
  - Correlation between Kerberos anomalies and privileged access spread across multiple systems
- Tabletop / purple-team:
  - Exercise the KRBTGT reset playbook and monitoring plan (pre/post reset verification).
