# Indicator Removal on Host: Clear Network Connection History and Configuration (T1070.007)

## 1. Summary
Clear Network Connection History and Configuration describes adversaries **removing evidence of network connections and altering network configuration artifacts** to obscure malicious communications and lateral movement. This technique targets artifacts that record historical network activity and system network state.

Attackers use this technique to:
- Conceal command-and-control communications
- Obscure lateral movement paths
- Remove forensic traces of network access
- Reduce attribution of external or internal connections

---

## 2. Technical Overview
Operating systems maintain records of network connections, routing tables, DNS caches, and interface configurations. Adversaries impair these artifacts by:

- Clearing network connection histories
- Flushing DNS caches
- Removing or resetting routing and interface configurations
- Deleting network configuration files
- Resetting firewall or connection tracking state

Common environments include:
- Endpoints with persistent network history
- Servers hosting network services
- Cloud workloads maintaining network state

Indicators include:
- Sudden loss of network history artifacts
- Network configuration resets without change tickets
- DNS cache flushes coinciding with suspicious activity
- Network behavior without corresponding historical context

---

## 3. Subtechnique Considerations
Key considerations for T1070.007:
- Often follows **Command and Control (C2)** activity
- Frequently paired with **Proxy (T1090)** or **Remote Services (T1021)**
- Reduces fidelity of network-based investigations
- Requires elevated privileges for configuration changes

This technique primarily affects **network forensics** rather than endpoint execution visibility.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Clearing DNS caches to remove domain resolution evidence
- Resetting network interfaces after malicious communications
- Removing connection tracking artifacts
- Deleting network configuration files post-intrusion

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **network configuration and state changes**:
- Alert on unexpected network configuration resets
- Monitor DNS cache flush events
- Detect changes to routing tables or interfaces
- Correlate network artifact removal with suspicious processes

### Data Source Notes
- **Network logs**: Primary visibility into connection behavior
- **Firewall logs**: Detect resets and configuration changes
- **EDR telemetry**: Attribute network changes to processes

Common false positives:
- Network troubleshooting
- System reboots
- Legitimate configuration updates

Tuning guidance:
- Baseline expected network configuration changes
- Increase severity when artifact removal coincides with suspicious activity

---

## 6. Response Guidance
When suspected:
1. Capture current network configuration and state
2. Review recent network changes and responsible accounts
3. Correlate network activity with endpoint telemetry
4. Investigate for hidden C2 or lateral movement
5. Expand hunt for similar behavior across hosts

## 8. SOC Relevance
T1070.007 is particularly relevant when:
- Network activity is suspected but poorly evidenced
- Analysts observe unexplained gaps in connection history
- C2 communications appear intermittent or hidden

This technique often explains **missing network context** in investigations.

---

## 9. Threat Actor Usage
Commonly used by:
- Advanced persistent threats
- Ransomware operators
- Intruders emphasizing stealth and cleanup

---

## 10. Campaign Usage
Observed in:
- Long-dwell intrusions
- Espionage campaigns
- Operations requiring covert communications

---

## 11. Malware Usage
Associated with:
- Advanced backdoors
- Network-aware malware
- Post-exploitation frameworks

---

## 12. Mitigations
Recommended mitigations:
- Centralize and retain network logs
- Restrict network configuration privileges
- Monitor DNS cache and routing changes
- Correlate endpoint and network telemetry

---

## 13. Testing & Validation
Validation approaches:
- Clear DNS cache and network state in lab environments
- Validate alerts on network configuration resets
- Test SOC workflows for missing network artifacts
