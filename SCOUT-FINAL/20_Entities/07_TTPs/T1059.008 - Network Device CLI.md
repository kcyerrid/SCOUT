# Network Device CLI (T1059.008)

## 1. Summary
Network Device CLI describes adversary abuse of command-line interfaces on network infrastructure devices (such as routers, switches, firewalls, and load balancers) to execute commands, modify configurations, or perform reconnaissance. Because network device CLIs are designed for direct administrative control, successful abuse provides high-impact access with limited visibility in many environments.

This subtechnique is frequently associated with credential compromise and network-level persistence or disruption.

---

## 2. Technical Overview
Network devices expose command-line interfaces accessed via protocols such as:
- SSH
- Telnet
- Serial console access
- Vendor-specific management interfaces

Adversaries leverage valid credentials or exploit exposed management services to access the CLI and issue commands for configuration changes, traffic manipulation, or payload execution where supported. Artifacts include authentication logs, command histories, configuration changes, and network device syslogs.

---

## 3. Subtechnique Considerations
T1059.008 is specific to network infrastructure and differs significantly from endpoint-based interpreter abuse.

Key considerations include:
- Limited logging and telemetry on many network devices
- Vendor-specific command syntax and logging behavior
- Persistence via configuration changes rather than files
- High operational impact of configuration manipulation

Detection strategies must be tailored per vendor and device class.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Logging into routers or firewalls using stolen credentials
- Modifying access control lists or routing configurations
- Enabling remote management services
- Deploying malicious firmware or startup configurations

Analysts may observe configuration drift or unexpected administrative sessions.

---

## 5. Detection Guidance
Detection should focus on:
- CLI access from unusual source IP addresses
- Authentication outside approved administrative windows
- High-risk commands executed by non-standard accounts
- Unexpected configuration changes

Correlation between authentication logs and configuration changes improves detection fidelity.

### Data Source Notes
- **Authentication Logs:** Critical for identifying unauthorized access
- **Device Logs:** Often limited; require centralized collection
- **Configuration Logs:** High-value indicators of persistence or impact

---

## 6. Response Guidance
When malicious network device CLI activity is suspected:
- Immediately revoke or rotate affected credentials
- Review recent configuration changes and restore from known-good backups
- Isolate compromised management interfaces
- Conduct integrity checks on device firmware

Preserve device logs and configurations for forensic review.

## 8. SOC Relevance
Network device CLI abuse represents a high-risk but often under-monitored attack surface. SOCs frequently lack deep visibility into network infrastructure activity, making proactive logging and access control essential.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Advanced persistent threat groups
- State-sponsored actors targeting network infrastructure
- Adversaries conducting long-term reconnaissance or disruption

Confidence in targeted but high-impact usage is high.

---

## 10. Campaign Usage
Network device CLI abuse has appeared in:
- Nation-state espionage campaigns
- Supply chain and infrastructure targeting operations
- Long-dwell network compromises

## 12. Mitigations
Effective mitigations include:
- Enforcing strong authentication and MFA for device access
- Restricting management interface exposure
- Centralizing and monitoring device logs
- Implementing configuration change monitoring
- Applying least-privilege administrative access

---

## 13. Testing & Validation
Validation approaches include:
- Simulated unauthorized CLI access in lab environments
- Purple team exercises targeting network device management planes
- Review of alerting on configuration changes

Successful validation results in detection of unauthorized network device access.
