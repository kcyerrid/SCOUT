# T1574.001 – DLL Search Order Hijacking

## 1. Technique Overview
**DLL Search Order Hijacking (T1574.001)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries exploit the **Windows DLL search order** by placing a malicious DLL in a directory that is searched before the directory containing the legitimate dependency. When the vulnerable application loads the DLL by name without specifying a full path, Windows loads the attacker-controlled library instead.

This technique enables execution within the context of the legitimate application and is frequently used for persistence and privilege escalation.

## 2. Adversary Objectives
Adversaries use DLL search order hijacking to:
- Execute malicious code within trusted applications
- Establish stealthy persistence without explicit autorun artifacts
- Escalate privileges when targeting elevated or auto-started programs
- Evade detection by leveraging normal application behavior

## 3. Common Abuse Patterns
- Dropping malicious DLLs in application working directories
- Targeting binaries that load DLLs without absolute paths
- Hijacking dependencies of signed or trusted executables
- Exploiting writable directories in the DLL search path
- Combining with service or scheduled execution for reliability

## 4. Detection Considerations
Detection relies on **process and module load telemetry**, including:
- Monitoring DLL loads from non-standard or user-writable directories
- Detecting unsigned or unexpected DLLs loaded by trusted binaries
- Correlating application execution with anomalous library paths
- Baseline comparison of known-good DLL load behavior
- Reviewing application manifests and dependency resolution behavior

## 5. Defensive Mitigations
- Use absolute paths when loading DLLs in custom applications
- Enable Safe DLL Search Mode and modern DLL loading protections
- Restrict write permissions on application directories
- Enforce code signing for loaded libraries
- Monitor DLL load events with endpoint detection tooling

## 6. Operational Impact
If successful, T1574.001 can:
- Provide stealthy execution inside legitimate processes
- Enable persistence without modifying startup locations
- Facilitate privilege escalation via high-privilege executables
- Complicate detection due to legitimate execution context

## 7. Analyst Notes
DLL search order hijacking remains one of the most prevalent Windows execution hijacking techniques due to the large number of legacy and third-party applications that load DLLs insecurely. Analysts should focus on **why a DLL was resolved from a particular directory**, not just whether it is malicious.
