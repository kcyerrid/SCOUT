# T1546.005 – Trap

## 1. Technique Overview
**Trap (T1546.005)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse **shell `trap` commands** to register malicious code that executes automatically when a shell receives specific signals or events, such as shell exit, interrupts, or errors.

Because traps are a legitimate shell feature and can be embedded invisibly within scripts or configuration files, this technique enables stealthy, event-driven persistence in Unix-like environments.

## 2. Adversary Objectives
Adversaries use traps to:
- Execute malicious code in response to shell lifecycle events
- Maintain persistence without traditional startup artifacts
- Trigger payloads conditionally to reduce behavioral noise
- Evade detection by embedding logic in trusted shell scripts

## 3. Common Abuse Patterns
- Adding `trap` commands to shell initialization files
- Embedding traps in scripts executed during login or automation
- Triggering execution on signals such as `EXIT`, `ERR`, or `INT`
- Masquerading trap logic as legitimate cleanup or error-handling code
- Combining traps with other shell-based persistence mechanisms

## 4. Detection Considerations
Detection relies on **script content inspection and shell behavior analysis**, including:
- Monitoring shell configuration and script files for `trap` usage
- Alerting on unexpected or suspicious trap definitions
- Correlating shell exit or error events with anomalous process execution
- Reviewing scripts for hidden or obfuscated trap commands
- Auditing automation scripts that run with elevated privileges

## 5. Defensive Mitigations
- Monitor shell scripts and configuration files for unauthorized modifications
- Use file integrity monitoring on shell-related files
- Enforce least privilege for users and scripts
- Educate administrators on secure shell scripting practices
- Remove unauthorized trap definitions during incident response

## 6. Operational Impact
If successful, T1546.005 can:
- Provide low-noise, conditional execution
- Evade detection mechanisms focused on startup persistence
- Execute malicious code at shell termination or error conditions
- Complicate forensic timelines due to indirect execution triggers

## 7. Analyst Notes
Trap-based persistence is subtle and often overlooked because it leverages legitimate scripting constructs. Analysts should scrutinize **error-handling and cleanup sections** of shell scripts, especially those executed automatically or with elevated privileges, as these are common hiding places for malicious traps.
