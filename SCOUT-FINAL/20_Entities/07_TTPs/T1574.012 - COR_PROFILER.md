# T1574.012 – COR_PROFILER

## 1. Technique Overview
**COR_PROFILER (T1574.012)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries exploit the **.NET Common Language Runtime (CLR) profiling feature** by configuring environment variables that instruct the CLR to load a specified profiler DLL whenever a .NET application starts.

Because CLR profiling is a legitimate debugging and performance analysis capability, malicious profiler DLLs can execute **inside trusted .NET processes** with minimal visibility.

## 2. Adversary Objectives
Adversaries use COR_PROFILER abuse to:
- Execute malicious code within .NET applications
- Achieve persistence tied to .NET process execution
- Hijack application logic or inspect sensitive runtime data
- Evade detection by leveraging trusted runtime instrumentation

## 3. Common Abuse Patterns
- Setting environment variables such as:
  - `COR_ENABLE_PROFILING=1`
  - `COR_PROFILER={CLSID}`
  - `COR_PROFILER_PATH=<path_to_dll>`
- Registering malicious profiler DLLs via COM
- Targeting applications that frequently launch .NET runtimes
- Using profiler callbacks to inject or manipulate code
- Maintaining persistence through system-wide or user-level environment variables

## 4. Detection Considerations
Detection relies on **environment, registry, and module load monitoring**, including:
- Monitoring creation or modification of COR_PROFILER-related environment variables
- Detecting unexpected profiler DLL loads in .NET processes
- Auditing COM registrations for unauthorized profiler CLSIDs
- Correlating .NET process launches with anomalous DLL paths
- Reviewing startup scripts and registry locations that set environment variables

## 5. Defensive Mitigations
- Monitor and alert on COR_PROFILER and related environment variable usage
- Restrict permissions to set system-wide environment variables
- Enforce code signing and allowlisting for profiler DLLs
- Disable CLR profiling in production environments where not required
- Remove unauthorized profiler configurations during incident response

## 6. Operational Impact
If successful, T1574.012 can:
- Provide stealthy execution inside trusted .NET applications
- Enable persistent access without traditional autorun artifacts
- Facilitate credential access or application manipulation
- Complicate detection due to legitimate profiling behavior

## 7. Analyst Notes
COR_PROFILER abuse is particularly effective in **.NET-heavy enterprise environments**, including those using IIS, management tools, or custom business applications. Analysts should treat any **unexpected profiler configuration as high-risk**, especially when present on production systems where profiling is not normally enabled.
