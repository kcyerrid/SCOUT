# JavaScript (T1059.007)

## 1. Summary
JavaScript describes adversary abuse of JavaScript engines to execute malicious code across multiple environments. JavaScript is commonly abused through Windows Script Host, browsers, Node.js runtimes, and embedded application contexts. Its ubiquity and flexibility make it a favored execution mechanism for phishing, initial access, and post-exploitation activity.

Because JavaScript execution is widespread and often expected, malicious usage can blend into legitimate activity without detailed behavioral analysis.

---

## 2. Technical Overview
JavaScript can be executed in multiple contexts:
- Windows Script Host (`wscript.exe`, `cscript.exe`)
- Web browsers
- Node.js runtime
- Embedded application frameworks (Electron, installers)

Adversaries use JavaScript to download payloads, execute system commands, perform reconnaissance, and stage additional malware. Artifacts include script execution events, process creation, command-line arguments, and network connections initiated by JavaScript runtimes.

---

## 3. Subtechnique Considerations
T1059.007 spans multiple execution contexts, increasing detection complexity.

Key considerations include:
- Browser-based vs. standalone execution
- Use of Node.js in server and cloud environments
- Obfuscated or packed JavaScript code
- Abuse of trusted application frameworks

Detection strategies must be tailored to the execution environment.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing malicious `.js` files delivered via phishing
- Using JavaScript to download and execute secondary payloads
- Leveraging Node.js for post-exploitation automation
- Embedding JavaScript within installers or application bundles

Analysts may observe JavaScript engines spawning shell interpreters or network tools.

---

## 5. Detection Guidance
Detection should focus on:
- Execution of JavaScript runtimes from unexpected parent processes
- Script execution originating from user-writable directories
- JavaScript processes initiating suspicious network activity
- Obfuscated or packed script content

Correlation between process execution and network telemetry improves detection fidelity.

### Data Source Notes
- **Process Execution:** Primary indicator of JavaScript execution
- **Script Logs:** Useful when available, especially in Node.js
- **Network Traffic:** Critical for identifying payload retrieval

---

## 6. Response Guidance
When malicious JavaScript activity is suspected:
- Capture and preserve script content
- Identify downloaded payloads or follow-on stages
- Isolate affected systems or workloads if compromise is confirmed
- Review delivery vectors such as email or web downloads

Preserve runtime logs and network telemetry for investigation.

## 12. Mitigations
Effective mitigations include:
- Restricting execution of `.js` files where feasible
- Monitoring JavaScript runtime usage
- Applying least-privilege principles
- Hardening email and web delivery controls
- Blocking execution from user-writable directories

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for JavaScript execution
- Purple team simulations using malicious script files
- Review of alerts tied to JavaScript runtime activity

Successful validation results in detection of unauthorized JavaScript execution.
