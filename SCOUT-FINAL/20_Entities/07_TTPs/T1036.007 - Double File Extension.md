# Masquerading: Double File Extension (T1036.007)

## 1. Summary
Double File Extension describes adversaries **naming files with multiple extensions** so that a malicious executable appears to be a benign document or image. This technique exploits user expectations and default operating system behaviors that hide known file extensions.

Attackers use this technique to:
- Deceive users into executing malware
- Bypass superficial attachment filtering
- Evade casual inspection during triage
- Increase success rates of phishing campaigns

---

## 2. Technical Overview
Many operating systems and email clients display only the last extension or hide known executable extensions. Adversaries abuse this behavior by:

- Appending benign extensions before executable ones
- Crafting filenames that appear legitimate at a glance
- Relying on UI truncation or extension hiding
- Pairing misleading names with familiar icons

Key characteristics:
- Filename contains more than one extension
- Displayed filename does not clearly indicate executability
- Execution occurs after user interaction
- Commonly delivered via email or downloads

Indicators include:
- Attachments or downloads with multiple extensions
- Executable MIME types masquerading as documents
- User-initiated execution following delivery
- Filenames inconsistent with content type

---

## 3. Subtechnique Considerations
Key considerations for T1036.007:
- Highly effective in phishing and social engineering
- Commonly paired with **User Execution (T1204)**
- Overlaps with **Right-to-Left Override (T1036.002)** and **Space After Filename (T1036.006)**
- Relies on default OS settings that hide extensions

This technique primarily targets **human perception and UI behavior**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Sending email attachments with misleading double extensions
- Hosting disguised executables on malicious websites
- Using document-like names to lower suspicion
- Combining double extensions with spoofed sender identities

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **file metadata and execution context**:
- Detect files with multiple extensions
- Compare MIME type to filename extension
- Alert on execution of files with misleading names
- Correlate with delivery vectors such as email or web downloads

### Data Source Notes
- **Email gateway logs**: Detect suspicious attachments
- **File system telemetry**: Identify extension anomalies
- **EDR telemetry**: Capture execution events

Common false positives:
- Archive files (e.g., `.tar.gz`)
- Legitimate multi-extension formats

Tuning guidance:
- Exclude known archive formats
- Elevate severity for executable MIME types
- Focus on files delivered externally

---

## 6. Response Guidance
When suspected:
1. Quarantine the suspicious file
2. Validate actual file type and MIME information
3. Identify affected users and delivery vector
4. Remove malicious files and block similar attachments
5. Expand hunt for similarly named files

## 12. Mitigations
Recommended mitigations:
- Display full file extensions to users
- Block executable attachments by default
- Enhance attachment content inspection
- Educate users on file extension risks
