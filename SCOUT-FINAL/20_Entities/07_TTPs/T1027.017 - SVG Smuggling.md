# Obfuscated Files or Information: SVG Smuggling (T1027.017)

## 1. Summary
SVG Smuggling describes adversaries **embedding malicious payloads or scripts within SVG (Scalable Vector Graphics) files**, leveraging the SVG format’s support for scripting, encoding, and complex data structures. SVG files are often treated as benign images, allowing adversaries to bypass security controls and deliver malicious content covertly.

Adversaries use this technique to:
- Evade content filtering and file-type restrictions
- Deliver payloads via email or web channels
- Abuse trusted image-handling workflows
- Execute malicious logic in browser contexts

---

## 2. Technical Overview
SVG is an XML-based vector image format that supports:
- Embedded scripts (e.g., JavaScript)
- Base64-encoded data
- External resource references
- Complex document object models

Adversaries abuse SVG files by:
- Embedding encoded payloads within SVG elements
- Using inline or external JavaScript for decoding
- Triggering file downloads or execution via browser rendering
- Masquerading SVG files as simple images

Indicators include:
- SVG files containing script tags or encoded blobs
- Browser processes creating files after rendering SVGs
- SVG attachments delivered via phishing
- Unusual SVG file sizes or structures

---

## 3. Subtechnique Considerations
Key considerations for T1027.017:
- Closely related to **HTML Smuggling (T1027.006)**
- Often paired with **Phishing (T1566)**
- Relies on browser trust and user interaction
- Effectiveness varies by browser and security settings

SVG smuggling exploits **assumptions about image safety**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Sending SVG attachments that reconstruct payloads
- Hosting malicious SVG files on compromised websites
- Embedding encoded scripts within SVG XML
- Triggering downloads during SVG rendering

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **file content inspection and browser behavior**:
- Inspect SVG files for scripts or encoded data
- Monitor browsers generating files after rendering SVGs
- Detect email delivery of SVG attachments
- Correlate SVG access with suspicious follow-on execution

### Data Source Notes
- **Email gateway logs**: Identify SVG-based delivery
- **Browser telemetry**: Detect script execution from SVGs
- **EDR telemetry**: Observe file creation and execution chains

Common false positives:
- Legitimate SVGs with embedded scripts
- Web applications using dynamic SVG graphics

Tuning guidance:
- Baseline legitimate SVG usage
- Elevate alerts when SVG rendering leads to execution

---

## 6. Response Guidance
When suspected:
1. Quarantine the SVG file
2. Analyze SVG XML structure and embedded content
3. Identify any decoded or downloaded payloads
4. Hunt for similar SVG artifacts across the environment
5. Block delivery channels and update content filters

## 8. SOC Relevance
T1027.017 is critical because:
- Image formats are often implicitly trusted
- Payload delivery may bypass traditional controls
- Browser telemetry is required for visibility

SOC teams must scrutinize **non-traditional delivery formats**.

---

## 9. Threat Actor Usage
Commonly used by:
- Initial access brokers
- Malware delivery operations
- Ransomware affiliates

---

## 10. Campaign Usage
Observed in:
- Phishing campaigns using image attachments
- Loader-based malware delivery
- Web-based initial access operations

---

## 11. Malware Usage
Associated with:
- Loaders and droppers
- Script-based malware
- Browser-delivered payloads

---

## 12. Mitigations
Recommended mitigations:
- Restrict or block SVG attachments
- Sanitize SVG files at gateways
- Disable scripting in SVG rendering where possible
- Educate users about image-based threats

---

## 13. Testing & Validation
Validation approaches:
- Deliver benign SVG smuggling samples in lab
- Validate alerts on SVG rendering behaviors
- Test SOC playbooks for image-based delivery
- Ensure tooling inspects SVG content
