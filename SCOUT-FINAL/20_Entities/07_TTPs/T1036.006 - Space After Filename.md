# Masquerading: Space After Filename (T1036.006)

## 1. Summary
Space After Filename describes adversaries **adding trailing whitespace to filenames** to visually obscure the true file extension or executable nature of a file. This technique exploits inconsistencies in how operating systems and user interfaces render filenames, leading users and analysts to misinterpret file types.

Attackers use this technique to:
- Trick users into executing malicious files
- Bypass superficial filename inspection
- Evade simple extension-based filtering
- Increase success of social engineering

---

## 2. Technical Overview
Most filesystems permit filenames that include trailing spaces or whitespace characters, even though many graphical interfaces trim or hide these characters when rendering names.

Adversaries abuse this by:
- Appending spaces after the filename or extension
- Crafting filenames that appear benign in UI views
- Leveraging differences between filesystem storage and UI display
- Combining whitespace abuse with misleading extensions or icons

Key characteristics:
- Actual filename differs from displayed filename
- Executable extensions may be hidden or visually displaced
- Files may appear as documents or images in file explorers

Indicators include:
- Filenames with trailing whitespace characters
- Mismatch between displayed filename and actual filename
- Execution of files that appear non-executable
- Suspicious attachments with formatting anomalies

---

## 3. Subtechnique Considerations
Key considerations for T1036.006:
- Highly effective in phishing and user-execution scenarios
- Commonly paired with **User Execution (T1204)**
- Overlaps with **Right-to-Left Override (T1036.002)** and **Double File Extension (T1036.007)**
- Relies on UI and human perception weaknesses

This technique targets **human trust**, not system vulnerabilities.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering email attachments with trailing spaces in filenames
- Hosting disguised executables on download sites
- Combining whitespace with misleading icons or extensions
- Using filename formatting to bypass visual inspection

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **filename normalization and metadata inspection**:
- Detect filenames containing trailing whitespace
- Alert on mismatches between filename and MIME type
- Monitor execution of files with suspicious naming patterns
- Correlate filename anomalies with delivery vectors (email, web)

### Data Source Notes
- **File system telemetry**: Identify whitespace characters in filenames
- **Email security logs**: Detect suspicious attachments
- **EDR telemetry**: Capture execution of disguised binaries

Common false positives:
- Rare edge-case filenames
- Improperly formatted user files

Tuning guidance:
- Restrict alerts to executable MIME types
- Elevate severity when files originate from external sources

---

## 6. Response Guidance
When suspected:
1. Quarantine affected files immediately
2. Inspect filenames at the filesystem level
3. Identify delivery vector and affected users
4. Remove malicious files safely
5. Expand hunt for similarly named artifacts

T1036.006 is especially relevant in:

- Malware delivery via email or downloads

## 11. Malware Usage

## 12. Mitigations
Recommended mitigations:
- Display full filenames and extensions
- Block or flag files with trailing whitespace
- Enhance email attachment inspection
- Train users on filename-based deception

- Create benign files with trailing whitespace in lab environments
- Validate alerts on filename anomalies
- Test SOC workflows for phishing-driven delivery
