# Obfuscated Files or Information: Compression (T1027.015)

## 1. Summary
Compression describes adversaries **using compressed archives or compressed data formats to obscure malicious content**, complicating inspection and delaying detection until decompression occurs. While compression is inherently benign, adversaries abuse it to conceal payloads, stage multi-file deliveries, and bypass security controls.

Adversaries use this technique to:
- Hide malicious payloads from content inspection
- Bundle multiple components into a single artifact
- Evade email and web gateway scanning
- Control when malicious content becomes visible

---

## 2. Technical Overview
Adversaries leverage common compression formats such as:
- ZIP, RAR, 7z, TAR, GZIP
- Nested or multi-layer archives
- Password-protected or malformed archives

Typical behaviors:
- Delivery of compressed payloads via email or web
- Extraction of archives shortly before execution
- Use of nested archives to delay inspection
- Compression combined with encryption or encoding

Indicators include:
- Archive extraction followed by suspicious execution
- Nested archive chains
- Unusual compression usage in user contexts
- Archive contents that resolve to executables or scripts

---

## 3. Subtechnique Considerations
Key considerations for T1027.015:
- Often paired with **Encrypted or Encoded File (T1027.013)**
- Common in phishing delivery chains
- Compression alone is not malicious
- Context and follow-on behavior are critical

Compression targets **inspection timing**, not functionality.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Sending compressed malware attachments
- Hosting compressed payloads for download
- Using nested archives to evade scanning
- Extracting payloads dynamically during execution

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **archive handling and execution context**:
- Monitor archive extraction followed by execution
- Detect nested or unusual archive structures
- Correlate archive delivery with user execution
- Identify scripting or binary execution from extracted paths

### Data Source Notes
- **File monitoring**: Track archive creation and extraction
- **EDR telemetry**: Observe execution chains post-extraction
- **Email logs**: Identify archive-based delivery

Common false positives:
- Legitimate file sharing and software distribution
- Backup or packaging workflows

Tuning guidance:
- Baseline normal archive usage patterns
- Elevate alerts when extraction precedes malicious behavior

---

## 6. Response Guidance
When suspected:
1. Quarantine archive and extracted contents
2. Analyze archive structure and layers
3. Identify all extracted files and execution paths
4. Hunt for similar archive artifacts
5. Block delivery sources and educate users

## 8. SOC Relevance
T1027.015 is relevant because:
- Compression delays visibility of payloads
- Detection depends on observing extraction behavior
- User interaction often triggers exposure

SOC teams must monitor **archive handling and post-extraction activity**.

---

## 9. Threat Actor Usage
Commonly used by:
- Initial access brokers

- Ransomware affiliates

## 10. Campaign Usage
Observed in:
- Phishing-based malware delivery campaigns
- Loader distribution operations
- Mass malware propagation efforts

---

## 11. Malware Usage
Associated with:
- Loaders and droppers
- Ransomware payloads
- Script-based malware

---

## 12. Mitigations
Recommended mitigations:
- Scan and detonate archives in sandboxes
- Restrict execution from extracted locations
- Block suspicious archive attachments
- Educate users about archive-based threats

---

## 13. Testing & Validation
Validation approaches:
- Deliver benign compressed samples in lab
- Validate alerts on extraction-to-execution chains
- Test SOC workflows for archive abuse
- Ensure tooling captures archive metadata
