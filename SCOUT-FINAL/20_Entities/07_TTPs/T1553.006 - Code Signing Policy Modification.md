# Subvert Trust Controls: Code Signing Policy Modification (T1553.006)

## 1. Summary
Code Signing Policy Modification describes adversaries **altering or weakening operating system policies that govern how code-signing is enforced**, allowing unsigned or improperly signed code to execute without restriction. Rather than forging trust artifacts, this technique undermines the *rules* that determine whether signatures are required or validated.

Adversaries use this technique to:
- Disable or relax code-signing enforcement
- Allow execution of unsigned or malicious binaries
- Bypass application control mechanisms
- Enable follow-on malware execution with reduced friction

---

## 2. Technical Overview
Modern Windows environments enforce code-signing through:
- Software Restriction Policies (SRP)
- Windows Defender Application Control (WDAC)
- AppLocker rules
- Group Policy–based trust settings

Adversaries modify these controls by:
- Editing registry keys controlling signature enforcement
- Altering local or domain Group Policy Objects (GPOs)
- Weakening WDAC or AppLocker configurations
- Disabling enforcement or switching policies to audit-only mode

Indicators include:
- Changes to code-signing or application control policies
- Sudden execution of unsigned binaries in restricted environments
- Policy modifications outside maintenance windows
- Policy drift following privilege escalation events

---

## 3. Subtechnique Considerations
Key considerations for T1553.006:
- Requires administrative or domain-level privileges
- Impact is broad and systemic
- Often paired with signed or masqueraded malware
- Changes may persist across reboots and updates

Policy modification attacks **turn enforcement into optional guidance**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Modifying WDAC policies to permit unsigned executables
- Switching application control policies to audit mode
- Editing registry-based signature enforcement settings
- Altering GPOs to weaken trust requirements

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **policy integrity and execution anomalies**:
- Monitor changes to application control and code-signing policies
- Alert on registry modifications tied to trust enforcement
- Detect unsigned execution in previously restricted environments
- Correlate policy changes with suspicious execution chains

### Data Source Notes
- **Group Policy logs**: Detect unauthorized policy changes
- **Registry monitoring**: Identify trust enforcement modifications
- **EDR telemetry**: Observe execution post-policy change

Common false positives:
- Legitimate policy tuning or rollout
- Approved application control updates

Tuning guidance:
- Baseline policy states and require approval metadata
- Elevate alerts when policy changes precede malicious activity

---

## 6. Response Guidance
When suspected:
1. Identify altered code-signing or application control policies
2. Restore known-good policy configurations
3. Review execution activity during policy gap
4. Remove unauthorized binaries introduced post-change
5. Assess for additional trust-control subversion

## 8. SOC Relevance
T1553.006 is critical because:
- It undermines preventative security controls
- Malicious execution may appear policy-compliant
- Detection gaps persist until policy review occurs

SOC teams must treat **policy changes as potential attack activity**, not administrative noise.

---

## 11. Malware Usage

## 12. Mitigations
Recommended mitigations:
- Restrict who can modify code-signing policies
- Monitor and alert on policy changes
- Enforce change-control validation
- Regularly audit application control effectiveness

---

## 13. Testing & Validation
Validation approaches:
- Simulate unauthorized policy modification in lab
- Validate alerts on enforcement changes
- Test execution blocking post-restoration
- Exercise SOC playbooks for policy tampering

Include:
- Preconditions: policy auditing enabled
- Required roles/tools: SOC, endpoint engineering, GRC
- Expected outcomes: detection of policy tampering
- Success criteria: rapid alerting and rollback
