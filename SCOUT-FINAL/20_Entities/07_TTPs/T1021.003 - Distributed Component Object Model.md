# T1021.003 - Distributed Component Object Model

## 1. Summary
Adversaries may abuse DCOM to execute or activate COM objects on remote Windows systems for lateral movement, often leveraging RPC-based communication and built-in Windows functionality.

## 2. Technical Overview
Typical patterns:
- Remote activation/instantiation of COM objects (often via built-in utilities or frameworks).
- Use of RPC endpoints and Windows components that can be difficult to distinguish from legitimate enterprise management traffic without context.

High-signal indicators:
- DCOM/RPC activity between endpoints that do not normally communicate.
- Remote object activation aligned with suspicious authentication events and follow-on execution on the destination.
- DCOM activity from user workstations toward servers/DCs outside normal admin tooling paths.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- DCOM can be noisy in Windows networks due to legitimate management and application behavior—detections typically require correlation (auth + RPC/DCOM + endpoint execution).

## 5. Detection Guidance
Detection should emphasize **sequence and context**:
- Correlate remote authentication events with subsequent RPC/DCOM activity to the same destination.
- Look for remote activation followed by suspicious process creation on the destination host.
- Baseline expected DCOM/RPC relationships (management servers, SCCM, monitoring tools) and alert on outliers.

Practical approaches:
- Detect unusual RPC endpoint mapper usage followed by remote object activation patterns.
- Alert on DCOM activity originating from non-admin endpoints to privileged-tier assets.

### 5.1. Data Source Notes
Useful telemetry typically includes:
- Windows authentication logs on the destination (success/failure) aligned to the timeframe.
- Network telemetry for RPC/DCOM (e.g., TCP/135 plus dynamic RPC ports), including source/destination pairs.
- Endpoint telemetry on destination: process creation and COM-related suspicious parentage where available.

## 6. Response Guidance
- Contain: isolate destination host if suspicious post-auth activity is confirmed.
- Validate: identify the initiating process/user on the source host; confirm whether sanctioned management tooling was in use.
- Scope: hunt for similar RPC/DCOM patterns from the same source or account across additional hosts.
- Harden: restrict RPC/DCOM exposure between segments where feasible; ensure strong admin credential controls.

Key pivots:
- Identify whether the source host is an approved management system.
- Compare against baseline DCOM/RPC communication graphs.
- Correlate with authentication anomalies and suspicious destination-side process trees.
- Confirm whether lateral movement continued from the destination after the DCOM activity.

## 12. Mitigations
ATT&CK-listed mitigations for T1021.003 include:
- M1035 Limit Access to Resource Over Network: block or limit DCOM communications between network segments.
- M1026 Privileged Account Management: remove users from local Administrators group on systems where they do not need it.

## 13. Testing & Validation
- Validate that RPC/DCOM traffic is visible in network telemetry (including dynamic RPC port ranges).
- Build allowlists for known management servers and software that legitimately use DCOM/RPC.
- Run controlled lab tests to confirm correlation between remote auth, RPC/DCOM activity, and destination process execution.
