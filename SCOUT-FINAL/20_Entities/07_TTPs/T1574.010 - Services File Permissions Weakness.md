# T1574.010 – Services File Permissions Weakness

## 1. Technique Overview
**Services File Permissions Weakness (T1574.010)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries abuse **improper file or directory permissions** associated with Windows service executables or supporting files. If a service runs with elevated privileges (e.g., SYSTEM) and its executable or dependent files are writable by a low-privilege user, attackers can replace or modify those files to gain execution in a higher-privilege context when the service starts or restarts.

This technique relies on misconfiguration rather than exploitation of a software vulnerability.

## 2. Adversary Objectives
Adversaries use this technique to:
- Escalate privileges to SYSTEM or service accounts
- Establish persistence through auto-start services
- Execute malicious code under a trusted service context
- Avoid detection by leveraging legitimate service execution

## 3. Common Abuse Patterns
- Identifying services whose executable paths point to user-writable locations
- Replacing service binaries with malicious executables
- Modifying DLLs or configuration files loaded by the service
- Triggering execution via service restart or system reboot
- Targeting third-party services with weak default permissions

## 4. Detection Considerations
Detection relies on **file integrity, permission auditing, and service telemetry**, including:
- Auditing service executable and directory permissions
- Monitoring changes to service binaries and related files
- Detecting service restarts followed by anomalous behavior
- Correlating privilege escalation events with service execution
- Baseline comparison of known-good service file hashes

## 5. Defensive Mitigations
- Enforce least-privilege permissions on service executables and directories
- Ensure only administrators can modify service-related files
- Monitor and alert on unauthorized changes to service binaries
- Regularly audit installed services, especially third-party software
- Remove or reconfigure services with insecure file permissions

## 6. Operational Impact
If successful, T1574.010 can:
- Provide reliable privilege escalation
- Enable persistent execution via auto-start services
- Bypass exploit-based detection controls
- Complicate response due to legitimate service execution context

## 7. Analyst Notes
Services file permission weaknesses are common in environments with unmanaged third-party software. Analysts should prioritize identifying **services that both auto-start and run with high privileges while pointing to writable paths**, as these represent deterministic escalation and persistence opportunities.
