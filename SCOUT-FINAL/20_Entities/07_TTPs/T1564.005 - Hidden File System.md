# Hide Artifacts: Hidden File System (T1564.005)

## 1. Summary
Hidden File System describes adversaries **storing malicious artifacts within file systems, partitions, or mount points that are not normally visible or mounted during standard operating system operation**. By leveraging hidden, alternate, or unmounted file systems, attackers significantly reduce the likelihood of discovery during routine inspection.

This technique is commonly used to:
- Conceal payloads and tooling
- Store stolen data or staging artifacts
- Maintain long-term stealth during extended intrusions
- Evade file-based detection and forensic workflows

---

## 2. Technical Overview
Operating systems support multiple mechanisms that can result in file systems being hidden or non-enumerated. Adversaries may abuse:

- **Windows**
  - Alternate or unmounted volumes
  - Raw disk access
  - Volume shadow or hidden partition abuse

- **Linux**
  - Unmounted block devices
  - Custom mount namespaces
  - Overlay or loopback file systems

- **macOS**
  - Hidden APFS volumes
  - Unmounted disk images
  - Non-standard mount points

Artifacts and indicators may include:
- Disk activity not correlated with visible files
- Execution or access originating from unusual mount points
- Processes interacting with raw block devices
- Discrepancies between disk usage and enumerated files

---

## 3. Subtechnique Considerations
Key considerations for T1564.005:
- High stealth, but requires elevated privileges in many cases
- Often paired with encryption or obfuscation (T1027)
- Difficult to detect without kernel-level or disk telemetry
- Discovery often occurs late in investigations or during full forensic imaging

Hidden file systems are typically used by more advanced operators.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Mounting a hidden or loopback file system to store payloads
- Writing stolen data to an unmounted partition
- Executing binaries from non-enumerated mount points
- Using raw disk writes to bypass file-based monitoring

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection requires **low-level visibility and reconciliation**:
- Monitor disk I/O against visible filesystem activity
- Detect mount/unmount operations outside expected workflows
- Alert on processes accessing raw block devices
- Identify execution paths originating from uncommon mount locations

### Data Source Notes
- **Kernel / OS telemetry**: Required for mount and block-device visibility
- **EDR with disk monitoring**: Useful for correlating access with processes
- **File integrity monitoring**: Helps identify discrepancies between disk usage and file enumeration

False positives may include:
- Backup software
- Virtualization tooling
- Container runtime operations

---

## 6. Response Guidance
When suspected:
1. Capture disk and mount state from the affected system
2. Enumerate all block devices and mounted volumes
3. Perform offline forensic analysis if necessary
4. Identify artifacts stored in hidden file systems
5. Remove malicious data and remediate compromised privileges

## 8. SOC Relevance
T1564.005 is most relevant in:
- High-value, long-dwell intrusions
- Espionage and data-theft investigations
- Environments with limited disk-level monitoring

Hidden file systems often explain why expected artifacts are missing.

---

## 9. Threat Actor Usage
This subtechnique has been observed among:
- Advanced persistent threats
- Espionage-focused intrusion sets
- Highly skilled operators with deep OS knowledge

Usage typically signals a higher level of sophistication.

---

## 10. Campaign Usage
Observed in:
- Long-term espionage campaigns
- Stealthy data staging operations
- Intrusions seeking to evade forensic discovery

---

## 11. Malware Usage
Associated with:
- Advanced backdoors
- Custom espionage implants
- Toolkits designed for long-term covert storage

---

## 12. Mitigations
Recommended mitigations:
- Monitor mount and unmount activity
- Restrict raw disk access to trusted processes
- Enable kernel-level telemetry where feasible
- Perform periodic full-disk audits on high-risk systems
- Harden privilege controls around disk and filesystem operations

---

## 13. Testing & Validation
Validation approaches:
- Create hidden or unmounted file systems in lab environments
- Validate detection of mount and raw disk access events
- Test SOC workflows for disk-level investigations
- Review visibility gaps in EDR and OS telemetry
