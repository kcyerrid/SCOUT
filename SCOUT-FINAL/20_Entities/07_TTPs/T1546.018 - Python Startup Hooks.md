# T1546.018 – Python Startup Hooks

## 1. Technique Overview
**Python Startup Hooks (T1546.018)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries establish persistence and/or enable privilege escalation by abusing **Python’s startup and initialization behaviors** so that attacker-controlled code executes automatically when a Python interpreter launches. :contentReference[oaicite:0]{index=0}

This technique is particularly relevant in environments where Python is widely used for automation, administration, data workflows, DevOps tasks, or application runtime components.

## 2. Adversary Objectives
Adversaries use Python startup hooks to:
- Achieve persistence tied to Python execution (interactive or scripted)
- Trigger execution in trusted automation pipelines and admin workflows
- Reduce noise by executing only when Python runs
- Maintain access across reboots without classic autorun artifacts

## 3. Common Abuse Patterns
- Creating/modifying Python customization files so code runs on interpreter startup (e.g., **`sitecustomize.py`** / **`usercustomize.py`**) :contentReference[oaicite:1]{index=1}
- Using **`.pth`** files to influence import behavior or execute startup logic (common in site-packages paths) :contentReference[oaicite:2]{index=2}
- Targeting Python locations used by system services, cron jobs, CI/CD runners, or management tooling
- Masquerading malicious startup logic as legitimate library initialization
- Leveraging elevated execution contexts when Python runs under privileged automation (e.g., root/admin-run jobs)

## 4. Detection Considerations
Detection depends on **file integrity + interpreter-context telemetry**, including:
- Monitoring creation/modification of `sitecustomize.py`, `usercustomize.py`, and suspicious `.pth` files in Python environment paths :contentReference[oaicite:3]{index=3}
- Correlating Python process starts with unexpected module imports, file writes, or network connections early in execution
- Baseline comparison of Python environment contents (virtualenvs, site-packages) against known-good states
- Alerting on Python startup artifacts written by unusual processes (e.g., non-admin apps writing into global site-packages)

## 5. Defensive Mitigations
- Restrict write access to Python installation directories and global site-packages
- Prefer isolated, least-privilege Python environments (virtual environments/containers) for automation
- Continuously monitor Python environment paths for unauthorized changes (FIM + EDR)
- Enforce trusted software supply chain controls for Python packages and environment provisioning (signed artifacts where available)

## 6. Operational Impact
If successful, T1546.018 can:
- Provide durable persistence that survives reboots and user logons (so long as Python is invoked)
- Blend into legitimate Python-driven automation and development workflows
- Enable execution under privileged contexts when Python is used by elevated tasks
- Complicate incident response due to distributed Python environments across hosts and projects

## 7. Analyst Notes
This technique is operationally important because Python is frequently embedded into business processes (ETL jobs, CI/CD, config management, security automation). A single compromised Python startup hook can create a **“persistence multiplier”**: it executes across many scripts and operators without requiring additional triggers. MITRE’s v18 addition of this sub-technique reflects the growing prevalence of adversaries targeting developer and automation ecosystems. :contentReference[oaicite:4]{index=4}
