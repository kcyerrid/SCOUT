# Hide Artifacts: File/Path Exclusions (T1564.012)

## 1. Summary
File/Path Exclusions describes adversaries **configuring security tools, operating systems, or applications to exclude specific files, directories, or paths from scanning, logging, or enforcement**. By doing so, attackers can hide malicious artifacts and ensure continued execution without interference from defensive controls.

This technique is commonly used to:
- Evade endpoint security detection
- Ensure malware persistence and reliability
- Conceal payloads in excluded directories
- Reduce visibility during post-exploitation activity

---

## 2. Technical Overview
Many security controls allow administrators to define exclusions for performance or compatibility reasons. Adversaries abuse these features by:

- Adding malware directories to antivirus or EDR exclusion lists
- Configuring file or path exclusions in endpoint protection policies
- Modifying registry or configuration settings controlling exclusions
- Leveraging administrative or compromised credentials to apply exclusions

Platform considerations:
- **Windows**: Defender exclusions via registry, PowerShell, or WMI
- **Linux**: Security agent configuration file modifications
- **macOS**: Endpoint protection and system extension exclusions

Typical artifacts and indicators include:
- New or modified exclusion rules
- Security settings changes outside normal workflows
- Malware execution from excluded paths
- Reduced or missing telemetry for excluded locations

---

## 3. Subtechnique Considerations
Key considerations for T1564.012:
- Strongly overlaps with **Impair Defenses (T1562)** but focuses on concealment
- Often follows privilege escalation or valid account compromise
- Highly effective against default security configurations
- Indicates intentional evasion of endpoint protection

Detection depends on **configuration change monitoring**, not file scanning alone.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Adding ransomware directories to antivirus exclusion lists
- Configuring EDR to ignore attacker-controlled paths
- Deploying malware specifically into excluded directories
- Modifying security policies to suppress scanning

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **security configuration changes**:
- Monitor creation or modification of exclusion rules
- Alert on exclusions applied outside approved workflows
- Correlate exclusions with suspicious process or file activity
- Detect execution originating from newly excluded paths

### Data Source Notes
- **Security configuration logs**: Primary detection source
- **EDR telemetry**: Identify execution within excluded paths
- **Registry and policy monitoring**: Required on Windows systems

Common false positives:
- Legitimate performance tuning by administrators
- Vendor-required exclusions for specific applications

Tuning guidance:
- Baseline approved exclusions
- Require justification and change tracking for new exclusions

---

## 6. Response Guidance
When suspected:
1. Enumerate all exclusion rules across security tools
2. Remove unauthorized exclusions
3. Re-scan affected paths and systems
4. Investigate malware placed in excluded locations
5. Reset credentials used to apply exclusions

## 8. SOC Relevance
T1564.012 is highly relevant when:
- Malware executes without security alerts
- Telemetry gaps appear in specific directories
- Endpoint protection appears partially disabled

File/path exclusions often explain “why nothing fired.”

---

## 9. Threat Actor Usage
This technique is commonly used by:
- Ransomware operators
- Post-exploitation frameworks
- Advanced attackers targeting enterprise endpoints

Its use often precedes lateral movement or data exfiltration.

---

## 10. Campaign Usage
Observed in:
- Ransomware deployment phases
- Long-dwell intrusions
- Attacks prioritizing reliability over speed

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Loaders and droppers
- Malware designed to persist on protected endpoints

---

## 12. Mitigations
Recommended mitigations:
- Restrict who can create security exclusions
- Require approval workflows for exclusion changes
- Monitor and audit exclusion configurations regularly
- Deploy tamper protection for security tools
- Alert on execution from excluded paths

---

## 13. Testing & Validation
Validation approaches:
- Create test exclusions in lab environments
- Verify alerts on unauthorized exclusion changes
- Test execution detection within excluded paths
- Validate SOC playbooks for exclusion abuse

- Treat unauthorized exclusions as high-severity events.
