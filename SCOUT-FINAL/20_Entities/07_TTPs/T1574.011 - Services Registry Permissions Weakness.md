# T1574.011 – Services Registry Permissions Weakness

## 1. Technique Overview
**Services Registry Permissions Weakness (T1574.011)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries abuse **improper registry access controls** on Windows service configuration keys to alter how services execute. By modifying values such as the service binary path or startup parameters, attackers can redirect execution to malicious payloads that run with the service’s privilege level.

This technique relies on misconfiguration rather than exploitation of a software vulnerability.

## 2. Adversary Objectives
Adversaries use this technique to:
- Escalate privileges to SYSTEM or service accounts
- Establish persistence via auto-start services
- Execute malicious code under a trusted service context
- Avoid detection by leveraging legitimate service infrastructure

## 3. Common Abuse Patterns
- Modifying service registry keys under:
  - `HKLM\SYSTEM\CurrentControlSet\Services\`
- Changing `ImagePath` values to point to malicious executables
- Adjusting service parameters or dependencies to influence execution
- Targeting third-party services with weak default permissions
- Triggering execution via service restart or system reboot

## 4. Detection Considerations
Detection relies on **registry integrity and service telemetry**, including:
- Auditing permissions on service registry keys
- Monitoring changes to service configuration values
- Correlating service configuration changes with privilege escalation
- Detecting service restarts followed by anomalous behavior
- Baseline comparison of known-good service registry settings

## 5. Defensive Mitigations
- Enforce strict permissions on service registry keys
- Monitor and alert on unauthorized service registry modifications
- Restrict administrative rights required to modify services
- Regularly audit installed services for insecure configurations
- Restore legitimate service configurations during incident response

## 6. Operational Impact
If successful, T1574.011 can:
- Provide reliable privilege escalation
- Enable persistent execution via auto-start services
- Bypass exploit-based detection controls
- Complicate response due to legitimate service execution context

## 7. Analyst Notes
Registry permission weaknesses are frequently overlooked during service hardening. Analysts should prioritize services that both **auto-start and run with high privileges**, especially when their registry keys are writable by non-administrative users.
