# T1021.002 - SMB/Windows Admin Shares

## 1. Summary
Adversaries use SMB and built-in Windows administrative shares (e.g., ADMIN$, C$) to access remote systems, stage tools, and move laterally—often as part of “copy then execute” workflows.

## 2. Technical Overview
Common attacker behaviors:
- Authenticate to remote SMB shares using valid credentials.
- Write tools or payloads to ADMIN$/C$ paths (often Windows directories) on remote hosts.
- Follow-on remote execution via other techniques (service creation, scheduled tasks, WMI/WinRM), or interactive operator activity.

High-signal indicators:
- Access to ADMIN$/C$ from unusual sources or by unusual accounts.
- Rapid sequence: SMB admin share access → remote execution artifact on the same target.
- Fan-out patterns: same source/account accessing many hosts’ admin shares in a short time.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- SMB admin share telemetry is often noisy in enterprise environments (patching, software deployment). Strong detection relies on correlation with follow-on execution or anomalous access patterns.

## 4. Procedure Examples
ATT&CK documents SMB/admin share usage including:
- [[30_CIPHER/03_Threat_Actors/G0102 - Wizard Spider|Wizard Spider]] using SMB to drop tooling on high-value systems.
- [[30_CIPHER/03_Threat_Actors/G0010 - Turla|Turla]] using SMB connections (e.g., `net use`) in lateral activity.
- [[30_CIPHER/03_Threat_Actors/G1022 - ToddyCat|ToddyCat]] using mounted network shares for lateral movement.
- [[30_CIPHER/05_Malware/S0140 - Shamoon|Shamoon]] spreading via SMB.
- [[30_CIPHER/05_Malware/S0603 - Stuxnet|Stuxnet]] leveraging share-based propagation paths.

## 5. Detection Guidance
Best practice: detect SMB admin share usage as a **multi-event pattern**, not a single event.

Detection ideas:
- Alert on ADMIN$/C$ access where:
  - The account is not part of a known admin/software deployment group.
  - The source host is a workstation (not a sanctioned deployment/jump host).
  - The destination is privileged-tier (servers, DCs).
- Correlate SMB admin share access with:
  - Remote service creation / scheduled task creation on the same host shortly after.
  - New executable/script writes into Windows directories followed by execution.
  - Authentication anomalies (new device, unusual subnet, spikes in failures then success).

### 5.1. Data Source Notes
Useful telemetry typically includes:
- Windows share/object access auditing (where enabled) for ADMIN$/C$ and sensitive paths.
- Authentication logs on destination (SMB logons).
- Network telemetry for SMB (TCP/445) including source/destination pairs and volume.
- Endpoint telemetry: file create/write events and subsequent process starts on the destination.

## 6. Response Guidance
- Contain: isolate impacted hosts; if active lateral movement is ongoing, consider temporarily restricting SMB between segments.
- Credential actions: rotate/disable suspected admin credentials; ensure local admin password uniqueness.
- Scope: identify additional hosts accessed via ADMIN$/C$ from the same source/account; hunt for staged binaries/scripts.
- Eradicate: remove staged tools, validate persistence, and ensure software deployment tooling wasn’t abused.

## 8. SOC Relevance
Key triage questions:
- Was the SMB access to ADMIN$/C$ expected for that source and account?
- Did it precede remote execution or suspicious process creation on the destination?
- Did the same account/source touch many hosts (spray/fan-out)?
- Was the destination a privileged-tier system or file server with sensitive data?

## 12. Mitigations
ATT&CK-listed mitigations for T1021.002 include:
- M1037 Filter Network Traffic: restrict SMB/file sharing communications via host firewalls and network controls.
- M1035 Limit Access to Resource Over Network: consider disabling Windows administrative shares where feasible.
- M1027 Password Policies: avoid local admin password reuse; enforce strong/unique passwords.
- M1026 Privileged Account Management: deny remote use of local admin creds where possible; avoid broad local admin membership.

## 13. Testing & Validation
- Confirm ADMIN$/C$ access auditing and SMB authentication logs are available on representative hosts.
- Simulate authorized admin share access from approved deployment systems and ensure allowlisted patterns don’t alert.
- Simulate unauthorized share access in a lab and verify correlation rules (share access → follow-on execution).
