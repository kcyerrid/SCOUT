# Obfuscated Files or Information: Compile After Delivery (T1027.004)

## 1. Summary
Compile After Delivery describes adversaries **delivering source code or partially complete artifacts to a target system and compiling them locally**, rather than delivering a fully compiled binary. This evades static detection controls and complicates pre-execution inspection.

Adversaries use this technique to:
- Avoid static malware signatures
- Bypass file-based inspection and sandboxing
- Tailor payloads to the target environment
- Reduce exposure during transit and delivery

---

## 2. Technical Overview
Instead of delivering a compiled executable, adversaries provide:
- Source code (C/C++, Go, Rust, C#, etc.)
- Script-generated source artifacts
- Intermediate representations requiring compilation

Compilation occurs on the victim system using:
- Native compilers (e.g., `gcc`, `clang`, `csc`)
- Scripting language compilers or interpreters
- Build tools already present on the system
- Downloaded compiler toolchains

Common behaviors:
- Invocation of compilers shortly after file delivery
- Creation of executables in user-writable directories
- Execution of newly compiled binaries
- Removal of source code after compilation

Indicators include:
- Unexpected compiler execution
- Compilation in non-development environments
- Short-lived source files
- Execution of binaries shortly after creation

---

## 3. Subtechnique Considerations
Key considerations for T1027.004:
- Highly effective in developer-heavy environments
- Often paired with **Command and Scripting Interpreter (T1059)**
- May bypass reputation-based file scanning
- Enables environment-specific payload optimization

This technique **shifts detection from delivery to execution**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Downloading source code and compiling locally
- Generating source files via scripts before compilation
- Compiling payloads with system-provided tools
- Deleting source artifacts after successful build

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **compiler usage and execution chains**:
- Alert on compiler execution in non-developer contexts
- Correlate compiler use with subsequent binary execution
- Monitor for source files created and deleted rapidly
- Detect command-line flags indicative of malicious builds

### Data Source Notes
- **Process creation logs**: Identify compiler execution
- **Command-line logging**: Reveal build parameters
- **File monitoring**: Detect transient source artifacts

Common false positives:
- Legitimate development or CI/CD activity
- Administrative scripting in IT environments

Tuning guidance:
- Baseline expected compiler usage by role and host
- Elevate alerts for compilation followed by execution

---

## 6. Response Guidance
When suspected:
1. Isolate the affected host if malicious behavior is confirmed
2. Preserve source files and compiled artifacts
3. Analyze compiled binaries and build commands
4. Identify toolchains or scripts involved
5. Hunt for similar compile-and-execute patterns

## 8. SOC Relevance
T1027.004 is critical because:
- Payloads may not exist pre-execution
- Detection shifts to behavioral monitoring
- Developer environments increase attack surface

SOC teams should monitor **unexpected compilation activity** closely.

---

## 9. Threat Actor Usage
Commonly used by:
- Advanced persistent threats
- Supply-chain–focused actors
- Intruders targeting development environments

---

## 10. Campaign Usage
Observed in:
- Cloud and CI/CD compromises
- Developer workstation intrusions
- Post-compromise payload staging

---

## 11. Malware Usage
Associated with:
- Custom backdoors
- Environment-specific payloads
- Fileless or semi-fileless malware

---

## 12. Mitigations
Recommended mitigations:
- Restrict compiler availability where unnecessary
- Monitor and alert on compiler execution
- Enforce application control policies
- Separate development and production environments

---

## 13. Testing & Validation
Validation approaches:
- Execute benign compile-and-run workflows in lab
- Validate alerts on unexpected compiler usage
- Test SOC response to transient artifacts
- Ensure logging captures build activity
