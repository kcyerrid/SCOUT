# Scheduled Task/Job: Container Orchestration Job (T1053.007)

## 1. Summary
Container Orchestration Job describes adversaries **abusing container orchestration platforms—such as Kubernetes—to create or modify scheduled or one-off jobs that execute malicious containers or commands**. These jobs can provide persistence, execution, or privilege escalation within containerized environments.

T1053.007 is commonly used to:
- Achieve execution within Kubernetes clusters
- Maintain persistence via recurring jobs (e.g., CronJobs)
- Execute payloads across nodes or namespaces
- Blend malicious activity with legitimate orchestration operations

---

## 2. Technical Overview
Modern container platforms support scheduled and batch execution constructs, including:
- Kubernetes `Job`
- Kubernetes `CronJob`
- OpenShift scheduled jobs
- Cloud-managed container tasks

Adversaries abuse these by:
- Creating malicious job manifests
- Modifying existing jobs to include attacker-controlled images or commands
- Scheduling recurring execution for persistence
- Running jobs under privileged service accounts

Artifacts often include:
- New or modified Job/CronJob resources
- Execution of unexpected container images
- Jobs running outside normal deployment workflows
- Elevated permissions tied to job service accounts

---

## 3. Subtechnique Considerations
Key considerations for T1053.007:
- Often overlooked compared to pod or deployment abuse
- Can persist independently of application workloads
- Leverages trusted orchestration APIs
- Detection requires control-plane visibility

This technique is increasingly common in cloud-native intrusions.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Creating CronJobs that periodically deploy backdoor containers
- Modifying existing maintenance jobs to execute malicious scripts
- Using Jobs to run cryptominers across cluster nodes
- Executing reconnaissance or lateral movement tooling via jobs

These activities typically occur after cluster access is obtained.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring creation and modification of Job and CronJob resources
- Alerting on execution of unknown or untrusted container images
- Detecting jobs created outside CI/CD pipelines
- Correlating job execution with suspicious API activity

### Data Source Notes
- **Kubernetes audit logs**: Primary detection source
- **API server logs**: Required for attribution
- **Cloud control plane logs**: Useful in managed environments

---

## 6. Response Guidance
When detected:
1. Identify and suspend malicious jobs
2. Revoke compromised service accounts
3. Investigate executed containers and images
4. Isolate affected namespaces or clusters
5. Review RBAC and admission control policies

## 8. SOC Relevance
T1053.007 is highly relevant in:
- Kubernetes and OpenShift environments
- Cloud-native production clusters
- Intrusions involving cryptomining or backdoors

Abuse of orchestration jobs can enable stealthy, durable access.

- Cryptomining campaigns
- Advanced attackers targeting Kubernetes environments

Usage reflects understanding of container-native operations.

---

Observed in:
- Cloud workload compromise campaigns
- Kubernetes cluster intrusions

---

## 11. Malware Usage
Malware leveraging orchestration jobs includes:
- Cryptominers
- Backdoored container images
- Reconnaissance and lateral movement tooling

---

## 12. Mitigations
Recommended mitigations:
- Restrict job creation via RBAC
- Monitor and baseline Job/CronJob usage
- Enforce image allowlisting and signing
- Use admission controllers to validate manifests
- Apply least privilege to service accounts

---

## 13. Testing & Validation
Validation approaches:
- Create test Jobs/CronJobs in lab clusters
- Validate SOC alerts for job creation events
- Conduct red team testing in container environments
- Review control-plane logging coverage
