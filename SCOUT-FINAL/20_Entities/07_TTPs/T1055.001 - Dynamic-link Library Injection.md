# Process Injection: Dynamic-link Library Injection (T1055.001)

## 1. Summary
Dynamic-link Library (DLL) Injection describes adversaries **forcing a target process to load a malicious DLL** into its address space. Once loaded, the attacker-controlled code executes within the context of a legitimate process, enabling stealthy execution, defense evasion, and privilege escalation.

T1055.001 is commonly used to:
- Execute malicious code under trusted process identities
- Bypass application allowlisting and signature-based detection
- Maintain persistence and conceal malicious activity
- Facilitate credential access or lateral movement

---

## 2. Technical Overview
Windows processes dynamically load DLLs to extend functionality. Adversaries abuse this mechanism by:
- Writing a malicious DLL path into the memory of a target process
- Triggering the target process to load the DLL
- Executing malicious code during DLL initialization

Common APIs involved include:
- `CreateRemoteThread`
- `LoadLibraryA/W`
- `WriteProcessMemory`
- `VirtualAllocEx`

Artifacts often include:
- Unexpected DLLs loaded into trusted processes
- Memory allocations associated with DLL paths
- API call sequences indicative of remote DLL loading
- Legitimate processes exhibiting anomalous behavior

---

## 3. Subtechnique Considerations
Key considerations for T1055.001:
- Requires access to a process with sufficient privileges
- Injection into high-privilege processes may require elevation
- Detection depends heavily on module load monitoring
- Often paired with token manipulation or process discovery

DLL injection remains one of the most common and well-understood injection techniques.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting malicious DLLs into system processes (e.g., `explorer.exe`)
- Loading payloads into long-running processes to maintain execution
- Using DLL injection to bypass endpoint controls
- Pairing injection with credential dumping or keylogging

These actions typically occur after initial execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring DLL/module load events
- Alerting on unsigned or unexpected DLLs loaded by trusted processes
- Detecting suspicious API call sequences
- Correlating injection behavior with prior process access

### Data Source Notes
- **Module load telemetry**: Critical for detecting malicious DLLs
- **Memory telemetry**: Useful for identifying injected artifacts
- **API monitoring**: Enables detection of injection techniques

---

## 6. Response Guidance
When suspected:
1. Identify injected processes and loaded DLLs
2. Isolate affected systems
3. Capture memory for forensic analysis
4. Remove malicious DLLs from disk
5. Investigate for additional injection or persistence mechanisms

## 12. Mitigations
Recommended mitigations:
- Monitor and restrict DLL loading behavior
- Use application allowlisting
- Enable EDR with module load visibility
- Block suspicious inter-process memory access
- Apply least privilege principles
