# Impair Defenses: Downgrade Attack (T1562.010)

## 1. Summary
Downgrade Attack describes adversaries **forcing software, operating systems, or security components to revert to older, less secure versions** in order to exploit known weaknesses or bypass modern protections. By downgrading components, attackers can reintroduce vulnerabilities that have already been patched.

Attackers use this technique to:
- Bypass security improvements in newer versions
- Re-enable deprecated or insecure functionality
- Evade modern detection and hardening controls
- Exploit known vulnerabilities in older software

---

## 2. Technical Overview
Modern systems rely on updates and versioning to maintain security posture. Adversaries perform downgrade attacks by:

- Replacing binaries with older signed versions
- Manipulating update mechanisms or package managers
- Blocking updates and enforcing version rollback
- Exploiting insecure update or rollback logic
- Leveraging trusted signatures on older components

Common targets include:
- Security software engines
- Operating system components
- Cryptographic libraries
- Cloud service configurations and APIs

Typical indicators and artifacts:
- Unexpected version regressions
- Update logs showing rollbacks or blocked updates
- Security features missing after update cycles
- Known-vulnerable versions present on hosts

---

## 3. Subtechnique Considerations
Key considerations for T1562.010:
- Often overlaps with **Subvert Trust Controls (T1553)**
- May be combined with **Component Firmware (T1601)** in advanced attacks
- Requires elevated privileges or control over update pipelines
- Particularly dangerous in environments without strict version enforcement

Downgrade attacks can persist undetected if version checks are weak.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Replacing updated binaries with older trusted versions
- Downgrading security engines to disable protections
- Preventing updates while enforcing rollback
- Exploiting signed legacy installers or packages

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **version integrity and update behavior**:
- Alert on unexpected software downgrades
- Monitor package manager rollback activity
- Detect blocked or suppressed update attempts
- Correlate downgrade events with suspicious execution

### Data Source Notes
- **Update and package logs**: Primary detection source
- **EDR telemetry**: Identify version anomalies
- **Registry and configuration monitoring**: Detect forced rollbacks

Common false positives:
- Legitimate rollback during troubleshooting
- Compatibility-related downgrades

Tuning guidance:
- Require approval for version rollbacks
- Baseline approved versions for critical software

---

## 6. Response Guidance
When suspected:
1. Identify downgraded components and versions
2. Restore systems to approved, secure versions
3. Investigate how downgrade was enforced
4. Review actions taken while vulnerable versions were active
5. Patch and harden update mechanisms

## 8. SOC Relevance
T1562.010 is **highly impactful** because it silently reintroduces risk. Downgrade attacks undermine patch management and can invalidate assumptions about system security posture.

Any unexplained downgrade should be treated as a security incident.

---

## 9. Threat Actor Usage
This technique has been observed in:
- Advanced persistent threat campaigns
- Supply chain compromise scenarios
- Long-dwell intrusions targeting hardened environments

Its use indicates **strategic planning and persistence**.

---

## 10. Campaign Usage
Observed in:
- Targeted espionage campaigns
- Pre-exploitation hardening bypass phases
- Attacks leveraging known-vulnerable components

---

## 11. Malware Usage
Associated with:
- Advanced loaders and backdoors
- Malware exploiting legacy vulnerabilities
- Tooling that targets specific software versions

---

## 12. Mitigations
Recommended mitigations:
- Enforce minimum version policies
- Monitor and restrict downgrade capabilities
- Validate integrity and versioning of critical components
- Harden update and rollback mechanisms
- Use allowlists for approved software versions

---

## 13. Testing & Validation
Validation approaches:
- Attempt controlled rollbacks in test environments
- Validate alerts on downgrade events
- Test SOC response to version regressions
- Ensure rollback controls are enforced
