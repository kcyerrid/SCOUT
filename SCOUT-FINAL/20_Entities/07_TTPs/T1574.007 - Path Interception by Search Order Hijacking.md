# T1574.007 – Path Interception by Search Order Hijacking

## 1. Technique Overview
**Path Interception by Search Order Hijacking (T1574.007)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries exploit the **Windows executable search order** so that a malicious executable is found and run before the intended legitimate binary when a command is executed without specifying an absolute path.

This technique differs from PATH environment variable abuse by relying on **Windows’ default search precedence** (e.g., current working directory) rather than modifying environment variables.

## 2. Adversary Objectives
Adversaries use this technique to:
- Execute malicious code in place of legitimate commands
- Establish persistence tied to routine command execution
- Escalate privileges by targeting elevated scripts or services
- Blend execution into normal administrative activity

## 3. Common Abuse Patterns
- Dropping malicious executables into directories searched early (e.g., current working directory)
- Naming malicious binaries after common system commands
- Targeting scheduled tasks, services, or scripts that invoke commands without full paths
- Exploiting writable directories used as working directories by privileged processes
- Leveraging search order hijacking for repeated execution opportunities

## 4. Detection Considerations
Detection relies on **process creation and execution context analysis**, including:
- Monitoring execution of binaries from unexpected or user-writable directories
- Detecting processes launched from the current working directory when not expected
- Correlating elevated executions with non-standard binary paths
- Auditing scripts and services for missing absolute paths
- Baseline comparison of known-good execution behaviors

## 5. Defensive Mitigations
- Use absolute paths when invoking executables in scripts and services
- Restrict write permissions on directories used by privileged processes
- Monitor and alert on execution from user-writable locations
- Enforce application allowlisting
- Review scheduled tasks and service configurations for unsafe command usage

## 6. Operational Impact
If successful, T1574.007 can:
- Enable stealthy execution without modifying startup locations
- Provide persistence tied to normal operations
- Facilitate privilege escalation via trusted processes
- Complicate detection due to legitimate execution context

## 7. Analyst Notes
Search order hijacking is often overlooked because it does not require modifying system-wide settings. Analysts should always examine **the resolved path of executed binaries**, especially when commands are invoked without absolute paths in privileged contexts.
