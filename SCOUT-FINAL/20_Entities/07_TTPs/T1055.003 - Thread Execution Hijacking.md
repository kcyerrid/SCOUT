# Process Injection: Thread Execution Hijacking (T1055.003)

## 1. Summary
Thread Execution Hijacking describes adversaries **redirecting the execution flow of an existing thread** within a legitimate process to execute malicious code. Instead of creating new threads or loading new modules, attackers suspend a thread, modify its execution context, and resume it, causing execution to jump to attacker-controlled code.

T1055.003 is commonly used to:
- Execute payloads without creating new threads
- Evade thread-creation-based detections
- Blend malicious execution into legitimate process behavior
- Support stealthy post-exploitation operations

---

## 2. Technical Overview
Windows threads maintain execution context, including instruction pointers and registers. Adversaries abuse this by:
- Suspending a running thread in a target process
- Modifying the thread’s context to redirect execution
- Resuming the thread so it executes malicious code
- Restoring original execution flow after payload execution

Common APIs and mechanisms involved:
- `SuspendThread`
- `GetThreadContext`
- `SetThreadContext`
- `ResumeThread`

Artifacts often include:
- Threads executing from non-module-backed memory regions
- Unexpected changes in thread instruction pointers
- Legitimate processes performing anomalous actions
- Memory regions with executable permissions but no file backing

---

## 3. Subtechnique Considerations
Key considerations for T1055.003:
- Requires access to manipulate thread handles
- Often paired with token abuse or process discovery
- Highly stealthy due to lack of new threads or modules
- Detection depends on deep memory and thread telemetry

This subtechnique is favored when stealth is a priority.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Hijacking a GUI thread in a trusted process
- Redirecting execution to shellcode in allocated memory
- Temporarily executing payloads before restoring thread state
- Combining thread hijacking with encrypted in-memory payloads

These actions typically occur after initial code execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring thread suspension and context modification APIs
- Detecting threads executing from non-image memory
- Alerting on anomalous thread behavior in trusted processes
- Correlating thread hijacking with prior process access events

### Data Source Notes
- **Thread telemetry**: Essential for detecting hijacking behavior
- **Memory telemetry**: Required to identify injected code regions
- **API monitoring**: Enables detection of context manipulation calls

---

## 6. Response Guidance
When suspected:
1. Identify affected processes and threads
2. Isolate compromised systems
3. Capture memory for forensic analysis
4. Terminate malicious processes if appropriate
5. Investigate for additional injection or persistence techniques
