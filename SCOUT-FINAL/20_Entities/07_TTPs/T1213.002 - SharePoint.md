## 1. Summary
Adversaries may mine SharePoint for sensitive internal documents and operational information, including network diagrams, project plans, and insecurely stored credentials. Abnormal bulk access—especially by privileged or rarely-used identities—can be a strong indicator of scripted collection and pre-exfiltration staging.

## 2. Technical Overview
SharePoint data mining commonly includes:
- Browsing site collections, document libraries, and lists via the UI.
- Enumerating and downloading files/metadata via SharePoint/M365 APIs and client tooling.
- Querying content (search) to locate specific keywords (VPN, MFA enrollment, onboarding, incident response, “password”, “token”).
- High-volume download patterns from sensitive sites.

Key defender-relevant behaviors:
- Many **FileAccessed/FileDownloaded** events in short windows.
- Search queries followed by targeted downloads (search → open → download chain).
- Access from unusual IPs/devices/geographies or newly created sessions/tokens.
- Service accounts or privileged users accessing HR/Finance/Security repositories unexpectedly.

## 3. Subtechnique Considerations
- SharePoint spans multiple deployment models (on-prem SharePoint vs Microsoft 365). Logging and control points differ:
  - M365 unified audit log + Entra ID sign-ins for SaaS usage
  - Server-side audit logs and Windows events for on-prem
- “Rarely used” accounts (break-glass, legacy admins, service principals) are particularly valuable correlation pivots.
- Search telemetry can be as valuable as download telemetry; adversaries often “keyword hunt” before bulk pulls.

## 5. Detection Guidance
Prioritize detections that combine content access + identity risk:
- **Bulk access thresholds**: Count unique files accessed/downloaded per user within a short time window; tune by site sensitivity.
- **Search-to-download chaining**: Alert when a user runs numerous searches followed by multiple downloads from sensitive libraries.
- **Privileged/rare identity monitoring**: Apply stricter thresholds to privileged roles and rarely used accounts.
- **Conditional access and sign-in anomaly correlation**: Join SharePoint access bursts to Entra ID sign-in anomalies (new device, impossible travel, risk score).
- **Scope-based baselining**: Baseline per department (e.g., HR power users vs engineering) and suppress expected backup/indexing activity.

### Data Source Notes
- M365 unified audit log events (e.g., FileAccessed, FileDownloaded, SearchQueried) are primary for SaaS SharePoint telemetry.
- Entra ID sign-in logs provide session creation context (UserLogin, conditional access evaluation).
- Site-level SharePoint telemetry can provide “many downloads from a site in a short window” patterns for privileged accounts.
- MITRE detection strategy DET0500 provides a detection blueprint and tunable thresholds (time window, download count, site scope).

## 6. Response Guidance
1. **Validate access**: Confirm the user/session legitimacy; check device, geo, conditional access results, and sign-in risk indicators.
2. **Contain**: Revoke sessions/tokens, reset passwords, rotate secrets, disable suspicious OAuth apps/service principals if involved.
3. **Scope documents**: Enumerate which libraries/files were accessed/downloaded; prioritize sensitive repositories.
4. **Assess credential exposure**: Identify whether accessed documents include passwords, keys, VPN instructions, or admin runbooks; rotate impacted secrets.
5. **Hunt follow-on**: Look for subsequent access to VPN/IdP/admin portals, mailbox rule changes, or privilege escalations.

## 8. SOC Relevance
High-impact SOC signals:
- Mass file access/download from sensitive sites by privileged or rare accounts.
- SharePoint access bursts shortly after suspicious sign-ins.
- Search-heavy behavior followed by downloads of “how-to”/runbook documentation.

Triage pivots:
- User/session novelty (device/IP/geo), CA policy results, token creation events.
- Which sites/libraries were accessed and whether downloads occurred vs view-only access.

## 12. Mitigations
- **Audit (M1047)**: Periodically review SharePoint permissions and privileged access, especially for sensitive sites.
- **User Account Management (M1018)**: Enforce least-privilege and strong authz controls for site collections/libraries.
- **User Training (M1017)**: Define acceptable information storage policies; reduce secrets/runbooks stored in broadly accessible libraries.

## 13. Testing & Validation
- In a test tenant/site, simulate benign bulk activity (e.g., batch file opens/downloads) using approved admin testing to validate detection thresholds.
- Validate correlation between:
  - Unified audit log access events and Entra ID sign-in anomalies
  - SearchQueried → FileAccessed/FileDownloaded sequences
- Confirm reduced false positives by scoping to sensitive sites and excluding known-good service accounts (with compensating controls).

## 15. Notes
- Treat scripted SharePoint collection as a “precursor” to credential discovery and broader compromise; prioritize rapid containment.
- Maintain an allowlist of legitimate bulk download workflows (eDiscovery, legal holds, migrations) and require change tickets for exceptions.
