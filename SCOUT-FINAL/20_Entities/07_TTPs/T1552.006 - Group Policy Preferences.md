## 1. Summary
Adversaries may locate and decrypt credentials embedded in Group Policy Preferences (GPP) artifacts stored in SYSVOL. Because SYSVOL is broadly readable by domain users, legacy GPP “cpassword” data can represent an org-wide credential exposure risk and is frequently leveraged for rapid privilege escalation and lateral movement.

## 2. Technical Overview
GPP can contain embedded credentials used to configure local accounts and other settings. Vulnerable artifacts are stored under domain SYSVOL paths as XML files. If present, the embedded password field can be decrypted using publicly known methods, turning a low-privileged domain foothold into privileged local/admin credentials across many systems.

Typical adversary behavior:
- Enumerate SYSVOL for GPP XML files
- Extract embedded credential material
- Use recovered credentials for remote access, privilege escalation, or broader credential dumping

## 3. Subtechnique Considerations
- Risk is **environment-wide**: a single legacy GPP secret can impact many endpoints.
- Modern environments may have partial remediation; attackers still hunt for **forgotten** or **newly introduced** GPP artifacts.
- Detection must focus on **SYSVOL access patterns** and **XML parsing/decryption behaviors**, not just file reads.

## 4. Procedure Examples
Observed usage includes:
- Threat actors leveraging publicly available tooling to retrieve and decrypt GPP credentials
- Post-exploitation frameworks/modules harvesting credentials from SYSVOL-stored GPP XML files

## 5. Detection Guidance
**File access & enumeration**
- Alert on recursive enumeration of SYSVOL paths for XML files by unusual processes/users.
- Watch for access to known GPP preference directories followed by reads of multiple XML files in a short period.

**Process & script behaviors**
- Identify suspicious PowerShell/script activity that:
  - Reads SYSVOL-based XMLs
  - Performs decryption-like operations
  - Writes extracted secrets to disk or stdout/logs
- Correlate with remote logons shortly afterward using newly discovered local/admin accounts.

**Authentication correlation**
- Sequence detections:
  1) SYSVOL enumeration + XML reads
  2) credential material staged (clipboard/log/file) or outbound beacons
  3) follow-on admin logons, service creation, remote execution

### Data Source Notes
- Key telemetry: Windows file share auditing (SYSVOL), PowerShell logging, process creation, and authentication logs (Kerberos/NTLM logons, remote interactive/service logons).
- False positives are reduced by baselining legitimate GPO maintenance accounts/tools and focusing on **non-admin users** or **unusual hosts** accessing SYSVOL.

## 6. Response Guidance
1. **Containment**
   - Identify the accessing principal/host; isolate if malicious.
2. **Credential rotation**
   - Rotate any recovered credentials; assume reuse across hosts until proven otherwise.
3. **Eradication**
   - Remove vulnerable GPP artifacts; validate SYSVOL for additional embedded credentials.
4. **Hunt**
   - Review domain authentication for new admin logons originating from the initial host after SYSVOL access.
5. **Hardening**
   - Enforce least privilege and continuous scanning of SYSVOL for credential-like patterns.

- The technique is often a **fast escalation** step after initial foothold
- Strong correlation exists between **SYSVOL enumeration** and **immediate follow-on admin activity**

## 12. Mitigations
- **M1015 - Active Directory Configuration**: Remove vulnerable GPP preferences and embedded credentials from SYSVOL.
- **M1047 - Audit**: Regularly scan SYSVOL for GPP artifacts that contain credentials and remediate.
- **M1051 - Update Software**: Apply updates that prevent storing credentials in GPP and enforce modern alternatives.

  - Validate correlation alerts: SYSVOL read burst → suspicious PowerShell → privileged logon.
  - Ensure privileged accounts used for GPO management are protected and monitored separately.
