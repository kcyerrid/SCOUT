# Dynamic Data Exchange (T1559.002)

## 1. Summary
Dynamic Data Exchange (DDE) describes adversaries abusing the legacy Windows inter-process communication protocol to execute commands in the context of another application. DDE is most commonly exploited through Microsoft Office documents, allowing command execution without the use of macros.

This subtechnique is frequently used to bypass macro security controls and relies on social engineering to trigger execution.

---

## 2. Technical Overview
DDE is a deprecated Windows IPC mechanism that allows applications to exchange messages and data.

Adversaries abuse DDE by:
- Embedding DDE fields in Office documents
- Triggering command execution via trusted applications (e.g., Excel, Word)
- Launching interpreters or executables through DDE requests
- Avoiding macro-based detection mechanisms

Artifacts include Office application execution, child processes spawned by Office apps, IPC events, and user interaction prompts.

---

## 3. Subtechnique Considerations
T1559.002 is tightly coupled with user interaction and Office-based delivery.

Key considerations include:
- DDE does not require macros to be enabled
- User prompts may appear benign or confusing
- Legacy environments are more susceptible
- Limited native logging for DDE activity

Detection must correlate document interaction with execution events.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Sending weaponized Excel spreadsheets with DDE fields
- Using DDE to launch PowerShell or cmd.exe
- Bypassing macro-restricted environments
- Embedding DDE execution in phishing attachments

Analysts may observe Office processes spawning command interpreters unexpectedly.

---

## 5. Detection Guidance
Detection should focus on:
- Office applications spawning child processes
- Command interpreters launched by document viewers
- Execution shortly after document open events
- Abnormal IPC activity associated with Office processes

Correlation between email telemetry and endpoint execution is critical.

### Data Source Notes
- **Process Execution:** High-value signal for detection
- **Application Logs:** Useful for Office execution context
- **IPC Logs:** Limited but helpful when available

---

## 6. Response Guidance
When DDE abuse is suspected:
- Identify and quarantine the malicious document
- Isolate affected endpoints if execution occurred
- Review email delivery vectors and recipient scope
- Assess for follow-on payload execution or persistence

Preserve document samples and execution telemetry for investigation.

## 8. SOC Relevance
DDE-based execution is less common today but remains relevant in environments with legacy Office configurations. SOCs should treat Office-spawned command execution as high-signal activity.

---

## 9. Threat Actor Usage
This subtechnique has been used by:
- Commodity malware operators
- Initial access brokers
- Phishing-focused threat actors

Confidence in moderate but declining usage is medium.

---

## 10. Campaign Usage
DDE abuse has appeared in:
- Phishing-based malware delivery campaigns
- Early-stage ransomware access operations
- Macro-bypass attack waves

## 12. Mitigations
Effective mitigations include:
- Disabling DDE functionality in Office where possible
- Monitoring Office child process execution
- Applying email attachment filtering
- Enforcing least-privilege user execution
- User awareness training on document security prompts

---

## 13. Testing & Validation
Validation approaches include:
- Purple team testing with DDE-enabled documents
- Detection validation for Office-spawned interpreters
- Review of alerts tied to document-based execution

Successful validation results in detection of unauthorized DDE execution.
