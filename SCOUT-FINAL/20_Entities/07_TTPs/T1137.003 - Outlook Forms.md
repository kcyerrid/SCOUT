# T1137.003 – Outlook Forms

## 1. Technique Overview
**Outlook Forms (T1137.003)** is a sub-technique of [[20_Entities/07_TTPs/T1137 - Office Application Startup|T1137]] in **MITRE ATT&CK v18**. Adversaries abuse **custom Microsoft Outlook forms**, which are designed to extend email functionality, to execute attacker-controlled code when a message using the form is opened, previewed, or otherwise processed by Outlook.

Because Outlook forms can be trusted and persist within the user’s Outlook environment, this technique provides reliable user-context persistence without relying on traditional startup locations.

## 2. Adversary Objectives
Adversaries use Outlook form abuse to:
- Execute malicious code when emails are viewed or interacted with
- Maintain persistence tied to routine email usage
- Blend execution into legitimate Outlook functionality
- Evade detection by leveraging trusted Office extensibility features

## 3. Common Abuse Patterns
- Creating malicious custom Outlook forms containing script or executable logic
- Publishing forms to local or organizational form libraries
- Sending emails that reference the malicious form
- Leveraging preview pane or automatic form rendering for execution
- Using forms to trigger secondary payloads or command-and-control activity

## 4. Detection Considerations
Detection relies on **Outlook configuration and behavior monitoring**, including:
- Auditing installed and published Outlook forms
- Monitoring changes to Outlook form libraries
- Detecting unexpected script execution associated with Outlook
- Correlating email interaction with anomalous child process creation
- Reviewing Outlook security and trust settings for form usage

## 5. Defensive Mitigations
- Restrict the use and publication of custom Outlook forms
- Monitor and alert on creation or modification of Outlook forms
- Apply security policies limiting script execution in Outlook
- Educate users and administrators on risks of custom forms
- Remove unauthorized forms during incident response

## 6. Operational Impact
If successful, T1137.003 can:
- Provide stealthy, user-driven persistence
- Execute code without explicit macro prompts
- Leverage trusted email workflows for repeated execution
- Complicate detection due to legitimate Outlook behavior

## 7. Analyst Notes
Outlook Forms are a **less common but effective persistence mechanism**. Analysts should include form library inspection when investigating suspicious Outlook behavior, especially in cases where execution appears tied to email viewing rather than document opening.
