# T1547.001 – Registry Run Keys or Startup Folder

## 1. Technique Overview
**Registry Run Keys or Startup Folder (T1547.001)** is a sub-technique of **Boot or Logon Autostart Execution (T1547)** in MITRE ATT&CK v18. Adversaries abuse **well-known Windows autostart extensibility points** to ensure malicious code executes automatically when a user logs on or when the system starts.

These mechanisms are widely used by legitimate software, making malicious use difficult to distinguish without contextual analysis.

## 2. Adversary Objectives
Adversaries use this technique to:
- Maintain persistence across reboots and user logons
- Re-establish execution after system restarts
- Blend malicious activity with legitimate startup behavior
- Support follow-on actions such as lateral movement or data exfiltration

## 3. Common Abuse Patterns
- Adding values to registry keys such as:
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
  - `RunOnce` and `RunServices` variants
- Dropping executables or scripts into:
  - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`
  - `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Startup`
- Using per-user run keys to avoid requiring administrative privileges
- Masquerading entries as legitimate software or system components

## 4. Detection Considerations
Detection relies on **startup artifact and registry monitoring**, including:
- Alerts on creation or modification of Run/RunOnce registry values
- Detection of unsigned or unexpected binaries referenced by startup keys
- Monitoring changes to Startup folders
- Correlation of startup modifications with suspicious process execution
- Baseline comparison against known-good startup configurations

## 5. Defensive Mitigations
- Monitor and audit registry autostart locations
- Restrict write access to startup directories where possible
- Use application allowlisting to block unauthorized binaries
- Enable endpoint detection rules for startup persistence behaviors
- Regularly review autorun entries using administrative tooling

## 6. Operational Impact
If successful, T1547.001 can:
- Provide reliable, long-term persistence
- Enable repeated malware execution without user interaction
- Survive system reboots and basic remediation attempts
- Serve as a launch point for additional malicious activity

## 7. Analyst Notes
T1547.001 remains one of the most frequently abused persistence mechanisms due to its simplicity and ubiquity. During incident response, analysts should review **both user- and system-level run keys**, as attackers often prefer per-user persistence to reduce detection risk and avoid privilege requirements.
