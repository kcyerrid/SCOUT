# Indicator Removal on Host: Clear Windows Event Logs (T1070.001)

## 1. Summary
Clear Windows Event Logs describes adversaries **deleting or clearing Windows event logs** to remove evidence of malicious activity. This subtechnique directly targets one of the most important forensic data sources available to defenders and is frequently observed during or after hands-on intrusion activity.

Attackers use this technique to:
- Obscure execution, persistence, and lateral movement
- Reduce SOC and SIEM visibility
- Delay detection and investigation
- Complicate incident reconstruction

---

## 2. Technical Overview
Windows records system, security, and application events in structured event logs. Adversaries clear these logs by:

- Clearing individual event logs (Security, System, Application)
- Removing log files from disk
- Triggering log truncation via administrative utilities
- Automating log clearing as part of post-exploitation workflows

Indicators include:
- Event log clear events themselves
- Sudden loss of historical events
- Log clearing followed by suspicious activity
- Correlation with administrative shell usage

---

## 3. Subtechnique Considerations
Key considerations for T1070.001:
- Requires administrative privileges
- Strongly overlaps with **Disable Windows Event Logging (T1562.002)**
- Often paired with **Impair Command History Logging (T1562.003)**
- High-confidence indicator of malicious intent

Legitimate log clearing is rare and should be well-documented.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Clearing Security, System, or Application logs
- Removing historical event records prior to payload execution
- Automating log clearing after privilege escalation
- Clearing logs to erase evidence of lateral movement

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **log integrity and continuity**:
- Alert on event log clearing events
- Detect sudden drops in log volume
- Monitor administrative shell activity preceding log clearing
- Correlate log clearing with suspicious process execution

### Data Source Notes
- **Windows Event Logs**: Primary source (ironically)
- **EDR telemetry**: Detect anti-forensic behavior
- **SIEM ingestion metrics**: Identify ingestion gaps

Common false positives:
- Rare legitimate maintenance actions
- System image resets or rebuilds

Tuning guidance:
- Require approval for any log clearing
- Treat unplanned log clearing as critical

---

## 6. Response Guidance
When suspected:
1. Preserve remaining logs immediately
2. Identify scope and timing of log clearing
3. Investigate activity before and after clearing
4. Review administrative access usage
5. Treat as confirmed malicious activity unless proven otherwise

## 8. SOC Relevance
T1070.001 is a **critical SOC detection**. Log clearing often occurs immediately before ransomware execution or exfiltration and should trigger emergency response.

---

## 9. Threat Actor Usage
This subtechnique is widely used by:
- Ransomware operators
- APT groups
- Financially motivated intruders

Its use strongly indicates **intentional, hands-on-keyboard activity**.

---

## 10. Campaign Usage
Observed in:
- Ransomware deployment phases
- Espionage operations
- Long-dwell intrusions

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Post-exploitation frameworks
- Automation scripts for anti-forensics

---

## 12. Mitigations
Recommended mitigations:
- Centralize and protect Windows event logs
- Enable immutable or write-once log storage
- Restrict administrative privileges
- Monitor for log clear events
- Ensure EDR captures activity independently of logs

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign log clearing in lab systems
- Validate alerts on log clear events
- Test SOC response playbooks
- Ensure ingestion gap detection is functional
