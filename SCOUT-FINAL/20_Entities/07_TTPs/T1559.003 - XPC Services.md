# Windows Management Instrumentation Event Subscription (T1559.003)

## 1. Summary
Windows Management Instrumentation (WMI) Event Subscription describes adversaries abusing WMI’s eventing framework to trigger execution of malicious actions when specific system events occur. Instead of directly launching processes, attackers register permanent or temporary WMI event subscriptions that execute code in response to defined conditions.

This subtechnique enables stealthy execution and often overlaps with persistence mechanisms.

---

## 2. Technical Overview
WMI supports event subscriptions through:
- **Event Filters** (define triggering conditions)
- **Consumers** (define actions to execute)
- **Bindings** (link filters and consumers)

Adversaries abuse WMI event subscriptions to:
- Execute commands or scripts upon system startup or user logon
- Trigger execution based on process, time, or system state changes
- Maintain execution capability without user interaction

Artifacts include WMI repository changes, event consumer registrations, registry entries, and execution of payloads by WMI-managed processes.

---

## 3. Subtechnique Considerations
T1559.003 is Windows-specific and frequently overlaps with persistence (e.g., WMI permanent event subscriptions).

Key considerations include:
- Execution may occur long after initial compromise
- Subscriptions can survive reboots
- Limited default logging for WMI activity
- Execution often occurs under system or service contexts

Detection requires specialized telemetry and periodic auditing.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Creating permanent WMI event subscriptions for execution at startup
- Using time-based triggers for delayed execution
- Leveraging WMI consumers to launch PowerShell or executables
- Combining execution with persistence via permanent subscriptions

Analysts may observe unexpected execution without clear parent processes.

---

## 5. Detection Guidance
Detection should focus on:
- Creation or modification of WMI event filters and consumers
- Execution of scripts or binaries by WMI processes
- Registry changes associated with WMI persistence
- WMI activity initiated by non-administrative users

Periodic audits of WMI subscriptions significantly improve detection fidelity.

### Data Source Notes
- **WMI Logs:** High value but often disabled by default
- **Registry:** Useful for identifying persistent subscriptions
- **Process Execution:** Provides indirect execution evidence

---

## 6. Response Guidance
When malicious WMI event subscription activity is suspected:
- Enumerate and remove unauthorized WMI subscriptions
- Isolate affected systems if execution is confirmed
- Identify payloads executed by WMI consumers
- Assess for persistence mechanisms using WMI

Preserve WMI repository data and execution logs for forensic analysis.

WMI event subscription abuse is difficult to detect due to limited default logging and delayed execution. SOC teams must proactively monitor WMI configuration changes to identify this behavior.

## 12. Mitigations
Effective mitigations include:
- Auditing and monitoring WMI event subscriptions
- Restricting WMI permissions
- Deploying EDR with WMI visibility
- Applying least-privilege principles
- Regular system integrity checks
