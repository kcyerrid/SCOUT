# Malicious File (T1204.002)

## 1. Summary
Malicious File describes adversaries relying on a user to open or execute a file that contains or triggers malicious code. This includes documents, scripts, installers, archives, and executables delivered through phishing, web downloads, removable media, or shared collaboration platforms.

This subtechnique is one of the most prevalent execution mechanisms in real-world intrusions and underpins a wide range of malware delivery and ransomware campaigns.

---

## 2. Technical Overview
Malicious files may take many forms, including:
- Office documents with embedded macros
- Executable files disguised as legitimate software
- Script files (`.js`, `.vbs`, `.ps1`, `.sh`)
- Archives containing embedded payloads
- Disk images (`.iso`, `.img`) used to bypass controls

Upon user execution, the file may:
- Directly execute malicious code
- Launch an interpreter or loader
- Drop and execute secondary payloads
- Establish persistence or download additional tooling

Artifacts include file creation events, process execution initiated by user context, command-line arguments, and application logs indicating file access.

---

## 3. Subtechnique Considerations
T1204.002 focuses specifically on *file-based* execution initiated by user interaction.

Key considerations include:
- File type abuse to bypass security controls
- Use of trusted file formats to evade suspicion
- Chaining with script interpreters or exploit techniques
- Increasing use of container formats (ISO, ZIP) to bypass email defenses

Detection must account for delivery vector, file type, and execution context.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Delivering weaponized Office documents via phishing
- Disguising malware as invoices, resumes, or updates
- Using compressed archives to obscure payloads
- Leveraging disk image formats to evade attachment filtering

Analysts may observe execution shortly after file download or email interaction.

---

## 5. Detection Guidance
Detection should focus on:
- Execution of newly created or downloaded files
- User-launched processes from temporary or download directories
- Files with mismatched extensions or suspicious metadata
- Child processes spawned by document readers or archive utilities

Correlation across email, endpoint, and file telemetry significantly improves detection fidelity.

### Data Source Notes
- **File Creation:** High value for identifying initial payloads
- **Process Execution:** Core signal for execution tracking
- **Email Logs:** Provide delivery context for malicious files

---

## 6. Response Guidance
When malicious file execution is suspected:
- Identify and isolate affected endpoints
- Capture the executed file and associated artifacts
- Determine the delivery vector and scope of exposure
- Assess for follow-on persistence, credential access, or lateral movement

Preserve original files, email headers, and execution logs for investigation.

## 8. SOC Relevance
Malicious file execution is one of the highest-volume alert categories for SOC teams. High false-positive rates require behavioral correlation rather than reliance on file reputation alone.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Commodity malware operators
- Ransomware affiliates
- Initial access brokers
- Advanced persistent threat groups

Confidence in ubiquitous usage is extremely high.

## 10. Campaign Usage
Malicious file execution appears in:
- Phishing-based malware delivery campaigns
- Ransomware initial access operations
- Social engineering-driven intrusions

## 12. Mitigations
Effective mitigations include:
- Blocking or restricting high-risk file types
- Enforcing macro and script execution policies
- Email and attachment sandboxing
- Application control and allowlisting
- User awareness training focused on file-based threats

---

## 13. Testing & Validation
Validation approaches include:
- Phishing simulations using malicious attachments
- Purple team testing of file-based execution chains
- Review of alerts tied to newly created file execution

Successful validation results in detection of unauthorized file-based execution.
