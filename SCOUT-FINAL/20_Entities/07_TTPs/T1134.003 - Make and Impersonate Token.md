# Access Token Manipulation: Make and Impersonate Token (T1134.003)

## 1. Summary
This subtechnique describes adversaries **creating forged or manipulated Windows access tokens** and then impersonating them to execute actions under a different security context. Unlike token theft, this technique involves **manufacturing a token** that represents another user, often one with elevated privileges.

T1134.003 is commonly used to:
- Escalate privileges without stealing an existing token
- Impersonate accounts that are not currently logged on
- Bypass authentication mechanisms
- Enable stealthy privilege escalation in post-exploitation scenarios

---

## 2. Technical Overview
Windows supports token creation and manipulation through low-level APIs that are typically restricted to privileged contexts. Adversaries abuse these capabilities by:
- Creating primary or impersonation tokens
- Assigning security identifiers (SIDs) and privileges to tokens
- Impersonating those tokens at the thread level
- Executing privileged actions using the forged token

Common APIs and mechanisms involved include:
- `CreateToken`
- `DuplicateTokenEx`
- `SetThreadToken`
- `ImpersonateLoggedOnUser`

Artifacts often include:
- Privileged operations without corresponding logon events
- Token privilege sets that do not match known user profiles
- SYSTEM or admin-level actions initiated by user-level processes

---

## 3. Subtechnique Considerations
Key considerations for T1134.003:
- Requires high privileges to create tokens
- Often used after initial privilege escalation
- Difficult to detect without deep token telemetry
- Can impersonate users who are not actively logged in

This technique provides attackers with fine-grained control over privilege contexts.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Forging tokens with administrative SIDs
- Impersonating fabricated tokens to access restricted resources
- Using token impersonation to bypass access control checks
- Combining token creation with process injection for stealth

These procedures typically follow local privilege escalation or credential compromise.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying token creation events outside normal system activity
- Detecting impersonation without corresponding authentication
- Monitoring for unusual token privilege combinations
- Alerting on SYSTEM-level operations from unexpected processes

### Data Source Notes
- **Security Event Logs**: Limited visibility but useful when correlated
- **Process telemetry**: Essential for execution chain analysis
- **API monitoring**: Required for detecting token creation calls

---

## 6. Response Guidance
When suspected:
1. Identify processes creating or impersonating tokens
2. Terminate malicious processes using forged tokens
3. Investigate how token creation privileges were obtained
4. Review for follow-on actions such as lateral movement
5. Reset credentials and review privilege assignments
