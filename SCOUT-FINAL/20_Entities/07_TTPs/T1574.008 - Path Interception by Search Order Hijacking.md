# T1574.008 – Path Interception by Search Order Hijacking

## 1. Technique Overview
**Path Interception by Search Order Hijacking (T1574.008)** is a sub-technique of **Hijack Execution Flow (T1574)** in **MITRE ATT&CK v18**. Adversaries abuse the **Windows executable search order** so that when a command is executed without an absolute path, a malicious executable located in a higher-priority search location is executed instead of the legitimate binary.

Unlike PATH environment variable manipulation, this technique relies on **default Windows search precedence**, such as the current working directory or application directory.

## 2. Adversary Objectives
Adversaries use search order hijacking to:
- Execute malicious binaries in place of trusted commands
- Establish persistence through routine command execution
- Escalate privileges by targeting elevated scripts or services
- Blend execution into normal administrative workflows

## 3. Common Abuse Patterns
- Dropping malicious executables into the current working directory
- Naming binaries after common administrative commands
- Targeting scripts, services, or scheduled tasks lacking absolute paths
- Exploiting writable directories used by privileged processes
- Leveraging repeated execution opportunities for persistence

## 4. Detection Considerations
Detection relies on **process execution context analysis**, including:
- Monitoring execution from unexpected directories
- Detecting elevated processes launched from user-writable paths
- Auditing scripts and services for missing absolute paths
- Correlating command execution with anomalous binary locations
- Baseline comparison of known-good execution behavior

## 5. Defensive Mitigations
- Use absolute paths when invoking executables
- Restrict write access to directories in execution search paths
- Monitor execution from user-writable locations
- Apply application allowlisting controls
- Audit services and scheduled tasks for unsafe command usage

## 6. Operational Impact
If successful, T1574.008 can:
- Enable stealthy execution without modifying startup artifacts
- Provide persistence tied to normal operations
- Facilitate privilege escalation via trusted execution contexts
- Complicate detection due to legitimate process lineage

## 7. Analyst Notes
Search order hijacking is subtle and frequently overlooked. Analysts should focus on **where an executable was resolved from**, not just its name or parent process, particularly when investigating suspicious activity originating from administrative scripts or services.
