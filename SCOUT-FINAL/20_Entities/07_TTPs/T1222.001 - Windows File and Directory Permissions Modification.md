# File and Directory Permissions Modification: Windows (T1222.001)

## 1. Summary
Windows File and Directory Permissions Modification describes adversaries **modifying Windows access control mechanisms (DACLs, ownership, or inheritance)** to gain unauthorized access, enable file tampering, or evade security controls. This subtechnique commonly supports persistence, privilege escalation, or defense evasion by weakening access protections on critical resources.

---

## 2. Technical Overview
Windows enforces access control using **Discretionary Access Control Lists (DACLs)** attached to files and directories. Adversaries abuse this model by:
- Changing DACL entries to grant themselves write or full control
- Taking ownership of protected files or directories
- Disabling inheritance to preserve malicious permissions
- Removing access for legitimate users or security services

Common tools and APIs involved:
- `icacls`
- `takeown`
- PowerShell ACL cmdlets
- Windows native APIs for security descriptors

Artifacts often include:
- Modified ACLs on sensitive files or directories
- Ownership changes on system or application paths
- Permission changes preceding file modification or execution
- Security logs indicating object access changes

---

## 3. Subtechnique Considerations
Key considerations for T1222.001:
- Often a **precursor** to binary replacement or persistence
- ACL changes alone may be benign; context is critical
- High-risk when targeting system directories, service paths, or security tooling
- Detection requires correlating permission changes with follow-on behavior

---

## 4. Procedure Examples
Observed adversary behaviors include:
- Granting write access to system binaries prior to replacement
- Taking ownership of service configuration files
- Weakening permissions on startup folders or scripts
- Modifying ACLs to block security software access

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **sequence-based analysis**:
- Permission/ownership change → file write → execution
- ACL changes outside approved maintenance windows
- Changes initiated by unusual processes or accounts
- Modifications to high-value paths (e.g., `System32`, Program Files)

### Data Source Notes
- **Windows Security Logs**: Events such as 4670 and 4663
- **Process telemetry**: Identify tools performing ACL changes
- **EDR telemetry**: Correlate permission changes with file and process activity

False positives commonly include:
- Legitimate administrative maintenance
- Software installation or patching
- Configuration management tools

---

## 6. Response Guidance
When detected:
1. Identify the account and process responsible
2. Review which objects were modified and how
3. Check for follow-on file changes or execution
4. Restore permissions from known-good baselines
5. Investigate for additional persistence mechanisms

## 8. SOC Relevance
T1222.001 is highly relevant in:
- Windows enterprise environments
- Ransomware and post-exploitation activity
- Intrusions targeting persistence or binary tampering

Permission changes on protected paths should be treated as high-risk.

---

## 9. Threat Actor Usage
This subtechnique is commonly used by:
- Ransomware operators
- Advanced persistent threats
- Post-exploitation frameworks

Usage typically reflects deliberate preparation for follow-on actions.

---

## 10. Campaign Usage
Observed in:
- Ransomware intrusion chains
- Persistence establishment phases
- Malware staging operations

---

## 11. Malware Usage
Associated with:
- Loaders and implants that replace binaries
- Ransomware adjusting permissions to access files
- Tooling that disables or bypasses defenses

---

## 12. Mitigations
Recommended mitigations:
- Restrict administrative privileges
- Monitor and baseline ACL changes on sensitive paths
- Enforce application control policies
- Use file integrity monitoring
- Harden permissions on startup and service-related files

---

## 13. Testing & Validation
Validation approaches:
- Perform controlled ACL changes in lab systems
- Validate SOC alerting on high-risk permission modifications
- Test correlation logic with follow-on file writes
- Review detection gaps across Windows telemetry
