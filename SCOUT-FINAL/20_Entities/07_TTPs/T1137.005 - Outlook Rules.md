# T1137.005 – Outlook Rules

## 1. Technique Overview
**Outlook Rules (T1137.005)** is a sub-technique of [[20_Entities/07_TTPs/T1137 - Office Application Startup|T1137]] in **MITRE ATT&CK v18**. Adversaries abuse **Microsoft Outlook message rules** to trigger malicious actions automatically when emails are received, sent, or processed. Rules can execute scripts, launch applications, forward messages, or move content in ways that support persistence and follow-on activity.

Because rules operate transparently during normal email handling, this technique enables low-noise, user-context persistence.

## 2. Adversary Objectives
Adversaries use Outlook Rules to:
- Execute malicious actions without direct user interaction
- Maintain persistence tied to routine email traffic
- Facilitate data collection or exfiltration via automated forwarding
- Blend malicious behavior into legitimate Outlook automation

## 3. Common Abuse Patterns
- Creating rules that run programs or scripts on message receipt
- Auto-forwarding or copying emails to attacker-controlled accounts
- Triggering execution when emails with specific subjects or senders arrive
- Using hidden or obscure rules to reduce user visibility
- Combining with malicious attachments or forms to chain execution

## 4. Detection Considerations
Detection relies on **email client configuration and behavior monitoring**, including:
- Auditing Outlook rules for unexpected actions or conditions
- Monitoring changes to rule sets via client-side or server-side logs
- Detecting execution of programs initiated by Outlook
- Correlating rule creation/modification with suspicious email activity
- Reviewing mailbox audit logs where available

## 5. Defensive Mitigations
- Restrict the ability to create rules that execute programs or scripts
- Monitor and alert on creation or modification of Outlook rules
- Educate users on reviewing and managing their Outlook rules
- Apply mailbox auditing and logging for rule changes
- Remove unauthorized rules during incident response

## 6. Operational Impact
If successful, T1137.005 can:
- Provide stealthy persistence driven by normal email workflows
- Enable automated execution or data exfiltration
- Persist across system reboots without additional artifacts
- Complicate detection due to legitimate-looking automation

## 7. Analyst Notes
Outlook Rules abuse often surfaces as **unexpected email forwarding or silent execution**. Analysts should review both client-side and server-side rule configurations when investigating email-centric intrusions, especially when activity correlates with message receipt rather than document interaction.
