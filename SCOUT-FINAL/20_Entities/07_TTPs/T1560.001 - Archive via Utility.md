## 1. Summary
Adversaries may use built-in or third-party **utilities** to compress, encrypt, or encode collected data prior to exfiltration (e.g., `zip`, `tar`, `7z`, `rar`, `makecab/diantz`, and Windows encoding via `certutil`). Utility-based archiving is typically high-visibility and high-signal when correlated with staging paths and subsequent outbound transfer.

## 2. Technical Overview
**What it is:** Execution of an archiving/encoding tool to produce a container (archive) or encoded blob for transport.

**Common utility patterns (defender view):**
- **Windows:** `makecab.exe` / `diantz.exe` to generate `.cab`; PowerShell `Compress-Archive`; third-party archivers (7-Zip/WinRAR/WinZip); `certutil` for Base64 encoding.
- **Linux/macOS:** `tar`, `gzip`, `bzip2`, `xz`, `zip`, `openssl` (for encryption) producing `.tar.*`, `.zip`, encrypted outputs.

**High-signal behaviors:**
- Non-admin/atypical processes spawning archivers (Office, browsers, scripting hosts).
- Archive creation in `%TEMP%`, user profile cache folders, `/tmp`, `/var/tmp`, newly created hidden directories.
- Password-protected archives (where command-line switches are visible) and unusually large archives or rapid bursts of many archives.

## 5. Detection Guidance
Focus on **execution-to-artifact correlation** and **context anomalies**.

**MITRE Detection Strategy (DET0298) highlights:**
- Correlate **process creation** of archiving tools with **file creation** of archive extensions (e.g., `.zip/.rar/.7z/.cab/.tar.gz`) in suspicious directories.
- Detect anomalous **module loads** indicating encryption activity during archiving (e.g., crypto-related libraries loaded by unexpected processes).
- On Linux/macOS, correlate **command execution** of archivers/encryption utilities with archive outputs in staging paths.

**Recommended analytic enrichments:**
- Allowlist known business archivers and scheduled backup tasks.
- Add thresholds for file size and rate-of-creation (bursting archive outputs is suspicious).
- Track “rare parent” relationships (archiver executed by unusual parent processes).

### 5.1 Data Source Notes
Primary data components from DET0298:
- **Process Creation (DC0032)**: Windows 4688/Sysmon, macOS unified logs
- **File Creation (DC0039)**: Sysmon 11, auditd file events, macOS file IO telemetry
- **Module Load (DC0016)**: Sysmon 7 (notable for crypto/compression libraries)
- **Command Execution (DC0064)**: auditd execve for tar/gzip/zip/openssl, etc.

**Practical telemetry requirements:**
- Command line capture for utility invocation (to spot archive switches, password flags, output paths).
- File metadata capture: path, size, extension, hash; optional entropy measurement for encrypted archives.

## 6. Response Guidance
1. **Preserve artifacts:** Collect the created archive(s) and compute hashes; note size and creation time.
2. **Reconstruct lineage:** Identify the full process tree, user context, and origin (interactive shell, script, RMM, service).
3. **Check for staging + egress:** Determine whether archives were moved, uploaded, emailed, or sent via C2/exfil channels.
4. **Contain and remediate:** Isolate host if active exfil; block destinations; rotate credentials that may be included in archives.
5. **Enterprise hunt:** Search for the same archiver binary/hash/command line patterns across fleet.

## 8. SOC Relevance
**Alerting sweet spots:**
- Archive utility execution from “rare” parents + archive output in staging paths.
- Archive creation immediately preceding spikes in outbound traffic or new external connections.
- Password-protected archive creation by non-admin users or service accounts.

**Noise management:**
- Backups, developer workflows, and packaging pipelines can be noisy—control via allowlists, directory scopes, and maintenance windows.
