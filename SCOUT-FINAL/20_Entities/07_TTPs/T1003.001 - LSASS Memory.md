## 1. Summary
LSASS Memory (T1003.001) is a subtechnique of OS Credential Dumping where adversaries attempt to access credential material stored in the memory of the Local Security Authority Subsystem Service (LSASS) on Windows. This can yield hashes and, depending on configuration, plaintext or reusable credential material.

## 2. Technical Overview
Credential material is present in LSASS after logon events and may include authentication artifacts used by Windows subsystems. Adversaries commonly:
- Read LSASS process memory directly (requires high privileges).
- Trigger a process memory dump of LSASS and analyze it offline.
- Abuse legitimate/dual-use mechanisms to produce dumps, then parse for credential artifacts.

Defender-relevant traits:
- **Handle access to `lsass.exe`** with suspicious access rights.
- **Dump artifact creation** (file writes) combined with unusual process lineage.
- **Execution from atypical hosts** (e.g., DCs, jump servers) and **post-dump lateral authentication**.

## 3. Subtechnique Considerations
- This note covers the Windows-specific LSASS memory target; broader T1003 detections should include other subtechniques (SAM, NTDS, LSA Secrets, DCSync, etc.).
- LSASS protections vary by OS version and configuration; detection logic should incorporate whether protections like protected processes are enabled.

## 4. Procedure Examples
- C0025 - 2016 Ukraine Electric Power Attack: [[30_CIPHER/03_Threat_Actors/G0034 - Sandworm Team]] used [[30_CIPHER/05_Malware/S0002 - Mimikatz]] for credential capture/use (per ATT&CK procedure examples).
- [[30_CIPHER/03_Threat_Actors/G1030 - Agrius]]: used credential dumping tooling (including [[30_CIPHER/05_Malware/S0002 - Mimikatz]]) to dump LSASS memory.
- [[30_CIPHER/03_Threat_Actors/G0006 - APT1]]: known to use credential dumping with [[30_CIPHER/05_Malware/S0002 - Mimikatz]].
- [[30_CIPHER/03_Threat_Actors/G0007 - APT28]]: dumped LSASS memory and used publicly available credential dumping tooling.

## 5. Detection Guidance
Strongest detections are behavior chains, not single events.

Recommended analytics:
- **Process access → dump sequence (high confidence)**
  - A process opens a handle to `lsass.exe` with high access rights, followed by:
    - memory dump-related behavior, and/or
    - creation of a dump file, and/or
    - suspicious registry modifications associated with credential harvesting workflows
- **Untrusted dumper identification**
  - Flag dump activity when the process lineage is unusual for the host role (e.g., Office child process dumping LSASS on a server).
- **Dump file handling**
  - Detect creation of large dump-like files in user/temp paths and immediate read/compression/exfil behavior.
- **Post-dump credential use**
  - Correlate with rapid new authentications (SMB/RDP/WinRM/LDAP) from the same host/account following suspected dump activity.

Tuning guidance:
- Maintain an allowlist of legitimate security/IR tooling used in your environment; alert on everything else.
- Pay special attention to LSASS access from non-admin contexts, LOLBin-like lineage, and suspicious remote sessions.

### Data Source Notes
Map to telemetry you actually collect:
- **EDR**: process handle operations, memory access, suspicious API usage, process injection indicators, file creation for dumps, parent/child chains.
- **Windows eventing**: security logs (new logons, special privileges), Sysmon-like telemetry if deployed, protected process configuration state.
- **Network/identity**: downstream lateral authentication attempts and service access after the dump.

## 6. Response Guidance
- **Contain**: isolate host; terminate suspicious processes; prevent further credential use (block outbound admin protocols temporarily if needed).
- **Credential actions**: reset impacted accounts; rotate privileged credentials; invalidate sessions/tickets as appropriate.
- **Scope & hunt**: search for similar LSASS access patterns across fleet; identify any follow-on lateral movement.
- **Hardening**: enable/validate OS protections for credential material and tighten privileged account exposure.

## 8. SOC Relevance
- **Critical**: LSASS dumping often precedes domain-wide compromise, ransomware, or rapid privilege escalation.
- **Fastest pivots**: (1) the dumping process + lineage, (2) dump artifact path, (3) subsequent authentication spread.

## 9. Threat Actor Usage
- Many actors use LSASS dumping due to its high ROI on Windows estates.
- Notable examples: [[30_CIPHER/03_Threat_Actors/G0034 - Sandworm Team]], [[30_CIPHER/03_Threat_Actors/G1030 - Agrius]], [[30_CIPHER/03_Threat_Actors/G0007 - APT28]].

## 10. Campaign Usage
- C0025 - 2016 Ukraine Electric Power Attack: included LSASS credential dumping activity (per ATT&CK procedure examples).

## 11. Malware Usage
- [[30_CIPHER/05_Malware/S0002 - Mimikatz]]: commonly used to extract credential material from LSASS dumps/memory.

## 12. Mitigations
(From ATT&CK mitigation guidance for this subtechnique)
- **M1025 - Privileged Process Integrity**: enable protections for sensitive processes where supported (e.g., protected process settings for LSA/LSASS-related components).
- **M1017 - User Training**: reduce password reuse/overlap; reinforces that credential hygiene limits the blast radius after dumping.

## 13. Testing & Validation
- In an isolated lab:
  - Use approved internal tools to generate LSASS access + dump artifact creation.
  - Validate detection logic for the chain: handle access → dump → file write → suspicious follow-on auth.
- Validate allowlists for legitimate security tooling to control false positives.
