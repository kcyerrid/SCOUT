# Subvert Trust Controls: SIP and Trust Provider Hijacking (T1553.003)

## 1. Summary
SIP and Trust Provider Hijacking describes adversaries **manipulating or replacing system components responsible for validating digital signatures and trust decisions**, causing the operating system to incorrectly treat malicious code as trusted. On Windows, this involves hijacking or modifying Software Identification Policy (SIP) or trust providers; on macOS, it may involve tampering with trust evaluation mechanisms tied to code signing and integrity enforcement.

Adversaries use this technique to:
- Bypass signature validation
- Execute malicious code without warnings
- Undermine application control mechanisms
- Enable stealthy execution of unsigned or modified binaries

---

## 2. Technical Overview
Operating systems rely on trust providers to determine whether code is trusted before execution. Adversaries subvert these mechanisms by:
- Modifying or replacing trust provider DLLs or libraries
- Altering registry keys that define trust provider behavior (Windows)
- Hijacking trust validation flows used by code-signing checks
- Abusing misconfigurations or legacy trust settings

Common artifacts include:
- Unauthorized modifications to trust provider binaries
- Registry changes impacting signature validation
- Execution of binaries that should fail trust checks
- Altered system libraries related to code integrity

---

## 3. Subtechnique Considerations
Key considerations for T1553.003:
- Requires elevated privileges
- Impact is systemic and affects multiple applications
- Detection is difficult without integrity monitoring
- Often paired with masquerading or signed malware delivery

Trust provider hijacking **breaks the foundation of execution trust**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Replacing or modifying trust provider components
- Altering registry entries to redirect trust checks
- Forcing trust validation to always succeed
- Executing unsigned malware that appears trusted

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **integrity and configuration monitoring**:
- Monitor changes to trust provider binaries and libraries
- Alert on registry modifications tied to trust validation
- Detect execution of unsigned code without warnings
- Correlate trust provider changes with suspicious execution

### Data Source Notes
- **Registry monitoring**: Detect changes to SIP and trust provider keys
- **File integrity monitoring**: Identify unauthorized library changes
- **EDR telemetry**: Observe anomalous execution paths

Common false positives:
- OS updates or patches
- Legitimate security software modifying trust behavior

Tuning guidance:
- Baseline known-good trust provider files and registry keys
- Correlate changes with patching or maintenance windows

---

## 6. Response Guidance
When suspected:
1. Identify modified trust provider components
2. Restore affected files and registry keys from trusted sources
3. Reboot systems to reinitialize trust mechanisms
4. Hunt for malware executed under compromised trust
5. Assess for additional defense evasion techniques

## 8. SOC Relevance
T1553.003 is critical because:
- It undermines the core trust model of the OS
- Malicious execution may appear fully legitimate
- Traditional signature-based defenses may fail

SOC teams must monitor **trust infrastructure integrity**, not just malware indicators.

## 12. Mitigations
Recommended mitigations:
- Protect trust provider files and registry keys
- Enforce file integrity monitoring
- Restrict administrative access
- Validate trust behavior after system changes

## 13. Testing & Validation
Validation approaches:
- Simulate trust provider tampering in a lab
- Validate alerts on registry and file modifications
- Test execution of unsigned code post-tamper
- Ensure rapid rollback procedures are in place

Include:
- Preconditions: integrity monitoring enabled
- Required roles/tools: SOC, endpoint engineering
- Expected outcomes: detection of trust hijacking
- Success criteria: alerting before widespread abuse
