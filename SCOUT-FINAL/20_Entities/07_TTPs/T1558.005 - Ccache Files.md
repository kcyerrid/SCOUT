## 1. Summary
**Ccache Files (T1558.005)** involves stealing Kerberos tickets stored in **credential cache (ccache)** locations on Linux/macOS systems to enable **Pass the Ticket** style authentication without re-entering user passwords. This is especially relevant on systems joined to AD realms or otherwise using Kerberos.

## 2. Technical Overview
Defender-relevant behaviors:
- **Accessing ccache storage** paths or interfaces:
  - Linux commonly stores tickets under `/tmp` in formats like `krb5cc_%UID%` or `krb5.ccache`.
  - macOS may store ccache entries in memory with an `API:{uuid}` naming scheme.
- Configuration influences:
  - `/etc/krb5.conf` and the `KRB5CCNAME` environment variable can control ccache storage location.
- Legitimate utilities:
  - Built-in binaries (e.g., `kinit`, `klist`) commonly interact with ticket storage; anomalous usage outside normal context is high signal.

## 3. Subtechnique Considerations
- Linux/macOS Kerberos environments are often under-instrumented compared to Windows DC logging.
- High-signal conditions:
  - Access to many users’ ccache files on shared systems
  - Non-standard processes enumerating `/tmp/krb5cc_*` patterns or attempting to extract memory-based caches
- This subtechnique can be a precursor to lateral movement and privilege escalation.

## 4. Procedure Examples
MITRE ATT&CK procedure examples include:
- [[30_CIPHER/05_Malware/S0357 - Impacket]] tools (e.g., `getST.py`, `ticketer.py`) used to steal or forge Kerberos tickets using ccache files given relevant authentication material.

## 5. Detection Guidance
Prioritize **file access + process context** (aligned to ATT&CK Detection Strategy **DET0024**):

High-signal detection themes:
- **Unauthorized access/copy/modification** of ccache files:
  - `/tmp/krb5cc_*` or `/tmp/krb5.ccache`
  - Custom paths set via `KRB5CCNAME`
- **Process allowlisting**:
  - Alert when non-baselined processes access ccache files; treat unexpected access by interpreters or newly dropped binaries as high risk.
- **Correlation to auth activity**:
  - ccache access → subsequent anomalous Kerberos authentication from unusual processes or contexts
- macOS-specific:
  - Abnormal interactions with memory-based Kerberos cache APIs by non-standard processes

### Data Source Notes
Recommended telemetry:
- Linux audit telemetry (e.g., auditd/eBPF/EDR) for file open/read/copy events on `/tmp/krb5cc_*`
- Process execution telemetry (execve lineage, user, working directory)
- Kerberos authentication telemetry (where available) from impacted hosts and realm infrastructure
- Environment variable capture (e.g., unusual `KRB5CCNAME` usage)

## 6. Response Guidance
- **Contain**: isolate suspicious processes/hosts; terminate unauthorized collectors.
- **Credential actions**: invalidate tickets by forcing reauthentication where feasible; rotate credentials for impacted users/service accounts if compromise is suspected.
- **Scope**:
  - Identify which users’ caches were accessed and by which processes
  - Hunt for subsequent Kerberos-authenticated access from unusual contexts
- **Hardening**:
  - Tighten permissions and monitoring on ticket storage locations; ensure Kerberos is disabled where not required.

- High relevance for Linux/macOS fleets joined to AD or using Kerberos (engineering workstations, build servers, bastions).
- Best pivots:
  - File-access events on `/tmp/krb5cc_*` → process lineage and binary provenance
  - `KRB5CCNAME` overrides → unusual cache locations and persistence patterns
  - Follow-on Kerberos-authenticated activity from unexpected processes

## 12. Mitigations
- **M1047 - Audit**: enable audits/scans of permissions and insecure configurations; use auditing to monitor access to `/tmp` ccache artifacts and ticket-related files.
- **M1043 - Credential Access Protection**: protect resources using mechanisms such as SELinux by defining entry points, process types, and file labels.

## 13. Testing & Validation
- Validate detections for:
  - Access to `/tmp/krb5cc_*` by non-baselined processes
  - Abnormal `KRB5CCNAME` usage and unexpected cache locations
  - Correlation of cache access with follow-on Kerberos authentication anomalies
- Ensure SOC runbooks include rapid scoping of impacted user caches and downstream access.
