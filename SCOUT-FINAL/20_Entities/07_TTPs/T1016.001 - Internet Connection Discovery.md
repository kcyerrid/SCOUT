## 1. Summary
Internet Connection Discovery is used to determine whether a compromised host has Internet access and, in some cases, what path it uses (routing/proxy/redirectors) before initiating C2 or staging additional activity.

## 2. Technical Overview
Typical behaviors include:
- Connectivity probes (ICMP, traceroute-like utilities, or lightweight HTTP(S) requests)
- “Reachability” checks to known external domains or infrastructure
- Optional bandwidth/latency checks in automation pipelines

This commonly appears as a prerequisite to C2, tool download, or data exfiltration.

## 3. Subtechnique Considerations
- Sub-technique of [[20_Entities/07_TTPs/TA0007 - Discovery/T1016 - System Network Configuration Discovery|T1016]].
- Detection is often **high-noise** because many legitimate applications perform network connectivity checks. Prioritize:
  - Unusual process ancestry (unknown binary performing repeated probes)
  - Newly dropped binaries performing immediate outbound checks
  - Connectivity checks immediately preceding suspicious domain beacons/downloads

## 4. Procedure Examples
- **[[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29 (G0016)]]** ensured systems were Internet accessible before transferring tools/malware.
- **[[30_CIPHER/05_Malware/S1066 - DarkTortilla|DarkTortilla (S1066)]]** can verify connectivity via HTTP GET requests.
- **[[30_CIPHER/03_Threat_Actors/G1016 - FIN13|FIN13 (G1016)]]** used common connectivity tools for reconnaissance.

## 5. Detection Guidance
Detection focus areas:
- **Process-centric**: first-seen executables initiating external connectivity tests.
- **Temporal correlation**: connectivity checks followed by new outbound destinations, download activity, or C2 framework launch.
- **Frequency anomalies**: repeated/periodic checks at unusual intervals by non-browser/non-agent processes.

Practical detection patterns:
- PowerShell: unusual scripts invoking web request primitives shortly after execution.
- Endpoint tools invoking traceroute-like behavior in non-admin user context.
- Short-lived processes whose only behavior is outbound “test” traffic.

### Data Source Notes
Common telemetry sources:
- Process creation + command line
- PowerShell script block and module logging (Windows)
- DNS query logs (resolver, EDR) + proxy logs (HTTP CONNECT, GET/HEAD)
- Network flow logs (egress to uncommon destinations)

## 6. Response Guidance
1. **Identify the checking process** and validate signer, prevalence, and origin path.
2. **Pivot to subsequent activity** (new domains, downloads, C2) within minutes of the check.
3. **Block/contain** only after confirming malicious context to avoid disrupting legitimate health checks.

- Useful as an **early-stage marker** when paired with suspicious execution context.
- Alone, it is rarely sufficient for alerting due to routine software behavior.

## 12. Mitigations
- Maintain robust egress controls and proxy logging
- Restrict execution of untrusted binaries from user-writable locations
- Improve detection precision with allowlisted enterprise agents (EDR, browser updaters)
