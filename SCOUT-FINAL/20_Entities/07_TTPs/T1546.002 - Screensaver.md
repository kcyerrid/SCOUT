# T1546.002 – Screensaver

## 1. Technique Overview
**Screensaver (T1546.002)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse the Windows screensaver mechanism by configuring a malicious `.scr` file or altering screensaver settings so that attacker-controlled code executes automatically when the system enters an idle state.

Because screensavers are a legitimate feature and execution is event-driven, this technique can provide low-noise persistence that blends into normal user behavior.

## 2. Adversary Objectives
Adversaries use screensaver abuse to:
- Establish persistence tied to system idle events
- Execute malicious code without direct user interaction
- Avoid more commonly monitored startup mechanisms
- Trigger payloads in predictable but infrequent intervals

## 3. Common Abuse Patterns
- Setting a malicious `.scr` file as the active screensaver
- Modifying registry keys such as:
  - `HKCU\Control Panel\Desktop\SCRNSAVE.EXE`
- Reducing screensaver timeout values to increase execution frequency
- Masquerading malicious screensavers as legitimate system files
- Deploying screensavers that launch secondary payloads

## 4. Detection Considerations
Detection relies on **registry, configuration, and process monitoring**, including:
- Monitoring changes to screensaver-related registry keys
- Alerting on non-standard `.scr` files configured as screensavers
- Correlating idle events with suspicious process execution
- Reviewing screensaver paths for unexpected locations
- Comparing screensaver configurations against known-good baselines

## 5. Defensive Mitigations
- Restrict permissions to modify screensaver settings where feasible
- Monitor and alert on changes to screensaver configuration
- Enforce application allowlisting for `.scr` files
- Regularly audit screensaver settings across endpoints
- Disable screensavers entirely if not required

## 6. Operational Impact
If successful, T1546.002 can:
- Provide event-driven persistence with minimal user interaction
- Evade detection mechanisms focused on boot or logon persistence
- Enable execution at predictable idle intervals
- Complicate forensic timelines due to delayed execution

## 7. Analyst Notes
Screensaver-based persistence is less common today but remains effective in environments where screensavers are still enabled and lightly monitored. During investigations, analysts should review **screensaver configuration and file provenance**, especially if malicious activity correlates with idle periods.
