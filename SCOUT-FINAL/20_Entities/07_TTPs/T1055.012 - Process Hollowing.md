# Process Injection: Process Hollowing (T1055.012)

## 1. Summary
Process Hollowing describes adversaries **creating a legitimate process in a suspended state, removing its original code from memory, and replacing it with malicious code before resuming execution**. The resulting process appears legitimate on disk while executing attacker-controlled payloads in memory.

T1055.012 is commonly used to:
- Evade application allowlisting and signature-based detection
- Execute malware under trusted process identities
- Bypass parent–child process relationship heuristics
- Support stealthy loaders and multi-stage malware

---

## 2. Technical Overview
Process hollowing typically involves the following steps:
1. Create a benign process in a suspended state (e.g., `CreateProcess` with `CREATE_SUSPENDED`)
2. Unmap or overwrite the process’s original executable image
3. Inject a malicious PE into the process’s address space
4. Update the process entry point to the injected payload
5. Resume the process thread

Common APIs and mechanisms involved:
- `CreateProcess`
- `NtUnmapViewOfSection`
- `VirtualAllocEx`
- `WriteProcessMemory`
- `SetThreadContext`
- `ResumeThread`

Artifacts often include:
- Legitimate executables executing unexpected behavior
- Memory regions containing PE structures not backed by disk files
- Suspended process creation followed by memory modification
- Entry points differing from on-disk images

---

## 3. Subtechnique Considerations
Key considerations for T1055.012:
- Highly effective against disk-based detections
- Requires careful PE mapping and thread manipulation
- Often used by loaders and droppers
- Detection requires correlating process creation with memory behavior

Process hollowing remains one of the most widely abused injection techniques.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Hollowing system utilities (e.g., `svchost.exe`, `notepad.exe`)
- Using process hollowing as a first-stage loader
- Injecting encrypted or packed payloads
- Combining hollowing with user execution or phishing delivery

These actions typically occur early in the execution chain.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying suspended process creation followed by memory writes
- Detecting mismatches between process memory and on-disk images
- Monitoring thread context manipulation
- Correlating module load anomalies with process startup events

### Data Source Notes
- **Process telemetry**: Required for detecting suspended starts
- **Memory telemetry**: Essential for identifying hollowed images
- **API telemetry**: Enables detection of unmap and context changes

---

## 6. Response Guidance
When suspected:
1. Identify hollowed processes and isolate affected systems
2. Capture memory images for forensic analysis
3. Terminate malicious processes where operationally safe
4. Investigate parent processes and delivery vectors
5. Search for additional payloads or persistence mechanisms

Malware leveraging process hollowing includes:
- Loaders and droppers

## 12. Mitigations
Recommended mitigations:
- Use EDR capable of memory and behavior analysis
- Monitor for suspended process creation abuse
- Enforce application control and exploit mitigation
- Correlate process startup with memory behavior
- Apply least privilege principles
