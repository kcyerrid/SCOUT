# Modify Cloud Compute Infrastructure: Delete Cloud Instance (T1578.003)

## 1. Summary
Delete Cloud Instance describes adversaries **intentionally deleting cloud compute resources** to disrupt operations, destroy evidence, evade detection, or impede incident response. In cloud environments, deletion may be irreversible or require significant effort to recover.

Attackers use this technique to:
- Cause service outages or data loss
- Destroy forensic evidence
- Disrupt incident response and recovery
- Accelerate impact during destructive operations

---

## 2. Technical Overview
Cloud providers allow privileged identities to delete compute resources via control-plane APIs. Adversaries abuse this capability by:

- Terminating virtual machines or instances
- Deleting container workloads or node pools
- Removing serverless functions
- Targeting systems hosting logs, sensors, or business-critical services

Key characteristics:
- Resource termination events in audit logs
- Loss of compute without prior scaling activity
- Deletion shortly after suspicious authentication
- Gaps in telemetry following resource removal

Indicators include:
- Instance deletion outside change windows
- Deletion performed by non-standard identities
- Coordinated deletion of multiple resources
- Absence of backups or snapshots prior to deletion

---

## 3. Subtechnique Considerations
Key considerations for T1578.003:
- Strong overlap with **Indicator Removal on Host (T1070)** in cloud contexts
- Frequently paired with **Data Destruction (T1485)** or **Inhibit System Recovery (T1490)**
- Often used late in the attack lifecycle
- Impact may be immediate and severe

This technique is **both evasive and destructive**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Deleting instances hosting security tooling
- Terminating workloads to cover tracks
- Coordinated deletion to cause outages
- Removing resources before credential revocation

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **resource deletion monitoring and blast-radius analysis**:
- Alert on instance deletion events
- Detect deletions performed by unusual identities
- Correlate deletions with authentication anomalies
- Monitor for rapid or bulk deletion activity

### Data Source Notes
- **Cloud audit logs**: Primary detection source
- **IAM logs**: Attribute deletion to identities
- **Backup logs**: Detect absence of recovery points

Common false positives:
- Legitimate decommissioning
- Approved infrastructure changes

Tuning guidance:
- Require approvals for deletion actions
- Protect critical resources with deletion safeguards
- Elevate severity for deletions following suspicious access

---

## 6. Response Guidance
When suspected:
1. Immediately identify scope of deleted resources
2. Initiate recovery from snapshots or backups
3. Revoke credentials used for deletion
4. Preserve audit logs and control-plane telemetry
5. Harden deletion permissions and safeguards

## 8. SOC Relevance
T1578.003 is critical because:
- Cloud deletions can be instantaneous and irreversible
- Forensic artifacts may be permanently lost
- Impact may exceed on-prem destructive actions

SOC teams must treat **deletion events as high-severity incidents**.

---

## 9. Threat Actor Usage
Commonly used by:
- Destructive actors
- Ransomware operators
- Intruders seeking to erase evidence

---

## 10. Campaign Usage
Observed in:
- Ransomware and extortion campaigns
- Cloud sabotage operations
- Final-stage intrusion cleanup

---

## 11. Malware Usage
Associated with:
- Little or no malware
- Scripted cloud abuse
- Control-plane–only attacks

---

## 12. Mitigations
Recommended mitigations:
- Enforce least-privilege IAM policies
- Enable deletion protection on critical resources
- Require multi-party approval for destructive actions
- Maintain frequent backups and snapshots

---

## 13. Testing & Validation
Validation approaches:
- Simulate controlled instance deletions in test environments
- Validate alerts on deletion events
- Test IR workflows for cloud destruction scenarios
- Ensure backup and recovery procedures are effective
