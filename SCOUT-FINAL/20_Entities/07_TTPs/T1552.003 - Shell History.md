## 1. Summary
Adversaries may search shell/command history for insecurely stored credentials (e.g., users typing passwords/tokens on the command line as arguments). This can yield secrets without needing credential dumping.

## 2. Technical Overview
Common locations/artifacts:
- **Linux/macOS**: `~/.bash_history`, `~/.zsh_history`, and related shell history files
- **Windows PowerShell**:
  - Session history (non-persistent)
  - Persistent history (e.g., PSReadLine history file in user profile)

Defender-relevant behavior:
- Direct reads of history files by non-interactive or unexpected processes
- Credential-like pattern discovery (e.g., `-p <password>`, `--token`, `AWS_SECRET_ACCESS_KEY`)
- Follow-on authentication attempts using discovered secrets

## 3. Subtechnique Considerations
- History file reads can be legitimate (backup, search by user), but:
  - Non-user processes reading history files is high-signal
  - Access shortly after privilege escalation or account compromise is particularly suspicious

## 4. Procedure Examples
MITRE documents:
- [[30_CIPHER/05_Malware/S0599 - Kinsing|Kinsing]] searching `bash_history` for credentials.

## 5. Detection Guidance
High-signal detections:
- Non-interactive processes reading `~/.bash_history` / `~/.zsh_history`
- Utility access patterns (`cat`, `less`, `grep`) launched from suspicious parents or automation contexts
- On Windows, unexpected access to PowerShell persistent history file by non-console processes

Correlation opportunities:
- History file read → outbound auth attempts (SSH, cloud CLI usage, SaaS login) within a short time window
- History file read across multiple user profiles (fleetwide credential harvesting)

### Data Source Notes
Telemetry to prioritize (vendor-neutral):
- EDR file read/open telemetry for history paths
- Linux auditd (file access) or equivalent EDR sensor logs
- macOS EndpointSecurity Framework telemetry (via EDR) for file reads
- PowerShell logging and Windows file access telemetry for PSReadLine history file
- Network/auth logs for subsequent credential use

## 6. Response Guidance
1. **Containment**
   - Rotate any credentials discovered in history (keys/tokens/passwords) and invalidate sessions.
2. **Eradication**
   - Remove malicious tooling; investigate for broader credential access.
3. **Hardening**
   - Educate admins/devs to avoid passing secrets on command lines.
   - Migrate to secret managers and env-var/STDIN patterns for tooling.

## 8. SOC Relevance
Moderate-to-high relevance in environments with:
- Heavy CLI usage (admins, developers, SRE)
- Cloud tooling usage where tokens might be passed as args
- Shared bastion/jump hosts with many users

SOC triage:
- Confirm whether the accessing process is user-initiated.
- Determine if credential-like strings exist in history around the access time.
- Hunt for similar access on other users/hosts.
