# Access Token Manipulation: Create Process with Token (T1134.002)

## 1. Summary
This subtechnique describes adversaries **creating new processes using stolen or duplicated access tokens** to run code under the security context of another user or service. Unlike pure token impersonation, this approach results in a **new primary process** that inherits the privileges of the supplied token.

T1134.002 is commonly used to:
- Spawn SYSTEM- or administrator-level processes
- Maintain elevated execution without continuous impersonation
- Blend malicious processes with legitimate privileged activity

---

## 2. Technical Overview
Windows provides APIs that allow a process holding a valid token to spawn a new process under that token’s context. Adversaries abuse this by:
- Stealing or duplicating privileged tokens
- Using those tokens to create new processes
- Running commands or payloads with elevated privileges

Common APIs involved include:
- `CreateProcessAsUser`
- `CreateProcessWithTokenW`
- `CreateProcessWithLogonW`

Artifacts often include:
- Elevated processes with no corresponding interactive logon
- Parent–child relationships inconsistent with normal administrative workflows
- Privileged processes launched from user-space parents

---

## 3. Subtechnique Considerations
Key considerations for T1134.002:
- Requires access to a valid privileged token
- Often paired with token theft or impersonation
- Generates persistent elevated processes, increasing dwell time
- Detection hinges on correlating process context with authentication activity

This subtechnique is highly reliable once token access is achieved.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Creating SYSTEM-level shells from user-level malware
- Spawning elevated command interpreters to perform follow-on actions
- Using stolen service account tokens to launch tooling
- Combining process creation with token duplication for stealth

These actions typically occur after local privilege escalation or credential access.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying processes created with privileged tokens but lacking logon events
- Detecting unusual parent–child process relationships
- Monitoring usage of process-creation APIs associated with token abuse
- Correlating token usage with prior token theft activity

### Data Source Notes
- **Process telemetry**: Critical for detecting anomalous execution chains
- **Security logs**: Help validate whether legitimate authentication occurred
- **API monitoring**: Enables detection of token-based process creation

---

## 6. Response Guidance
When suspected:
1. Identify processes created with stolen or duplicated tokens
2. Terminate malicious elevated processes
3. Investigate the source of the token used
4. Review for additional token abuse or lateral movement
5. Reset credentials tied to the abused token

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege for services and users
- Monitor and restrict token manipulation APIs
- Detect anomalous privileged process creation
- Apply OS and security patches
- Use EDR with deep process and token visibility
