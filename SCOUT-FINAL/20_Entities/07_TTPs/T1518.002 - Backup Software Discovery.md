# T1518.002 - Software Discovery: Backup Software Discovery

## 1. Summary
Adversaries discover **backup software and backup-related configurations** to inform follow-on actions such as inhibiting recovery, targeting backup repositories, or shaping destructive/impact activity.

## 2. Technical Overview
Backup discovery may include:
- Enumerating installed backup products and agents
- Identifying backup services, scheduled jobs, or configuration files
- Locating backup storage paths, repositories, or management consoles
- Checking for common backup vendor artifacts (software, services, directories, registry keys)

This behavior is commonly associated with **impact preparation**, especially when paired with privilege escalation and lateral movement toward backup infrastructure.

## 3. Subtechnique Considerations
- This sub-technique is more specific than generic software discovery:
  - Use **T1518.002** when the discovery clearly targets backup tooling/configuration.
  - If the discovery targets security tooling broadly, use **T1518.001**.
  - If discovery is broad and non-specific, use **T1518**.

## 4. Procedure Examples
MITRE procedure examples include:
- [[30_CIPHER/03_Threat_Actors/G0102 - Wizard Spider|Wizard Spider]] using a PowerShell script to collect installed backup software information from compromised machines (per the technique page).

## 5. Detection Guidance
Treat as high priority because it often precedes **inhibit recovery** and **data encrypted/destruction** behaviors.

High-signal patterns:
- Backup discovery from **non-admin endpoints** or **user workstations**.
- Discovery executed soon after privilege escalation or shortly before service disruption events.
- Repeated attempts to identify specific backup vendor artifacts across filesystem/services/registry.

Detection engineering patterns:
- Detect enumeration of:
  - backup-related services and installed software
  - backup-related directories and known configuration locations
  - registry/service manager queries aligned to backup products
- Correlate with:
  - access to backup servers/management consoles
  - suspicious credential use by privileged accounts
  - attempts to disable/stop services or delete snapshots

### Data Source Notes
Key telemetry:
- Endpoint process creation + command line (PowerShell/cmd/shell invocations)
- Service enumeration telemetry (EDR/Windows)
- Registry access telemetry (Windows/EDR)
- Server-side logging on backup management systems (where available)

## 6. Response Guidance
1. **Escalate quickly**: determine if the actor has privileged access and whether backup systems are reachable.
2. **Scope targets**: identify which backup products/repositories were queried.
3. **Protect recovery**: isolate backup infrastructure, enforce MFA/conditional access, verify immutability where available.
4. **Hunt for impact prep**: look for stop/disable/delete activity, snapshot deletion attempts, and bulk encryption precursors.

## 12. Mitigations
Preventive controls are limited; prioritize resilience:
- Network segmentation and access control around backup infrastructure
- Privileged access hardening for backup admin accounts
- Immutable/append-only backup storage where supported
- Monitor and restrict remote management tooling that can enumerate/modify backup configs

## 13. Testing & Validation
- In a lab, validate that your telemetry captures:
  - backup product discovery via service/registry/filesystem checks
  - execution context (user, parent process, remote session)
- Validate detections can distinguish:
  - scheduled IT backup inventory vs. anomalous discovery from endpoints
