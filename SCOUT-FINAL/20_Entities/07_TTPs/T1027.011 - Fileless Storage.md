# Obfuscated Files or Information: Fileless Storage (T1027.011)

## 1. Summary
Fileless Storage describes adversaries **storing malicious code, configuration data, or payloads in non-file locations**, such as memory, registry keys, environment variables, or other system artifacts, to evade file-based detection and forensic recovery.

Adversaries use this technique to:
- Avoid writing payloads to disk
- Evade antivirus and file integrity monitoring
- Reduce forensic artifacts
- Enable stealthy, memory-resident operations

---

## 2. Technical Overview
Instead of persisting malicious data in files, adversaries leverage alternative storage mechanisms, including:
- Windows Registry values or keys
- Environment variables
- In-memory objects or shared memory
- Scheduled task metadata
- WMI objects or system configuration stores

Common behaviors:
- Writing encoded or encrypted data into registry keys
- Reading and decoding stored data at runtime
- Executing payloads directly from memory
- Cleaning up storage artifacts after use

Indicators include:
- Unusual registry keys containing high-entropy data
- Processes reading executable content from non-file sources
- Runtime decoding of data retrieved from system artifacts
- Lack of corresponding files for observed execution behavior

---

## 3. Subtechnique Considerations
Key considerations for T1027.011:
- Often paired with **Command and Scripting Interpreter (T1059)**
- Common in fileless malware and living-off-the-land attacks
- Detection relies heavily on endpoint telemetry
- Artifacts may be volatile or ephemeral

Fileless storage shifts detection from **filesystem monitoring to behavioral correlation**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Storing payloads in registry values and loading them into memory
- Using environment variables to hold encoded scripts
- Leveraging WMI or task metadata as storage
- Executing decoded content directly from memory

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **non-file data access and execution patterns**:
- Monitor registry keys for encoded or executable content
- Detect processes decoding data retrieved from system artifacts
- Correlate memory execution with absence of disk artifacts
- Identify scripting engines loading content from non-file sources

### Data Source Notes
- **Registry monitoring**: Identify anomalous data storage
- **EDR telemetry**: Detect memory-only execution
- **Script logs**: Reveal decode-and-execute patterns

Common false positives:
- Legitimate configuration data stored in registry
- Software caching encoded data for performance

Tuning guidance:
- Baseline normal registry and environment variable usage
- Elevate alerts when high-entropy data is executed

---

## 6. Response Guidance
When suspected:
1. Capture volatile memory if possible
2. Export and preserve non-file storage artifacts
3. Analyze decoding and execution logic
4. Hunt for similar storage patterns across hosts
5. Update detections to monitor non-file execution paths

## 8. SOC Relevance
T1027.011 is critical because:
- File-based detections may see nothing
- Artifacts may exist only briefly or in memory
- Investigation requires advanced telemetry and timing

SOC teams must prioritize **memory visibility and behavioral correlation**.

---

## 9. Threat Actor Usage
Commonly used by:
- Advanced persistent threats
- Fileless malware operators
- Living-off-the-land attackers

---

## 10. Campaign Usage
Observed in:
- Fileless intrusion campaigns
- Credential theft operations
- Long-dwell stealth intrusions

---

## 11. Malware Usage
Associated with:
- Fileless backdoors
- Script-based malware
- In-memory loaders

---

## 12. Mitigations
Recommended mitigations:
- Enable enhanced endpoint telemetry
- Monitor registry and non-file storage locations
- Restrict script interpreter abuse
- Deploy memory-capable EDR solutions

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign registry-based storage in lab
- Validate alerts on decode-and-execute behavior
- Test SOC response to memory-only malware
- Ensure tooling captures volatile artifacts
