## 1. Summary
Adversaries collect email directly from an endpoint by accessing locally stored email data (e.g., Outlook data stores) or interacting with a local mail client/session to harvest messages, attachments, or address books.

## 2. Technical Overview
Local email collection typically involves:
- Reading **email store files** and client databases (e.g., Outlook PST/OST and related artifacts).
- Enumerating mail folders and extracting message bodies/attachments.
- Using client automation or client session interaction to scrape mailbox contents.

Defender-relevant signals:
- Unusual processes accessing PST/OST-like stores (especially non-Outlook parents).
- Bulk reads of mail storage files followed by staging/compression or outbound transfer.
- Mail client automation patterns (where instrumented).

## 3. Subtechnique Considerations
- Coverage is highly dependent on endpoint telemetry:
  - If file access telemetry is limited, prioritize process + network correlations.
- Legitimate tools (backup, eDiscovery clients, migration tools) can mimic access patterns—baseline expected behavior by host role/user group.

## 4. Procedure Examples
Examples observed in ATT&CK procedure examples include:
- [[30_CIPHER/05_Malware/S0192 - Pupy|Pupy]] interacting with an Outlook session to browse folders/emails.
- [[30_CIPHER/05_Malware/S0650 - QakBot|QakBot]] stealing locally stored emails to support phishing/thread hijacking.
- [[30_CIPHER/05_Malware/S0226 - Smoke Loader|Smoke Loader]] searching Outlook file locations and mail-related directories.
- [[30_CIPHER/03_Threat_Actors/G1039 - RedCurl|RedCurl]] collecting emails for use in future phishing.

## 5. Detection Guidance
High-signal patterns
- **Non-mail processes** reading large volumes of Outlook data files (PST/OST) or mail caches.
- **Process lineage** consistent with automation (script hosts, unusual binaries) accessing mail stores.
- Subsequent **archive/staging** in temp/public folders and outbound transfer shortly after access.

Analytic building blocks
- “Mail store access” rule:
  - Identify access to PST/OST-like extensions/paths.
  - Alert when the accessing process is not in an allowlist of expected mail clients or enterprise tooling.
- “Local mail harvest chain”:
  - mail store access → creation of new large file/archive in temp → outbound connection spike.

### Data Source Notes
- Endpoint:
  - process creation (with full command line),
  - file access telemetry for mail store files (where available),
  - network connections.
- Consider enabling enhanced auditing/EDR rules for mail store access on high-value users (execs, legal, IR team).

## 6. Response Guidance
1) **Contain**
- Isolate host if active harvesting is suspected.
- Disable/kill offending process tree; preserve volatile evidence first if possible.

2) **Scope**
- Enumerate accessed mail stores, folders, and any newly created staging artifacts.
- Determine credential exposure risk (mail often contains passwords/tokens).

3) **Remediate**
- Remove malware/tooling, rotate credentials, and review email-based follow-on risks (phishing from stolen threads).

## 12. Mitigations
- **M1041 Encrypt Sensitive Information**: Use encryption for sensitive email content where feasible.
- **M1060 Out-of-Band Communications Channel**: Implement OOB verification/alerts for unusual local email activity or suspected collection/exfil patterns.

## 13. Testing & Validation
- Simulate benign access:
  - Use an approved script/tool to read a test PST/OST and write extracted text to a temp directory.
- Validate:
  - detection triggers on non-mail process mail-store access,
  - alerts include process tree, file paths, user, and subsequent staging artifacts.
