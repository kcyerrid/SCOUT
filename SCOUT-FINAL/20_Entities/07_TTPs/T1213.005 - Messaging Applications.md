## 1. Summary
Adversaries may mine enterprise messaging applications (e.g., Slack, Microsoft Teams) for sensitive discussions, shared credentials, code snippets, internal links, proprietary data, and real-time incident-response communications. Collection frequently involves bulk access to chat history via APIs, automation tokens, or export/eDiscovery mechanisms—especially after account takeover.

## 2. Technical Overview
Messaging application collection commonly includes:
- Viewing channel/chat history and searching for keywords (IR, “password”, “VPN”, “MFA”, “token”, “admin”).
- Bulk retrieval via APIs (chat history, file lists, user info) using OAuth tokens/bots.
- Export mechanisms (eDiscovery, admin exports, bulk message export) that enable large-scale collection.

Defender-relevant behaviors:
- Atypical volume of conversation history pulls and file listings.
- API-heavy access patterns compared to normal interactive usage.
- Access to conversations about active incidents or security operations shortly after suspicious sign-ins.
- Use of compliance/eDiscovery exports by accounts that do not normally perform those functions.

## 3. Subtechnique Considerations
- Logging differs by platform and plan: Slack enterprise audit logs vs workspace logs; Teams content access may surface in Microsoft Purview audit logs.
- High signal often comes from “how the access happened” (token/app/eDiscovery) rather than simply “message viewed.”
- Messaging apps frequently contain credentials shared informally; treat this technique as closely tied to credential exposure and incident-response disruption risks.

## 4. Procedure Examples
- [[30_CIPHER/03_Threat_Actors/G0117 - Fox Kitten|Fox Kitten]] accessed victim security/IT environments and Microsoft Teams to mine valuable information.
- [[30_CIPHER/03_Threat_Actors/G1004 - LAPSUS$|LAPSUS$]] searched collaboration channels like Teams/Slack to discover high-privilege credentials.
- [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider|Scattered Spider]] searched Slack and Teams for conversations about the intrusion and incident response.

## 5. Detection Guidance
- **API/automation detections**: Alert on unusual or high-rate API calls that retrieve conversation history, files, or workspace metadata.
- **Export/eDiscovery monitoring**: Alert on message exports, eDiscovery message access, and bulk export operations—especially by non-compliance roles.
- **Sign-in anomaly correlation**: Join bulk chat access with rare sign-ins, new devices, and risky authentication patterns.
- **Sensitive-channel focus**: Apply stricter thresholds to security/IT/IR channels and executive channels.
- **Access method classification**: Distinguish user UI access vs bot/token vs compliance export; prioritize non-UI, bulk-capable methods.

### Data Source Notes
- Slack: monitor audit log and API event patterns (e.g., conversations.history, files.list, users.info) and admin audit events.
- Teams: monitor Microsoft Purview audit events tied to message access/export (e.g., TeamsMessagesAccessedViaEDiscovery, TeamsGraphMessageExport).
- Identity: correlate with sign-in logs (UserLoggedIn) and session creation anomalies.
- MITRE detection strategy DET0567 provides two analytics (Slack/Teams) and enumerates key channels and tunable thresholds.

## 6. Response Guidance
1. **Contain identity and tokens**: Revoke OAuth tokens, disable suspicious apps/bots, reset passwords, enforce MFA re-registration if needed.
2. **Scope collection**: Identify channels/chats/files accessed; prioritize security/IT/IR channels and shared-file repositories.
3. **Protect IR communications**: Move active incident coordination to a secure out-of-band channel if compromise is suspected.
4. **Rotate exposed secrets**: Treat credentials shared in chat as potentially compromised; rotate keys/tokens/passwords.
5. **Hunt follow-on**: Look for subsequent lateral movement or privilege abuse using information gleaned from messages.

## 8. SOC Relevance
High SOC signal:
- Bulk chat history access via API token/bot shortly after suspicious sign-in.
- eDiscovery/export events for Teams messages by non-compliance accounts.
- Access focused on IR/security channels during an active incident.

Triage pivots:
- Which access method (UI vs token vs export) was used?
- Which channels and files were accessed?
- Was there correlated identity risk (new device/geo, risky auth, token creation)?

## 12. Mitigations
- **Audit (M1047)**: Proactively search communication services for inappropriately shared data and reduce exposure when found.
- **Out-of-Band Communications Channel (M1060)**: Use secure out-of-band channels for incident communications to prevent adversary monitoring in compromised chat systems.
- **User Training (M1017)**: Define acceptable information to post in chat applications; discourage sharing credentials or sensitive operational details.

## 13. Testing & Validation
- Validate detections for:
  - Slack API-heavy access patterns in test workspaces (high-rate history/file listing)
  - Teams message export/eDiscovery access events in controlled compliance testing
  - Correlation between suspicious sign-ins and immediate bulk message access
- Confirm tuning for:
  - Admin/compliance roles that legitimately use exports
  - Known bots with narrow scopes and expected access patterns

## 15. Notes
- Treat access to IR/security channels as “critical” and escalate rapidly—this can directly enable evasion and extortion.
- Strong detections usually require both app telemetry (API/export) and identity telemetry (rare sign-ins, token issuance).
