# Hide Artifacts: Resource Forking (T1564.009)

## 1. Summary
Resource Forking describes adversaries **hiding malicious content within the resource fork of files on macOS systems**, rather than in the primary data fork. By abusing macOS file system structures, attackers can conceal payloads or configuration data from standard file inspection tools.

This technique is primarily used to:
- Evade file-based detection
- Conceal payloads within seemingly benign files
- Bypass basic static analysis
- Reduce analyst visibility during triage

---

## 2. Technical Overview
macOS (and historically HFS+) file systems support **resource forks**, which allow files to contain additional metadata and structured data separate from the main content.

Adversaries abuse this by:
- Embedding executable or malicious data in the resource fork
- Delivering files that appear benign when opened normally
- Extracting or executing malicious content programmatically
- Leveraging APIs that access resource forks directly

Typical artifacts and indicators include:
- Files whose data fork appears benign
- Unexpected resource fork content
- Execution or decoding routines accessing extended file data
- File sizes or metadata inconsistent with visible content

---

## 3. Subtechnique Considerations
Key considerations for T1564.009:
- Largely macOS-specific
- Rare in commodity malware, more common in targeted attacks
- Detection depends on filesystem metadata visibility
- Often combined with obfuscation (T1027)

This technique reflects **platform-specific attacker knowledge**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering a benign-looking document with a malicious resource fork
- Storing configuration data in resource forks to avoid detection
- Extracting payloads from resource forks at runtime
- Executing hidden content via macOS APIs

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **filesystem metadata inspection**:
- Enumerate and inspect resource forks on downloaded or executed files
- Alert on files with unexpected or large resource fork data
- Detect access to resource forks by scripting engines or binaries
- Correlate resource fork access with execution behavior

### Data Source Notes
- **File system telemetry**: Required for resource fork visibility
- **Process telemetry**: Identify which processes access resource forks
- **Application logs**: Useful for correlating file access and execution

Common false positives:
- Legitimate macOS application metadata
- Legacy application resource usage

Tuning guidance:
- Baseline expected resource fork usage
- Elevate alerts when resource forks contain executable content

---

## 6. Response Guidance
When suspected:
1. Extract and analyze resource fork contents
2. Validate whether content is executable or malicious
3. Review file origin and execution history
4. Quarantine affected files
5. Hunt for similar artifacts across endpoints

T1564.009 is relevant in:

- Investigations where files appear benign but behave maliciously

Resource forking often explains **false-negative static analysis results**.

## 11. Malware Usage
Associated with:
- macOS backdoors
- Custom loaders
- Malware designed to evade conventional file scanning

---

## 12. Mitigations
Recommended mitigations:
- Inspect resource forks on downloaded files
- Use EDR capable of extended file metadata analysis
- Restrict execution of untrusted files
- Educate analysts on macOS filesystem nuances
- Include resource fork checks in IR playbooks

---

## 13. Testing & Validation
Validation approaches:
- Create benign files with resource fork data in lab environments
- Validate detection of unexpected resource fork usage
- Test SOC workflows for macOS-specific artifact analysis
- Ensure telemetry includes extended file metadata
