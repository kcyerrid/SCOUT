# T1069.002 - Permission Groups Discovery: Domain Groups

## 1. Summary
Adversaries enumerate **domain-level permission groups** (e.g., Domain Admins, privileged security groups) to understand privilege distribution and identify escalation or lateral movement targets. This is often an early-to-mid **Discovery** action that enables credential targeting, privileged access pursuit, and high-value host selection.

## 2. Technical Overview
Domain group discovery commonly leverages:
- **Windows domain enumeration** via built-in utilities and directory queries (e.g., Net commands, directory services/LDAP-based queries).
- **macOS/Linux** enumeration where bound to directory services (e.g., directory/cache utilities, LDAP tooling).
- **Programmatic enumeration** from beacons/tools using AD APIs/LDAP libraries.

Output typically includes:
- Group names (security/distribution), SIDs/IDs
- Group membership lists (users/computers/service accounts)
- Group descriptions and privilege-indicating naming conventions

## 3. Subtechnique Considerations
- Domain-level group enumeration has **higher investigative value** than local-only group discovery because it can reveal:
  - Domain Admin / Tier-0 paths
  - Delegated admin groups (Helpdesk, Server Admins)
  - High-value application admin groups (Exchange, SQL, virtualization)
- Enumeration may be **noisy** in directory/audit logs, but can also be **low-and-slow** to blend with administrative behavior.

## 4. Procedure Examples
Observed in-the-wild usage includes:
- Use of discovery tooling (e.g., [[30_CIPHER/05_Malware/S0552 - AdFind|AdFind]], [[30_CIPHER/05_Malware/S0521 - BloodHound|BloodHound]]) to enumerate groups and membership.
- Post-compromise frameworks (e.g., [[30_CIPHER/05_Malware/S0154 - Cobalt Strike|Cobalt Strike]]) running domain group queries during environment mapping.
- Activity reported across multiple intrusion sets, including [[30_CIPHER/03_Threat_Actors/G0046 - FIN7|FIN7]], [[30_CIPHER/03_Threat_Actors/G0049 - OilRig|OilRig]], [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider|Scattered Spider]], and others (per MITRE procedure examples).

## 5. Detection Guidance
Prioritize detections that distinguish **interactive admin work** from **post-compromise discovery**.

High-signal detection patterns:
- **Non-admin endpoints** performing domain group discovery shortly after initial foothold indicators (new service, suspicious logon, unusual parent process).
- Group enumeration from **unusual principals** (workstation user context querying Tier-0 groups) or **unusual hosts** (non-IT workstations).
- Bursts of enumeration: multiple group queries across many groups in a short window; repeated membership expansions.

Practical analytics ideas:
- Correlate **process creation** (discovery utilities, directory-query capable tools) with **directory query activity** within a time window.
- Detect **directory query patterns** targeting well-known privileged groups (Domain Admins, Enterprise Admins, Schema Admins) plus delegated admin groups.
- Baseline: expected administrative hosts/accounts that routinely perform these queries; alert on deviations.

### Data Source Notes
Useful telemetry (platform-dependent):
- **Windows**: Security logs (logon events), process creation (4688 / EDR), PowerShell logging (Script Block), command line auditing, LDAP/AD query telemetry where available (DC auditing, sensor-based directory query monitoring).
- **Linux/macOS**: process exec telemetry, shell history where appropriate, LDAP client logs if enabled.
- **EDR/XDR**: process lineage, command line, user context, host role classification, identity risk signals.

## 6. Response Guidance
1. **Scope the principal**: identify account/host initiating group discovery; determine if it matches expected admin workflows.
2. **Triage adjacency**: look for follow-on actions (credential access attempts, privilege escalation, remote execution/lateral movement).
3. **Assess privilege exposure**: confirm whether enumerated groups include Tier-0; if yes, treat as elevated risk and expand containment.
4. **Contain**: isolate suspicious endpoints; revoke/rotate credentials if compromise suspected; restrict directory query ability for affected accounts where feasible.

- **Why it matters**: Often precedes targeting of privileged identities and Tier-0 systems.
- **Best logged**: Identity + endpoint telemetry; DC visibility significantly improves attribution of enumeration vs. benign admin tooling.
- **Alert fatigue risk**: High if not baselined—tune by admin host/account allowlists and time-of-day/role expectations.

## 12. Mitigations
Preventive mitigation is limited because this behavior can abuse legitimate directory features. Focus on:
- **Privileged access management** (separate admin accounts, just-in-time access)
- **Tiering** (restrict where privileged accounts can log on)
- **Directory query hardening** where feasible (limit overly broad read permissions; monitor sensitive group membership read patterns)
- **Attack surface reduction** (reduce availability of discovery tooling on endpoints; application control for known admin tools in non-admin contexts)

## 13. Testing & Validation
- Run purple-team validation using safe discovery simulations in a lab:
  - Generate controlled domain group queries from a test workstation and from an admin jump host.
  - Verify collection of process telemetry, command line, and directory query visibility.
- Map detections to: unusual host + unusual user + privileged group target + post-compromise precursor signals.
