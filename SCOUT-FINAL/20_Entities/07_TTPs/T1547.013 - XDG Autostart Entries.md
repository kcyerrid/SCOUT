# T1547.013 – XDG Autostart Entries

## 1. Technique Overview
**XDG Autostart Entries (T1547.013)** is a sub-technique of **Boot or Logon Autostart Execution (T1547)** in MITRE ATT&CK v18. Adversaries abuse the **XDG Autostart specification**, which is used by many Linux desktop environments to automatically launch applications when a user logs in.

By creating or modifying `.desktop` files in autostart directories, attackers can ensure malicious programs execute persistently during user sessions.

## 2. Adversary Objectives
Adversaries use this technique to:
- Maintain persistence across user logins
- Blend malicious execution with legitimate desktop applications
- Avoid system-level startup mechanisms that require elevated privileges
- Support follow-on actions such as credential access or lateral movement

## 3. Common Abuse Patterns
- Creating malicious `.desktop` files in:
  - `~/.config/autostart/`
  - `/etc/xdg/autostart/`
- Masquerading malicious entries as legitimate applications
- Modifying existing autostart entries to point to attacker-controlled binaries
- Leveraging user-level persistence to avoid detection
- Using desktop environment features to suppress visible application windows

## 4. Detection Considerations
Detection relies on **file integrity and configuration monitoring**, including:
- Monitoring creation or modification of `.desktop` files in autostart directories
- Detecting autostart entries referencing unusual executables or scripts
- Comparing autostart configurations against known-good baselines
- Correlating autostart execution with suspicious process behavior
- Monitoring user login events followed by unexpected application launches

## 5. Defensive Mitigations
- Audit user and system-level XDG autostart directories
- Restrict write permissions to system-wide autostart locations
- Monitor and alert on new or modified autostart entries
- Use endpoint security tools capable of tracking Linux persistence mechanisms
- Educate users to report unexpected application launches at login

## 6. Operational Impact
If successful, T1547.013 can:
- Provide reliable user-level persistence
- Enable repeated execution without elevated privileges
- Evade traditional startup detection mechanisms
- Increase dwell time in Linux desktop environments

## 7. Analyst Notes
XDG Autostart abuse is particularly relevant in Linux desktop and workstation environments, which are often less monitored than servers. During incident response, analysts should explicitly inspect autostart directories when malware reappears after user logins despite no obvious system-level persistence.
