# Pre-OS Boot: System Firmware (T1542.001)

## 1. Summary
System Firmware describes adversaries **modifying BIOS or UEFI firmware to execute malicious code before the operating system loads**. This grants attackers extremely stealthy and durable persistence that survives disk replacement, OS reinstallation, and many endpoint security controls.

Adversaries use this technique to:
- Establish near-permanent persistence
- Execute code before OS-level defenses initialize
- Bypass endpoint detection and disk-based controls
- Maintain control across system rebuilds

---

## 2. Technical Overview
System firmware governs the earliest stages of system startup. Adversaries may compromise it by:
- Implanting malicious UEFI drivers or modules
- Replacing legitimate firmware components
- Abusing firmware update mechanisms
- Exploiting vulnerabilities in firmware flashing processes

Common targets include:
- BIOS/UEFI firmware images
- NVRAM variables
- Secure Boot configuration data
- Firmware drivers loaded during boot

Indicators include:
- Unexpected firmware hash changes
- Secure Boot disablement or configuration drift
- Boot anomalies or unexplained persistence
- Malicious code executing prior to OS load

---

## 3. Subtechnique Considerations
Key considerations for T1542.001:
- Requires high privileges or physical/supply-chain access
- Extremely difficult to detect and remediate
- Rare but high-impact
- Often combined with Secure Boot bypass techniques

System firmware compromise operates **below the operating system trust boundary**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Flashing modified UEFI firmware images
- Installing malicious DXE drivers
- Modifying NVRAM to load attacker-controlled components
- Replacing firmware modules during update cycles

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **integrity and hardware-level monitoring**:
- Validate firmware images against trusted baselines
- Monitor Secure Boot state and configuration changes
- Detect unauthorized firmware update attempts
- Correlate persistence across OS rebuilds

### Data Source Notes
- **Firmware integrity monitoring**: Primary detection mechanism
- **Boot logs**: Identify abnormal pre-OS execution
- **Hardware telemetry**: Surface firmware state changes

Common false positives:
- Legitimate firmware updates
- Hardware maintenance or replacement

Tuning guidance:
- Maintain known-good firmware baselines
- Alert on unsigned or unexpected firmware changes

---

## 6. Response Guidance
When suspected:
1. Immediately isolate the affected system
2. Perform firmware integrity verification
3. Reflash firmware using vendor-trusted images
4. Reinstall OS after firmware remediation
5. Assess physical and supply-chain exposure

## 8. SOC Relevance
T1542.001 is critical because:
- Endpoint tools may have zero visibility
- Persistence survives traditional remediation
- Detection and response are resource-intensive

SOC teams must treat **firmware compromise as a top-tier incident**.

---

## 9. Threat Actor Usage
Commonly used by:
- Nation-state threat actors
- Advanced espionage groups
- Supply-chain compromise operators

---

## 10. Campaign Usage
Observed in:
- Long-term espionage campaigns
- Hardware and firmware targeting operations
- Covert persistence strategies

---

## 11. Malware Usage
Associated with:
- UEFI rootkits
- Firmware implants
- Pre-OS bootkits

---

## 12. Mitigations
Recommended mitigations:
- Enforce Secure Boot
- Restrict firmware update permissions
- Monitor firmware integrity continuously
- Use TPM and hardware-backed security

---

## 13. Testing & Validation
Validation approaches:
- Verify Secure Boot enforcement
- Test firmware integrity monitoring
- Conduct firmware incident response drills
- Validate recovery procedures for firmware compromise
