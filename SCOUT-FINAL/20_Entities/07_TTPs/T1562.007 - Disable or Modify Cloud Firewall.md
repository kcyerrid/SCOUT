# Impair Defenses: Disable or Modify Cloud Firewall (T1562.007)

## 1. Summary
Disable or Modify Cloud Firewall describes adversaries **weakening, disabling, or altering cloud-native firewall controls**—such as security groups, network security groups (NSGs), or firewall policies—to enable unauthorized network access. This technique removes a critical layer of network-based protection in cloud environments.

Attackers use this technique to:
- Enable command-and-control communication
- Allow inbound access to cloud resources
- Facilitate lateral movement between cloud assets
- Bypass network segmentation and guardrails

---

## 2. Technical Overview
Cloud firewalls enforce network access rules at the platform level. Adversaries impair these defenses by:

- Removing restrictive firewall rules
- Adding overly permissive allow rules
- Disabling firewall enforcement entirely
- Modifying source/destination CIDR ranges
- Turning off logging for firewall activity

Common environments:
- AWS Security Groups / Network ACLs
- Azure Network Security Groups (NSGs)
- Google Cloud Firewall Rules
- SaaS tenant firewall controls

Typical indicators include:
- Sudden rule changes allowing broad access
- Firewall logging disabled or reduced
- New inbound access paths without justification
- Network traffic patterns inconsistent with baseline

---

## 3. Subtechnique Considerations
Key considerations for T1562.007:
- Strongly overlaps with **Lateral Movement** and **C2 enablement**
- Frequently paired with **Cloud Logs Disablement (T1562.008)**
- Requires elevated cloud permissions
- High-confidence indicator of cloud compromise

Firewall modification is rarely legitimate outside change windows.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Opening inbound access to management ports
- Allowing unrestricted outbound traffic
- Removing deny rules protecting sensitive services
- Disabling firewall rule logging

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **firewall configuration integrity**:
- Alert on firewall rule creation, deletion, or modification
- Detect changes that significantly broaden access scope
- Monitor for logging disablement
- Correlate firewall changes with suspicious identity activity

### Data Source Notes
- **Cloud firewall logs**: Primary source
- **Cloud audit logs**: Track who made changes
- **Network telemetry**: Detect newly permitted flows

Common false positives:
- Planned infrastructure changes
- Auto-scaling or deployment automation

Tuning guidance:
- Require approvals for firewall modifications
- Baseline expected rules per workload and environment

---

## 6. Response Guidance
When suspected:
1. Immediately review and revert firewall changes
2. Identify exposed resources and access windows
3. Investigate network traffic during exposure
4. Review identity permissions used to modify rules
5. Rotate credentials and apply least privilege

## 8. SOC Relevance
T1562.007 is **one of the most critical cloud defense evasion techniques**. Firewall changes often directly enable attacker access and should be treated as high-severity events.

---

## 9. Threat Actor Usage
Commonly used by:
- Cloud-focused APT groups
- Ransomware operators targeting cloud-hosted assets
- Financially motivated actors abusing SaaS platforms

---

## 10. Campaign Usage
Observed in:
- Cloud account takeover campaigns
- SaaS data exfiltration operations
- Intrusions involving exposed management interfaces

---

## 11. Malware Usage
Associated with:
- Cloud post-exploitation tooling
- Automation scripts abusing cloud APIs
- Malware leveraging compromised cloud credentials

---

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege on firewall management roles
- Require MFA for cloud administrators
- Enable immutable firewall logging
- Monitor firewall drift continuously
- Use policy-as-code for firewall enforcement

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign firewall rule changes in test environments
- Validate alerts on broad access rule creation
- Test SOC response to exposed cloud services
- Ensure rollback procedures are documented and effective
