# T1098.004 – SSH Authorized Keys

## 1. Technique Overview
**SSH Authorized Keys (T1098.004)** is a MITRE ATT&CK sub-technique in which adversaries **add their own SSH public keys** to a user’s `authorized_keys` file. This grants persistent, passwordless access to systems without modifying account credentials, allowing attackers to blend in with legitimate administrative access.

This technique is commonly used after attackers obtain sufficient privileges to modify user home directories or system-wide SSH configurations.

## 2. Adversary Objectives
Adversaries leverage this technique to:
- Maintain **long-term, stealthy persistence**
- Bypass password rotation and credential resets
- Enable remote access from attacker-controlled infrastructure
- Retain access even after incident response actions

## 3. Common Abuse Patterns
- Appending attacker-controlled keys to `~/.ssh/authorized_keys`
- Adding keys to root or privileged user accounts
- Modifying system-wide SSH key configurations
- Injecting keys into service or automation accounts
- Using inconspicuous key comments to avoid detection

## 4. Detection Considerations
Detection relies on **file integrity and access monitoring**, including:
- Monitoring changes to `authorized_keys` files
- Detecting new SSH keys added outside approved workflows
- Alerts on SSH access from new or anomalous IP addresses
- Correlating key additions with suspicious privilege escalation events
- Reviewing SSH daemon logs for unexpected key-based logins

## 5. Defensive Mitigations
- Implement file integrity monitoring on `.ssh` directories
- Enforce strict controls over who can modify authorized keys
- Use centralized SSH key management solutions
- Require MFA or bastion hosts for privileged SSH access
- Periodically audit SSH keys and remove unused or unknown keys

## 6. Operational Impact
If successful, T1098.004 can:
- Provide attackers with durable, low-noise persistence
- Undermine credential-based security controls
- Complicate remediation if keys are overlooked
- Enable lateral movement across Unix-based environments

## 7. Analyst Notes
SSH key persistence is frequently missed during response efforts because it does not involve credential changes or malware artifacts. Effective remediation requires **explicit enumeration and validation of all authorized SSH keys**, especially on privileged and service accounts.
