## 1. Summary
Pass the Ticket (T1550.003) is adversary use of stolen Kerberos tickets (TGT/TGS) to authenticate and move laterally without access to the account password, bypassing normal access controls.

## 2. Technical Overview
- **Core behavior:** Kerberos tickets (service tickets or TGTs) are captured and then replayed/injected to authenticate to services.
- **Artifacts used**
  - **Service tickets (TGS):** Access to a specific resource/service.
  - **TGT (“golden ticket” variants):** Can be used to request service tickets broadly (high impact).
- **Related behaviors:** Ticket material may originate from credential access (dumping) and can be chained with other auth abuse (e.g., hash-derived ticket creation). :contentReference[oaicite:51]{index=51}

## 3. Subtechnique Considerations
- Sub-technique of [[20_Entities/07_TTPs/TA0005 - Defense Evasion/T1550 - Use Alternate Authentication Material|T1550]].
- Compared to PtH (T1550.002), PtT is **Kerberos-centric**: detection relies on **Kerberos event chains** and **ticket injection evidence** (LSASS access patterns, module loads, abnormal 4768/4769 relationships).

## 4. Procedure Examples
MITRE procedure examples include:
- **APT29:** Used Kerberos ticket attacks for lateral movement.
- **APT32:** Used pass-the-ticket for remote access.
- **BRONZE BUTLER:** Created forged TGT/TGS tickets to maintain admin access.
- **Mimikatz / Pupy / SeaDuke:** Documented capability/usage relating to pass-the-ticket. :contentReference[oaicite:52]{index=52}

## 5. Detection Guidance
Emphasize **authentication chain integrity**: Kerberos service ticket requests should align with legitimate logon flows.

**Core analytic goals (from MITRE detection strategy)**
- Correlate **TGS (4769)** with absent corresponding **logons (4624)** and lack of prior **TGT (4768)** activity.
- Highlight anomalous ticket generation chains and suspicious injection indicators (e.g., LSASS access + module loads). :contentReference[oaicite:53]{index=53}

**High-signal detection patterns**
- **Kerberos chain breaks**
  - 4769 without plausible preceding 4768 for the same principal/host/time window.
  - Service ticket activity from hosts where the user did not log on.
- **Ticket injection indicators**
  - LSASS access events (Sysmon 10 / EDR equivalents) near suspicious Kerberos use.
  - Unusual module loads into sensitive processes correlated with ticket usage timing.
- **Lateral movement proof**
  - Combine Kerberos auth anomalies with network connections and remote service usage.

## 6. Response Guidance
1. **Contain**
   - Isolate suspected source hosts; restrict Kerberos lateral paths where feasible.
2. **Invalidate high-risk tickets**
   - If golden ticket risk is suspected, follow domain guidance for KRBTGT password resets (two-step) and replication controls.
3. **Scope**
   - Enumerate abnormal 4768/4769 chains and affected services; identify all systems accessed via Kerberos by compromised principals.
4. **Eradicate**
   - Remove tooling and persistence; validate LSASS protection and endpoint hardening.
5. **Recover & harden**
   - Tighten privileged account boundaries; reduce service account exposure; enforce tiered admin model.

## 12. Mitigations
- **Active Directory Configuration:** KRBTGT password reset guidance to invalidate previously generated golden tickets. :contentReference[oaicite:62]{index=62}
- **Password Policies:** Ensure complex/unique local admin passwords (reduces related abuse paths). :contentReference[oaicite:63]{index=63}
- **Privileged Account Management:** Limit domain admin permissions; delegate admin roles. :contentReference[oaicite:64]{index=64}
- **User Account Management:** Reduce local admin reuse across systems. :contentReference[oaicite:65]{index=65}
