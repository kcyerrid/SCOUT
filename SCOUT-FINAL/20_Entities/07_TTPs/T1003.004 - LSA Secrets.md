## 1. Summary
LSA Secrets (T1003.004) is the extraction of credential material stored by the Windows Local Security Authority (LSA), including secrets associated with service accounts and other authentication-related data. Access typically requires SYSTEM-level privileges and may occur via registry extraction or memory-based collection.

## 2. Technical Overview
Common LSA secret access patterns:
- **Registry-based access**: Reads/exports of LSA secret-related registry locations (commonly under `HKLM\SECURITY\Policy\Secrets`).
- **Memory-based extraction**: Collection of secrets via in-memory access to security subsystem artifacts.
- **Offline extraction**: Dumping protected registry hives and parsing them on another system.

Operational impact:
- Can expose credentials tied to services, scheduled tasks, and legacy authentication configurations.
- Often enables lateral movement, privilege escalation, and persistence (service account reuse and hidden admin paths).

## 3. Subtechnique Considerations
- LSA Secrets is frequently paired with other credential dumping (LSASS, SAM) once SYSTEM privileges are obtained.
- Because secrets may include service account material, prioritize **server workloads** (application servers, management servers, jump hosts) where service credentials are more likely to have broad permissions.

## 4. Procedure Examples
ATT&CK procedure examples include:

- [[30_CIPHER/03_Threat_Actors/G0064 - APT33]] using credential collection tools to gather credentials consistent with LSA secret access.
- [[30_CIPHER/03_Threat_Actors/G0069 - MuddyWater]] and [[30_CIPHER/03_Threat_Actors/G0049 - OilRig]] using credential dumping tooling (including [[30_CIPHER/05_Malware/S0349 - LaZagne]]).

## 5. Detection Guidance
LSA secret access is a **high-confidence indicator** when paired with privilege context and artifact creation.

High-signal detection patterns:
- **Registry key export / hive access**
  - Export/read access to LSA secret-related locations by non-standard processes.
  - Security hive access followed by creation of `.hiv`, `.save`, `.dmp`, or similar artifacts.
- **Suspicious privilege context**
  - Processes running as SYSTEM that are unusual for the host role initiating registry exports or memory scraping behavior.
- **Tool/behavior correlation**
  - Credential dumping tool execution plus registry access to LSA secret paths.
  - Dump artifacts followed by compression/encryption and outbound transfers.
- **Follow-on credential use**
  - New service authentications, lateral movement, or remote admin activity using service accounts shortly after the dump window.

### Data Source Notes
Useful telemetry sources:
- EDR process execution + lineage
- Registry access auditing for sensitive SECURITY hive paths (tuned to reduce noise)
- File creation/access monitoring for dump artifacts
- Authentication logs for service account usage anomalies (new hosts, new geos, abnormal times)

## 6. Response Guidance
- **Contain**: isolate impacted hosts; stop active credential collection processes; preserve artifacts.
- **Credential actions**: rotate suspected service account passwords; evaluate service account scopes and privileges; invalidate sessions/tokens where applicable.
- **Scope**: identify whether secrets were exported for offline parsing; hunt for dump artifacts and staged archives.
- **Hardening**: reduce service account privileges, move to managed identities where possible, and enforce tiered admin controls.

## 8. SOC Relevance
- High SOC value due to likely **service account** exposure and downstream privilege.
- Best pivots:
  - Identify the SYSTEM process performing registry/memory access
  - Identify dump artifacts and exfil staging
  - Identify unusual service account authentications after the event

## 12. Mitigations
- **M1027 - Password Policies**: strong, unique service account passwords; rotate on compromise; reduce shared secrets.
- **M1026 - Privileged Account Management**: limit SYSTEM acquisition opportunities; apply tiering; constrain admin tooling and remote admin paths.
- **M1017 - User Training**: reduce credential overlap; reinforce privileged credential hygiene and service account stewardship.

## 13. Testing & Validation
- In a lab:
  - Simulate benign registry access attempts to LSA secret-related paths under controlled SYSTEM context and validate alerting.
  - Validate correlation: registry/hive access → dump artifact → suspicious service account auth.
- Ensure allowlists for legitimate backup/IR workflows are explicit and time-bounded.
