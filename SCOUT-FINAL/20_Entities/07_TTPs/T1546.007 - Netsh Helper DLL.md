# T1546.007 – Netsh Helper DLL

## 1. Technique Overview
**Netsh Helper DLL (T1546.007)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse the Windows **Network Shell (netsh)** extensibility feature by registering a malicious helper DLL. When `netsh.exe` executes relevant commands, the malicious DLL is loaded and executed within the context of the netsh process.

Because Netsh helpers are a legitimate extensibility mechanism and are infrequently inspected, this technique enables stealthy, on-demand execution and persistence.

## 2. Adversary Objectives
Adversaries use Netsh helper DLLs to:
- Achieve persistence tied to network configuration activity
- Execute code within a trusted Windows utility
- Evade detection by avoiding traditional startup mechanisms
- Run payloads under elevated privileges when netsh is invoked

## 3. Common Abuse Patterns
- Registering a malicious helper DLL using:
  - `netsh add helper <path_to_dll>`
- Placing the DLL in system or user-writable locations
- Masquerading the helper as a legitimate networking component
- Triggering execution when administrators or services use netsh
- Leveraging helper execution to deploy secondary payloads

## 4. Detection Considerations
Detection relies on **configuration, registry, and process monitoring**, including:
- Monitoring registration of new Netsh helper DLLs
- Detecting unexpected DLL loads by `netsh.exe`
- Auditing registry keys related to Netsh helpers
- Correlating netsh usage with anomalous DLL execution
- Reviewing systems for unknown Netsh extensions

## 5. Defensive Mitigations
- Restrict administrative privileges required to register Netsh helpers
- Monitor and alert on Netsh helper registration events
- Enforce DLL load path protections and code signing
- Audit Netsh configuration periodically
- Remove unauthorized helper DLLs during incident response

## 6. Operational Impact
If successful, T1546.007 can:
- Provide stealthy, event-driven execution
- Enable payload execution within trusted system utilities
- Evade detection mechanisms focused on startup persistence
- Complicate forensic analysis due to indirect execution triggers

## 7. Analyst Notes
Netsh helper DLL abuse is relatively uncommon but powerful due to its stealth and privileged execution context. Analysts should include **Netsh helper enumeration** in persistence-hunting playbooks, especially when investigating unexplained network-related activity.
