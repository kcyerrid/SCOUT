# T1543.005 – Container Service

## 1. Technique Overview
**Container Service (T1543.005)** is a sub-technique of **Create or Modify System Process (T1543)** in MITRE ATT&CK v18. Adversaries may **create or modify container or container cluster management services** that run as daemons, agents, or system processes on hosts to achieve persistence or privilege escalation. These services may include container runtimes (e.g., Docker, Podman) or Kubernetes node-level agents such as *kubelet*. By configuring these services to persistently run attacker-controlled containers or modify service behavior, adversaries can maintain long-term access and influence execution with elevated privileges.  :contentReference[oaicite:1]{index=1}

## 2. Adversary Objectives
Adversaries exploit container service mechanisms to:
- Maintain persistence on container hosts or clustered environments
- Execute malicious workloads automatically
- Escalate privileges via service-level access
- Survive container lifecycle events and host reboots

## 3. Common Abuse Patterns
- Running containers with restart policies such as `--restart=always`, ensuring they automatically restart on failure or host reboot  
- Modifying container service configurations to execute attacker-controlled images as services  
- Deploying Kubernetes DaemonSets to ensure persistent container execution on every node  
- Leveraging compromised container runtime access to escalate privileges on the host system  
- Embedding persistence logic into container management tooling or agents  :contentReference[oaicite:2]{index=2}

## 4. Detection Considerations
Detection relies on **container and orchestration telemetry**, including:
- Monitoring container creation with persistent restart policies  
- Detecting unauthorized container images or configurations  
- Correlating container runtime actions with elevated host access  
- Identifying unusual modifications to container agents or management daemons  
- Observing Kubernetes audit logs for unexpected DaemonSet deploys or privileged workloads  :contentReference[oaicite:3]{index=3}

## 5. Defensive Mitigations
- Restrict access to container runtimes and orchestration controls  
- Enforce least-privilege policies for container service accounts  
- Harden container runtime configurations (e.g., rootless modes)  
- Monitor and alert on persistent container configurations  
- Conduct periodic audits of Kubernetes DaemonSets and node-level services  :contentReference[oaicite:4]{index=4}

## 6. Operational Impact
If successfully abused, T1543.005 can:
- Provide persistent malicious activity in containerized environments  
- Enable execution that blends into normal service-orchestration workflows  
- Undermine cluster and host isolation guarantees  
- Complicate remediation due to distributed persistence vectors

## 7. Analyst Notes
Container Service abuse is an emerging persistence technique in modern cloud-native environments. Attackers frequently leverage legitimate container scheduling and service mechanisms to embed persistence logic. Detection and response require visibility into both container orchestration control planes and host-level runtime configurations.  :contentReference[oaicite:5]{index=5}
