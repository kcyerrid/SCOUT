# Exfiltration to Code Repository (T1567.002)

## 1. Summary
Exfiltration to Code Repository describes adversary use of public or private code hosting platforms to store or transmit stolen data. By abusing developer-focused services that rely on HTTPS and are widely permitted in enterprise environments, adversaries can conceal data theft within legitimate-looking development activity.

This subtechnique is frequently observed in espionage and ransomware operations where stealth and persistence are required during exfiltration.

---

## 2. Technical Overview
Adversaries authenticate to code repositories using attacker-controlled or compromised credentials, then upload stolen data in the form of commits, issues, releases, or repository artifacts.

Common mechanisms include:
- Committing stolen files to attacker-controlled repositories
- Encoding or compressing data within source files
- Uploading data as release artifacts or repository attachments
- Using repository APIs to automate data transfer

Artifacts include authentication events, repository activity logs, commit metadata, and outbound HTTPS connections to repository services.

---

## 3. Subtechnique Considerations
T1567.002 focuses specifically on **code repository platforms**, distinguishing it from:
- Cloud storage exfiltration
- Exfiltration over command-and-control channels

Detection difficulty increases when repositories are already heavily used within the organization.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Creating private repositories to store stolen data
- Hiding sensitive data within seemingly benign source files
- Using automated scripts to push data incrementally
- Leveraging release uploads to transfer large archives

Analysts may observe repository activity from non-developer hosts or accounts.

---

## 5. Detection Guidance
Detection should emphasize contextual and behavioral analysis:
- Repository access from systems or users without development roles
- Unusual commit volume or size
- Repository creation outside approved workflows
- Use of APIs or access tokens not previously observed

Correlation between proxy, identity, and repository audit logs is essential.

### Data Source Notes
- **Code Repository Audit Logs:** Primary source for detecting misuse
- **Web Proxy Logs:** Useful for identifying upload volume anomalies
- **Authentication Logs:** Help identify compromised credentials

---

## 6. Response Guidance
When repository-based exfiltration is suspected:
- Immediately revoke repository access tokens and credentials
- Identify scope and sensitivity of exfiltrated data
- Remove malicious repositories or content
- Notify legal and compliance teams as required

Preserve repository logs, commits, and network artifacts for analysis.

## 8. SOC Relevance
Exfiltration to code repositories can evade traditional DLP and network controls due to encrypted traffic and trusted destinations. SOC teams must monitor repository activity with role-based context to avoid blind spots.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Espionage-focused advanced persistent threat groups
- Ransomware operators prior to data extortion
- Insider threat actors abusing legitimate developer access

Confidence in continued usage is high.

---

## 10. Campaign Usage
Exfiltration to code repositories appears in:
- Long-dwell espionage campaigns
- Double-extortion ransomware operations
- Insider data theft incidents

---

---

## 12. Mitigations
Effective mitigations include:
- Restricting repository access to approved users
- Monitoring and alerting on anomalous repository activity
- Enforcing MFA and token rotation
- Applying DLP controls to repository uploads
- Auditing API usage and access tokens

---

## 13. Testing & Validation
Validation approaches include:
- Simulated exfiltration to test repository monitoring
- Purple team exercises focused on developer tool abuse
- Review of repository audit log alerting

Successful validation identifies anomalous data uploads.
