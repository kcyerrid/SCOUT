# T1556.005 – Reversible Encryption

## 1. Technique Overview
**Reversible Encryption (T1556.005)** is a sub-technique of [[20_Entities/07_TTPs/T1556 - Modify Authentication Process|T1556]] in **MITRE ATT&CK v18**. Adversaries configure or exploit authentication systems that store credentials using **reversible (decryptable) encryption**, enabling recovery of plaintext passwords rather than non-reversible hashes.

This technique directly undermines credential protection guarantees and can provide high-fidelity access to user secrets across systems.

## 2. Adversary Objectives
Adversaries use reversible encryption to:
- Recover plaintext passwords from authentication stores
- Bypass protections provided by one-way hashing
- Maintain persistent access despite password policy changes
- Enable downstream attacks such as lateral movement and privilege escalation

## 3. Common Abuse Patterns
- Enabling reversible encryption for password storage in directory services
- Modifying authentication or identity policy settings to allow decryptable storage
- Targeting environments where legacy compatibility requires reversible encryption
- Extracting and decrypting stored credentials from compromised systems
- Combining with authentication component access to scale credential theft

## 4. Detection Considerations
Detection requires **policy, configuration, and credential-store monitoring**, including:
- Auditing authentication policies for reversible encryption settings
- Monitoring directory services and identity platforms for policy changes
- Correlating policy modifications with subsequent credential access activity
- Inspecting authentication stores for evidence of decryptable credential storage
- Reviewing change logs and administrative actions affecting auth settings

## 5. Defensive Mitigations
- Disable reversible encryption for credential storage wherever possible
- Enforce modern authentication and password hashing standards
- Monitor and alert on changes to authentication storage policies
- Restrict administrative access to identity and authentication configuration
- Rotate credentials and remediate systems if reversible encryption is detected

## 6. Operational Impact
If successful, T1556.005 can:
- Expose large volumes of plaintext credentials
- Enable stealthy, long-term credential harvesting
- Undermine trust in identity and authentication infrastructure
- Require enterprise-wide credential resets and policy remediation

## 7. Analyst Notes
Reversible encryption is typically enabled only for **legacy compatibility reasons** and should be rare in modern environments. Its presence—especially when newly enabled—should be treated as a **critical security finding**, warranting immediate investigation into intent and scope.
