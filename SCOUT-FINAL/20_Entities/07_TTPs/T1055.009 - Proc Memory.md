# Process Injection: Proc Memory (T1055.009)

## 1. Summary
Proc Memory describes adversaries **injecting code into a running Linux process by directly writing to its memory through the `/proc/<pid>/mem` interface**. This technique allows attackers to modify a process’s memory space without using traditional debugging interfaces, enabling stealthy execution and defense evasion.

T1055.009 is commonly used to:
- Inject shellcode into long-lived Linux processes
- Hijack execution flow without spawning new processes
- Bypass userland monitoring controls
- Support fileless post-exploitation activity

---

## 2. Technical Overview
Linux exposes process memory through the proc filesystem. Adversaries abuse this by:
- Identifying a target process ID
- Opening `/proc/<pid>/mem` with write permissions
- Writing malicious code into executable memory regions
- Redirecting instruction pointers to injected code

This often requires:
- Matching UID or elevated privileges
- CAP_SYS_PTRACE or equivalent permissions
- Weak or misconfigured kernel protections

Artifacts often include:
- File access to `/proc/<pid>/mem`
- Memory modifications to running processes
- Execution flow anomalies
- Audit logs indicating procfs abuse

---

## 3. Subtechnique Considerations
Key considerations for T1055.009:
- Highly stealthy with minimal disk artifacts
- Requires strong kernel-level visibility for detection
- Often blocked in hardened or containerized systems
- Commonly used in advanced Linux intrusions

This technique bypasses many userland security controls.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Writing shellcode into service processes
- Modifying memory of daemons to establish backdoors
- Combining proc memory writes with exploit-based escalation
- Injecting payloads into container host processes

These actions typically occur after initial access.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring access to `/proc/<pid>/mem`
- Alerting on write operations to proc memory
- Correlating procfs abuse with execution anomalies
- Detecting privilege escalation attempts alongside memory writes

### Data Source Notes
- **Audit logs (auditd)**: Primary detection source
- **Syscall telemetry**: Required for procfs monitoring
- **Process telemetry**: Useful for identifying impacted processes

---

## 6. Response Guidance
When detected:
1. Identify the attacker process and target process
2. Isolate the affected system
3. Terminate malicious processes where appropriate
4. Capture memory for forensic analysis
5. Review permissions and kernel hardening settings

## 12. Mitigations
Recommended mitigations:
- Restrict access to `/proc/<pid>/mem`
- Harden kernel settings and procfs permissions
- Limit CAP_SYS_PTRACE and similar capabilities
- Monitor procfs access patterns
- Apply least privilege principles
