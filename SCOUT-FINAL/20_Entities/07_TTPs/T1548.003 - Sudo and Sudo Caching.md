# Abuse Elevation Control Mechanism: Sudo and Sudo Caching (T1548.003)

## 1. Summary
This subtechnique describes adversaries abusing **sudo** and **sudo credential caching** on Unix-like systems to execute commands with elevated privileges. Sudo is designed to allow delegated administrative access with authentication and auditing; however, misconfigurations, overly permissive rules, or cached credentials can be leveraged to escalate privileges without re-authentication.

T1548.003 is commonly used to:
- Escalate privileges from a compromised user account
- Execute administrative commands without prompting for credentials
- Blend malicious actions with legitimate administrative activity

---

## 2. Technical Overview
On Linux and macOS, sudo allows authorized users to execute commands as another user (typically root). By default, sudo caches successful authentication for a configurable time window. Adversaries abuse this mechanism by:
- Exploiting permissive `sudoers` configurations
- Reusing cached credentials to execute additional privileged commands
- Leveraging wildcard or unrestricted sudo rules
- Executing shells or interpreters via sudo to gain persistent root access

Technical artifacts often include:
- Sudden execution of privileged commands shortly after a legitimate sudo use
- Sudo execution chains originating from non-administrative workflows
- Use of shells or scripting interpreters launched via sudo

---

## 3. Subtechnique Considerations
Key considerations for T1548.003:
- Effectiveness depends heavily on sudoers configuration
- Sudo caching windows increase attacker opportunity
- Shared or reused user accounts amplify risk
- Cloud and DevOps environments frequently grant broad sudo access

Organizations should review both sudo rules and authentication caching behavior.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Enumerating sudo permissions to identify allowed commands
- Waiting for legitimate sudo use to leverage cached credentials
- Executing shells or file manipulation utilities with sudo
- Combining sudo abuse with scripting for automation

These actions often occur shortly after initial access or lateral movement.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring sudo usage patterns and command frequency
- Detecting unusual sudo-executed binaries or shells
- Correlating sudo execution with prior authentication events
- Alerting on sudo activity outside normal administrative hours

### Data Source Notes
- **Authentication logs**: Essential for understanding sudo context
- **Process telemetry**: High value for identifying privilege transitions
- **Command-line logging**: Critical for detecting misuse of allowed commands

---

## 6. Response Guidance
When suspicious sudo activity is detected:
1. Validate whether the commands align with legitimate administrative tasks
2. Identify the user account and sudo rule involved
3. Revoke or restrict overly permissive sudo rules
4. Investigate for follow-on actions such as persistence or credential access
5. Rotate credentials if root-level access was abused

## 8. SOC Relevance
T1548.003 is especially relevant in:
- Linux server environments
- Cloud infrastructure and DevOps pipelines
- Organizations with shared administrative access models

Sudo abuse can appear benign without sufficient context, making it a common detection blind spot.

---

## 9. Threat Actor Usage
This subtechnique is frequently leveraged by:
- Ransomware operators targeting Linux servers
- Cloud-focused intrusion sets
- Adversaries abusing valid credentials for stealthy escalation

Usage is opportunistic and configuration-dependent.

---

## 10. Campaign Usage
Observed in:
- Cloud infrastructure compromises
- Linux-focused ransomware campaigns
- Multi-stage intrusions involving credential theft

---

## 11. Malware Usage
Malware leveraging this technique often includes:
- Linux backdoors
- Post-exploitation frameworks
- Automation scripts used after initial access

---

## 12. Mitigations
Recommended mitigations:
- Enforce least-privilege sudo rules
- Disable or reduce sudo credential caching
- Monitor and log all sudo command execution
- Use MFA or additional controls for privileged actions
- Regularly audit sudoers configurations

---

Validation approaches:
- Review and test sudoers configurations
- Simulate cached-credential abuse scenarios
- Use Atomic Red Team tests for T1548.003
