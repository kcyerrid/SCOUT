# Obfuscated Files or Information: Software Packing (T1027.002)

## 1. Summary
Software Packing describes adversaries **compressing, encrypting, or otherwise transforming executables** so that the original code is hidden until runtime. Packed binaries evade static analysis, signature-based detection, and casual inspection by unpacking themselves in memory before execution.

Adversaries use this technique to:
- Hide malicious logic from static scanners
- Evade antivirus and signature-based detections
- Increase malware longevity and reuse
- Complicate reverse engineering and triage

---

## 2. Technical Overview
A packed executable typically consists of:
- A **stub loader** responsible for unpacking
- An **encrypted or compressed payload**
- Runtime logic to transfer execution to unpacked code

Adversaries employ packing by:
- Using commercial or open-source packers
- Modifying or chaining multiple packers
- Writing custom packers to evade detection
- Repacking payloads to create unique variants

Key characteristics:
- Small initial executable with high entropy sections
- Minimal imports until runtime
- Self-modifying or memory-writing behavior
- Code execution occurring only after unpacking

Indicators include:
- High entropy executable sections
- Execution of memory allocation and write APIs early in runtime
- Jump to dynamically generated code regions
- Unpacking behavior preceding malicious activity

---

## 3. Subtechnique Considerations
Key considerations for T1027.002:
- Extremely common across malware families
- Often layered with **Binary Padding (T1027.001)** and **Stripped Payloads (T1027.008)**
- Custom packers significantly reduce detection efficacy
- Unpacking often occurs entirely in memory

Software packing focuses on **static analysis evasion**, not execution stealth.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering packed loaders via phishing
- Repacking malware to evade updated signatures
- Using custom packers to avoid unpacking heuristics
- Unpacking payloads just before execution

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **runtime behavior over static structure**:
- Detect memory allocation followed by code execution
- Identify self-modifying code patterns
- Monitor for unpacking loops and decryption routines
- Correlate unpacking with subsequent malicious actions

### Data Source Notes
- **EDR telemetry**: Detect memory-based unpacking
- **Process creation logs**: Identify suspicious loaders
- **Memory analysis**: Reveal unpacked payloads

Common false positives:
- Legitimate packed commercial software
- DRM-protected applications

Tuning guidance:
- Maintain allowlists for known legitimate packers
- Elevate alerts when unpacking precedes suspicious behavior

---

## 6. Response Guidance
When suspected:
1. Capture memory during execution to extract unpacked payload
2. Analyze loader behavior and unpacking routines
3. Block based on behavioral indicators
4. Hunt for similar packed variants across environment
5. Share unpacked indicators with detection teams

## 8. SOC Relevance
T1027.002 is highly relevant because:
- Packed malware dominates modern threat landscapes
- Static signatures alone are insufficient
- Analysts must rely on behavior and memory inspection

SOC teams should expect **packing by default**, not as an exception.

---

## 9. Threat Actor Usage
Commonly used by:

- Commodity malware operators
- Advanced persistent threats

## 10. Campaign Usage
Observed in:
- Initial access loaders
- Malware-as-a-service campaigns
- Long-running evasion-heavy operations

---

## 11. Malware Usage
Associated with:
- Loaders and droppers
- Ransomware payloads
- Credential stealers and backdoors

---

## 12. Mitigations
Recommended mitigations:
- Deploy behavior-based endpoint protection
- Monitor for memory unpacking patterns
- Restrict execution of untrusted binaries
- Use sandbox detonation for suspicious executables

---

## 13. Testing & Validation
Validation approaches:
- Execute benign packed binaries in lab environments
- Validate alerts on unpacking behavior
- Test SOC workflows for memory-based extraction
- Ensure tooling captures unpacked code paths
