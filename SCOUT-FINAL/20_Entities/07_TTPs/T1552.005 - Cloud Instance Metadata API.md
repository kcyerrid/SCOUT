## 1. Summary
Adversaries may access a cloud instance metadata service to retrieve credentials and other sensitive instance data. Because metadata endpoints are typically reachable from within the instance/workload, a foothold on the host (or an SSRF path into the host) can translate into cloud credential theft and rapid expansion across cloud resources.

## 2. Technical Overview
Cloud providers expose instance metadata via a link-local endpoint (commonly `169.254.169.254`) to provide:
- Instance identity and configuration metadata
- Temporary credentials / tokens
- UserData or bootstrap scripts that may contain secrets

Common adversary paths:
- **Post-compromise**: direct requests from within a VM/container workload to metadata endpoints
- **SSRF exploitation**: coercing a vulnerable service to request metadata endpoints on behalf of the attacker
- **Credential replay**: using harvested temporary credentials to access cloud APIs, storage, secrets managers, or IAM

## 3. Subtechnique Considerations
- Metadata services can be **versioned**; older/less secure modes increase risk if not restricted.
- SSRF-driven access often manifests as **application-layer anomalies** rather than interactive host behavior.
- Workloads may legitimately access metadata—detections must focus on **unusual call patterns**, **unusual processes**, and **subsequent API activity** inconsistent with baseline.

## 4. Procedure Examples
Observed usage includes:
- Querying metadata APIs from compromised cloud instances to extract credentials
- Tooling that automates enumeration across AWS/GCP metadata services

## 5. Detection Guidance
**Host / workload telemetry**
- Detect connections to **169.254.169.254** (or provider-specific metadata IPs/hostnames) by:
  - Unusual processes (web servers, scripting engines, newly spawned binaries)
  - Unexpected users/containers/pods
  - Abnormal frequency/bursting or novel URIs

**Web / application telemetry (SSRF)**
- Detect SSRF-like patterns:
  - Requests where the app fetches internal link-local addresses
  - Sudden metadata endpoint access following malformed URLs, redirect chains, or suspicious headers
  - WAF signals indicating SSRF probes followed by metadata retrieval

**Cloud control-plane telemetry**
- Correlate metadata access with:
  - New/rare API calls using temporary credentials shortly afterward
  - Enumeration of IAM, secrets, storage, or compute resources from atypical source IPs/regions/user agents

### Data Source Notes
- Prioritize: VPC flow logs / eBPF network telemetry, container network telemetry, web proxy/WAF logs, cloud audit logs (e.g., API activity), and workload process telemetry.
- For containerized workloads, include **pod identity** and **service account** context to reduce false positives.

## 6. Response Guidance
1. **Containment**
   - Isolate affected instances/workloads; block metadata endpoint access where feasible during triage.
2. **Credential invalidation**
   - Rotate or revoke exposed cloud credentials; invalidate short-lived tokens if supported.
3. **Cloud hunting**
   - Review cloud audit logs for post-theft actions: IAM changes, secret reads, storage access, and new compute creation.
4. **SSRF remediation**
   - Patch SSRF vulnerabilities; implement egress controls and metadata protections.
5. **Hardening**
   - Restrict metadata endpoint access to only necessary workloads; enforce safer metadata service modes and request requirements.

## 8. SOC Relevance
High-impact cloud escalation technique. The strongest detections are **correlated**:
- Metadata endpoint access (network/workload)
- Follow-on cloud API activity (control plane)
- Asset criticality (internet-facing apps, CI/CD, bastions, Kubernetes nodes)

## 12. Mitigations
- **M1042 - Disable or Remove Feature or Program**: Disable unnecessary metadata services; restrict insecure versions/modes.
- **M1037 - Filter Network Traffic**: Use WAF/egress controls to prevent SSRF-driven metadata access; restrict link-local calls where feasible.
- **M1035 - Limit Access to Resource Over Network**: Host-based firewall rules to limit metadata endpoint access to only approved processes/workloads.
