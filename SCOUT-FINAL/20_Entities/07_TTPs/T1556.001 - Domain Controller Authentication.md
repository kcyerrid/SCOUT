# T1556.001 – Domain Controller Authentication

## 1. Technique Overview
**Domain Controller Authentication (T1556.001)** is a sub-technique of [[20_Entities/07_TTPs/T1556 - Modify Authentication Process|T1556]] in **MITRE ATT&CK v18**. Adversaries tamper with or abuse **Active Directory domain controller (DC) authentication components** to intercept credentials, weaken authentication enforcement, or preserve access at the core of enterprise identity infrastructure.

Because domain controllers are authoritative for authentication and authorization, successful abuse provides broad, durable control and is typically associated with advanced intrusions.

## 2. Adversary Objectives
Adversaries use DC authentication modification to:
- Capture credentials during Kerberos or NTLM authentication
- Bypass or weaken domain-wide authentication controls
- Maintain persistence despite password resets or account remediation
- Establish long-term access at the identity control plane

## 3. Common Abuse Patterns
- Modifying authentication-related binaries or configurations on domain controllers
- Injecting malicious logic into DC processes responsible for authentication
- Abusing replication or trust relationships to propagate malicious changes
- Leveraging privileged access to persist within authentication workflows
- Combining with credential theft to reinforce identity compromise

## 4. Detection Considerations
Detection requires **deep identity and DC-specific telemetry**, including:
- Monitoring changes to authentication-related files, services, and registry keys on DCs
- Auditing DC configuration changes and service restarts
- Correlating authentication events with anomalous credential usage
- Inspecting LSASS and Kerberos-related activity on domain controllers
- Applying integrity monitoring to critical DC binaries

## 5. Defensive Mitigations
- Enforce strict change control and monitoring on domain controllers
- Limit administrative access to DCs and authentication infrastructure
- Apply code integrity and signing enforcement where supported
- Monitor DCs with dedicated identity-focused security tooling
- Rapidly isolate and rebuild compromised domain controllers

## 6. Operational Impact
If successful, T1556.001 can:
- Undermine trust across the entire Active Directory environment
- Enable persistent credential theft and authentication bypass
- Force enterprise-wide credential resets and infrastructure rebuilds
- Significantly complicate incident response and recovery

## 7. Analyst Notes
Any unexplained modification to domain controller authentication behavior should be treated as **critical severity**. Analysts should assume **full domain compromise** until proven otherwise and prioritize containment of identity infrastructure over endpoint-level remediation.
