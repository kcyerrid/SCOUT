# Process Injection: Process Doppelgänging (T1055.013)

## 1. Summary
Process Doppelgänging describes adversaries **executing malicious code by abusing the Windows NTFS transaction feature (TxF)** to create a process from a malicious image that never exists as a committed file on disk. The resulting process appears to originate from a legitimate executable, enabling strong defense evasion.

T1055.013 is commonly used to:
- Evade file-based and signature-based detection
- Execute payloads without a persistent malicious file on disk
- Masquerade as legitimate system binaries
- Support stealthy loader and implant execution

---

## 2. Technical Overview
Process Doppelgänging relies on **NTFS Transactional File System (TxF)** behavior. Adversaries abuse this by:
1. Creating a transacted file containing malicious PE content
2. Creating a section object from the transacted file
3. Rolling back the transaction, removing the file from disk
4. Creating a process from the section object

Key APIs involved include:
- `CreateTransaction`
- `CreateFileTransacted`
- `NtCreateSection`
- `NtCreateProcessEx`

Artifacts often include:
- Process execution without a corresponding on-disk executable
- Use of NTFS transaction APIs
- Section objects backed by deleted or rolled-back files
- Legitimate binary names executing malicious behavior

---

## 3. Subtechnique Considerations
Key considerations for T1055.013:
- Highly stealthy and fileless execution method
- Depends on NTFS TxF support (deprecated but still present)
- Rarely used due to complexity
- Detection requires deep kernel and API telemetry

This technique is closely related to, but distinct from, process hollowing.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing payloads via transacted NTFS files
- Launching malware under the guise of system binaries
- Rolling back transactions to erase disk artifacts
- Using Doppelgänging as a first-stage loader

These actions typically occur early in execution chains.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring usage of NTFS transaction APIs
- Detecting process creation without backing image files
- Identifying section objects linked to deleted files
- Correlating anomalous API sequences with process startup

### Data Source Notes
- **API telemetry**: Critical for detecting TxF abuse
- **Process telemetry**: Required to detect image mismatches
- **Kernel events**: Useful for section object creation analysis

---

## 6. Response Guidance
When suspected:
1. Identify suspicious processes lacking disk-backed images
2. Isolate affected systems
3. Capture memory for forensic analysis
4. Review parent process behavior and API usage
5. Investigate for additional loaders or persistence mechanisms

## 11. Malware Usage
Malware leveraging process doppelgänging includes:
- Advanced loaders
- Fileless malware frameworks

---

## 12. Mitigations
Recommended mitigations:
- Monitor and restrict NTFS transaction usage
- Use EDR capable of detecting diskless process execution
- Correlate process creation with file system events
- Apply least privilege principles
- Keep Windows systems fully patched

Validation approaches:

- Validate SOC detection of TxF API usage
- Review alerts for process-image mismatches
