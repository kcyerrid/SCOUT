# Cron (T1053.006)

## 1. Summary
Cron describes adversary abuse of Unix-like operating system scheduling mechanisms to execute commands or scripts at specified times or intervals. This subtechnique is commonly used to automate malicious execution, establish persistence, and, in some cases, maintain privileged access on Linux and macOS systems.

Because cron is a core administrative utility, malicious cron jobs can blend into legitimate system maintenance activity if not properly monitored.

---

## 2. Technical Overview
Cron allows users and services to schedule tasks via crontab files or system-wide cron directories.

Adversaries may:
- Create or modify user-level crontab entries
- Add scripts to system cron directories (e.g., `/etc/cron.*`)
- Schedule jobs to execute payloads from writable directories
- Use environment variables or obfuscated commands within cron entries

Artifacts include crontab file modifications, scheduled execution events, and child processes spawned by `cron` or `crond`.

---

## 3. Subtechnique Considerations
T1053.006 is the Unix/macOS-specific implementation of scheduled execution.

Key considerations include:
- User vs. system-level cron jobs
- Use of `@reboot` or high-frequency schedules
- Limited default logging on many distributions
- Abuse of writable cron directories or scripts

Detection requires visibility into crontab changes and execution behavior.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Adding malicious entries to user crontabs
- Dropping scripts into `/etc/cron.hourly` or similar directories
- Scheduling reverse shell or downloader execution
- Using base64-encoded or heavily obfuscated commands

Analysts may observe periodic execution of suspicious processes aligned with cron schedules.

---

## 5. Detection Guidance
Detection should focus on:
- Creation or modification of crontab files outside approved workflows
- Cron jobs executing from temporary or user-writable directories
- High-frequency or unusual scheduling intervals
- Execution of interpreters (e.g., bash, python) via cron

Correlation between file modification and process execution improves fidelity.

### Data Source Notes
- **Cron Logs:** Often limited; require explicit configuration
- **File Creation:** Useful for detecting crontab changes
- **Process Execution:** Required to confirm payload execution

---

## 6. Response Guidance
When malicious cron jobs are identified:
- Remove or disable the malicious cron entry
- Identify associated scripts or payloads
- Review system for additional persistence mechanisms
- Rotate credentials associated with affected users

Preserve crontab files and execution logs for forensic analysis.

## 8. SOC Relevance
Cron abuse is a common persistence and execution mechanism in Linux- and macOS-based intrusions. SOC visibility is often limited due to sparse default logging, making proactive configuration essential.

---

## 9. Threat Actor Usage
This subtechnique is frequently used by:
- Ransomware operators targeting Linux servers
- Advanced persistent threat groups
- Cloud and container-focused adversaries

Confidence in widespread usage is high.

---

## 10. Campaign Usage
Cron-based execution has appeared in:
- Linux ransomware campaigns
- Cloud workload compromises
- Long-dwell server intrusions

## 12. Mitigations
Effective mitigations include:
- Restricting cron access to authorized users
- Monitoring and alerting on crontab modifications
- Enforcing file permissions on cron directories
- Enabling enhanced logging for cron execution
- Applying least-privilege principles

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for cron persistence
- Purple team simulations of scheduled execution
- Review of alerts tied to crontab changes

Successful validation results in detection of unauthorized cron activity.
