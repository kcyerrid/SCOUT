## 1. Summary
Adversaries may query the Windows Registry for **insecurely stored credentials**, such as auto-logon values, application passwords, proxy creds, PuTTY sessions, Outlook profiles, or other software configuration values containing secrets.

## 2. Technical Overview
Typical targets:
- Auto-logon configuration keys
- Application credential storage locations (varies widely by vendor/app)
- Email client profiles and stored connection values
- Remote access tooling configuration (e.g., session definitions)
- “Password-like” keywords and common secret fields within registry values

Defender-relevant behavior:
- Registry enumeration using command-line utilities, PowerShell, WMI, or custom binaries
- Keyword searching for “password/cred/logon/token/key”
- Access to specific known sensitive paths (baseline these for your org)

## 3. Subtechnique Considerations
- Registry reads are common for legitimate software; context is crucial.
- Highest signal comes from:
  - Registry enumeration from unusual parent processes/users
  - Broad hive searching (`HKLM`, `HKCU`) combined with keyword filters
  - Correlation with later authentication or lateral movement activity

## 4. Procedure Examples
MITRE documents examples including:
- [[30_CIPHER/05_Malware/S0331 - Agent Tesla|Agent Tesla]] extracting credentials from the Registry.
- [[30_CIPHER/03_Threat_Actors/G0050 - APT32|APT32]] using tooling to harvest credentials stored in Registry-related locations.
- [[30_CIPHER/05_Malware/S0266 - TrickBot|TrickBot]] querying registry keys to retrieve stored session credentials.
- [[30_CIPHER/05_Malware/S1183 - StrelaStealer|StrelaStealer]] enumerating Outlook profile-related keys to extract values associated with email configuration.

## 5. Detection Guidance
Key detections focus on **registry access patterns** that resemble credential discovery rather than normal application behavior.

Detection patterns:
- Process creation of `reg.exe` with suspicious arguments (search `/f password` style queries; broad `/s` recursion)
- PowerShell scripts invoking registry provider reads at scale
- Non-admin user contexts reading high-risk keys unexpectedly
- Registry discovery shortly followed by:
  - interactive logons, network logons, RDP/SMB/WinRM activity
  - credential use in browsers/IdP sessions, service auth

### Data Source Notes
Telemetry to prioritize (vendor-neutral):
- Windows Security logs where configured (process creation, privileged logons)
- EDR telemetry for registry read operations (key path + process)
- PowerShell logging (script block, module logging)
- Command line auditing (Sysmon Event ID 1, if deployed)
- UEBA/IdP logs for downstream credential misuse

## 6. Response Guidance
1. **Containment**
   - If sensitive creds were stored, rotate them immediately (service accounts, app creds).
2. **Eradication**
   - Remove/disable insecure Registry-stored credentials; reconfigure apps to use secure stores.
3. **Scope**
   - Identify all accessed key paths and values; determine impacted accounts/systems.
4. **Hardening**
   - Implement GPO/secure configuration baselines prohibiting password storage in Registry.

## 8. SOC Relevance
This is a strong signal when paired with:
- Endpoint process chains that don’t align with installed software
- Registry discovery + immediate remote access/lateral movement attempts
- Known credential-theft tool presence

SOC quick triage:
- What keys were accessed?
- Which process performed the reads? Is it signed/expected?
- Any subsequent authentications using those credentials?

## 12. Mitigations
- **M1047 - Audit**: Proactively search for and remediate credentials stored in Registry.
- **M1027 - Password Policies**: Prohibit storing credentials in Registry.
- **M1026 - Privileged Account Management**: Minimize privilege of accounts whose credentials may be exposed.

## 13. Testing & Validation
- Validate detection for suspicious registry enumeration in a lab:

  - Ensure alerts trigger on broad/recursive searches with password-like keywords
