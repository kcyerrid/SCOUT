# Impair Defenses: Impair Command History Logging (T1562.003)

## 1. Summary
Impair Command History Logging describes adversaries **preventing the recording of command-line activity** by disabling, modifying, or clearing shell and interpreter history mechanisms. This technique reduces forensic visibility into attacker actions performed through interactive shells or scripting environments.

Attackers use this technique to:
- Conceal commands executed during an intrusion
- Evade post-incident reconstruction
- Reduce attribution and forensic detail
- Support stealthy, hands-on-keyboard activity

---

## 2. Technical Overview
Most operating systems and shells record user command history by default. Adversaries impair this logging by:

- Disabling history recording entirely
- Redirecting history files to null locations
- Clearing or truncating history files
- Modifying environment variables or shell settings
- Altering interpreter-specific history mechanisms

Platform-specific examples:
- **Linux/macOS**: Bash/Zsh history (`HISTFILE`, `HISTSIZE`, `HISTCONTROL`)
- **Windows PowerShell**: PSReadLine history manipulation
- **Cross-platform**: Using non-interactive or memory-only shells

Typical artifacts and indicators include:
- Missing or empty history files
- History settings modified mid-session
- Commands executed without corresponding history entries
- Shell configuration changes outside normal workflows

---

## 3. Subtechnique Considerations
Key considerations for T1562.003:
- Often used during interactive intrusion phases
- Frequently paired with **Indicator Removal on Host (T1070)**
- Complements obfuscation (T1027) and scripting abuse (T1059)
- Reduces analyst visibility rather than preventing execution

This technique is common in **manual intrusions**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Disabling shell history before executing commands
- Clearing history after performing malicious actions
- Using environment variables to suppress logging
- Running commands via interpreters that bypass history

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **shell behavior and configuration changes**:
- Alert on history file truncation or deletion
- Monitor changes to history-related environment variables
- Correlate command execution with missing history entries
- Detect abnormal shell configuration modifications

### Data Source Notes
- **Shell history telemetry**: Primary source where available
- **Process telemetry**: Identify interactive shell usage
- **EDR telemetry**: Correlate execution without history

Common false positives:
- Privacy-conscious users disabling history
- Automated scripts or CI/CD pipelines
- Ephemeral or containerized shells

Tuning guidance:
- Baseline history behavior by user role
- Elevate alerts when history changes coincide with suspicious activity

---

## 6. Response Guidance
When suspected:
1. Preserve existing history files immediately
2. Review shell configuration and environment variables
3. Correlate shell activity with process and network telemetry
4. Investigate for additional defense-evasion techniques
5. Expand scope to identify other affected systems

## 8. SOC Relevance
T1562.003 is especially relevant when:
- Analysts observe suspicious shell activity with limited context
- Incident timelines contain unexplained gaps
- Interactive intrusion is suspected

Impaired command history often explains **missing attacker steps**.

## 12. Mitigations
Recommended mitigations:
- Enforce centralized command logging where possible
- Monitor shell configuration files for changes
- Use EDR to capture command execution independently of history
- Limit interactive shell access
- Train analysts to recognize history suppression indicators

---

## 13. Testing & Validation
Validation approaches:
- Disable shell history in lab environments
- Validate alerts on history file changes
- Test SOC workflows for incomplete command timelines
- Ensure alternate telemetry sources fill gaps
