# Process Injection: Asynchronous Procedure Call (T1055.004)

## 1. Summary
Asynchronous Procedure Call (APC) Injection describes adversaries **queuing malicious code for execution within the context of an existing thread** by abusing the Windows APC mechanism. APCs are designed to allow code execution in a thread when it enters an alertable state; attackers exploit this feature to execute payloads without creating new threads.

T1055.004 is commonly used to:
- Execute code stealthily inside trusted processes
- Avoid detection mechanisms that focus on thread creation
- Blend malicious execution into legitimate thread activity
- Support in-memory and fileless malware execution

---

## 2. Technical Overview
Windows supports APCs to schedule functions to execute asynchronously in the context of a specific thread. Adversaries abuse this mechanism by:
- Allocating executable memory in a remote process
- Writing shellcode or payloads into that memory
- Queuing an APC to a target thread pointing to the malicious code
- Triggering execution when the thread enters an alertable state

Common APIs involved include:
- `QueueUserAPC`
- `NtQueueApcThread`
- `VirtualAllocEx`
- `WriteProcessMemory`

Artifacts often include:
- Threads executing code from non-module memory
- APC queues referencing suspicious memory addresses
- Legitimate processes performing anomalous actions
- Memory regions with RWX or RX permissions created at runtime

---

## 3. Subtechnique Considerations
Key considerations for T1055.004:
- Payload executes only when the target thread becomes alertable
- Often paired with thread enumeration and process discovery
- Highly stealthy due to lack of new threads or module loads
- Detection requires deep thread and memory telemetry

APC injection is frequently used by advanced loaders and implants.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting shellcode via APC into GUI or worker threads
- Using APC injection to execute second-stage payloads
- Combining APC injection with encrypted in-memory loaders
- Leveraging APCs for delayed or opportunistic execution

These actions typically occur after initial execution or persistence establishment.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring APC-related API usage
- Detecting threads executing from non-image memory regions
- Identifying unusual memory allocation and protection changes
- Correlating APC activity with prior process access or injection attempts

### Data Source Notes
- **Thread telemetry**: Essential for detecting APC execution
- **Memory telemetry**: Required to identify injected payloads
- **API telemetry**: Enables detection of APC queuing behavior

---

## 6. Response Guidance
When suspected:
1. Identify affected processes and threads
2. Isolate compromised systems
3. Capture memory for forensic analysis
4. Terminate malicious processes if operationally safe
5. Investigate for additional injection or persistence techniques

- Monitor for suspicious APC queuing behavior
- Restrict inter-process handle access

- Apply least privilege principles
