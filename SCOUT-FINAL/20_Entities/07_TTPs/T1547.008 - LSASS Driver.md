# T1547.008 – LSASS Driver

## 1. Technique Overview
**LSASS Driver (T1547.008)** is a sub-technique of **Boot or Logon Autostart Execution (T1547)** in MITRE ATT&CK v18. Adversaries abuse support for **LSASS-loaded drivers** to execute malicious code within or alongside the Local Security Authority Subsystem Service (LSASS). These drivers are loaded during system startup or authentication events and operate with **SYSTEM-level privileges**.

Because LSASS is a core Windows security process, this technique provides highly stealthy persistence and significant control over authentication-related operations.

## 2. Adversary Objectives
Adversaries use this technique to:
- Achieve persistent, high-privilege execution
- Operate within the Windows authentication subsystem
- Facilitate credential access or manipulation
- Evade user-mode security controls

## 3. Common Abuse Patterns
- Installing malicious drivers configured to load with LSASS
- Registering drivers via Windows service or driver configuration mechanisms
- Masquerading malicious drivers as legitimate security components
- Using LSASS drivers to intercept or manipulate authentication data
- Pairing LSASS driver persistence with credential dumping techniques

## 4. Detection Considerations
Detection is difficult and requires **kernel- and security-process monitoring**, including:
- Monitoring installation of new or unsigned drivers
- Detecting unexpected drivers associated with LSASS
- Alerting on modifications to LSASS-related configuration
- Inspecting driver load events during boot
- Correlating LSASS anomalies with authentication issues

## 5. Defensive Mitigations
- Enforce driver signing and Secure Boot
- Enable LSASS protection (RunAsPPL) where supported
- Restrict administrative privileges required to install drivers
- Monitor driver installation and load events
- Reimage systems suspected of LSASS driver compromise

## 6. Operational Impact
If successful, T1547.008 can:
- Provide durable, stealthy persistence
- Grant attackers deep control over authentication mechanisms
- Enable credential interception or manipulation
- Severely complicate detection and remediation

## 7. Analyst Notes
LSASS driver abuse represents one of the most severe Windows persistence mechanisms. Once attackers gain code execution at this level, traditional endpoint defenses may be ineffective. Incident response should prioritize **system isolation, offline analysis, and full rebuilds** when this technique is suspected.
