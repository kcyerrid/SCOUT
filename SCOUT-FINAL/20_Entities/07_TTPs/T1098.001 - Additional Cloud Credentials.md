# T1098.001 – Additional Cloud Credentials

## 1. Technique Overview
**Additional Cloud Credentials (T1098.001)** is a MITRE ATT&CK sub-technique in which adversaries **add new authentication material**—such as access keys, tokens, or certificates—to an **existing cloud identity**. This enables persistent access without creating new accounts, allowing attackers to blend into legitimate identity usage.

This technique is most commonly observed in cloud environments following credential compromise or privilege escalation.

## 2. Adversary Objectives
Adversaries leverage this technique to:
- Maintain **long-term persistence** in cloud environments
- Bypass password rotation or credential revocation
- Enable access from external infrastructure
- Support follow-on actions such as data exfiltration or resource abuse

## 3. Common Credential Types Abused
- AWS access keys (Access Key ID / Secret Access Key)
- Azure service principal secrets or certificates
- GCP service account keys
- OAuth tokens or application credentials

## 4. Common Abuse Patterns
- Adding new access keys to an existing IAM user
- Creating service principal secrets for compromised Azure AD accounts
- Generating service account keys in GCP for off-platform access
- Leaving credentials active even after initial access vectors are remediated

## 5. Detection Considerations
Detection relies heavily on **cloud audit and identity logs**, including:
- Creation of new access keys or secrets
- Service account key generation events
- Credential creation outside approved workflows
- Credential creation followed by immediate external API usage
- Access from anomalous IP addresses or geolocations

## 6. Defensive Mitigations
- Enforce **least privilege** and restrict credential creation rights
- Require approval workflows for IAM credential generation
- Monitor and alert on creation of new access keys or secrets
- Regularly audit and rotate cloud credentials
- Prefer short-lived credentials and managed identities over static keys

## 7. Operational Impact
Successful execution of T1098.001 can:
- Provide **stealthy, durable persistence**
- Undermine incident response if credentials are not fully enumerated
- Enable continued access even after password resets
- Facilitate data theft, cryptomining, or infrastructure abuse

## 8. Analyst Notes
T1098.001 is frequently missed during cloud incident response because defenders focus on **accounts**, not **credentials**. Full remediation requires enumerating and revoking *all* authentication artifacts tied to compromised identities, not just resetting passwords.
