# T1098.006 – Additional Container Cluster Roles

## 1. Technique Overview
**Additional Container Cluster Roles (T1098.006)** is a sub-technique of **Account Manipulation (T1098)** in MITRE ATT&CK v18. It describes adversary behavior where **additional roles, role bindings, or permissions** are granted to existing identities within container orchestration platforms, most commonly **Kubernetes**. By modifying authorization rather than creating new accounts, attackers achieve stealthy persistence or privilege escalation.

This technique is typically observed after initial access to container management interfaces or compromise of credentials with limited cluster privileges.

## 2. Adversary Objectives
Adversaries use this technique to:
- Escalate privileges within a container cluster
- Maintain long-term access to Kubernetes control planes
- Enable lateral movement across namespaces and workloads
- Gain the ability to deploy, modify, or access sensitive containers

## 3. Common Abuse Patterns
- Creating or modifying **ClusterRoleBindings** to grant cluster-admin privileges
- Assigning additional **Roles** or **ClusterRoles** to compromised service accounts
- Expanding permissions of existing Kubernetes users
- Granting access to secrets, config maps, or the Kubernetes API
- Binding high-privilege roles across multiple namespaces

## 4. Detection Considerations
Detection relies on **container security and audit telemetry**, including:
- Kubernetes audit logs showing role or role binding changes
- Creation or modification of ClusterRoles and RoleBindings
- Privilege changes occurring outside approved deployment pipelines
- Sudden expansion of permissions for service accounts
- Administrative actions performed by identities with historically low privileges

## 5. Defensive Mitigations
- Enforce **least privilege** for Kubernetes users and service accounts
- Restrict who can create or modify Roles and ClusterRoleBindings
- Monitor and alert on RBAC changes in cluster environments
- Use admission controllers and policy engines (e.g., OPA/Gatekeeper)
- Regularly audit RBAC configurations and remove excessive permissions

## 6. Operational Impact
Successful abuse of T1098.006 can:
- Provide attackers with cluster-wide administrative control
- Enable deployment of malicious containers or workloads
- Facilitate access to secrets and sensitive data
- Undermine container isolation and security boundaries

## 7. Analyst Notes
Container RBAC abuse is a high-impact but often under-monitored persistence vector. Many organizations focus detection on workloads rather than **authorization state changes** within orchestration platforms. Effective response requires reviewing historical and current RBAC bindings, not just container images or running pods.
