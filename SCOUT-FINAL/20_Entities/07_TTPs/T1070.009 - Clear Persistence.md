# Indicator Removal on Host: Clear Persistence (T1070.009)

## 1. Summary
Clear Persistence describes adversaries **removing or disabling persistence mechanisms** they previously established on a compromised system. This is typically performed during cleanup phases, prior to attacker exit, or to evade detection once objectives are achieved.

Attackers use this technique to:
- Reduce forensic evidence of compromise
- Evade long-term detection
- Transition from persistent to ephemeral access
- Conceal operational tooling and footholds

---

## 2. Technical Overview
Persistence mechanisms create durable artifacts across operating systems and cloud platforms. Adversaries clear persistence by:

- Removing scheduled tasks, cron jobs, or launch agents
- Deleting registry run keys or startup items
- Removing or disabling malicious services
- Deleting cloud IAM persistence mechanisms
- Cleaning container startup configurations

Common artifacts targeted:
- Autorun entries
- Scheduled jobs
- Services and daemons
- Cloud identities and access bindings

Indicators include:
- Sudden removal of persistence artifacts
- Cleanup following privilege escalation or lateral movement
- Loss of previously identified footholds
- Persistence artifacts removed without change tickets

---

## 3. Subtechnique Considerations
Key considerations for T1070.009:
- Often follows **Persistence (TA0003)** activity
- Common in **ransomware and smash-and-grab intrusions**
- May indicate attacker exit or operational completion
- Can reduce detection if not already observed

Clear persistence is often a **late-stage behavior**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Deleting scheduled tasks after payload execution
- Removing startup entries post-exfiltration
- Cleaning up cloud IAM persistence after data theft
- Disabling services used for backdoor access

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **unexpected removal of persistence artifacts**:
- Alert on deletion of scheduled tasks or autoruns
- Detect removal of services without administrative tickets
- Monitor cloud IAM changes removing access
- Correlate persistence removal with suspicious activity

### Data Source Notes
- **Startup and task logs**: Primary visibility
- **Registry and service logs**: Attribute changes
- **Cloud configuration logs**: Detect IAM cleanup
- **EDR telemetry**: Link cleanup to processes

Common false positives:
- Legitimate software uninstallers
- System reconfiguration or decommissioning
- Patch or upgrade workflows

Tuning guidance:
- Baseline persistence artifact lifecycle
- Increase severity when removal follows malicious activity

---

## 6. Response Guidance
When suspected:
1. Identify what persistence artifacts were removed
2. Determine why and when removal occurred
3. Correlate with execution, network, and identity activity
4. Investigate for missed earlier intrusion phases
5. Expand hunt for remaining footholds

- Require approvals for persistence changes
- Centralize persistence telemetry
- Investigate unexplained artifact removal
