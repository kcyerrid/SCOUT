# Process Injection: Extra Window Memory Injection (T1055.011)

## 1. Summary
Extra Window Memory Injection describes adversaries **abusing the Windows GUI subsystem to write malicious code into the extra window memory of another process**. Windows allows applications to associate additional memory with window objects; attackers exploit this feature to store payloads and redirect execution.

T1055.011 is commonly used to:
- Inject code into GUI-based processes
- Evade detection by avoiding classic injection APIs
- Execute payloads within trusted applications
- Support stealthy execution and persistence

---

## 2. Technical Overview
Windows GUI applications may allocate **extra window memory** using `SetWindowLongPtr` and related APIs. Adversaries abuse this by:
- Locating a target window handle (`HWND`)
- Writing attacker-controlled data into the window’s extra memory
- Redirecting window procedure pointers
- Triggering execution via window messages

Common APIs involved include:
- `SetWindowLongPtr`
- `GetWindowLongPtr`
- `SendMessage`
- `PostMessage`

Artifacts often include:
- Unexpected changes to window procedure pointers
- GUI processes executing abnormal code paths
- Message handling leading to execution from non-image memory
- Anomalous window message patterns

---

## 3. Subtechnique Considerations
Key considerations for T1055.011:
- Limited to GUI-enabled processes
- Requires understanding of Windows message handling
- Highly stealthy due to uncommon API usage
- Detection depends on GUI-aware telemetry

This subtechnique is less common but effective against mature defenses.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting payloads into browser or file explorer windows
- Modifying window procedure callbacks
- Executing shellcode in response to window messages
- Pairing window memory injection with other injection techniques

These actions typically occur after initial execution.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring `SetWindowLongPtr` and related API usage
- Detecting abnormal window procedure changes
- Identifying GUI processes executing code from unusual memory regions
- Correlating window message abuse with prior process access

### Data Source Notes
- **API telemetry**: Critical for detecting GUI manipulation
- **Memory telemetry**: Required for identifying injected payloads
- **Process telemetry**: Useful for behavioral correlation

---

## 6. Response Guidance
When suspected:
1. Identify affected GUI processes and windows
2. Isolate compromised systems
3. Capture memory for forensic analysis
4. Restart affected applications where safe
5. Investigate for additional injection or persistence mechanisms
