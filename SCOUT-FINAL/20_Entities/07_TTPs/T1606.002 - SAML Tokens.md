## 1. Summary
Adversaries may forge **SAML tokens** to authenticate as arbitrary users (including highly privileged identities) across federated services without completing normal authentication/MFA, typically by abusing token-signing certificates or federation trust (“Golden SAML”-style outcomes).

## 2. Technical Overview
Common mechanics:
- **Compromise or obtain access to the SAML token-signing certificate** (or establish a trusted signing path).
- **Mint assertions** with attacker-chosen claims (user identity, roles, audiences) and potentially altered lifetimes.
- **Use forged assertions** to authenticate to SaaS/Office Suite/IdP-federated apps as if legitimately issued.

Defender-observable outcomes:
- Authentication succeeds with **valid signatures** while normal preceding authentication telemetry (e.g., expected Kerberos/auth events or IdP issuance patterns) may be absent or inconsistent.

## 4. Procedure Examples
- [[30_CIPHER/05_Malware/S0677 - AADInternals|AADInternals]] (S0677) can be used to create SAML tokens using the AD FS token signing certificate.
- **SolarWinds Compromise (C0024):** [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] created tokens using compromised SAML signing certificates.

## 5. Detection Guidance
Primary detection goal: **identify valid SAML assertions that do not match expected issuance/authentication prerequisites or baseline claims.**

**High-signal detection themes**
- **Correlation gaps**
  - SAML-authenticated sessions with valid signatures but **missing expected preceding authentication artifacts** in the relevant time window (per environment baseline).
- **Issuer/claims anomalies**
  - Unexpected issuer, audience, NameID formats, role/privilege claims, or token lifetimes compared to baseline.
  - High-privilege claims for users not typically elevated.
- **IdP/AD FS operational anomalies**
  - Unusual access to token-signing certs, changes in federation trusts, or signing key rotation outside change windows.
- **SaaS/O365 usage anomalies**
  - Successful access without MFA where MFA is normally required; concurrent sessions from disparate geographies using federated auth.

### Data Source Notes
- **IdP/AD FS logs:** assertion issuance, certificate usage, federation trust changes, admin actions, audit policies.
- **Entra ID / SaaS sign-in logs:** federated sign-in events, conditional access/MFA outcomes, device context.
- **Directory/audit logs:** changes to privileged groups/roles, federation objects, certificate stores.
- **Cloud/IaaS logs:** federated role assumption traces correlated with SAML assertions.

## 6. Response Guidance
1. **Invalidate forged-token trust**
   - Rotate token-signing certs and invalidate tokens as recommended for the environment (see mitigations).
2. **Contain identity admin plane**
   - Restrict access to AD FS/IdP hosts; require privileged access workstations; review admin sessions and lateral movement.
3. **Scope impact**
   - Enumerate accounts/apps accessed via federated sign-ins; identify anomalous claims/issuers; pivot on assertion IDs and signing thumbprints.
4. **Rebuild confidence**
   - Re-establish federation trust cleanly; validate signing cert custody; audit all federation endpoints and related secrets.

## 8. SOC Relevance
- **Priority:** Critical. Successful forged SAML often equals **enterprise-wide identity compromise**.
- **Best alerts:** token accepted without expected prerequisites; abnormal issuer/claims/lifetime; signing-certificate access/rotation anomalies.
- **Operational reality:** you may only see “successful login” unless you instrument issuer/claims and correlate with IdP/admin telemetry.

## 12. Mitigations
- **M1015 – Active Directory Configuration:** For containing impact of forged SAML tokens, rotate the token-signing AD FS certificate **in rapid succession twice** to invalidate previously forged tokens.
- **M1047 – Audit:** Enable advanced auditing on AD FS and review success/failure and application-generated audit events.
- **M1026 – Privileged Account Management:** Restrict access to AD FS/IdP systems (prefer privileged access workstations).
- **M1018 – User Account Management:** Reduce highly privileged role memberships; enforce strong authentication and identity hygiene.

## 13. Testing & Validation
- Validate detections in a lab by confirming you can:
  - Parse and baseline SAML issuer/audience/claims/lifetime
  - Alert on sign-ins that are inconsistent with expected precursor events for your environment
- Atomic Red Team note: there is content mapped to this technique; use only in a controlled lab, and focus on confirming **log visibility and correlation** rather than executing high-impact identity forgery steps.
