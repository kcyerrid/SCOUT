# Access Token Manipulation: SID-History Injection (T1134.005)

## 1. Summary
SID-History Injection describes adversaries **modifying or abusing the SIDHistory attribute in Active Directory accounts** to gain the privileges associated with additional security identifiers (SIDs). Because Windows authorization evaluates SIDHistory during access checks, injected SIDs can grant elevated permissions without changing group memberships.

T1134.005 is commonly used to:
- Escalate privileges to domain or enterprise administrator
- Maintain stealthy access without modifying group memberships
- Persist elevated privileges across authentication events
- Evade detection focused on group membership changes

---

## 2. Technical Overview
In Active Directory environments, the `SIDHistory` attribute is intended to support account migration by preserving access tied to old SIDs. Adversaries abuse this by:
- Injecting high-privilege SIDs into the SIDHistory attribute
- Leveraging injected SIDs during authentication
- Gaining access to resources protected by the injected SID
- Avoiding direct modification of group memberships

Common artifacts include:
- Authentication tokens containing unexpected or high-privilege SIDs
- Elevated access without corresponding group membership changes
- Directory modifications to SIDHistory attributes

---

## 3. Subtechnique Considerations
Key considerations for T1134.005:
- Requires write access to Active Directory objects
- Often follows domain compromise or replication abuse
- Detection is difficult without deep AD auditing
- SIDHistory changes may persist indefinitely

This subtechnique is highly impactful in domain environments.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Injecting Domain Admin SIDs into compromised user accounts
- Using directory service APIs to modify SIDHistory
- Authenticating normally to inherit injected privileges
- Combining SIDHistory abuse with valid credentials

These procedures typically occur after achieving domain-level access.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring changes to SIDHistory attributes
- Detecting authentication tokens containing unexpected SIDs
- Alerting on elevated access without group changes
- Auditing directory modifications by non-administrative accounts

### Data Source Notes
- **Active Directory logs**: Essential for attribute change tracking
- **Authentication logs**: Useful for identifying SID anomalies
- **Security event logs**: Help correlate privilege usage

---

## 6. Response Guidance
When detected:
1. Identify accounts with unauthorized SIDHistory entries
2. Remove injected SIDs immediately
3. Investigate how directory write access was obtained
4. Audit authentication and access logs for abuse
5. Reset credentials and review privileged accounts

## 8. SOC Relevance
T1134.005 is especially relevant in:
- Active Directory environments
- Domain and enterprise privilege escalation scenarios
- Attacks seeking long-term stealthy persistence

SIDHistory abuse enables powerful access with minimal visible changes.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Advanced persistent threats
- Sophisticated ransomware operators
- Adversaries targeting domain dominance

Usage reflects high attacker maturity and AD expertise.

---

## 10. Campaign Usage
Observed in:
- Domain takeover campaigns
- Long-term enterprise intrusions
- Attacks following directory replication abuse

---

## 11. Malware Usage
Malware leveraging SID-History injection includes:
- Custom Active Directory manipulation tools
- Post-exploitation frameworks
- Domain-focused attack toolchains

---

## 12. Mitigations
Recommended mitigations:
- Restrict write access to SIDHistory attributes
- Monitor and alert on SIDHistory changes
- Regularly audit directory attributes
- Enforce strong separation of administrative duties
- Apply least privilege across AD environments

---
