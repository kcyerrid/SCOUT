## 1. Summary
Adversaries may compress or encrypt collected data using a **custom method** (e.g., bespoke XOR/stream-cipher routines, custom containers, or custom implementations of known algorithms) to avoid detection that relies on known utilities or common library artifacts. This is often the hardest Archive Collected Data variant to detect and generally requires behavior-based analytics.

## 2. Technical Overview
**What it is:** Archiving/encryption performed by bespoke code paths without clearly identifiable external archiving utilities or standard compression library usage.

**Defender-relevant behaviors:**
- Creation of archive-like/high-entropy outputs without corresponding use of `zip/tar/7z/rar` utilities.
- Suspicious scripts/binaries producing container files with non-standard headers or “unknown” formats.
- High-entropy file creation bursts in staging directories.
- Memory/process behaviors consistent with encoding/encryption loops (e.g., unusual bitwise operations patterns, CryptoAPI usage on Windows in unexpected contexts).

## 3. Subtechnique Considerations
Prefer this subtechnique when:
- There is no clear evidence of standard utilities (T1560.001) or library API usage (T1560.002).
- Output artifacts appear bespoke (unknown extension/format) or are high-entropy blobs generated by suspicious processes.

In environments with strong EDR telemetry, this can be approached via behavioral correlation and entropy/format classification rather than signature.

## 5. Detection Guidance
**Core idea:** Detect the *absence* of normal tooling coupled with the *presence* of suspicious file outputs and anomalous process behavior.

**MITRE Detection Strategy (DET0438) highlights:**
- Identify anomalous script/binary executions that generate high-entropy files with non-standard headers.
- Correlate interpreter execution (Python/Perl/Bash) with output file creation that does not align with known archivers.
- Use process access/modification telemetry where available to highlight suspicious memory behaviors associated with custom encoding/encryption.

### 5.1 Data Source Notes
Primary data components from DET0438:
- **Process Creation (DC0032)**: script/binary execution context and parent-child anomalies
- **File Creation (DC0039)**: high-entropy or unusual-format outputs in staging directories
- **Process Access (DC0035)**: Windows Sysmon 10 for suspicious access patterns (where applicable)
- **Process Modification (DC0020)**: platform-specific process modification/memory operation signals (e.g., osquery/macos unified logs per DET0438)
- **Command Execution (DC0064)**: Linux auditd execve for interpreter execution correlation

**Enrichment recommendations:**
- File entropy scoring and “magic header” inspection in pipeline (to flag unknown containers).
- “Known-good” compression/encryption allowlists for internal apps that legitimately generate high-entropy outputs.

## 6. Response Guidance
1. **Preserve suspicious outputs:** Acquire the generated files, capture hashes, sizes, and first-seen timestamps.
2. **Characterize the container:** Determine if it matches known archive formats (even with custom extensions) and whether it is encrypted/compressed.
3. **Investigate process behavior:** Review process tree, binary provenance, signing, prevalence, and execution source.
4. **Egress correlation:** Determine if outputs were transmitted externally or staged for later transfer.
5. **Contain and hunt:** Isolate affected hosts and search for similar high-entropy file creation + rare process patterns across the fleet.

## 8. SOC Relevance
**Why it’s important:** Custom archiving often indicates higher sophistication or intent to evade standard pre-exfil detections.

**SOC prioritization cues:**
- High-entropy file outputs created by low-prevalence binaries or scripts.
- Output written to staging paths and followed by outbound connections.
- Rare parent processes or unusual user contexts producing encrypted blobs.

## 12. Mitigations
ATT&CK notes this technique is difficult to mitigate preventively because it abuses common system features. Emphasize:
- Strong logging/EDR coverage
- Least privilege and data access controls
- DLP/egress controls to reduce impact even when custom archiving succeeds

## 13. Testing & Validation
- Validate behavioral detections by simulating:
  - Creation of high-entropy files by scripts/binaries in staging directories.
  - Correlation between script execution and suspicious outputs without standard archiver utilities.
- Ensure your pipeline can compute file entropy and capture process ancestry/module usage as available.
