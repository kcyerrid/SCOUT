## 1. Summary
Adversaries may directly collect unsecured credentials stored or transmitted through enterprise communication and collaboration services (e.g., email, chat platforms, ticketing/collaboration tools). Credentials shared in messages (passwords, API keys, tokens) can enable immediate follow-on access and are commonly overlooked compared to file-based secret exposure.

## 2. Technical Overview
This subtechnique focuses on credentials that appear in:
- **Direct messages / channels** (chat platforms)
- **Email threads**
- **Collaboration tools** (tickets, tasks, wikis, project boards)
- **Workflow/integration tooling** that can search or export messages

Adversary access paths include:
- Compromised endpoints with authenticated sessions
- Compromised SaaS accounts and admin portals
- Abuse of integrations/bots/workflows to search message content or export histories

## 3. Subtechnique Considerations
- Content access can occur via **UI**, **API**, or **admin export** mechanisms—each has different telemetry.
- False positives are common if scanning is performed for DLP/security; detections must prioritize:
  - **New/rare principals**
  - **Bulk access/export patterns**
  - **Suspicious forwarding/copying behavior**
  - **Integration/workflow changes** enabling automated harvesting
- Credential patterns should be scoped to organizational context (token formats, internal key prefixes) to reduce noise.

## 4. Procedure Examples
Observed usage includes:
- Targeting collaboration tools (e.g., Slack/Teams/Jira/Confluence) to hunt for exposed credentials to support privilege escalation and lateral movement.

## 5. Detection Guidance
**Content scanning / DLP-aligned detections**
- Detect messages containing likely secret patterns (password assignments, API keys, token-like strings) and:
  - Alert when posted by high-privilege users or service accounts
  - Alert on secrets posted in public or broadly visible channels
  - Alert on repeated occurrences (indicates habitual secret sharing)

**Behavior-based detections**
- Bulk retrieval of chat/email content by non-admin users
- Unusual search queries or exports related to secrets (when available)
- Suspicious forwarding, mass downloads, or large-scale attachment retrieval tied to secret-containing content

**Integration & workflow monitoring**
- Changes to workflows/bots that introduce automated scanning/export of messages
- New tokens/permissions granted to integrations followed by large message history reads

### Data Source Notes
- Primary telemetry: SaaS audit logs (message read/search/export, admin actions), email audit logs, DLP events, and endpoint telemetry for client-side scraping tools.
- Where message read telemetry is limited, focus on **export events**, **admin portal actions**, and **API token usage**.

## 6. Response Guidance
1. **Containment**
   - Disable suspicious integrations/tokens; lock or reset compromised accounts.
2. **Credential invalidation**
   - Rotate exposed secrets immediately (API keys, tokens, passwords); check for downstream reuse.
3. **Content remediation**
   - Remove/expire messages containing secrets; implement DLP quarantines where supported.
4. **Investigation**
   - Review SaaS audit logs for bulk access/export; identify which messages/secrets were accessed.
5. **Prevention**
   - Enforce secret-sharing policies; adopt managed secret stores and short-lived credentials.

## 8. SOC Relevance
Moderate-to-high relevance in SaaS-heavy enterprises:
- High-value detections come from **bulk access/export** and **integration permission changes**, not just single message views.
- Combine DLP-like pattern detection with identity risk signals (new device, impossible travel, token anomalies).

## 12. Mitigations
- **M1047 - Audit**: Proactively search communication services for shared credentials; remediate findings.
- **M1017 - User Training**: Train users/admins/developers not to share secrets in messages and to use managed secret storage.
