# Unix Shell (T1059.004)

## 1. Summary
Unix Shell describes adversary abuse of command-line shells on Unix-like operating systems, such as Linux and macOS, to execute commands and scripts. Common shells include `bash`, `sh`, `zsh`, and `dash`. This subtechnique enables flexible, interactive, and automated execution across server, workstation, and cloud-hosted environments.

Because shell usage is fundamental to system administration and application operation, malicious activity can closely resemble benign behavior without strong contextual analysis.

---

## 2. Technical Overview
Unix shells provide a command interpreter for executing built-in commands, scripts, and external binaries.

Adversaries commonly abuse Unix shells to:
- Execute inline commands or shell scripts
- Chain commands using pipes and logical operators
- Download and execute payloads via shell one-liners
- Perform environment discovery and automation

Artifacts include shell process execution (`bash`, `sh`, `zsh`), command-line arguments, script file creation, and child processes spawned by the shell.

---

## 3. Subtechnique Considerations
T1059.004 is the Unix/macOS-specific implementation of interpreter-based execution.

Key considerations include:
- Differences between interactive and non-interactive shells
- Use of login vs. non-login shells
- Shell initialization files (`.bashrc`, `.profile`) abused for persistence
- Variability in shell logging and history configuration

Detection efficacy varies significantly by environment and logging posture.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing shell one-liners to download and run payloads
- Using shell scripts for automation and persistence
- Leveraging environment variables to obfuscate commands
- Chaining shell commands to evade simplistic detection

Analysts may observe unexpected shell execution on servers or cloud workloads.

---

## 5. Detection Guidance
Detection should focus on:
- Shell execution by unusual parent processes
- Suspicious command-line arguments or obfuscation
- Shell scripts executing from temporary or user-writable directories
- Network connections initiated by shell processes

Correlation between process execution, file creation, and network activity improves detection fidelity.

### Data Source Notes
- **Process Execution:** Primary indicator of shell activity
- **Command-Line Parameters:** Critical for detecting malicious intent
- **Shell History:** Useful but often incomplete or disabled

---

## 6. Response Guidance
When malicious Unix shell activity is suspected:
- Capture full command-line arguments and script content
- Identify downloaded payloads or follow-on execution
- Isolate affected systems or workloads if compromise is confirmed
- Review user accounts and credentials involved in execution

Preserve shell history files and execution logs for forensic analysis.

## 8. SOC Relevance
Unix shell abuse is pervasive in Linux server, container, and cloud intrusions. SOC teams must account for high baseline shell activity while identifying behavioral anomalies indicative of malicious use.

## 12. Mitigations
Effective mitigations include:
- Restricting shell access where feasible
- Enforcing least-privilege user permissions
- Monitoring shell execution and command arguments
- Hardening SSH and remote access controls
- Applying application allowlisting on servers

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for Unix shell execution
- Purple team simulations using shell one-liners
- Review of alerts tied to suspicious shell activity

Successful validation results in detection of unauthorized shell execution.
