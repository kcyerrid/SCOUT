## 1. Summary
Adversaries may **forge web cookies** to authenticate to web apps/services as a user without completing the normal login/MFA flow. Unlike cookie theft, the cookie value is **newly generated** by the adversary using secrets or key material.

## 2. Technical Overview
Common mechanics:
- **Derive or steal cookie-signing/validation secrets** (e.g., AD FS/OWA-related secrets, app secrets, private keys).
- **Construct cookie values** matching application-specific formats (often documented/standardized in common apps).
- **Inject/plant cookies** into browser stores or attach as headers, then access target web resources to establish authenticated sessions.

Typical defender-observable outcomes:
- Web sessions appear valid but may lack normal upstream authentication artifacts (interactive login, MFA step, device compliance).

## 4. Procedure Examples
- **SolarWinds Compromise (C0024):** [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] bypassed MFA on OWA accounts by **generating a cookie value** using a previously stolen secret key.  

## 5. Detection Guidance
Key detection goal: **identify cookie creation/injection or anomalous use of valid cookies without expected auth flows.**

**High-signal detection themes**
- **Cookie store access/write anomalies (endpoint)**
  - Non-browser processes reading/writing browser cookie stores (e.g., Chrome/Edge SQLite cookie DBs) shortly before suspicious web sessions.
  - Sudden/rare modifications to cookie DB files outside normal browser update windows.
- **Session/auth correlation anomalies (web/IdP)**
  - Valid sessions established **without preceding interactive login/MFA**, or with missing/atypical device fingerprints.
  - Concurrent valid sessions across distant geographies (impossible travel) tied to the same user/cookie family.
- **App-specific indicators**
  - “New” sessions where cookie structure is valid but issuance does not align with server-side session creation patterns.

### Data Source Notes
- **Endpoint telemetry:** process/file events for browser cookie paths; EDR file-write ancestry; browser extension inventories.
- **Web access logs:** session IDs, cookie presence, auth state, IP/geo/user-agent/device identifiers.
- **Identity telemetry:** MFA enforcement logs; sign-in risk; conditional access outcomes (when applicable).
- **Secrets/key telemetry (if available):** key access, certificate store access, AD FS auditing.

## 6. Response Guidance
1. **Invalidate sessions/cookies**
   - Force sign-out, revoke sessions, and enforce re-authentication for affected accounts/apps.
2. **Rotate secrets**
   - Rotate cookie-signing secrets and related key material; review and remediate secret exposure paths.
3. **Scope access**
   - Identify resources accessed with forged sessions; review logs for missing-auth patterns and unusual IP/device.
4. **Harden**
   - Tighten conditional access, device trust, and session binding (where supported); reduce cookie lifetime where feasible.

## 8. SOC Relevance
- **Primary signal:** cookie-store modification/access + anomalous authenticated web session.
- **Best detections:** endpoint + web log correlation (process writes cookie DB → privileged web access).
- **Fast triage questions:** Was MFA satisfied? Was there an interactive login? Does device context match baseline?

## 12. Mitigations
- **M1047 – Audit:** Audit web app permissions/access lists and investigate suspicious credentials/sessions.
- **M1054 – Software Configuration:** Configure browsers/applications to regularly delete persistent web cookies.

## 13. Testing & Validation
- Validate detection by ensuring you can alert on:
  - Non-browser process write access to cookie stores
  - Web session creation/usage with missing auth/MFA precursors
- Atomic Red Team status: many indexes list this technique as “contribute a test”; validate via log replay and controlled browser-profile manipulation in a lab rather than running real forgery procedures.
