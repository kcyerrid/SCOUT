## 1. Summary
Adversaries may collect data directly from database systems (on-prem or cloud-hosted) to obtain high-value information such as PII, financial records, internal business data, and operational metadata. This activity often precedes data theft/extortion and may be performed via legitimate administration interfaces, database clients, or application-layer access.

## 2. Technical Overview
Common defender-observable patterns include:
- **Interactive querying** via database clients or admin tools from non-standard hosts/users.
- **Bulk extraction** behaviors (large result sets, repeated table exports, schema-wide reads).
- **Abuse of legitimate access paths** (valid accounts/roles, service accounts, application credentials).
- **Staging artifacts** (export files, temporary tables/stages, dumps/backups) prior to exfiltration.
- **Cloud database access** using web UI/CLI plus anomalous client fingerprints (new user agents/driver versions, unusual IPs/ASNs).

Key operational risks:
- Databases centralize sensitive data, so **single-account compromise** can yield large impact.
- In cloud/SaaS, **audit retention** and **telemetry availability** often determine detection feasibility.

## 3. Subtechnique Considerations
- This is a subtechnique of **T1213 - Data from Information Repositories**; focus is specifically on **database** repositories (SQL/NoSQL/warehouse platforms).
- Detection should distinguish:
  - **Normal admin operations** (maintenance windows, known DBA jump hosts) vs. **adversary collection** (new endpoints, unusual query patterns, atypical hours/volumes).
  - **Application-layer reads** vs. **direct DB access** (new DB clients, JDBC/ODBC driver usage, unexpected admin tools).

## 5. Detection Guidance
ATT&CK provides a detection strategy for this subtechnique (DET0242) with analytics emphasizing anomalous querying and bulk extraction.

High-signal detection opportunities:
- **DB authentication anomalies**
  - New DB users/roles, privilege elevation, sudden role grants.
  - Logins from new hosts, unusual geolocation/ASN, or atypical client drivers.
- **Query/operation anomalies**
  - Large SELECTs across sensitive tables, repeated full-table scans, schema enumeration followed by export.
  - Unusual use of export/backup/dump functions.
- **Staging indicators**
  - Creation of large export files (CSV/JSON dumps), temp stages, or bulk unload operations followed by outbound transfer.
- **Cross-telemetry correlation**
  - DB audit events + endpoint process telemetry (unexpected DB client binaries) + network egress spikes.

### Data Source Notes
Recommended telemetry to enable detections:
- **Database audit logs** (auth, query execution, export/backup operations, role/permission changes).
- **Cloud/SaaS audit logs** (API calls, session metadata, client identifiers, IP allowlist/deny events).
- **Endpoint telemetry** on DB servers and admin workstations (process creation, command-line, file creation for exports).
- **Network telemetry** (DB protocol flows, unusual lateral access to DB ports, outbound transfer from DB hosts).

## 6. Response Guidance
1. **Containment**
   - Restrict DB network access (temporary allowlist to DBA jump hosts), revoke suspicious sessions/tokens.
   - Disable/rotate compromised credentials (DB users, app secrets, service accounts).
2. **Eradication**
   - Remove unauthorized admin tools/web shells; validate DB server integrity and patch exposure paths.
   - Review and revert unauthorized role grants/permission changes.
3. **Investigation**
   - Pull DB audit logs around suspected access windows; enumerate touched tables/exports.
   - Identify staging locations (local exports, cloud stages/buckets) and confirm any exfil routes.
4. **Recovery**
   - Enforce MFA/SSO where supported, tighten IP allowlists, and increase audit retention.
   - Add guardrails: least privilege DB roles, separate read/reporting roles, and monitored break-glass accounts.

## 8. SOC Relevance
- **Primary risk:** high-volume theft of regulated data (PII/PCI/PHI), competitive intelligence, or credentials.
- **Best detections:** “new principal + unusual client + bulk read/export” and “export/stage then egress.”
- **Operational note:** false positives often come from BI/reporting jobs—baseline scheduled workloads and known service accounts.

## 12. Mitigations
- **M1022 - Restrict File and Directory Permissions:** limit access to DB config/secrets and export paths.
- **M1030 - Network Segmentation:** isolate DB servers; restrict admin interfaces to hardened jump hosts.
- **M1032 - Multi-factor Authentication:** enforce MFA/SSO for DB consoles and privileged DB access where supported.
- **M1037 - Filter Network Traffic:** restrict DB ports and management endpoints to approved sources.
- **M1047 - Audit:** enable and retain detailed DB auditing (auth, queries, exports, permissions).

## 13. Testing & Validation

  - Known-good DBA workflows vs. “new host/user bulk export” patterns.
  - Cloud/SaaS: anomalous client identifiers and IP allowlist violations.
