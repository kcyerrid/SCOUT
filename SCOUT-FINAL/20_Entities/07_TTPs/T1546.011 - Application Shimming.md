# T1546.011 – Application Shimming

## 1. Technique Overview
**Application Shimming (T1546.011)** is a sub-technique of **Event Triggered Execution (T1546)** in **MITRE ATT&CK v18**. Adversaries abuse the Windows **Application Compatibility Framework**, which uses *shims* to modify application behavior for compatibility purposes. By creating or modifying shim databases (`.sdb` files), attackers can cause malicious code to execute automatically whenever a targeted application is launched.

Because shimming is a legitimate Windows feature commonly used by administrators and software vendors, malicious shims can persist with low visibility.

## 2. Adversary Objectives
Adversaries use application shimming to:
- Achieve persistence tied to execution of specific applications
- Inject or execute malicious code within trusted processes
- Evade detection by leveraging a legitimate compatibility mechanism
- Maintain execution without relying on traditional autorun locations

## 3. Common Abuse Patterns
- Creating custom shim databases using tools such as `sdbinst.exe`
- Registering shims that load malicious DLLs or redirect API calls
- Targeting commonly used or privileged applications
- Masquerading shim entries as legitimate compatibility fixes
- Leveraging shims to bypass security controls or inject code

## 4. Detection Considerations
Detection relies on **compatibility framework and binary integrity monitoring**, including:
- Monitoring installation of new `.sdb` files
- Alerting on use of `sdbinst.exe` or similar shim installation tools
- Auditing registered shim databases on endpoints
- Correlating application launches with unexpected DLL loads
- Reviewing compatibility settings for unauthorized entries

## 5. Defensive Mitigations
- Restrict permissions required to install or modify shim databases
- Monitor and alert on shim installation events
- Use application allowlisting and code signing enforcement
- Regularly audit installed shims against known-good baselines
- Remove unauthorized shim databases during incident response

## 6. Operational Impact
If successful, T1546.011 can:
- Provide stealthy, application-specific persistence
- Enable execution within trusted process contexts
- Evade detection mechanisms focused on startup artifacts
- Complicate forensic analysis due to indirect execution triggers

## 7. Analyst Notes
Application shimming is a favored persistence method among sophisticated Windows attackers due to its stealth and flexibility. Analysts should include **shim database enumeration** and `sdbinst` usage review in persistence-hunting playbooks, especially when investigating unexplained application behavior.
