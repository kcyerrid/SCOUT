# Access Token Manipulation: Token Impersonation/Theft (T1134.001)

## 1. Summary
This subtechnique describes adversaries **stealing or impersonating Windows access tokens** to assume the security context of another user or service. By abusing token handling mechanisms, attackers can perform actions with the privileges of the impersonated account without possessing its credentials.

T1134.001 is commonly used to:
- Escalate privileges to administrator or SYSTEM
- Impersonate service or domain accounts
- Bypass access control checks
- Enable stealthy lateral movement

---

## 2. Technical Overview
Windows access tokens represent the identity and privileges of a process or thread. Adversaries abuse this by:
- Stealing tokens from privileged processes
- Impersonating tokens at the thread level
- Reusing tokens associated with active logon sessions
- Leveraging token impersonation APIs to perform privileged actions

Common APIs and mechanisms involved:
- `ImpersonateLoggedOnUser`
- `SetThreadToken`
- `OpenProcessToken`
- `DuplicateTokenEx`

Artifacts often include:
- Processes executing under unexpected user contexts
- Privileged operations without corresponding authentication events
- SYSTEM-level activity originating from user-level processes

---

## 3. Subtechnique Considerations
Key considerations for T1134.001:
- Requires access to a process holding a privileged token
- Often paired with process injection or handle theft
- Detection depends on detailed process and token telemetry
- Common in post-exploitation and hands-on-keyboard attacks

This subtechnique is one of the most reliable Windows privilege escalation methods once local execution is achieved.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Stealing tokens from SYSTEM services to execute commands
- Impersonating service accounts to access protected resources
- Abusing tokens to bypass UAC or file system ACLs
- Combining token impersonation with process injection for stealth

These actions typically follow initial access or local privilege escalation.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Identifying token impersonation API usage
- Detecting mismatches between process owner and logon context
- Monitoring SYSTEM-level actions without interactive logons
- Alerting on unusual token privilege escalation patterns

### Data Source Notes
- **Security Event Logs**: Useful for tracking privilege usage
- **Process telemetry**: Critical for detecting anomalous execution chains
- **API monitoring**: Enables detection of impersonation calls

---

## 6. Response Guidance
When detected:
1. Identify the impersonated account and affected processes
2. Terminate malicious processes using stolen tokens
3. Investigate how token access was obtained
4. Review for lateral movement or persistence
5. Reset credentials for impersonated accounts if necessary

T1134.001 is highly relevant in:
- Windows enterprise environments
- Domain-joined systems
- Post-exploitation attack chains

Token impersonation enables powerful privilege escalation with limited forensic artifacts.

## 12. Mitigations
Recommended mitigations:
- Enforce least privilege on services and users
- Monitor and restrict token manipulation APIs
- Protect LSASS and related processes
- Apply OS and security patches
- Use EDR solutions with token-level visibility
