# Hide Artifacts: Ignore Process Interrupts (T1564.011)

## 1. Summary
Ignore Process Interrupts describes adversaries **configuring malicious processes to ignore or suppress operating system interrupt signals**, allowing execution to continue uninterrupted and reducing visibility during user interaction, system shutdown attempts, or administrative intervention.

This technique enables malware to:
- Resist termination by users or administrators
- Persist during incident response activity
- Avoid disruption by system signals
- Maintain stealthy, long-running execution

---

## 2. Technical Overview
Operating systems use **signals, interrupts, and events** to manage process execution and termination. Adversaries abuse these mechanisms by:

- Registering custom signal handlers that ignore termination requests
- Masking or suppressing interrupt signals
- Handling system events without propagating termination
- Overriding default OS interrupt behavior

Platform-specific considerations:
- **Linux/macOS**: Signal handling (e.g., SIGINT, SIGTERM, SIGHUP)
- **Windows**: Console control handlers and process event handling

Artifacts and indicators include:
- Processes that persist despite termination attempts
- Unresponsive processes during shutdown or user logoff
- Lack of expected termination events in logs
- EDR alerts showing repeated termination failures

---

## 3. Subtechnique Considerations
Key considerations for T1564.011:
- Distinct from persistence techniques; focuses on **execution survivability**
- Often paired with process injection (T1055)
- May accompany defense impairment techniques (T1562)
- Indicates deliberate resistance to containment

Detection requires visibility into **signal handling and process lifecycle events**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Malware registering handlers to ignore interrupt signals
- Background processes continuing during system shutdown
- Processes that must be forcibly killed at the kernel level
- Long-running malicious tasks resistant to user termination

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **process behavior under stress**:
- Alert on processes ignoring repeated termination attempts
- Detect anomalies in shutdown or logoff behavior
- Correlate signal handling with suspicious execution context
- Monitor for custom signal handler registration

### Data Source Notes
- **EDR telemetry**: Primary source for detecting interrupt resistance
- **Audit logs**: Provide context on termination attempts
- **OS event logs**: Capture abnormal process lifecycle behavior

Common false positives:
- Legitimate daemons and services
- System-critical processes
- Database engines and long-running workloads

Tuning guidance:
- Baseline expected interrupt behavior by process role
- Elevate alerts when non-service processes ignore interrupts

---

## 6. Response Guidance
When suspected:
1. Attempt controlled termination and observe behavior
2. Capture process memory and execution context
3. Use elevated tools to forcibly terminate if required
4. Investigate for injection or persistence mechanisms
5. Isolate system if termination resistance is confirmed

## 8. SOC Relevance
T1564.011 is particularly relevant when:
- Malware resists standard containment actions
- Analysts report “unkillable” processes
- Shutdown or reboot behavior appears abnormal

Interrupt resistance often signals advanced post-exploitation tooling.

---

## 9. Threat Actor Usage
This technique has been observed in:
- Advanced intrusion frameworks
- Espionage-oriented malware
- Custom implants designed for resilience

Its use suggests **intentional evasion of response actions**.

---

## 10. Campaign Usage
Observed in:
- Long-dwell intrusions
- Stealthy backdoor operations
- Campaigns prioritizing persistence and survivability

---

## 11. Malware Usage
Associated with:
- Advanced backdoors
- In-memory implants
- Malware designed to resist cleanup

---

## 12. Mitigations
Recommended mitigations:
- Use EDR capable of forced process termination
- Monitor shutdown and termination anomalies
- Restrict ability to register custom signal handlers
- Ensure SOC has tools for kernel-level termination
- Harden response playbooks for resistant processes

---

## 13. Testing & Validation
Validation approaches:
- Create benign processes that ignore interrupts in a lab
- Validate alerts on termination resistance
- Test SOC workflows for forced containment
- Ensure telemetry captures repeated termination attempts
