## 1. Summary
Wi-Fi Discovery covers attempts to enumerate wireless networks and/or recover saved Wi-Fi profile information (including credentials where accessible). This can support lateral movement planning, credential access, or expansion into nearby networks.

## 2. Technical Overview
Observed behaviors include:
- Enumerating saved Wi-Fi profiles and their properties on endpoints.
- Reading OS-managed Wi-Fi configuration stores (e.g., NetworkManager connection configs on Linux).
- Accessing OS APIs used for wireless enumeration (Windows WLAN APIs).
- Enumerating nearby wireless networks/interfaces and connected SSIDs.

Defender-relevant nuance: activity that attempts to obtain **saved Wi-Fi keys/PSKs** is generally higher-risk than simple SSID enumeration.

## 3. Subtechnique Considerations
- Sub-technique of [[20_Entities/07_TTPs/TA0007 - Discovery/T1016 - System Network Configuration Discovery|T1016]].
- Often overlaps with **Credential Access** when saved wireless credentials are targeted.
- Treat as **high-signal** when executed by non-IT tooling, from user-writable directories, or adjacent to privilege escalation attempts.

## 4. Procedure Examples
- **[[30_CIPHER/05_Malware/S0331 - Agent Tesla|Agent Tesla (S0331)]]** has been reported collecting Wi-Fi names/passwords from previously connected networks.
- **[[30_CIPHER/03_Threat_Actors/G0007 - APT28|APT28 (G0007)]]** performed wireless interface discovery during **C0051 - APT28 Nearest Neighbor Campaign**.
- **[[30_CIPHER/05_Malware/S0367 - Emotet|Emotet (S0367)]]** has been associated with extracting nearby Wi-Fi information and using it to support spread.

## 5. Detection Guidance
Recommended high-fidelity signals:
- Execution of wireless profile enumeration utilities by suspicious parents (Office → shell → wireless tooling).
- Access to files/paths commonly holding Wi-Fi configuration secrets (platform-dependent) by non-standard processes.
- API-level access to wireless enumeration functions by unsigned or rare binaries.

Detection engineering tips:
- Build rules that combine **process lineage + argument indicators + user context** (interactive user vs. SYSTEM).
- Add environment-aware suppression for legitimate IT scripts and OEM wireless utilities.

### Data Source Notes
Telemetry that tends to be most useful:
- Process creation + command line
- File access/audit to Wi-Fi configuration stores (Linux/macOS)
- OS API telemetry (EDR) for WLAN-related calls
- Privilege context (token elevation) and subsequent credential access patterns

## 6. Response Guidance
1. **Determine scope**: identify whether activity is limited to enumeration or attempts credential recovery.
2. **Check privilege context**: credential recovery attempts often require elevated context or access to secure stores.
3. **Contain and rotate**: if Wi-Fi credentials may be exposed, rotate PSKs and review wireless auth posture.
4. **Hunt adjacency**: look for follow-on lateral movement attempts and credential dumping.

## 8. SOC Relevance
- Strong indicator when observed on endpoints that are not expected to run wireless tooling (servers, VDI, jump boxes).
- Particularly relevant for environments with Wi-Fi that bridges into sensitive segments or uses shared PSKs.

## 12. Mitigations
- Enforce least privilege; restrict access to credential stores.
- Prefer WPA2-Enterprise/WPA3-Enterprise over shared PSKs where feasible.
- Monitor and restrict use of wireless profile tooling on endpoints where not required.
