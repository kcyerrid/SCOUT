# Obfuscated Files or Information: Binary Padding (T1027.001)

## 1. Summary
Binary Padding describes adversaries **adding non-functional or meaningless data to executable files** in order to alter file size, hashes, or signatures without changing runtime behavior. This technique is commonly used to evade static detection mechanisms that rely on known hashes or byte patterns.

Adversaries use this technique to:
- Evade hash-based detection
- Bypass signature-based malware defenses
- Increase entropy or alter file characteristics
- Enable polymorphic or repacked malware delivery

---

## 2. Technical Overview
Binary padding involves modifying a binary by inserting unused data that does not affect execution. Adversaries achieve this by:

- Appending junk data to the end of executables
- Inserting no-op data into unused sections
- Expanding padding within PE, ELF, or Mach-O structures
- Randomizing padding to generate unique file hashes

Key characteristics:
- Executables larger than expected for their functionality
- Identical runtime behavior across differently sized binaries
- Repeated file variants with distinct hashes
- Padding regions containing high-entropy or null data

Indicators include:
- PE/ELF section size anomalies
- Large unused or non-referenced sections
- Inconsistent file sizes across samples with similar behavior

---

## 3. Subtechnique Considerations
Key considerations for T1027.001:
- Often used in combination with **Software Packing (T1027.002)**
- Enables rapid malware re-signing and redistribution
- Ineffective against behavior-based detection alone
- Common in loader and dropper malware

Binary padding focuses on **static evasion**, not runtime concealment.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Generating padded variants of the same malware
- Adding random data blocks during build or delivery
- Automating padding to evade signature updates

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **structural and behavioral analysis**:
- Identify abnormal section sizes or padding regions
- Detect repeated behavior across differently hashed files
- Correlate static anomalies with runtime activity
- Use similarity or fuzzy hashing techniques

### Data Source Notes
- **File monitoring**: Identify size and structure anomalies
- **Malware analysis**: Compare padded variants
- **EDR telemetry**: Correlate file execution with behavior

Common false positives:
- Legitimate software with embedded resources
- Packed commercial applications

Tuning guidance:
- Baseline expected file sizes for common binaries
- Focus on behavior over static signatures

---

## 6. Response Guidance
When suspected:
1. Collect multiple file variants for comparison
2. Analyze execution behavior rather than hashes
3. Identify common functionality across variants
4. Block behaviorally rather than by hash alone
5. Hunt for similar padded files across the environment

## 8. SOC Relevance
T1027.001 is relevant because:
- Hash-based blocking becomes ineffective
- Malware families generate numerous variants
- Analysts may underestimate padded samples as unique

SOC teams should prioritize **behavioral correlation over static uniqueness**.

---

## 9. Threat Actor Usage
Commonly used by:
- Commodity malware operators
- Loader and dropper authors
- Ransomware affiliates

---

## 10. Campaign Usage
Observed in:
- Mass malware distribution campaigns
- Loader-based initial access chains
- Evasion-heavy delivery stages

---

## 11. Malware Usage
Associated with:
- Loaders and droppers
- Packed executables
- Polymorphic malware families

---

## 12. Mitigations
Recommended mitigations:
- Use behavior-based detection engines
- Employ fuzzy hashing and similarity analysis
- Limit execution of untrusted binaries
- Monitor for anomalous file structures

---

## 13. Testing & Validation
Validation approaches:
- Generate padded variants of benign binaries
- Validate detection of behavior across variants
- Test SOC workflows for hash-agnostic response
- Ensure tooling highlights structural anomalies
