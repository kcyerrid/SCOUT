# Subvert Trust Controls: Mark-of-the-Web Bypass (T1553.005)

## 1. Summary
Mark-of-the-Web (MOTW) Bypass describes adversaries **removing, avoiding, or neutralizing Windows download provenance metadata** so that malicious files execute without security warnings or reduced trust enforcement. MOTW is commonly used by Windows to trigger Protected View, SmartScreen warnings, and other safeguards for content originating from untrusted sources.

Adversaries use this technique to:
- Suppress user security warnings
- Increase success of phishing-delivered payloads
- Bypass SmartScreen and Protected View
- Enable seamless execution of malicious content

---

## 2. Technical Overview
When files are downloaded from the internet or external sources, Windows attaches a **Zone.Identifier alternate data stream (ADS)** that records the file’s origin. Applications use this data to:
- Display security warnings
- Open documents in Protected View
- Apply stricter execution policies

Adversaries bypass MOTW by:
- Removing or modifying the Zone.Identifier ADS
- Delivering files via archive formats or containers that strip MOTW
- Transferring files through mechanisms that do not preserve ADS
- Copying or rewriting files in ways that remove provenance metadata

Indicators include:
- Executables or documents lacking expected MOTW metadata
- Files delivered through user-facing vectors without warnings
- Execution of content that should trigger Protected View but does not

---

## 3. Subtechnique Considerations
Key considerations for T1553.005:
- Windows-specific technique
- Frequently paired with phishing and user execution
- Highly dependent on delivery method
- Often combined with file or archive manipulation

MOTW bypass enables **low-friction initial execution**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Removing Zone.Identifier ADS prior to execution
- Packaging malware in archive formats that drop MOTW
- Rewriting files locally to clear provenance metadata
- Delivering payloads through mechanisms that avoid ADS preservation

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **provenance inconsistencies and execution context**:
- Monitor execution of files lacking MOTW from untrusted locations
- Detect creation or execution of files without expected Zone.Identifier data
- Alert when Office or script content executes outside Protected View
- Correlate execution with recent downloads or email delivery

### Data Source Notes
- **File monitoring**: Identify missing or removed ADS
- **Process creation**: Detect execution of untrusted files without warnings
- **EDR telemetry**: Correlate delivery and execution behavior

Common false positives:
- Files transferred via trusted internal channels
- Legacy file-sharing workflows

Tuning guidance:
- Baseline trusted delivery mechanisms
- Elevate alerts for user-facing delivery vectors

---

## 6. Response Guidance
When suspected:
1. Identify files missing expected MOTW metadata
2. Trace delivery mechanism and user interaction
3. Quarantine or remove affected files
4. Review user activity leading to execution
5. Hunt for additional payloads delivered via similar paths

## 8. SOC Relevance
T1553.005 is critical because:
- MOTW underpins many Windows user-protection mechanisms
- Bypass significantly increases phishing success
- Detection gaps enable repeated payload execution

SOC teams must monitor **how files are delivered, marked, and executed**.

---

## 9. Threat Actor Usage
Commonly used by:
- Phishing-centric threat actors
- Malware distributors
- Ransomware initial access operations

---

## 10. Campaign Usage
Observed in:
- Email-delivered malware campaigns
- Document-based initial access operations
- Archive-based payload delivery

---

## 11. Malware Usage
Associated with:
- Loaders delivered via email
- Malicious documents and scripts
- Payloads relying on user execution

---

## 12. Mitigations
Recommended mitigations:
- Enforce Protected View and SmartScreen
- Block execution from user-writeable directories
- Monitor and alert on MOTW removal
- Harden email and download handling policies

---

## 13. Testing & Validation
Validation approaches:
- Deliver test files with MOTW and validate warning behavior
- Test execution of files with removed ADS
- Validate SOC alerts on missing provenance
- Simulate phishing delivery scenarios

Include:
- Preconditions: file provenance logging enabled
- Required roles/tools: SOC, EDR, email security
- Expected outcomes: detection of MOTW bypass
- Success criteria: alert before payload execution
