# Hide Artifacts: Extended Attributes (T1564.014)

## 1. Summary
Extended Attributes describes adversaries **storing malicious data, configuration information, or payloads within filesystem extended attributes (xattrs)** rather than within the primary file content. This allows attackers to hide artifacts from standard file inspection tools and evade detection mechanisms that focus on visible file data.

This technique is primarily used to:
- Conceal payloads or configuration data
- Evade static file analysis
- Reduce on-disk indicators of compromise
- Support stealthy execution and persistence

---

## 2. Technical Overview
Extended attributes are filesystem features that allow files to store **additional metadata beyond standard file contents**. Common attribute namespaces include:

- `user.*`
- `security.*`
- `trusted.*`
- `com.apple.*` (macOS)

Adversaries abuse this capability by:
- Storing encoded or encrypted payloads in extended attributes
- Retrieving hidden data at runtime via OS APIs
- Using benign-looking files as containers for malicious content
- Avoiding detection by tools that do not enumerate xattrs

Typical artifacts and indicators:
- Files with unusually large or unexpected extended attributes
- Execution behavior not explained by file contents
- Processes accessing xattrs shortly before execution
- Metadata inconsistencies during forensic analysis

---

## 3. Subtechnique Considerations
Key considerations for T1564.014:
- Strongly platform-specific (Linux/macOS)
- Rare in commodity malware; more common in targeted attacks
- Often paired with obfuscation (T1027)
- Detection requires explicit metadata inspection

Extended attributes are frequently ignored by default security tooling.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Storing encoded payloads in extended attributes of benign files
- Retrieving and executing data stored in xattrs at runtime
- Hiding configuration data outside visible file contents
- Using scripts or native APIs to access extended attributes

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **metadata visibility**:
- Enumerate extended attributes on downloaded or executed files
- Alert on large or anomalous xattr values
- Monitor API calls related to xattr access
- Correlate xattr access with suspicious execution behavior

### Data Source Notes
- **File metadata telemetry**: Required for xattr visibility
- **Process telemetry**: Identify who accesses extended attributes
- **Audit logs**: Capture filesystem metadata changes

Common false positives:
- Legitimate application metadata
- macOS quarantine or Finder attributes
- Security labels or SELinux metadata

Tuning guidance:
- Baseline normal xattr usage by platform
- Elevate alerts when xattrs contain encoded or executable data

---

## 6. Response Guidance
When suspected:
1. Extract and inspect extended attributes
2. Decode or analyze hidden data
3. Review file origin and execution context
4. Quarantine affected files
5. Hunt for similar xattr usage across systems

## 12. Mitigations
Recommended mitigations:
- Enable extended attribute inspection in tooling
- Restrict execution of untrusted files
- Monitor filesystem metadata changes
- Include xattr checks in IR playbooks
- Use EDR capable of deep file metadata analysis
