# Impair Defenses: Disable or Modify Tools (T1562.001)

## 1. Summary
Disable or Modify Tools describes adversaries **disabling, stopping, uninstalling, or otherwise altering security tools** such as antivirus, endpoint detection and response (EDR), logging agents, or monitoring software. This subtechnique is one of the most direct and impactful forms of defense evasion, significantly reducing an organization’s ability to detect and respond to malicious activity.

Attackers commonly use this technique to:
- Prevent malware detection or quarantine
- Suppress alerts and telemetry
- Increase dwell time and operational freedom
- Enable follow-on actions such as lateral movement or ransomware deployment

---

## 2. Technical Overview
Security tools rely on services, agents, drivers, and scheduled tasks to function correctly. Adversaries impair these tools by:

- Stopping or disabling security-related services
- Uninstalling or corrupting security agents
- Modifying configuration files or registry settings
- Blocking updates or communications with management servers
- Tampering with kernel drivers or sensor components

Platform-specific considerations:
- **Windows**: Service Control Manager abuse, registry modification, driver tampering
- **Linux**: Daemon termination, package removal, configuration file edits
- **macOS**: LaunchDaemon/Agent manipulation, system extension interference
- **Cloud/Containers**: Disabling security agents or audit logging integrations

Indicators include:
- Sudden termination of security services
- Changes to security tool configuration outside maintenance windows
- Loss of endpoint or log telemetry
- Malware execution without corresponding security alerts

---

## 3. Subtechnique Considerations
Key considerations for T1562.001:
- Often occurs early after initial access or privilege escalation
- Frequently paired with **Hide Artifacts (T1564)** and **Indicator Removal (T1070)**
- Strong indicator of hands-on-keyboard or advanced automation
- High-confidence signal of malicious intent

Detection and response should treat any unauthorized tool impairment as a **critical security event**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Stopping antivirus or EDR services via native OS utilities
- Uninstalling endpoint protection software
- Modifying agent configuration to disable detections
- Blocking communication between sensors and management servers
- Killing security-related processes prior to payload execution

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **security tool integrity**:
- Alert on service stop, disable, or uninstall events
- Monitor configuration and registry changes affecting security tools
- Detect loss of expected telemetry (“sensor silence”)
- Correlate tool impairment with suspicious process execution

### Data Source Notes
- **Security software logs**: Primary detection source
- **EDR telemetry**: Detect tampering attempts and service state changes
- **Audit and configuration logs**: Identify unauthorized modifications
- **Cloud logs**: Detect disabling of cloud-native security controls

Common false positives:
- Legitimate IT maintenance or upgrades
- Endpoint performance troubleshooting
- Security agent updates

Tuning guidance:
- Require change approval for security tool modifications
- Baseline normal maintenance behavior and timing

---

## 6. Response Guidance
When suspected:
1. Verify the state and integrity of affected security tools
2. Restore disabled or modified components
3. Identify the account or process responsible for the change
4. Investigate preceding and subsequent attacker actions
5. Isolate impacted systems if tampering is confirmed

## 8. SOC Relevance
T1562.001 is one of the **highest-priority techniques** for SOC monitoring. Successful disabling of security tools dramatically increases attacker success and often precedes high-impact actions such as data theft or ransomware execution.

Any unauthorized security tool modification should be escalated immediately.

---

## 9. Threat Actor Usage
This technique is universally used by:
- Advanced persistent threat (APT) groups
- Ransomware operators
- Financially motivated crimeware actors

Its presence strongly indicates **intentional, hands-on intrusion activity**.

---

## 10. Campaign Usage
Observed in:
- Ransomware deployment phases
- Espionage campaigns
- Long-dwell intrusions
- Cloud account takeover incidents

---

## 11. Malware Usage
Associated with:
- Ransomware families
- Loaders and droppers
- Post-exploitation frameworks
- Custom implants designed to evade detection

---

## 12. Mitigations
Recommended mitigations:
- Enable tamper protection for security tools
- Restrict administrative privileges
- Monitor and alert on security configuration changes
- Enforce least privilege and MFA
- Maintain defense-in-depth across endpoint, network, and cloud

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign security tool disablement in lab environments
- Validate alerting on service stop or uninstall events
- Test SOC workflows for tool impairment scenarios
- Ensure telemetry loss triggers investigation
