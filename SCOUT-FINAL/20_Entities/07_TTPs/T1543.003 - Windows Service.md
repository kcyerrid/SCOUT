# T1543.003 – Windows Service

## 1. Technique Overview
**Windows Service (T1543.003)** is a sub-technique of **Create or Modify System Process (T1543)** in **MITRE ATT&CK v18**. Adversaries abuse the Windows **Service Control Manager (SCM)** to create new services or modify existing ones so that attacker-controlled executables are launched automatically. Windows services commonly run as **SYSTEM**, making this a highly reliable persistence and privilege escalation mechanism.

This technique is one of the most frequently observed persistence methods across both commodity malware and advanced threat actor operations.

## 2. Adversary Objectives
Adversaries use Windows services to:
- Maintain persistence across system reboots
- Execute malicious payloads with SYSTEM-level privileges
- Blend malicious activity into legitimate service infrastructure
- Regain execution after credential resets or partial remediation

## 3. Common Abuse Patterns
- Creating new services using native tools such as `sc.exe`, PowerShell, or WMI
- Modifying existing services to change the `ImagePath` to attacker-controlled binaries
- Assigning benign or system-like service names and descriptions
- Configuring services for automatic start or restart-on-failure
- Running services under highly privileged accounts

## 4. Detection Considerations
Detection relies on **service configuration and process telemetry**, including:
- Monitoring service creation and modification events
- Alerting on changes to service binary paths or arguments
- Detecting unsigned or unexpected executables referenced by services
- Correlating service changes with suspicious process execution
- Auditing auto-start services against known-good baselines

## 5. Defensive Mitigations
- Restrict permissions required to create or modify services
- Enable detailed auditing for service management events
- Monitor and alert on SCM configuration changes
- Enforce application allowlisting and code signing
- Investigate unknown or newly modified services immediately

## 6. Operational Impact
If successful, T1543.003 can:
- Provide durable, high-privilege persistence
- Enable execution without user interaction
- Facilitate lateral movement and follow-on attacks
- Complicate detection due to legitimate service behavior

## 7. Analyst Notes
Windows service persistence is reliable, flexible, and low-noise when implemented carefully. During incident response, analysts must enumerate **all services configured to start automatically**, not just newly created ones, as attackers frequently modify existing services to reduce visibility.
