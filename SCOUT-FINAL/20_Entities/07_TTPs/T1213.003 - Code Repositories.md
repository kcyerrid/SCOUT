## 1. Summary
Adversaries may mine private code repositories (e.g., GitHub/GitLab/Bitbucket) to obtain proprietary source code and discover embedded secrets. Repository cloning or bulk file access by unusual identities—especially after anomalous logins or token creation—can indicate collection activity.

## 2. Technical Overview
Code repository mining often includes:
- Bulk repository cloning/downloading and mass file retrieval via UI or API.
- Enumerating organizations, repositories, branches, and commit histories.
- Keyword hunting for secrets (API keys, credentials, tokens) and operational information within code, config, and CI/CD artifacts.
- Creation/use of access tokens or OAuth authorizations to persistently query repository content.

Defender-relevant behaviors:
- **repo.clone/repo.download** events outside developer norms.
- Spike in repository content API calls (get content, list repos, enumerate orgs).
- New or unusual OAuth/token authorizations followed by immediate bulk access.
- Access from non-corporate IP ranges, unfamiliar devices, or rare geolocations.

## 3. Subtechnique Considerations
- Private repositories are often accessed via automation (CI/CD). Detections must distinguish legitimate pipeline access from adversary automation.
- Sensitive repositories (build/signing, deployment, secrets management) warrant strict thresholds and access reviews.
- Credential exposure within code can rapidly become “multi-system” compromise; treat detected mining as a high-impact incident, even if no malware is observed.

## 4. Procedure Examples
- [[30_CIPHER/03_Threat_Actors/G0096 - APT41|APT41]] cloned victim Git repositories during intrusions.
- [[30_CIPHER/03_Threat_Actors/G1004 - LAPSUS$|LAPSUS$]] searched for code repositories (GitLab/GitHub) to find high-privilege credentials.
- [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider|Scattered Spider]] enumerated data in internal code repositories, including internal GitHub repositories.
- During **C0024 - SolarWinds Compromise**, [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] downloaded source code from code repositories.

## 5. Detection Guidance
- **Bulk clone/download detection**: Alert on clones/downloads above baseline per user within a short time window; tighten for sensitive repos.
- **Role-based anomalies**: Detect non-developer accounts performing developer-like operations (clone, branch listing, mass file reads).
- **Token/OAuth correlation**: Trigger investigations when new tokens/apps are authorized and immediately followed by bulk repo access.
- **Geo/device novelty**: Join repository access events with unusual sign-ins and new device fingerprints.
- **Cross-repo traversal**: Flag rapid access across many repositories (horizontal sweep) versus normal “one repo at a time” workflows.

### Data Source Notes
- Repository audit logs should provide actor identity, IP, user agent, repo, operation type (clone/download/content read), and token/app context.
- Sign-in/session telemetry should capture rare IP/device/geo and token creation activity.
- MITRE detection strategy DET0263 outlines key signals (repo downloads/clones, OAuth authorization) and tunable thresholds for time windows and sensitivity labels.

## 6. Response Guidance
1. **Contain access**: Revoke suspicious tokens/OAuth grants, rotate credentials, and reset affected identities.
2. **Scope repository exposure**: Identify which repos were cloned/downloaded and whether secrets-bearing paths were accessed (config, CI/CD, infra-as-code).
3. **Rotate exposed secrets**: Treat potential secrets in code as compromised; rotate keys/tokens and invalidate hardcoded credentials.
4. **Hunt for downstream use**: Look for subsequent authentication to cloud services, CI/CD, artifact registries, and admin portals using newly exposed credentials.
5. **Hardening**: Enforce MFA, limit PAT/token scopes, and implement secret scanning + pre-commit protections.

## 8. SOC Relevance
High-value SOC alerts include:
- New token creation followed by repo cloning/download bursts.
- Non-developer identities accessing many repos or sensitive repos.
- Access to secrets-likely paths (infra configs, CI scripts) in rapid succession.

Key pivots:
- Token/app used, scope granted, and first-use time.
- Repo sensitivity classification and whether exfil-like patterns exist (large downloads).

## 12. Mitigations
- **Audit (M1047)**: Review repository access and privileges; routinely scan for exposed credentials/sensitive information.
- **Multi-factor Authentication (M1032)**: Enforce MFA for repository logons.
- **User Account Management (M1018)**: Apply least-privilege and scoped permissions for repositories and org-level controls.
- **User Training (M1017)**: Establish policies for acceptable information storage; prevent embedding secrets in code.

## 13. Testing & Validation
- Validate alerting on:
  - Bulk clone/download from a test repo by a non-developer test account
  - New token creation followed by immediate bulk access
  - Cross-repo traversal (many repos accessed in short window)
- Confirm tuning:
  - Exclude known CI/CD service principals (with strict token scoping and monitoring)
  - Increase sensitivity thresholds for crown-jewel repos
