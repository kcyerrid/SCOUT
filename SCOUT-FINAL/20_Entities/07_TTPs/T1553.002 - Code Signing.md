# Subvert Trust Controls: Code Signing (T1553.002)

## 1. Summary
Code Signing describes adversaries **abusing digital code-signing mechanisms to make malicious software appear legitimate and trusted** by the operating system and security controls. By leveraging valid, stolen, fraudulently obtained, or improperly trusted certificates, attackers can bypass application control, suppress warnings, and increase the likelihood of successful execution.

Adversaries use this technique to:
- Evade application control and reputation-based defenses
- Suppress user warnings during execution
- Increase trust and execution success of malware
- Blend malicious binaries into legitimate software ecosystems

---

## 2. Technical Overview
Operating systems rely on digital signatures to validate software authenticity and integrity. Adversaries subvert this trust by:
- Signing malware with stolen or leaked certificates
- Abusing legitimately issued certificates for malicious purposes
- Using compromised build pipelines to sign malicious payloads
- Exploiting weak certificate revocation or trust enforcement

Common signing ecosystems abused include:
- Windows Authenticode
- macOS Developer ID and notarization
- Linux package signing systems

Indicators include:
- Signed binaries exhibiting malicious behavior
- Use of newly issued or rarely seen certificates
- Execution of signed malware from unusual locations
- Certificate chains that terminate in compromised or untrusted roots

---

## 3. Subtechnique Considerations
Key considerations for T1553.002:
- Signed malware may bypass allowlisting controls
- Revocation delays reduce defensive effectiveness
- Code signing abuse often pairs with masquerading
- Detection must focus on behavior, not signature presence

Code signing abuse turns **trust into an attack surface**.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Signing malware with stolen vendor certificates
- Using valid developer certificates to distribute trojanized software
- Delivering signed loaders to bypass execution restrictions
- Re-signing modified binaries to retain trusted status

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **certificate context and behavior correlation**:
- Monitor execution of newly signed or rare certificates
- Detect signed binaries exhibiting anomalous behavior
- Alert on code signing certificates associated with malware
- Correlate signing metadata with execution patterns

### Data Source Notes
- **Certificate authentication logs**: Identify certificate usage
- **EDR telemetry**: Correlate signing status with malicious behavior
- **File monitoring**: Detect signed malware placement

Common false positives:
- Legitimate newly released software
- Internal development builds

Tuning guidance:
- Maintain allowlists of trusted publishers
- Elevate alerts when signed binaries deviate from baseline behavior

---

## 6. Response Guidance
When suspected:
1. Identify affected binaries and certificates
2. Revoke or block abused certificates where possible
3. Remove signed malicious payloads
4. Hunt for additional binaries signed with the same certificate
5. Notify certificate authorities if abuse is confirmed

## 8. SOC Relevance
T1553.002 is critical because:
- Signed malware is often implicitly trusted
- Signature-based defenses are insufficient
- Detection relies on behavioral analysis

SOC teams must scrutinize **what is trusted, not just what is signed**.

---

## 9. Threat Actor Usage
Commonly used by:
- Advanced persistent threat actors
- Malware distributors seeking high execution success
- Supply-chain compromise operators

---

## 10. Campaign Usage
Observed in:
- Trojanized software campaigns
- Supply-chain intrusions
- Initial access operations targeting hardened environments

---

## 11. Malware Usage
Associated with:
- Signed loaders and droppers
- Trojanized legitimate software
- Backdoors leveraging trusted execution

---

## 12. Mitigations
Recommended mitigations:
- Enforce application allowlisting
- Monitor and audit code signing certificate usage
- Implement certificate reputation scoring
- Rapidly revoke compromised certificates

---

## 13. Testing & Validation
Validation approaches:
- Simulate execution of signed test binaries
- Validate alerts on rare or anomalous certificates
- Test SOC workflows for signed malware detection
- Ensure certificate metadata is retained

Include:
- Preconditions: certificate telemetry enabled
- Required roles/tools: SOC, PKI, EDR
- Expected outcomes: detection of malicious signed binaries
- Success criteria: timely alerting and response
