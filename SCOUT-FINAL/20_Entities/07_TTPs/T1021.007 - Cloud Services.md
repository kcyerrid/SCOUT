# T1021.007 - Remote Services: Cloud Services

## 1. Summary
Adversaries may log into accessible cloud services using valid accounts that are synchronized with or federated to on-premises identities, then perform management actions or access cloud-hosted resources as the logged-on user. This enables lateral movement across cloud control planes and cloud-hosted assets.

## 2. Technical Overview
Typical behaviors include:
- Authenticating to cloud consoles, cloud CLIs, or cloud APIs using federated credentials or synchronized identities.
- Using cloud-native tooling (console/CLI/API) to enumerate resources, manipulate identity/permissions, and access data/services.
- Leveraging app access tokens (where applicable) instead of username/password authentication.

High-signal behaviors:
- Cloud logins from atypical geolocation, ASN, source IP ranges, or unusual user-agent/CLI signatures.
- CLI/API authentication followed by rapid enumeration, IAM/role changes, credential creation, or new compute/resource provisioning.
- Federated/SSO logins immediately followed by directory or permission group discovery in the IdP.

## 3. Subtechnique Considerations
This is a subtechnique of [[20_Entities/07_TTPs/TA0008 - Lateral Movement/T1021 - Remote Services|T1021]].
- Cloud Services is often the “pivot fabric” between on-prem and cloud; detections should treat identity events and cloud control plane actions as first-class telemetry.
- Cloud lateral movement frequently relies on identity compromise rather than host compromise; SOC workflows must unify IdP + cloud audit + endpoint signals.

## 4. Procedure Examples
MITRE ATT&CK documents Cloud Services usage including:
- [[30_CIPHER/03_Threat_Actors/G0016 - APT29|APT29]] using compromised high-privileged on-prem accounts synced to Office 365 to move laterally into cloud environments (including Azure AD PowerShell).
- During **C0027 - C0027**, [[30_CIPHER/03_Threat_Actors/G1015 - Scattered Spider|Scattered Spider]] used compromised Azure credentials for credential theft activity and lateral movement to on-premises systems.
- [[30_CIPHER/03_Threat_Actors/G1053 - Storm-0501|Storm-0501]] using compromised sync infrastructure to move laterally within victim environments.

## 5. Detection Guidance
Prioritize detection of **suspicious cloud authentication** coupled with **cloud control plane activity**.

Detection ideas:
- Alert on cloud/IdP logins with anomalies:
  - New geo / new device / new ASN
  - Unusual user-agent (CLI tooling where web console is baseline, or vice versa)
  - High-risk OAuth/SSO/federated grant patterns followed by privilege or directory actions
- Correlate login events to rapid post-auth sequences:
  - Resource enumeration (list/describe across services)
  - IAM/role manipulation, new credentials/tokens, or MFA device changes
  - New VM/instance provisioning or console/bastion usage
  - Bulk data access (mailboxes, documents, cloud storage)

MITRE Detection Strategy (technique analytics):
- **DET0008 – Behavioral Detection of Remote Cloud Logins via Valid Accounts** (includes patterns such as atypical geo/user-agent followed by enumeration or manipulation; SSO/OAuth grant followed by directory/permissions enumeration; and M365/Google Workspace access followed by mailbox/document access).

### 5.1. Data Source Notes
Telemetry that materially improves fidelity:
- IdP sign-in logs (interactive + non-interactive), conditional access outcomes, device identity, user-agent details.
- Cloud audit logs (control plane API calls), including identity context, source IP, and request parameters.
- OAuth/app-token issuance and use telemetry (token grants, consent events, app impersonation signals).
- Asset and identity context: tiering of admin roles, break-glass accounts, sync service accounts, expected admin workstations/bastions.

## 6. Response Guidance
- Contain: revoke active sessions/tokens where supported; enforce step-up auth; restrict compromised accounts and block suspicious source IPs/ASNs.
- Credential actions: rotate credentials, invalidate tokens, review OAuth consents, and remediate IdP configuration abuse.
- Scope: review cloud audit logs for resource enumeration, IAM changes, new credentials, and new compute/resource creation.
- Hardening: enforce MFA and conditional access, isolate cloud admin identities, and prevent on-prem identities from holding privileged cloud permissions unless explicitly required.

## 8. SOC Relevance
SOC triage pivots that reduce MTTR:
- Identify the identity entry point: federated login vs. password vs. token-based access.
- Validate conditional access/MFA posture and whether the login bypassed expected controls.
- Inspect immediate post-auth activity in cloud audit logs (enumeration, IAM changes, data access).
- Confirm whether the activity touched privileged identity systems (sync servers, admin roles, break-glass accounts).

## 12. Mitigations
ATT&CK-listed mitigations for T1021.007 include:
- **M1032 – Multi-factor Authentication**: use MFA on cloud services whenever possible.
- **M1026 – Privileged Account Management**: limit high-privileged domain/cloud accounts; ensure isolated cloud-only admin identities where feasible; avoid granting privileged cloud permissions to on-prem accounts unless required.

## 13. Testing & Validation
- Test detections for: atypical geo/user-agent sign-ins, unusual CLI/API authentication patterns, and suspicious OAuth/SSO grant sequences.
- Validate correlation: sign-in anomaly → enumeration/IAM actions within a short time window.
- Confirm response playbooks include token revocation, consent review, and cloud audit scoping.
