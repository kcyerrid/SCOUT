# Hide Artifacts: Process Argument Spoofing (T1564.010)

## 1. Summary
Process Argument Spoofing describes adversaries **manipulating the command-line arguments associated with a running process to conceal the true behavior or intent of that process**. By altering or falsifying argument data, attackers can evade detection mechanisms that rely on command-line inspection while executing malicious actions.

This technique is commonly used to:
- Evade command-line–based detections
- Mislead analysts during process triage
- Blend malicious execution with benign-looking processes
- Reduce forensic clarity during incident response

---

## 2. Technical Overview
Operating systems expose process arguments through APIs, logs, and userland tooling. Adversaries exploit discrepancies between:

- **Actual execution behavior**
- **Reported or visible command-line arguments**

Techniques include:
- Modifying argument memory after process start
- Using APIs or syscalls to overwrite argument buffers
- Launching processes with benign arguments while executing malicious logic elsewhere
- Leveraging platform-specific quirks in how arguments are stored and displayed

Platform considerations:
- **Linux/macOS**: `argv` memory manipulation
- **Windows**: PEB and process parameter manipulation

Typical artifacts and indicators:
- Process behavior inconsistent with visible arguments
- Network or file activity not explained by command line
- Memory artifacts showing argument mismatch
- EDR telemetry showing divergence between execution and reporting

---

## 3. Subtechnique Considerations
Key considerations for T1564.010:
- High-impact against detection logic relying on command-line strings
- Often paired with scripting or native API execution
- Strongly overlaps with obfuscation but is behaviorally distinct
- Indicates moderate to advanced attacker sophistication

Detection requires **runtime behavior correlation**, not static inspection.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Launching a process with benign arguments, then overwriting them in memory
- Masquerading malicious execution as a legitimate system utility
- Executing payloads whose arguments suggest non-malicious activity
- Hiding encoded or encrypted parameters from logging

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should emphasize **behavior-over-appearance**:
- Correlate command-line arguments with actual runtime behavior
- Detect memory manipulation of process parameters
- Alert on processes whose actions do not align with reported arguments
- Use EDR features that capture argument changes or inconsistencies

### Data Source Notes
- **EDR telemetry**: Critical for detecting argument spoofing
- **Process creation logs**: Provide baseline argument data
- **Memory inspection**: Required for high-confidence detection

Common false positives:
- Debugging tools
- Legitimate self-modifying applications
- Compatibility layers and runtime wrappers

---

## 6. Response Guidance
When suspected:
1. Capture full process telemetry and memory (if possible)
2. Compare initial vs current process arguments
3. Investigate associated child processes and network activity
4. Isolate affected systems
5. Hunt for additional defense-evasion techniques

## 8. SOC Relevance
T1564.010 is especially relevant when:
- Analysts see benign command lines with malicious behavior
- Detections relying on CLI inspection fail unexpectedly
- Advanced evasion is suspected post-compromise

Argument spoofing often explains “why the command line looked clean.”

---

## 9. Threat Actor Usage
This technique has been observed in:
- Advanced intrusion toolkits
- Post-exploitation frameworks
- Targeted attacks seeking stealth over speed

Its use typically signals **intentional evasion of modern EDR**.

---

## 10. Campaign Usage
Observed in:
- Long-dwell intrusions
- Stealthy post-exploitation phases
- Attacks against highly monitored environments

---

## 11. Malware Usage
Associated with:
- Advanced loaders
- In-memory malware
- Custom implants designed to evade telemetry

---

## 12. Mitigations
Recommended mitigations:
- Use EDR capable of detecting argument manipulation
- Correlate process behavior with command-line intent
- Avoid over-reliance on static command-line signatures
- Monitor memory modification APIs and syscalls
- Apply least privilege to reduce process manipulation capability

---

## 13. Testing & Validation
Validation approaches:
- Simulate benign processes with altered arguments in lab environments
- Validate alerts on argument/behavior mismatches
- Test SOC workflows for memory-based investigations
- Ensure command-line telemetry is retained and immutable
