# T1543.002 – Systemd Service

## 1. Technique Overview
**Systemd Service (T1543.002)** is a sub-technique of **Create or Modify System Process (T1543)** in **MITRE ATT&CK v18**. Adversaries abuse the **systemd init system** on Linux to create new services or modify existing unit files so that attacker-controlled commands or binaries are executed automatically at boot or when the service is started.

Because systemd services often run as **root** and are a standard mechanism for service management, this technique provides reliable persistence and potential privilege escalation while blending into legitimate system administration activity.

## 2. Adversary Objectives
Adversaries use systemd services to:
- Maintain persistence across system reboots
- Execute malicious code with elevated privileges
- Blend persistence into normal Linux service management
- Regain execution after remediation attempts

## 3. Common Abuse Patterns
- Creating malicious `.service` unit files under:
  - `/etc/systemd/system/`
  - `/usr/lib/systemd/system/`
- Modifying existing service unit files to change `ExecStart` commands
- Enabling services with `systemctl enable` to ensure startup execution
- Masquerading service names and descriptions as legitimate components
- Using service restart policies to ensure repeated execution

## 4. Detection Considerations
Detection relies on **service configuration and process monitoring**, including:
- Monitoring creation or modification of systemd unit files
- Alerting on changes to `ExecStart`, `ExecStartPre`, or `ExecStartPost`
- Detecting unexpected services enabled to start at boot
- Correlating service execution with suspicious binaries or scripts
- Auditing enabled services against known-good baselines

## 5. Defensive Mitigations
- Restrict privileges required to create or modify systemd services
- Monitor and alert on changes to systemd unit files
- Use file integrity monitoring on service directories
- Regularly audit enabled systemd services
- Investigate unknown or newly created services promptly

## 6. Operational Impact
If successful, T1543.002 can:
- Provide durable, root-level persistence
- Enable execution without user interaction
- Facilitate additional malicious activity on Linux hosts
- Complicate detection due to legitimate service behavior

## 7. Analyst Notes
Systemd service abuse is a common Linux persistence technique because it is stable, flexible, and deeply integrated into the OS. During incident response, analysts should enumerate **all enabled services**, review unit file contents, and validate the provenance of referenced executables—particularly on servers where systemd changes may go unnoticed.
