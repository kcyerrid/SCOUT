# Abuse Elevation Control Mechanism: Bypass User Account Control (T1548.002)

## 1. Summary
This subtechnique describes adversaries bypassing **Windows User Account Control (UAC)** to execute processes with elevated privileges without triggering user consent prompts. UAC is designed to limit the impact of malicious software by requiring explicit approval for administrative actions; however, adversaries exploit trusted binaries, auto-elevation features, and registry or file hijacking to bypass this control.

T1548.002 is commonly observed:
- Shortly after initial access
- Prior to credential dumping or persistence
- In ransomware and post-exploitation workflows

---

## 2. Technical Overview
Windows UAC relies on consent prompts and integrity levels to control privilege escalation. Adversaries bypass UAC by abusing:
- Auto-elevated signed binaries
- Registry hijacking of trusted executables
- DLL search order hijacking in elevated contexts
- Environment variable or file path manipulation

Common technical behaviors include:
- Execution of trusted Windows binaries spawning elevated child processes
- Registry modifications in UAC-related paths
- Elevated processes originating from non-administrative parents

---

## 3. Subtechnique Considerations
Key considerations for T1548.002:
- Effective only when UAC is enabled
- Dependent on Windows version and patch level
- Relies on misconfigurations or known bypass primitives
- Frequently combined with LOLBin abuse

Organizations with permissive UAC configurations face increased exposure.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Launching auto-elevated Windows binaries to execute malicious payloads
- Hijacking registry keys associated with trusted executables
- Leveraging DLL hijacking in elevated processes
- Abusing environment variables to influence privileged execution

These actions often leave subtle but detectable artifacts in process and registry telemetry.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring trusted binaries spawning unexpected child processes
- Detecting registry changes associated with UAC bypass paths
- Correlating integrity level transitions with execution ancestry
- Alerting on elevated execution without user interaction

### Data Source Notes
- **Process creation**: Critical for detecting elevation transitions
- **Registry telemetry**: Useful for identifying hijacking attempts
- **API monitoring**: Helps detect privilege manipulation behaviors

---

## 6. Response Guidance
Upon detection:
1. Validate whether the elevation was legitimate administrative activity
2. Identify the bypass method and affected binaries or registry keys
3. Remove malicious registry entries or files
4. Investigate for follow-on activity such as credential access or persistence
5. Reassess UAC configuration and hardening policies

## 8. SOC Relevance
T1548.002 is highly relevant in:
- Enterprise Windows environments
- Workstations with standard user accounts
- Ransomware and hands-on-keyboard intrusions

UAC bypass represents a critical inflection point where attacker impact increases dramatically.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Ransomware operators seeking rapid privilege escalation
- Commodity malware loaders
- Advanced persistent threats abusing trusted binaries

Usage is opportunistic and adapts to available bypass primitives.

---

## 10. Campaign Usage
Observed in:
- Ransomware campaigns prior to domain compromise
- Targeted intrusions abusing LOLBins
- Malware delivery chains requiring administrative access

---

## 11. Malware Usage
Malware families commonly leveraging UAC bypass include:
- Loaders and droppers
- Post-exploitation frameworks
- Privilege escalation utilities embedded in malware packages

---

## 12. Mitigations
Recommended mitigations:
- Enforce strict UAC settings
- Limit auto-elevation where possible
- Monitor and restrict trusted binary execution
- Apply Windows updates promptly
- Use application control (AppLocker, WDAC)

---
