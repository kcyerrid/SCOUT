# T1137.002 – Office Test

## 1. Technique Overview
**Office Test (T1137.002)** is a sub-technique of [[20_Entities/07_TTPs/T1137 - Office Application Startup|T1137]] in **MITRE ATT&CK v18**. Adversaries abuse **Microsoft Office test or diagnostic startup mechanisms** that are intended for development, debugging, or internal testing. When enabled or misused, these mechanisms can cause attacker-controlled code to execute automatically as Office applications start.

This technique provides user-context persistence without relying on traditional autorun locations or overt macro prompts.

## 2. Adversary Objectives
Adversaries use Office Test abuse to:
- Achieve execution whenever an Office application launches
- Maintain persistence with minimal user interaction
- Blend malicious behavior into legitimate Office startup workflows
- Evade detection by leveraging obscure or rarely audited features

## 3. Common Abuse Patterns
- Enabling Office test or diagnostic flags that trigger code execution
- Registering attacker-controlled components used during Office startup testing
- Leveraging legacy or undocumented Office testing features
- Persisting payloads that execute prior to normal document loading
- Combining with phishing-based initial access involving Office documents

## 4. Detection Considerations
Detection relies on **Office configuration and startup visibility**, including:
- Auditing Office configuration for enabled test or diagnostic settings
- Monitoring registry or configuration changes affecting Office startup behavior
- Correlating Office application launches with unexpected process creation
- Baseline comparison of Office startup configurations across endpoints
- Reviewing changes following suspicious document delivery or user compromise

## 5. Defensive Mitigations
- Disable or restrict Office test and diagnostic functionality in production environments
- Monitor and alert on changes to Office startup-related configuration
- Apply least-privilege principles to prevent unauthorized Office configuration changes
- Regularly audit Office settings as part of persistence-hunting activities
- Reimage affected systems if unauthorized Office startup execution is identified

## 6. Operational Impact
If successful, T1137.002 can:
- Provide reliable, low-noise user-context persistence
- Execute code without explicit macro enablement
- Evade detection due to limited visibility into Office test features
- Complicate remediation if persistence is overlooked during cleanup

## 7. Analyst Notes
Office Test–based persistence is **uncommon but high-value** due to its obscurity. Analysts should consider this technique when investigating persistent Office-related execution that cannot be explained by templates, add-ins, or macros. Attention to **nonstandard Office configuration changes** is critical.
