# Signed Binary Proxy Execution: Compiled HTML File (T1218.001)

## 1. Summary
Compiled HTML File describes adversaries **abusing the Windows HTML Help system (`hh.exe`) to execute malicious code embedded in compiled HTML (.chm) files**. Because `hh.exe` is a trusted, signed Windows binary, its abuse can bypass application allowlisting and reduce user suspicion.

Adversaries use this technique to:
- Execute malicious scripts or binaries via trusted Windows components
- Bypass application control and allowlisting
- Deliver payloads through phishing or file-based delivery
- Blend execution into legitimate system activity

---

## 2. Technical Overview
Compiled HTML (.chm) files are help files that can contain:
- HTML pages
- JavaScript or VBScript
- Embedded executables or ActiveX controls

When opened, `.chm` files are executed by **`hh.exe`**, a signed Windows binary. Adversaries abuse this by:
- Embedding scripts or binaries in CHM files
- Leveraging script execution capabilities within HTML Help
- Triggering execution through user interaction or auto-run features
- Delivering CHM files via email, web downloads, or archives

Indicators include:
- Execution of `hh.exe` with unusual file paths
- CHM files originating from user-writable directories
- Script or process execution spawned from `hh.exe`
- CHM files delivered shortly before execution

---

## 3. Subtechnique Considerations
Key considerations for T1218.001:
- Windows-specific LOLBin abuse
- Frequently paired with phishing (email attachments)
- Relies on user interaction in most cases
- CHM files may evade basic file-type filtering

CHM abuse enables **stealthy script-based execution** via a trusted binary.

---

## 4. Procedure Examples
Representative adversary behaviors include:
- Delivering malicious CHM files as email attachments
- Embedding JavaScript in CHM files to launch payloads
- Using CHM files to proxy execution of external binaries
- Abusing HTML Help auto-navigation features

*(Examples are representative and intentionally non-operational.)*

---

## 5. Detection Guidance
Detection should focus on **execution context and file provenance**:
- Monitor execution of `hh.exe` with command-line arguments
- Alert on CHM files executed from user-writeable directories
- Detect child processes spawned by `hh.exe`
- Correlate CHM execution with recent email or download activity

### Data Source Notes
- **Process creation**: Essential for identifying `hh.exe` usage
- **File monitoring**: Track creation and execution of CHM files
- **EDR telemetry**: Observe execution chains and spawned processes

Common false positives:
- Legitimate help file usage (rare in modern environments)

Tuning guidance:
- Baseline legitimate CHM usage (often minimal)
- Elevate alerts when CHM execution originates from email or downloads

---

## 6. Response Guidance
When suspected:
1. Identify and isolate affected host
2. Collect and analyze the CHM file
3. Remove malicious CHM and any dropped payloads
4. Review user activity leading to execution
5. Hunt for similar CHM files across the environment

## 8. SOC Relevance
T1218.001 is relevant because:
- CHM files are uncommon and high-signal
- Abuse bypasses allowlisting and file extension controls
- Detection opportunities are strong with proper telemetry

SOC teams should treat **CHM execution as suspicious by default**.

## 10. Campaign Usage
Seen in:
- Email-delivered malware campaigns
- Document-based initial access operations
- Living-off-the-land execution chains

---

## 11. Malware Usage
Associated with:
- Loaders delivered via CHM files
- Script-based droppers
- Malware leveraging user execution

---

## 12. Mitigations
Recommended mitigations:
- Block or restrict CHM file execution
- Disable `hh.exe` where not required
- Filter CHM attachments at email gateways
- Monitor and alert on `hh.exe` usage

---

## 13. Testing & Validation
Validation approaches:
- Execute benign CHM files in lab to validate alerts
- Test detection of `hh.exe` spawning child processes
- Simulate phishing delivery with CHM attachments
- Validate SOC response workflows

Include:
- Preconditions: process command-line logging enabled
- Required roles/tools: SOC, EDR, email security
- Expected outcomes: alert on CHM execution
- Success criteria: detection prior to payload execution
