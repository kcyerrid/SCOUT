# Cloud API (T1059.009)

## 1. Summary
Cloud API describes adversary abuse of cloud provider application programming interfaces (APIs) to execute actions within cloud environments. Instead of traditional command-line execution on hosts, attackers leverage authenticated API calls to perform operations such as resource creation, modification, or execution of managed services.

This subtechnique is foundational to cloud-native intrusions and often enables stealthy execution without deploying malware to virtual machines.

---

## 2. Technical Overview
Major cloud platforms (AWS, Azure, GCP) expose APIs that allow programmatic management of cloud resources.

Adversaries abuse Cloud APIs to:
- Execute serverless functions or workflows
- Create or modify compute resources
- Interact with storage, identity, and networking services
- Automate attack workflows using SDKs or CLI tools

Artifacts include API call logs, audit records, authentication events, and resource configuration changes.

---

## 3. Subtechnique Considerations
T1059.009 differs from host-based execution techniques by:
- Requiring valid credentials, tokens, or API keys
- Operating entirely through control plane activity
- Leaving minimal endpoint-level artifacts
- Being highly dependent on cloud logging configuration

Detection relies almost exclusively on cloud-native telemetry.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Executing serverless functions via API calls
- Spawning compute instances to run malicious workloads
- Using cloud SDKs to automate reconnaissance and execution
- Triggering managed workflows to execute attacker-controlled code

Analysts may observe bursts of API activity inconsistent with normal usage patterns.

---

## 5. Detection Guidance
Detection should focus on:
- API calls originating from unusual IPs or geolocations
- Execution-related API actions outside normal workflows
- Abuse of rarely used services (e.g., serverless, batch jobs)
- Sudden spikes in API usage or privilege scope

Behavioral baselining of cloud activity is critical for high-fidelity detection.

### Data Source Notes
- **Cloud Audit Logs:** Primary detection source
- **API Call Logs:** High-value for execution tracing
- **Authentication Logs:** Critical for identifying compromised identities

---

## 6. Response Guidance
When malicious Cloud API activity is suspected:
- Revoke and rotate affected credentials or tokens immediately
- Identify and terminate malicious resources or workflows
- Review IAM policies and privilege assignments
- Assess for data access or exfiltration activity

Preserve cloud audit logs and configuration snapshots for investigation.

## 8. SOC Relevance
Cloud API abuse is a critical execution vector in modern cloud intrusions. SOC teams must shift detection strategies from endpoint-centric monitoring to control-plane and identity-centric visibility.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Cloud-focused threat actors
- Ransomware groups targeting cloud infrastructure
- Advanced persistent threat groups
- Insider threat scenarios

Confidence in increasing usage is high.

---

## 10. Campaign Usage
Cloud API execution has appeared in:
- Cloud ransomware campaigns
- Cryptomining and resource hijacking operations
- Long-dwell cloud persistence intrusions

---

## 12. Mitigations
Effective mitigations include:
- Enforcing MFA for cloud identities
- Applying least-privilege IAM policies
- Monitoring and alerting on high-risk API actions
- Restricting long-lived credentials
- Implementing cloud security posture management (CSPM)

---

## 13. Testing & Validation
Validation approaches include:
- Simulated cloud API abuse using red team tooling
- Purple team exercises targeting serverless execution
- Review of alerts tied to anomalous API activity

Successful validation results in detection of unauthorized execution via Cloud APIs.
