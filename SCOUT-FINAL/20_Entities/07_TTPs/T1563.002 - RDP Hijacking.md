## 1. Summary
Adversaries hijack an existing Remote Desktop (RDP/RDS) session to move laterally without needing credentials or prompting the user, typically requiring elevated permissions and using system features that reassign or take over sessions. :contentReference[oaicite:82]{index=82}

## 2. Technical Overview
- **What it is:** Session takeover of a legitimate interactive RDP session.
- **Why it matters:** Can bypass “new logon” detection by attaching to an already-authenticated session.
- **Common indicators:** session reassignment, shadowing without consent, or suspicious invocation of session control utilities. :contentReference[oaicite:83]{index=83}

## 3. Subtechnique Considerations
- Compared to **SSH Hijacking (T1563.001)**, RDP hijacking is Windows/RDS-specific and typically yields richer **server-side session telemetry** (connect/disconnect, shadow events) if properly collected. :contentReference[oaicite:84]{index=84}

## 4. Procedure Examples
- [[30_CIPHER/03_Threat_Actors/G0001 - Axiom|Axiom]] has targeted victims with remote administration tools including RDP. :contentReference[oaicite:85]{index=85}  
- [[30_CIPHER/05_Malware/S0366 - WannaCry|WannaCry]] enumerates current remote desktop sessions and attempts execution on each session. :contentReference[oaicite:86]{index=86}  

## 5. Detection Guidance
**MITRE detection strategy-aligned analytics**
- Detect suspicious use of `tscon.exe` (or equivalent methods) to hijack RDP sessions, including:
  - session reassignments without corresponding authentication
  - processes spawned in hijacked session contexts
  - unusual RDP network flows deviating from baseline :contentReference[oaicite:87]{index=87}

**High-signal detection opportunities**
- **Process-based:** `tscon.exe` execution by unexpected principals, from unusual parents, or on hosts where it is rarely used.
- **Session telemetry:** session “takeover”/shadowing events without helpdesk workflow correlation.
- **Privilege context anomalies:** sudden high-privilege process activity within an existing session that previously belonged to a different user.

### Data Source Notes
*(Leave YAML `datasources` empty unless you have a canonical local mapping. Below are practical telemetry requirements.)*
- **Windows Event Logs:** Security logons (correlate with RDS activity), plus RDS/TerminalServices operational logs for session connect/disconnect/reconnect.
- **EDR telemetry:** process creation events (including command-line), session ID association, user context changes.
- **Network telemetry:** RDP flows and reconnection patterns; unusual lateral RDP between peers.

## 6. Response Guidance
1. **Kill sessions safely:** terminate suspicious RDS sessions and force logoff; capture volatile evidence first where possible.
2. **Confirm privilege path:** determine how elevated permissions were obtained (often prerequisite to silent takeover).
3. **Scope RDS hosts:** review other active sessions on the same RDS host; look for parallel takeovers.
4. **Harden RDP posture:** restrict who can RDP, require MFA/conditional access via gateways, reduce session lifetime.

## 12. Mitigations
- **Audit (M1047):** regularly audit Remote Desktop Users group membership; remove unnecessary access. :contentReference[oaicite:90]{index=90}  
- **Disable or Remove Feature or Program (M1042):** disable RDP if unnecessary. :contentReference[oaicite:91]{index=91}  
- **Limit Access to Resource Over Network (M1035):** use remote desktop gateways. :contentReference[oaicite:92]{index=92}  
- **Network Segmentation (M1030):** block RDP traffic between zones unless required. :contentReference[oaicite:93]{index=93}  
- **Operating System Configuration (M1028):** shorten session timeouts and limit disconnected session persistence via policy. :contentReference[oaicite:94]{index=94}  
- **Privileged Account Management (M1026):** restrict privileged groups from RDP access where feasible. :contentReference[oaicite:95]{index=95}  
- **User Account Management (M1018):** limit remote user permissions. :contentReference[oaicite:96]{index=96}  

## 13. Testing & Validation
- Validate alerts for:
  - `tscon.exe` execution and command-line monitoring
  - RDS session transitions without expected authentication chains
  - new high-privilege processes inside preexisting user sessions
- Validate SOC runbooks for rapid session termination + evidence capture.
