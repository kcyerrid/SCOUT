# Windows Command Shell (T1059.003)

## 1. Summary
Windows Command Shell describes adversary abuse of the native Windows command interpreter (`cmd.exe`) to execute commands and scripts. This subtechnique provides direct access to operating system functionality and is frequently used for quick command execution, scripting, and chaining of malicious actions.

Because `cmd.exe` is ubiquitous and heavily used by administrators and applications, malicious usage can blend into normal system activity without proper command-line visibility.

---

## 2. Technical Overview
The Windows Command Shell allows execution of built-in commands, batch scripts, and external binaries.

Adversaries commonly abuse `cmd.exe` to:
- Execute inline commands or batch files
- Chain commands using operators (`&`, `&&`, `|`)
- Launch other interpreters or executables
- Execute payloads downloaded to disk

Artifacts include process creation events for `cmd.exe`, command-line arguments, batch file execution, and child processes spawned by the shell.

---

## 3. Subtechnique Considerations
T1059.003 is the Windows Command Shell–specific implementation of command interpreter abuse.

Key considerations include:
- Extensive use in living-off-the-land activity
- Common chaining with PowerShell or native binaries
- Frequent use of obfuscation via environment variables or delayed expansion

Detection relies heavily on command-line logging and behavioral analysis.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Using `cmd.exe` to launch PowerShell or scripting engines
- Executing batch scripts dropped to disk
- Chaining multiple commands for automation
- Leveraging shell redirection to hide output

Analysts may observe `cmd.exe` spawning suspicious child processes or executing from unexpected parent processes.

---

## 5. Detection Guidance
Detection should focus on:
- `cmd.exe` execution by unexpected parent processes
- Suspicious or obfuscated command-line arguments
- Batch files executing from user-writable directories
- `cmd.exe` launching network-aware tools

Correlation with file creation and network activity improves detection fidelity.

### Data Source Notes
- **Process Execution:** Primary detection source
- **Command-Line Parameters:** Critical for identifying malicious intent
- **File Creation:** Useful for detecting dropped batch scripts

---

## 6. Response Guidance
When malicious Command Shell activity is suspected:
- Capture full command-line arguments
- Identify follow-on payloads or scripts
- Isolate affected systems if execution is confirmed
- Review for persistence or lateral movement activity

Preserve process execution artifacts and batch files for forensic analysis.

## 8. SOC Relevance
Command Shell abuse is extremely common across all stages of Windows intrusions. SOCs must rely on command-line telemetry and parent/child process analysis to distinguish malicious usage from legitimate administration.

## 12. Mitigations
Effective mitigations include:
- Enabling comprehensive command-line logging
- Restricting `cmd.exe` usage where feasible
- Applying least-privilege principles
- Monitoring for suspicious batch file execution
- Blocking execution from user-writable directories

---

## 13. Testing & Validation
Validation approaches include:
- Atomic Red Team tests for `cmd.exe` execution
- Purple team simulations using batch scripts
- Review of alerts tied to suspicious command chaining

Successful validation results in detection of unauthorized Command Shell activity.
