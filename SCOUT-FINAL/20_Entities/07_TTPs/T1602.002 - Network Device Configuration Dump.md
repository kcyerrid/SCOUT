## 1. Summary
Adversaries may collect sensitive data by **dumping network device configurations** (running/startup configs or exported configuration files). These configurations can reveal network topology, device/software details, and potentially **legitimate accounts/credentials** that enable follow-on access and lateral movement. :contentReference[oaicite:15]{index=15}

## 2. Technical Overview
Network device configuration dumps are typically obtained through:
- **Management protocols/tools** that enable reading configuration parameters or exporting full configurations (e.g., SNMP-driven access to configuration objects; vendor management services).
- **CLI/API commands** that retrieve full configurations (e.g., “show running-config” equivalents), often followed by copy/export operations.
- **Transfer mechanisms** used to move configuration files off the device (e.g., SCP/TFTP/FTP), sometimes opportunistically leveraging weaker protocols if permitted. :contentReference[oaicite:16]{index=16}

Common defender-relevant indicators:
- Unusual config retrieval commands from non-admin IP space
- Sudden bursts of read access for configuration-related objects
- Configuration exports during non-maintenance windows
- Outbound file transfers involving config file content

## 5. Detection Guidance
ATT&CK’s detection strategy highlights detecting attempts to collect or export full device configurations by monitoring:
- **Unusual SNMP queries**
- **Smart Install (SMI) activity** (where applicable)
- **CLI/API commands** that request running/startup configuration dumps
- **Unexpected transfers** (TFTP/SCP/FTP) containing configuration files
- Correlation with preceding auth anomalies or privilege escalation. :contentReference[oaicite:19]{index=19}

SOC-ready analytics (implementation-agnostic)
- **Command-based detection**
  - Alert on “show/copy/export config” commands from untrusted IPs, unusual accounts, or at unusual times.
- **Config export rate anomalies**
  - Baseline legitimate export frequency; alert on spikes (especially across many devices).
- **Weak protocol usage**
  - Alert when config exports use unexpected/weak transfer methods (e.g., TFTP where SCP is standard).
- **Sequence correlation**
  - auth anomalies → config dump command → outbound transfer within a short window.

### Data Source Notes
ATT&CK’s detection strategy lists the following log sources/data components as high-value:
- **User Account Authentication (DC0002)** via networkdevice:syslog: failed/successful logins outside approved admin IP ranges
- **Command Execution (DC0064)** via networkdevice:cli: execution of config dump/export commands
- **Network Traffic Content (DC0085)** via NSM:Flow: outbound SCP/TFTP/FTP sessions carrying configuration content
- **Network Connection Creation (DC0082)** via snmp:access: GETBULK/GETNEXT for OIDs associated with configuration parameters :contentReference[oaicite:20]{index=20}

## 6. Response Guidance
1. **Contain**
   - Restrict management-plane access (ACLs/management VRFs), and block unauthorized export/transfer protocols at boundaries.
2. **Scope**
   - Identify which devices had configurations accessed/exported; enumerate actor IPs, accounts, and commands; identify destination hosts for transfers.
3. **Credential risk handling**
   - Treat configuration dumps as potential credential exposure; rotate any secrets present (local accounts, shared keys, SNMP creds, TACACS/RADIUS secrets where relevant).
4. **Hardening**
   - Enforce least-privileged admin access, SNMPv3 with strong security, disable/limit SMI where unused, and standardize export mechanisms to approved secure protocols.

## 12. Mitigations
ATT&CK lists the following mitigations for this subtechnique:
- **M1041 – Encrypt Sensitive Information**: Configure SNMPv3 for strong security (authPriv). :contentReference[oaicite:25]{index=25}
- **M1037 – Filter Network Traffic**: Use ACLs to limit management protocol exposure to trusted networks. :contentReference[oaicite:26]{index=26}
- **M1031 – Network Intrusion Prevention**: Detect unusual SNMP/SMI usage and unauthorized query/command sources. :contentReference[oaicite:27]{index=27}
- **M1030 – Network Segmentation**: Separate management traffic from production traffic. :contentReference[oaicite:28]{index=28}
- **M1054 – Software Configuration**: Implement SNMP views/allowlists; disable Smart Install (SMI) if not used. :contentReference[oaicite:29]{index=29}
- **M1051 – Update Software**: Keep images/software updated; migrate to SNMPv3. :contentReference[oaicite:30]{index=30}

## 13. Testing & Validation
- Validate telemetry coverage:
  - device syslog for admin auth,
  - CLI command logging for config retrieval/export,
  - NSM flow/content for outbound transfers,
  - SNMP access logging for configuration-related OID access. :contentReference[oaicite:31]{index=31}
- Controlled validation (lab/authorized):
  - Perform a legitimate config display/export and confirm alerts fire only when baselines are exceeded (time window, source IP, protocol).
  - Test weak-protocol alerts by simulating a config transfer attempt via a disallowed method (e.g., TFTP where SCP is policy).
