## 1. Summary
DHCP spoofing involves a rogue DHCP server issuing DHCP responses to victims, assigning attacker-chosen network parameters (e.g., DNS servers, default gateway) to redirect traffic through adversary-controlled infrastructure for interception/collection. DHCP spoofing can also be abused to exhaust address pools (DHCP starvation/exhaustion patterns).

## 2. Technical Overview
- Adversary introduces a rogue DHCP server (or otherwise injects DHCP responses) into a broadcast domain.
- Victims accept malicious DHCP OFFER/ACK with:
  - Unexpected **DNS** resolvers
  - Unexpected **gateway** values
  - Other configuration changes that enable interception and redirection
- DHCP spoofing can be paired with exhaustion activity (many DISCOVER messages) to increase likelihood that victims accept the rogue server’s responses.

MITRE detection strategy emphasizes monitoring for rogue DHCP server activity and anomalous DHCP messages that assign unexpected DNS/gateway values.

## 3. Subtechnique Considerations
- DHCP behavior differs across environments (static vs dynamic addressing, BYOD, guest networks); baseline is essential.
- Prioritize detection in segments containing:
  - Admin workstations
  - Authentication services
  - Sensitive servers where redirected DNS/gateway can enable credential interception
- Ensure coverage for dual-stack environments; mitigation guidance notes blocking DHCPv6/router advertisements when IPv6 is unused.

## 5. Detection Guidance
Key detections:
- **Network-plane**
  - Multiple DHCP OFFER/ACK messages from competing servers
  - DHCP responses originating from unauthorized MACs/ports
  - Sudden shifts in assigned DNS/gateway across multiple endpoints
  - DHCP exhaustion signals (high DISCOVER volume, pool exhaustion warnings)
- **Endpoint-plane**
  - Host logs indicating unexpected DHCP parameters (DNS/gateway) changing abruptly
  - Subsequent spikes in failed authentications or new proxy-like traffic patterns following config change

### Data Source Notes
Telemetry that commonly supports detection:
- DHCP server logs and switch telemetry (DHCP snooping events)
- Network packet capture/IDS for DHCP DISCOVER/OFFER/REQUEST/ACK patterns
- Endpoint network configuration change logs (DNS server/gateway changes)

## 6. Response Guidance
1. Identify rogue DHCP source (switch port, MAC, AP, or compromised host) and isolate it.
2. Confirm impacted hosts and revert to known-good DHCP infrastructure or static remediation.
3. Investigate downstream effects:
   - DNS redirection outcomes
   - New proxy traffic paths
   - Authentication anomalies or credential interception indicators
4. Implement/verify prevention (DHCP snooping, port security, segmentation) and document authorized DHCP servers per segment.

## 8. SOC Relevance
DHCP spoofing is a strong indicator of **active network manipulation** and often precedes:
- Credential theft via redirected traffic
- Wider interception patterns (DNS/gateway manipulation)
- Availability impacts via exhaustion/starvation

High-value SOC correlations:
- Unauthorized DHCP OFFER/ACK + concurrent DNS/gateway drift + new outbound sessions to unknown resolvers/proxies.

## 12. Mitigations
- **M1037 Filter Network Traffic:** Filter DHCP traffic (ports 67/68) to/from unknown/untrusted DHCP servers; enable DHCP snooping and switch port security; track address pool health. Also consider blocking DHCPv6 traffic/router advertisements if IPv6 is unused.
- **M1031 Network Intrusion Prevention:** Use NIDS/NIPS to identify AiTM-related traffic patterns and rogue DHCP behavior.

## 13. Testing & Validation
- Validate that detections trigger on:
  - Competing DHCP OFFERs from non-authorized sources
  - Unexpected DNS/gateway assignments at scale
  - DHCP pool exhaustion-like patterns
- Confirm SOC playbooks include rapid isolation via switch port/AP controls and host remediation for DHCP parameters.
