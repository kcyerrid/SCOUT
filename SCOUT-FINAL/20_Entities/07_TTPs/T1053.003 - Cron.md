# Scheduled Task/Job: Cron (T1053.003)

## 1. Summary
Cron describes adversaries **abusing Unix-based cron scheduling mechanisms** to execute malicious commands or programs on a recurring or scheduled basis. Cron jobs are widely used for legitimate system administration, making malicious use difficult to distinguish from normal activity.

T1053.003 is commonly used to:
- Establish long-term persistence
- Execute payloads on a fixed or recurring schedule
- Run malicious code under elevated contexts
- Blend malicious activity with legitimate administrative behavior

---

## 2. Technical Overview
Cron is a time-based job scheduler used on Unix-like systems. Adversaries abuse this by:
- Creating or modifying crontab entries
- Dropping malicious scripts referenced by cron jobs
- Using system-wide cron directories (e.g., `/etc/cron.*`)
- Scheduling execution under root or privileged users

Relevant locations and components include:
- User crontabs (`crontab -e`)
- `/etc/crontab`
- `/etc/cron.d/`
- `/etc/cron.hourly/`, `/daily/`, `/weekly/`, `/monthly/`

Artifacts often include:
- New or modified cron entries
- Scripts executed at regular intervals
- Execution occurring during off-hours
- Commands running without interactive sessions

---

## 3. Subtechnique Considerations
Key considerations for T1053.003:
- Extremely common and reliable persistence mechanism
- Often poorly monitored in server environments
- Can survive reboots and user logouts
- Difficult to attribute without strong baselining

Cron is one of the most prevalent Unix persistence techniques.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Scheduling backdoor scripts to run every minute
- Executing remote payloads via cron-invoked commands
- Using cron to re-establish access if malware is removed
- Combining cron persistence with downloader malware

These actions typically occur post-compromise.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring creation and modification of crontab files
- Alerting on cron jobs referencing suspicious scripts or URLs
- Correlating cron execution with network activity
- Identifying execution by cron outside expected maintenance windows

### Data Source Notes
- **File monitoring**: Primary detection surface
- **Process telemetry**: Required for execution correlation
- **Audit logs**: Useful for attribution and timing analysis

---

## 6. Response Guidance
When detected:
1. Identify and remove malicious cron entries
2. Inspect referenced scripts and binaries
3. Isolate affected hosts if persistence is confirmed
4. Review account access and privilege usage
5. Hunt for additional persistence mechanisms

## 8. SOC Relevance
T1053.003 is especially relevant in:
- Linux and macOS server environments
- Cloud and container host systems
- Long-dwell intrusions and backdoor persistence

Cron abuse often indicates intent for long-term access.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Advanced persistent threats
- Commodity malware operators
- Cryptomining and botnet campaigns

Its ubiquity makes it a default persistence choice.

---

## 10. Campaign Usage
Observed in:
- Web server compromise campaigns
- Cloud infrastructure intrusions
- Long-running persistence-focused attacks

---

## 11. Malware Usage
Malware leveraging cron includes:
- Backdoors
- Cryptominers
- Loaders and downloader scripts

---

## 12. Mitigations
Recommended mitigations:
- Monitor and restrict cron usage
- Audit crontab entries regularly
- Enforce least privilege for scheduling
- Use file integrity monitoring on cron directories
- Baseline expected scheduled tasks

---

## 13. Testing & Validation
Validation approaches:
- Create test cron jobs in lab environments
- Validate SOC detection of cron modifications
- Conduct red team testing focused on Unix persistence
- Review monitoring gaps in scheduled execution
