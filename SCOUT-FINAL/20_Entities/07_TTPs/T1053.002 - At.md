# Scheduled Task/Job: At (T1053.002)

## 1. Summary
The **At** subtechnique describes adversaries **using the legacy `at` scheduling utility to execute commands or programs at a specified time**. Although deprecated in many modern systems, `at` remains present or installable in some environments and can be abused for persistence, delayed execution, or privilege escalation.

T1053.002 is commonly used to:
- Schedule one-time or delayed execution
- Maintain persistence with minimal visibility
- Execute payloads outside interactive sessions
- Abuse legacy scheduling mechanisms

---

## 2. Technical Overview
The `at` utility allows users to queue jobs for execution at a later time. Adversaries abuse this by:
- Creating scheduled jobs that execute malicious commands
- Running tasks under elevated or system-level contexts
- Leveraging non-interactive execution to evade detection
- Combining `at` with downloaded or staged payloads

Relevant components include:
- `at`, `atq`, `atrm`
- Windows Task Scheduler legacy support
- System job queues and cron alternatives

Artifacts often include:
- Scheduled jobs not associated with legitimate administration
- Commands executed outside normal user activity windows
- Process creation events tied to scheduler services
- Job queue entries with suspicious commands

---

## 3. Subtechnique Considerations
Key considerations for T1053.002:
- Often overlooked due to deprecation
- Less monitored than modern schedulers (cron, schtasks)
- Can still exist in legacy or misconfigured systems
- Useful for stealthy delayed execution

Detection coverage is frequently incomplete.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Scheduling malware execution during off-hours
- Using `at` to run scripts fetched from remote locations
- Establishing one-time persistence for payload delivery
- Executing commands under elevated scheduler contexts

These activities typically occur post-compromise.

---

## 5. Detection Guidance
Detection strategies should focus on:
- Monitoring creation and modification of scheduled jobs
- Detecting execution originating from scheduler services
- Alerting on use of deprecated scheduling utilities
- Correlating scheduled execution with prior compromise indicators

### Data Source Notes
- **Scheduled job logs**: Primary detection surface
- **Process telemetry**: Required for execution correlation
- **Command-line logging**: Useful for identifying malicious jobs

---

## 6. Response Guidance
When detected:
1. Identify and remove malicious scheduled jobs
2. Investigate commands and payloads executed
3. Isolate affected systems if persistence is confirmed
4. Review user accounts responsible for job creation
5. Search for additional persistence mechanisms

## 12. Mitigations
Recommended mitigations:
- Disable or remove legacy scheduling utilities where possible
- Monitor scheduled job creation and execution
- Enforce least privilege on job scheduling
- Harden systems against unauthorized scheduler access
