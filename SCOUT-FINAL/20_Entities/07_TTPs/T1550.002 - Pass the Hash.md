## 1. Summary
Pass the Hash (T1550.002) is adversary authentication using a stolen password hash (commonly NTLM) rather than a plaintext password, enabling remote access and lateral movement while appearing as valid logons.

## 2. Technical Overview
- **Core behavior:** An attacker uses an acquired hash to authenticate (often over SMB/RPC/WMI/WinRM) without needing the password.
- **Common operational outcomes (defender view):**
  - Remote logons and service execution tied to privileged accounts.
  - Rapid lateral movement after credential theft/dumping.
  - “Overpass-the-hash” variants can lead into Kerberos ticket activity. :contentReference[oaicite:31]{index=31}
- **Key risk:** Often bypasses controls that focus on password entry and can blend with admin workflows if not baselined.

## 3. Subtechnique Considerations
- Sub-technique of [[20_Entities/07_TTPs/TA0005 - Defense Evasion/T1550 - Use Alternate Authentication Material|T1550]].
- Typically **Windows-only**, and most reliably detected via **auth/session telemetry** correlated with **process/network** events, not via static signatures.

## 4. Procedure Examples
MITRE procedure examples include multiple groups and tools documented using PtH (e.g., APT1, APT28, APT32, APT41, Aquatic Panda; tools such as Mimikatz, CrackMapExec, Cobalt Strike, Empire, PoshC2). :contentReference[oaicite:32]{index=32}

## 5. Detection Guidance
Prioritize **behavioral correlation** proving suspicious NTLM network authentication that doesn’t align with baseline identity behavior.

**Core analytic goals (from MITRE detection strategy)**
- Detect **anomalous NTLM LogonType 3** authentications without expected accompanying domain logon events.
- Correlate **session creation → NTLM authentication → process/service initiation** to expose remote use of hashes. :contentReference[oaicite:33]{index=33}

**High-signal detection patterns**
- **Auth anomalies**
  - Spikes in 4624 LogonType 3 for privileged accounts from unusual sources.
  - Lateral systems authenticating without normal interactive precursors.
- **Context mismatch**
  - Source workstation not historically associated with the user/admin.
  - Authentication followed quickly by remote execution/service creation patterns.
- **Overpass indicators**
  - Kerberos ticket activity correlated with NTLM lateral authentication chains (hybrid sequence). :contentReference[oaicite:34]{index=34}

## 6. Response Guidance
1. **Contain**
   - Isolate the suspected source host(s); block lateral protocols temporarily if needed (SMB/RPC/WinRM) for containment.
2. **Credential remediation**
   - Reset impacted accounts; prioritize admins and service accounts; rotate local admin passwords (unique per host).
3. **Hunt scope**
   - Identify all LogonType 3 events for the principal; enumerate destination hosts, processes, and network connections in the time window.
4. **Eradicate**
   - Remove credential dumping tools/persistence; verify LSASS protection posture and EDR tamper events.
5. **Hardening**
   - Reduce credential reuse/overlap; apply relevant Windows protections; restrict admin logons and lateral credential exposure.

- **Critical** in Windows enterprise environments; frequently used by ransomware and espionage operators.
- **Best SOC leverage:** Correlation rules over authentication + endpoint + network telemetry; rapid identity containment playbooks.

## 12. Mitigations
- **Privileged Account Management:** Reduce credential overlap; prevent easy lateral movement. :contentReference[oaicite:42]{index=42}
- **Update Software:** Apply Windows patch guidance referenced by MITRE to reduce default admin credential abuse paths. :contentReference[oaicite:43]{index=43}
- **User Account Control:** Enforce network logon restrictions for local accounts; apply PtH mitigations. :contentReference[oaicite:44]{index=44}
- **User Account Management:** Prevent domain users/admins from being local admins on multiple systems. :contentReference[oaicite:45]{index=45}
