# Spearphishing Link (T1566.002)

## 1. Summary
Spearphishing Link describes adversary use of targeted phishing messages that contain malicious hyperlinks rather than attachments. These links typically lead to credential harvesting pages, malware delivery infrastructure, or compromised legitimate websites. This subtechnique is highly effective due to its simplicity and ability to evade some attachment-focused security controls.

Spearphishing links are frequently customized to the victim’s role, organization, or current events to increase the likelihood of interaction.

---

## 2. Technical Overview
Adversaries deliver phishing messages containing embedded URLs via email, messaging platforms, or collaboration tools.

Common technical elements include:
- Lookalike or typosquatted domains
- URL shorteners or redirect chains
- Links to cloud-hosted payloads or credential harvesting pages
- HTML smuggling or dynamic payload delivery after link access

Artifacts include email delivery metadata, DNS queries, HTTP requests, redirected web traffic, and subsequent authentication or endpoint activity.

---

## 3. Subtechnique Considerations
T1566.002 differs from other phishing subtechniques by:
- Relying on **URL-based delivery** rather than file attachments
- Frequently leveraging cloud services to host malicious content
- Often preceding credential abuse rather than immediate malware execution

Effectiveness depends heavily on URL reputation controls and user awareness.

---

## 4. Procedure Examples
Observed adversary procedures include:
- Impersonating SaaS login portals to harvest credentials
- Linking to cloud storage hosting malicious payloads
- Using redirect chains to evade URL scanning
- Delivering HTML smuggling pages that reconstruct payloads client-side

Analysts may observe credential submission followed by suspicious authentication activity.

---

## 5. Detection Guidance
Detection should focus on link interaction and downstream behavior:
- Emails containing newly registered or low-reputation domains
- User clicks followed by suspicious DNS or HTTP activity
- Authentication attempts shortly after link access
- Browser processes spawning child processes or downloads

Correlation between email, web, identity, and endpoint telemetry is essential.

### Data Source Notes
- **Email Gateway Logs:** Primary detection source for malicious links
- **Web Proxy Logs:** High value for identifying redirect chains
- **DNS Logs:** Useful for detecting access to newly registered domains
- **Authentication Logs:** Critical for identifying credential misuse

---

## 6. Response Guidance
When spearphishing links are identified:
- Remove malicious messages from all mailboxes
- Block malicious domains and URLs
- Reset credentials for affected users
- Review authentication and endpoint activity for follow-on compromise

Preserve email samples, URLs, and web artifacts for analysis.

## 8. SOC Relevance
Spearphishing links are one of the most common precursors to account compromise and ransomware activity. SOC teams must maintain strong visibility into user click behavior and rapid response workflows.

---

## 9. Threat Actor Usage
This subtechnique is used by:
- Ransomware operators and affiliates
- Credential harvesting operations
- Advanced persistent threat groups conducting targeted access

Confidence in widespread usage is extremely high.

---

## 10. Campaign Usage
Spearphishing links appear in:
- Large-scale credential harvesting campaigns
- Targeted access broker operations
- Malware loader distribution campaigns

---

## 11. Malware Usage
Malware frequently delivered or staged via spearphishing links includes:

## 12. Mitigations
Effective mitigations include:
- URL rewriting and time-of-click analysis
- Blocking newly registered or low-reputation domains
- Enforcing MFA to reduce credential theft impact
- User awareness training focused on link-based phishing
- Browser isolation for untrusted links

---

## 13. Testing & Validation
Validation approaches include:
- Phishing simulations using link-based payloads
- Purple team exercises testing URL detection and response
- Review of click-to-detection and remediation timelines

Successful validation results in rapid detection and containment.
