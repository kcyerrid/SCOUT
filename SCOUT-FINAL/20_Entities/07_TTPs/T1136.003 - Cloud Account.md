# T1136.003 – Cloud Account

## 1. Technique Overview
**Cloud Account (T1136.003)** is a sub-technique of **Create Account (T1136)** in **MITRE ATT&CK v18**. Adversaries create **new cloud-based identities**, including user accounts or service principals, to establish persistent access in cloud environments. Because these accounts are native to the cloud identity provider, they often evade detection mechanisms focused on endpoint or on-premises identity controls.

This technique is frequently observed in intrusions targeting **Azure AD / Entra ID, AWS IAM, Google Cloud IAM**, and other SaaS identity platforms.

## 2. Adversary Objectives
Adversaries create cloud accounts to:
- Maintain long-term access independent of stolen credentials
- Bypass password resets and token revocation
- Blend malicious identities into legitimate cloud user populations
- Enable persistent API, console, or service access

## 3. Common Abuse Patterns
- Creating new cloud users with benign or service-like names
- Registering service principals or IAM roles with elevated permissions
- Assigning excessive roles to attacker-created accounts
- Disabling MFA or enforcing weak authentication settings
- Using cloud-native APIs or consoles for account creation

## 4. Detection Considerations
Detection relies on **cloud identity and audit telemetry**, including:
- Monitoring cloud account creation events
- Alerting on new accounts assigned privileged roles
- Correlating account creation with anomalous API or console activity
- Reviewing cloud audit logs for unauthorized identity changes
- Identifying accounts created outside approved provisioning workflows

## 5. Defensive Mitigations
- Enforce least privilege and approval workflows for cloud account creation
- Require MFA for all cloud identities, including service accounts
- Monitor and alert on privileged role assignments
- Regularly audit cloud identity inventories
- Remove unauthorized cloud accounts immediately during response

## 6. Operational Impact
If successful, T1136.003 can:
- Provide durable, cloud-native persistence
- Enable stealthy access via trusted cloud identities
- Facilitate data access, exfiltration, or further compromise
- Complicate incident response due to distributed cloud scope

## 7. Analyst Notes
Cloud account creation is one of the most dangerous persistence techniques in modern environments because it often survives endpoint remediation and credential resets. Incident response must include **comprehensive cloud identity review**, including users, service principals, and API credentials, to fully eradicate attacker persistence.
