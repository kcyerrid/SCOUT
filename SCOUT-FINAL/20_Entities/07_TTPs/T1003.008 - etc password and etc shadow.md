## 1. Summary
**/etc/passwd and /etc/shadow (T1003.008)** is a Linux credential dumping subtechnique where adversaries read these sensitive files to obtain user/account metadata and password hashes (from `/etc/shadow`) for **offline cracking** and follow-on credential abuse.

## 2. Technical Overview
Defender-relevant behaviors:
- **Direct reads** of `/etc/passwd` and `/etc/shadow` via common utilities (e.g., `cat`, `less`) or via programmatic file reads.
- **Copy/stage artifacts**: creation of backups or temporary combined files for later cracking workflows.
- **Privilege requirement**: `/etc/shadow` is typically readable only by **root**; access by non-root users or unexpected processes is strong signal.
- **Follow-on**: stolen hashes are often cracked elsewhere; on-host cracking may or may not be observed.

## 3. Subtechnique Considerations
- This subtechnique is frequently paired with:
  - Privilege escalation to reach `/etc/shadow`
  - Discovery of local users/service accounts
  - Subsequent SSH/sudo abuse using cracked credentials
- Watch for targeting of high-value Linux nodes (container hosts, CI runners, GPU/AI nodes, bastions).

## 4. Procedure Examples
MITRE ATT&CK procedure examples include:
- [[30_CIPHER/05_Malware/S0349 - LaZagne]] obtaining credential information from `/etc/shadow`.
- **C0045 - ShadowRay**: threat actors used `cat /etc/shadow` to steal password hashes.

## 5. Detection Guidance
High-signal analytics:
- **Read access to `/etc/shadow`**
  - Any access by non-standard processes (especially not associated with auth/account mgmt)
  - Access by unusual users, cron contexts, or web/service accounts
- **Sequencing detections**
  - Privilege escalation → `/etc/shadow` read → creation of a new file in `/tmp`, user home, or app directories
  - `/etc/shadow` read followed by new SSH/sudo activity from atypical accounts
- **Staging and exfil**
  - Sensitive file read followed by compression/encryption utilities and outbound network connections

False-positive management:
- System utilities and legitimate administrative workflows may access `/etc/passwd`; prioritize `/etc/shadow` and any copy/stage behavior.

### Data Source Notes
Recommended telemetry:
- Linux **file access auditing** (auditd/eBPF/EDR) for `/etc/shadow` and `/etc/passwd`
- Process execution and parent/child lineage (shell, cron, services)
- Privilege escalation indicators (sudo, setuid, capabilities)
- Auth telemetry (sshd logs, sudo logs) for post-dump credential usage

## 6. Response Guidance
- **Contain**: isolate the host if active harvesting is confirmed; terminate suspicious sessions/processes.
- **Credential actions**: rotate affected local/service account passwords; consider forcing credential resets for accounts that logged in on the host.
- **Scope**: identify other Linux systems where the same account/process accessed `/etc/shadow`.
- **Hardening**: minimize root access, reduce password-based auth exposure, and enforce strong password policies.

## 12. Mitigations
- **M1027 - Password Policies**: strong, unique passwords for root and service accounts to reduce cracking success.
- **M1026 - Privileged Account Management**: restrict and monitor root access; apply least privilege and account separation.
- Reduce password-based auth exposure where feasible (e.g., enforce key-based SSH for admins and disable weak/legacy configs).

## 13. Testing & Validation
- In a lab:
  - Validate alerting on `/etc/shadow` read access with process + user context.
  - Validate correlation rules: sudo/priv-esc → `/etc/shadow` read → staging/exfil indicators.
- Ensure allowlists for legitimate compliance/audit tooling are explicit and reviewed.
