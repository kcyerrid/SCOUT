## 1. Summary
Adversaries hijack an existing SSH session to move laterally by abusing trust relationships established through active SSH connections (often via SSH agent compromise or access to the agent socket), rather than authenticating anew with credentials. :contentReference[oaicite:68]{index=68}

## 2. Technical Overview
- **What it is:** Takeover/reuse of SSH session state (e.g., via SSH agent or socket) to access additional hosts.
- **Key enabling conditions:**
  - long-lived SSH sessions
  - SSH agent forwarding enabled where not required
  - attacker access to the host and/or another user’s agent socket
- **How it differs from SSH (remote service use):** hijacks an existing session instead of creating a new one using valid accounts. :contentReference[oaicite:69]{index=69}

## 3. Subtechnique Considerations
- Compared to **RDP Hijacking (T1563.002)**, SSH Hijacking often pivots on **socket/agent access** and may not generate traditional “new login” artifacts on the destination host.
- Telemetry quality varies widely: without EDR/auditd/FIM, agent-socket access may be difficult to observe.

## 4. Procedure Examples
- [[30_CIPHER/05_Malware/S1220 - MEDUSA|MEDUSA]] can be configured to capture SSH credentials via SSH hijacking. :contentReference[oaicite:70]{index=70}  

## 5. Detection Guidance
**MITRE detection strategy-aligned analytics**
- Detect suspicious reuse of SSH agent sockets across users/processes, anomalous access to `~/.ssh/` or agent sockets (e.g., `/tmp/ssh-*`), and lateral SSH activity without corresponding new authentication events. :contentReference[oaicite:71]{index=71}
- Correlate agent-socket access with anomalous internal SSH network flows. :contentReference[oaicite:72]{index=72}

**High-signal detections**
- **Cross-user socket access:** a process owned by User A accessing User B’s `$SSH_AUTH_SOCK`.
- **Unusual agent-forward usage:** agent forwarding enabled from hosts that normally do not require it.
- **Pivot without login:** destination host sees command execution over an established connection without a fresh auth log sequence.

### Data Source Notes
*(Leave YAML `datasources` empty unless you have a canonical local mapping. Below are practical telemetry requirements.)*
- **Linux/macOS audit:** file/socket access auditing for agent sockets; process-to-socket correlation.
- **SSHD logs:** auth log correlation to session activity; session open/close; source host tracking.
- **EDR telemetry:** process trees initiating SSH connections; unusual access to `.ssh` material; suspicious lateral SSH flows.

## 6. Response Guidance
1. **Terminate suspect sessions:** kill SSH sessions and revoke agent forwarding where possible.
2. **Rotate keys/credentials:** replace affected SSH keys; enforce passphrases and modern key types.
3. **Check for privilege escalation:** root access makes session hijacking trivial—verify whether escalation occurred. :contentReference[oaicite:73]{index=73}
4. **Harden SSH posture:** disable agent forwarding by default; restrict which hosts/users can use it.

## 12. Mitigations
- **Disable or Remove Feature or Program (M1042):** disable agent forwarding on systems that don’t explicitly require it. :contentReference[oaicite:75]{index=75}  
- **Password Policies (M1027):** strong passphrases for SSH key pairs; avoid weakly protected key stores. :contentReference[oaicite:76]{index=76}  
- **Privileged Account Management (M1026):** avoid remote access via SSH as root/privileged accounts. :contentReference[oaicite:77]{index=77}  
- **Restrict File and Directory Permissions (M1022):** harden permissions and reduce escalation paths. :contentReference[oaicite:78]{index=78}  

## 13. Testing & Validation
- Validate detection for:
  - unusual access to `$SSH_AUTH_SOCK`
  - SSH pivots lacking corresponding auth events
  - `.ssh` directory access anomalies
- Purple-team by simulating benign agent forwarding use vs. abnormal cross-user socket access (no credential theft required).
